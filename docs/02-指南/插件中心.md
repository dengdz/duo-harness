# 插件中心

> 本文对齐 1.1.0，操作指南体裁。读者定位：想在 Web 页面上**装、停、换、卸插件**的部署者。机制与挂载地图查[插件扩展点清单](../05-参考/插件扩展点清单.md)，自己写插件查[插件包交货指南](../03-高级/插件包交货指南.md)。

## 入口

Web 页面状态区（右栏）顶部的**「插件中心」按钮**，点开右滑抽屉。前提：装配文件里有这一行（opt-in，不装行零感知）：

```yaml
plugins:
  - id: plugin-center
    name: dev.duo.harness.center.PluginCenterPlugin
```

抽屉分四区：**已装与装配行**、**待装（目录扫描）**、**挂类路径插件**、底部状态汇总行。

## 先读两句：信任模型与边界

- **装插件 = 装任意代码。** 插件以与你完全相同的权限运行在 duo 进程里（Java 同进程没有沙箱边界）。v1 的信任模型是**自用 + 熟人圈**：只装自己写的或信任作者给的包——装前点名是告知义务，不是安全审查。
- **审批策略槽位可换，内核闸门不放松。** 你可以用插件替换审批策略（见下文"换审批策略"），但 guard 单调否决、规则 deny 恒优先、审批挂起 fail-closed 三道内核闸门不随槽位替换放松。换掉审批策略 = 你自担档位语义。

## 待装：扫描 → 点名 → 安装

1. 把插件包（fat-jar，见[交货指南](../03-高级/插件包交货指南.md)）放进 `~/.duo/plugins/`；
2. 打开插件中心，**待装区**自动列出目录里的包（文件名 · 大小 · sha256 前 8 位）；
3. 点**安装**：确认入口类（唯一候选自动预填）与装配行 id、config JSON；
4. 装载运行期即时生效——服务、工具随包注册，无需重启。

安装同时写回装配文件 `~/.duo/plugins.yml`（新增带 `jar:` 来源的行），**重启后保持**。装配文件是唯一事实源：页面上的一切操作都落在它上面，排查"为什么在跑/为什么没跑"只看这一个文件。

## 已装行：停用 / 启用 / 改配置 / 卸载

已装区每行展示 id、六态状态与操作按钮：

| 操作 | 运行期效果 | 装配文件 |
|---|---|---|
| 停用 | 服务与工具即时摘除，依赖它的插件自动回落等待 | 行置 `disabled: true` |
| 启用 | 按装配行重建装载（插件包行重建类加载器） | 翻回 `disabled` |
| 改配置 | 停→改→启一步完成（服务端 `reconfigure`） | 行内 config 替换 |
| 卸载 | 彻底退场（同上，且删行） | 行删除 |

- **改配置**即"停→改→启"向导：弹出 JSON 编辑（预填现状），确认后拔了按新配置重装——无状态插件无需重启。
- 标注**「需重启生效」**的行（如 `cli` 呈现位——它的 apply 就是终端主循环；插件中心自身）不可运行期停/启：请编辑装配文件后重启进程。
- 卸载有**二次确认**；卸载后同包会重新出现在待装区，可再装。

## 挂类路径插件：换审批策略等

内置实现之间的替换走**挂类路径插件**表单（行 id + 入口类 FQCN + config）——典型场景是换审批策略。例：现行装配行是 `approval`（档位制），想换成全自动批准：

1. 在已装区**卸载**现行 `approval` 行（二次确认）；
2. 表单填：行 id `approval`、入口类 `dev.duo.harness.tools.ApprovalPlugin`、config 按需；
3. **挂载**（二次确认）——新行装载并写回装配文件。

内置三实现：`ApprovalPlugin`（always-deny / auto-approve）、`InteractiveApprovalPlugin`（全 ask）、`WorkspaceApprovalPlugin`（三档位制）。第三方实现同样走这个表单或[交货指南](../03-高级/插件包交货指南.md)的插件包通道。再次强调：换的是**策略**，guard / 规则 deny / fail-closed 三道内核闸门不随之放松。

## 状态汇总行

抽屉底部实时汇总：`共 N 行：X 活跃 / Y 未运行`。行状态为六态实时快照（`ACTIVE` / `PENDING` / `FAILED`…；装配文件里停用的行显示「已停用」）。`启用却显示「未运行」`是坏载信号——查服务端日志的启动点名。

## 已知边界

- 改配置/启停是**运行期**操作，配置文件仍是重启装配的依据——"改了 yml 没生效"请确认改的是页面写回的同一份 `~/.duo/plugins.yml`；
- 类加载器泄漏（罕见）时卸载不彻底，页面与日志会提示**需重启生效**；
- 贡献端点（`/plugins/center/**` 与其他插件的挂接）一律过 Web 鉴权栅栏，`auth: none` 时与普通端点同样裸奔——页面横幅会提醒你。
