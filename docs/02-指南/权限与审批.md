# 权限与审批

这篇讲 duo-harness 的权限控制面：agent 能动什么、什么时候需要你拍板、怎么把你的决定变成持久规则。配套的命令是 `/permission`，配置落在权限预设与规则文件两处。

## 三档权限预设

agent 的文件与命令权限按三档预设裁决，`mode` 在 `fs-tools` 装配行配置默认档，运行中随时切换：

```bash
/permission                    # 查看当前档位与规则清单
/permission read-only          # 切到只读档
/permission workspace-write    # 切到工作区写档（默认）
/permission danger-full-access # 切到危险档
```

| 档位 | 读 | 工作区内写 | 工作区外写 | bash | 联网 |
|---|---|---|---|---|---|
| `read-only` | ✅ | ❌ ask | ❌ ask | ask | ask |
| `workspace-write`（默认） | ✅ | ✅ 免审 | ❌ ask | ask | ✅ 放行 |
| `danger-full-access` | ✅ | ✅ | ✅ | ✅ | ✅ |

三档都是读放行；写与执行按「区内放行、越界必问」的边界裁决。bash 是特例——它的写范围不受 workspace 约束，所以**非危险档一律先问**，唯一例外是下面讲的只读命令免审。联网工具（抓取/搜索）按网络读档位：只读档 ask，其余档放行。

切档即时生效，不用重启。

## 审批如何发生

工具声明「需要审批」时，请求会送到你能看见的地方：

- **终端里**：行内 `y/n` 问答；
- **浏览器里**：消息流弹出审批卡，列出工具名、参数摘要与风险点。

两条铁律贯穿所有审批：

1. **一次性**——批准只对这一次调用生效，没有「永久放行」的按钮会跳过后续审批；
2. **无人应答等于拒绝**（fail-closed）——你不回答（终端 Ctrl+C/EOF、浏览器全部页面关闭且宽限期内无新连接），审批按拒绝收敛，模型会收到拒绝并继续解释或换路。

## 审批卡上的四个选择

浏览器审批卡给四个按钮，去向各不相同：

| 按钮 | 效果 |
|---|---|
| 批准 | 本次调用放行 |
| 拒绝 | 本次调用拦截，模型收到拒绝与你的理由（可附言） |
| **总是允许（项目）** | 生成一条 allow 规则写入项目 `.duo/settings.json`——同形请求此后免审 |
| **仅本会话** | 生成一条会话级 allow 规则，随会话持久、重启恢复，但只属于这个会话 |

「总是允许」生成的规则可以在规则清单里查看和移除（见下节）。

一条安全例外：**高危根命令永不放行**——`sudo` / `su` / `doas` / `rm` / `dd` / `mkfs` / `chmod` / `chown` / `shutdown` / `reboot` 十个提权或不可逆破坏命令，审批卡上**不出现**「总是允许」键，手写 allow 规则对它们也不生效（命中一律走 ask/档位裁决）。

## 权限规则：把决定持久化

规则是两级作用域的持久审批规则，裁决序是 **deny 恒优先 → allow 次之 → 未命中交内层链（档位与审批）**——一条 deny 规则压过任何 allow，与 guard 的单调否决同构。

### 项目级：`.duo/settings.json`

项目根（`.git` 标定，缺省为当前目录）的 `.duo/settings.json`：

```json
{
  "permissions": {
    "rules": [
      { "tool": "bash", "prefix": "npm test:*", "decision": "deny" },
      { "tool": "web_fetch", "decision": "allow" }
    ]
  }
}
```

- `tool` 与 `decision` 必填；`decision` 限 `allow` / `deny`；
- `prefix` 仅对 bash 有意义：`Bash(prefix:*)` 记法按**词边界**匹配——命令与前缀全等，或前缀之后紧跟空白（`ls:*` 吞不掉 `lsof`）；省略 `prefix` 即工具级规则（该工具任意参数）；
- **deny 规则只出手写**（审批卡不生成 deny）；allow 规则由审批卡「总是允许（项目）」生成；
- 文件缺席就是空规则；坏 JSON 记警告按空处理，不崩。

### 会话级：随会话走

「仅本会话」生成的规则随 `permission/rules` 事件持久在会话日志里，重启恢复后依然生效——但只属于那一个会话，不污染其他会话。

### 管理规则

```bash
/permission rules list         # 项目级（P#）与会话级（S#）规则清单
/permission rules rm P1        # 移除一条项目级规则（写回 settings.json）
/permission rules rm S2        # 移除一条会话级规则
```

## 只读命令免审

bash 在非危险档默认先问，但**只读命令**不用烦你：38 个常见只读命令（ls、cat、grep、find 等）加 git 的四件套只读子命令（status/log/diff/show）前置免审——它们被判定为不可能产生副作用。

防逃逸设计：git 命令叠加 `.git` 信任分类——`git -C <别处>` 指向非当前项目时按可疑处理，防止借只读皮执行越界操作。免审清单外的命令照常 ask。

## 计划模式：先看方案再动手

```bash
/plan                 # 进入计划模式（可带任务描述直接开始探索）
/plan 整理示例目录     # 进入并直接开始设计
/plan off             # 退出计划模式
```

计划模式下模型**只读推进**：探索代码、设计方案，写操作与执行被硬性禁止（`PlanBashGate` 拦截）。方案成型后模型调 `exit_plan_mode` 呈交计划，你选：

- **批准**——立即开始执行；
- **打回**——附反馈让模型改了再呈交。

不回答同样 fail-closed：计划不批准，保持计划模式。
