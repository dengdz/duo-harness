# 会话管理与恢复

这篇讲 duo-harness 的会话面：会话存在哪、怎么开新话题、换设备或重启后怎么找回现场、多标签多入口时怎么不打架。

## 会话存在哪

每个会话是一个 JSONL 文件，落在 `~/.duo/agent-sessions/`，文件名即会话 id。它是事件溯源日志——每一轮对话、每次工具调用、每个审批决定都完整在案，所以崩溃可回放、跨进程可续接。

一个细节对日常使用很重要：**新建会话不产生文件**。打开页面、新开标签、服务重启都不落盘——直到你发出第一条真实消息，会话才被写下来。所以侧栏里出现的都是真有内容的会话，不会堆积空壳。

## 日常操作

| 想做什么 | 怎么做 |
|---|---|
| 开新话题 | 终端 `/new`；浏览器侧栏「＋ 新话题」 |
| 改标题 | `/title 新标题`——侧栏与标签页即时生效（不设则首条消息自动生成，失败降级取前 20 字） |
| 结束终端会话 | `/exit`——锁释放、回答者摘除，插件树不受影响；彻底停止进程用 Ctrl+C |
| 切换历史会话 | 浏览器侧栏点击；**运行中不整页重载**，页面静默换绑到目标会话的尾部窗口 |

输入框里没发送的草稿在切换会话时按语境清空，不会串到别的会话。

## 重启与恢复

会话自动续接：终端重启后接着上次聊；浏览器刷新或重进也一样——首屏重建为**最近 50 条消息**的尾部窗口，更早的历史滚动到顶自动向上分页加载（顶部提示「更早还有 N 条」），视窗不跳屏。

`/model` 切换过的会话有一条保护语义：恢复时提示保存的模型意图但**不自动切**——执行绑定与保存意图分离，防误切。

## 多标签与多入口

浏览器多个标签页**各自绑定自己的会话**（每标签一个 sessionId），互不踩踏；同一会话同一时刻只允许一个属主（独占锁）：

- 先打开者持锁；后到者收到明确占用提示——CLI 改开新会话继续，Web 面启动失败并点名被占会话，不会静默双写；
- 被占用的会话在侧栏显示灰色「使用中」点；
- 悬空的审批卡片在刷新后仍可回答（不误杀）；全部页面关闭且宽限期内无人接手，审批按拒绝处理——人不在环等于不批准。

终端与浏览器操作**同一份会话**、同一套审批路由：模型在终端发起的写文件审批，你在浏览器卡片上批准同样有效。

## 找回历史内容

- **侧栏搜索框**：按关键词搜历史会话，命中列表带【】摘录标记，点击直达；只搜与当前工作目录相同的会话（防跨项目串味）；
- **让模型找**：对话里问「搜一下之前哪个会话讨论过 X」，模型调 `session_search` 引用会话 id 与摘录回答；
- **带走一份**：`/export` 导出人读记录（CLI 写盘当前目录，Web 自动下载）——详见[导出与检索指南](导出与检索.md)。
