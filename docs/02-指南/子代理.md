# 子代理

这篇讲怎么让主 agent 把大任务拆给子代理并行干：什么时候拆、模板怎么配、拆出去的任务怎么管。

## 什么时候拆子代理

两类任务值得拆：

- **独立子任务并行干**——比如「同时调研这几个目录的测试覆盖率」，几个子代理各领一块，互不等待；
- **大块脏活隔离干**——比如让子代理通读一个大型模块并产出摘要，几万 token 的中间过程不占主对话的上下文窗口。

一句话任务不需要拆；强依赖前序结论的串行步骤也不适合拆（子代理之间不共享上下文）。

## 模板：部署者说了算

子代理**不是模型随意定制的**——能用什么工具、跑多少轮，全由装配里的模板预审定：

```yaml
  - id: subagent
    name: dev.duo.harness.agent.subagent.SubagentPlugin
    config:
      templates:
        - name: researcher        # 模板名，spawn 时按名引用
          tools: [read, glob, grep]   # 该模板可用的工具白名单
          prompt: "你是代码调研员，只读不写，结论给出文件与行号。"
          maxIterations: 30       # 迭代上限（防失控）
```

- 未知字段直接装配失败（fail-fast 点名），不静默忽略；
- 不配 `templates` 则模型无子代理工具可用——不装行或零模板即零感知。

## 五件工具

| 工具 | 干什么 |
|---|---|
| `spawn` | 把子任务交给**全新**子代理：传入模板名 + 任务描述，立即返回 agent id，后台运行；完成后最终回答自动回流父对话 |
| `fork` | 带**当前对话背景**派生子代理——父对话的前因后果自动播种为子会话开头，子任务无须重新交代 |
| `send_message` | 给运行中的子代理**补充指示**（下一轮生效，中途纠偏不推倒重来）；给空闲/失败的子代理开启新一轮 |
| `list_agents` | 列出全部子代理的 id / 模板 / 状态（运行中/空闲/失败/中断） |
| `interrupt_agent` | 中止跑偏的子代理（协作式中止，中止痕迹留档可审计） |

治理权归父：控制面三件（`send_message` / `list_agents` / `interrupt_agent`）**不会出现在子代理自己的工具集里**——子代理不能再派生子代理的治理操作。

## 一个重要的边界：子代理看不到你的约定

子代理的 system 提示只含框架基线与模板提示词，**不带**你的技能名录与 AGENTS.md（此为已知限制，见[已知限制](../limitations.md)）。落到用法上：凡是子代理需要的项目约定、规范条文、路径线索，**必须由主 agent 写进任务描述原文**——告诉子代理「照着 AGENTS.md 的规范」没用，它看不到。
