## 1. 调用权分流（user-invoked 硬隔离）

**机理**：每个技能在 frontmatter 里回答"模型能否自主触达它"——这是编译期决定，不是运行时自觉。

- 唯一分流轴是 invocation（invocation.md:3）。user-invoked 技能设 `disable-model-invocation: true`，"reachable only by the human typing its name"（invocation.md:5），description 随之变为人类面向的一行摘要并**剥掉触发词表**（"Strip trigger lists"）。
- model-invoked 是缺省档：description 保留富触发措辞（"Use when the user wants…"）供自动点火；留下与否的判据测试是"**could the model usefully reach for this autonomously?**"，并强调"复用是提取技能的理由，不是这个测试"（invocation.md:6）。
- **硬隔离不变式**：user-invoked 技能任何其他技能都无法触达——"no other skill can fire it"（invocation.md:8）。流程类技能因此在结构上不可能被模型擅自启动或绕过。
- 两个 harness（Claude Code / Codex）的分流字段必须同步，"a skill is user-invoked in both harnesses or neither"（invocation.md:10）。

**一手实测分布**（修正背景线索的关键数字，见 §16.2）：37 个技能中 **22 个 user-invoked**（正式桶 14：engineering 9 + productivity 5；in-progress 8 个全部），**15 个 model-invoked**（正式桶 11 + misc 4）。正式桶内 user-invoked 占 14/25——流程命令档（grill-with-docs、implement、to-spec、to-tickets、triage、setup-matt-pocock-skills、wayfinder、ask-matt、improve-codebase-architecture、grill-me、wait-what、handoff、to-questionnaire、teach）全部模型不可达。

**其余锚点**：`grill-me/SKILL.md:4`（7 行技能的完整 frontmatter）、`handoff/SKILL.md:4`（`argument-hint` 字段：全库 4 处——handoff、teach、claude-handoff、loop-me）、`triage/SKILL.md:47-54`（user-invoked 技能自带 Invocation 节描述人工调用方式）、`wayfinder/SKILL.md:103-105`、`ask-matt/SKILL.md:4`（router 本身也是 user-invoked）、`SKILL-MECHANICS.md:7-12`（两档的负载权衡与选择判据："Pick model-invocation only when the agent must reach the skill on its own, or another skill must"）。

## 2. 依赖 = 显式 Skill-tool 调用

**机理**：技能间依赖写成对 Skill tool 的显式调用指令；"Naming the tool is what gets it fired"——点名工具才触发，丢一个 `/name` 进散文赌模型读成命令，命中率低得多（invocation.md:16）。

- 禁止两种弱形式：深层相对路径交叉引用（`../other-skill/FILE.md`）与裸 `/skill` 式提及（invocation.md:16）。不带前导 `/` 还让写法 harness 中立。
- 一次调用只装一个技能：需要两个就写两次——"Call the Skill tool twice, for \"grilling\" and \"domain-modeling\""，不写"call it with X and Y"（会被读成一次调用装两个名字）（invocation.md:20）。grill-with-docs 全文正文就这一句话（`grill-with-docs/SKILL.md:7`）；grill-me 同构（`grill-me/SKILL.md:7`）。
- **适用边界**：此规范只约束 operative 指令（技能自己的步骤让 agent 此刻去跑另一个技能）；路由散文（ask-matt、桶 README）只是给人看的名录，保留 `/skill` 式纯标签（invocation.md:18）。
- **前置条件是 user-invoked 时**：禁止试图用 Skill tool 触达，改为给人写指令——"tell the user to run `/setup-matt-pocock-skills`"（invocation.md:22）。工程技能的前置缺失兜底全部是这一句：`to-spec/SKILL.md:9`、`to-tickets/SKILL.md:11`、`triage/SKILL.md:43`、`code-review/SKILL.md:13`、`wayfinder/SKILL.md:25`。
- 区分"调用以执行"与"调用以取词汇"：tdd 需要设计词汇时写"call the Skill tool with \"codebase-design\" for the vocabulary. It is the shared source of … terms, **and it is a reference to consult, not a session to run**"（`tdd/SKILL.md:26`）。

**其余锚点**：`triage/SKILL.md:76`、`wayfinder/SKILL.md:77-79,111,115,124`、`improve-codebase-architecture/SKILL.md:13,64,66,71`、`in-progress/setup-ts-deep-modules/SKILL.md:11`、`in-progress/retro/SKILL.md:11`。

## 3. 完成判据（Done when / 出示证据）

**机理**：每个步骤以 completion criterion 收尾——告诉 agent "done 与 not-done 如何区分"。判据的两个杠杆属性：**clarity**（能分辨完成与否，模糊边界招致 premature completion 抢跑）与 **demand**（要求多少工作，"every modified model accounted for" 逼出彻底劳动而"produce a change list"不能）。"The strongest criteria are both checkable and exhaustive"（writing-for-agents/SKILL.md:47-52）。

- 判据要求**出示已运行的证据**：diagnosing-bugs 的 Phase 1 完成判据是"you can name **one command** … that you have **already run at least once (show the invocation and its output, redacted)**"（`diagnosing-bugs/SKILL.md:59-60`），并配四项 checklist（red-capable / deterministic / fast / agent-runnable）与防抢跑护栏 "**No red-capable command, no Phase 2**"（:61-66）。
- **Done when 成为步骤的惯用收尾词**：wizard 每步以 "**Done when:**" 收（`wizard/SKILL.md:25,31`）；to-questionnaire 三步各有 Done when，最后一步是"the file exists and every item the user named in step 2 is covered by a question"（`to-questionnaire/SKILL.md:12,14,16`）——落盘存在性 + 覆盖完整性，双判据。
- minimization 的判据是可逐项验证的："Done when **every remaining element is load-bearing**: removing any one of them makes the loop go green"（`diagnosing-bugs/SKILL.md:84`）；收尾清理也是 checklist（:132-138）。
- 会话级终止判据同样可判定：grilling "The session is **done when the frontier is empty**: every branch of the design tree visited, nothing left silently assumed"（`grilling/SKILL.md:28`）；loop-me 的 spec 完成判据："an implementer agent could build it without asking a single question"（`in-progress/loop-me/SKILL.md:27`）。
- 工程操作类判据落到机械验证：setup-ts-deep-modules 每步带 Done when，整技能的完成判据是"**prove the rules bite**"——观察到 pass → 注入违例观察到 fail → 还原再 pass（`in-progress/setup-ts-deep-modules/SKILL.md:79-95`）；setup-pre-commit 以五项 verify checklist 收尾（`misc/setup-pre-commit/SKILL.md:75-79`）；resolving-merge-conflicts 第 4 步强制跑项目自动检查（`resolving-merge-conflicts/SKILL.md:12`）。
- demand 的反面教材写在理论里：weak 判据（"be thorough"）若是 no-op，修法是换更强的词（"relentless"）而非换技巧（writing-for-agents/SKILL.md:81）。

## 4. 用户检查点（阻塞步骤 + Wait 语义；非阻塞变体显式声明）

**机理**：交用户决策不是括号内提示，而是带标题的独立步骤，配显式 Wait 语义；不该阻塞的检查点则**显式声明**不阻塞——两种都是写出来的决定，不留给模型临场裁量。

- **阻塞型**：grilling 的回合制——"number each question and give your recommended answer. **Then wait** for the user's answers before the next round"（`grilling/SKILL.md:8`）；事实与决策的分工是同一机理的两面："Finding _facts_ is your job, never the user's… The _decisions_ are the user's: put each to them and wait"（:26）；收尾再加一道："**Do not act on it until the user confirms** you have reached a shared understanding"（:28）。
- **独立成步型**：to-tickets 的 "### 4. Quiz the user" 整步是检查点——展示清单、三问（粒度/阻塞边/拆合）、"Iterate until the user approves the breakdown"（`to-tickets/SKILL.md:42-56`）；to-spec 的 seams 确认（`to-spec/SKILL.md:17`）；improve-codebase-architecture 报告落盘后 "ask the user: 'Which of these would you like to explore?'"（`improve-codebase-architecture/SKILL.md:60`）。
- **前置确认型**：tdd 开工前把 seams 写下来与用户确认，"No test is written at an unconfirmed seam"（`tdd/SKILL.md:22`）；wizard 展示阶段清单 "and confirm: they may add, drop, or reorder"（`wizard/SKILL.md:23`）；setup-matt-pocock-skills 的问答纪律是"One section, one answer, then the next"，且"Lead each section with the recommended answer so the user can accept it in a word"（`setup-matt-pocock-skills/SKILL.md:34-36`）——检查点省力设计。
- **非阻塞变体显式声明**：diagnosing-bugs 排序列表给用户看，"**Don't block on it**; proceed with your ranking if the user is AFK"，并给理由 "Cheap checkpoint, big time saver"（`diagnosing-bugs/SKILL.md:98`）；grilling 中事实探查不阻塞 frontier 其余问题（:26）。
- **冲突即停型**：triage 遇状态角色冲突，"flag it and ask the maintainer before doing anything else"（`triage/SKILL.md:41`）；建议给出后 "Wait for direction"（:72）；快速覆盖通道也要"Confirm what you're about to do … then act"（:90）。
- **HITL 不可代答**：wayfinder 把人只在场的票定义为 HITL，"the agent never stands in for the human's side of it (**a grilling agent that answers its own questions has broken this**)"（`wayfinder/SKILL.md:75`）。

## 5. 领先词（leading words）

**机理**：领先词是"预训练里已有的紧凑概念，agent 执行文档时用它思考"；以 token 而非句子反复出现，累积分布式定义，用最少 token 锚定一整片行为区域——靠招募模型已有的先验。自造词也可以，但"made-up word recruits no priors"，省下的定义 token 是净亏，所以先找现有词（writing-for-agents/SKILL.md:63）。

- **双重锚定**：正文里锚执行（词出现即触发同一行为；扁平参考里聚焦注意力到一类事物）；指针里锚触达（同一词活在提示词、文档与代码库中，agent 把共享语言连到材料，触达更可靠）（writing-for-agents/SKILL.md:65）。
- **猎取重构机会**：三处拼写出的三联式是指针在花一句话比划一个主意——都是 begging to collapse into a single token 的段落。官方两例："fast, deterministic, low-overhead" → _tight_；"a loop you believe in" → _red_（writing-for-agents/SKILL.md:67-72）。
- 落地密度全库可见：diagnosing-bugs 用 tight/red 驱动全部判断（"a **tight** pass/fail signal … **This is the skill**"，`diagnosing-bugs/SKILL.md:20`；"a 2-second deterministic one is tight, a debugging superpower"，:47）；tdd 的 seam / tracer bullet / vertical slices（`tdd/SKILL.md:20,32`）；to-tickets 的 tracer bullet + frontier（`to-tickets/SKILL.md:9,65`）；wayfinder 的 destination / fog of war / claim / zoom（`wayfinder/SKILL.md:7,67,82-88,124`）；codebase-design 的 deep module / seam / depth（`codebase-design/SKILL.md:8,20`）；prototype 的"throwaway code that answers a question"（`prototype/SKILL.md:8`）；ask-matt 的 flow / smart zone（`ask-matt/SKILL.md:11,32`）。写作三技能自己也在实践：writing-fragments 把 leading word 列为"最值钱的 fragment"（`in-progress/writing-fragments/SKILL.md:36-38`）。

## 6. 否定句治理（正向表述为默认，禁令只留硬护栏）

**机理**：以禁令转向是失败模式——"steering by prohibition drags the forbidden behaviour into context and makes it _more_ available, not less"；正向表述让被禁行为根本不被说出。禁令唯一的生存空间是"无法正向表述的硬护栏"，且即便那时也要配正向目标，让注意力落在该做什么上（writing-for-agents/SKILL.md:74）。

- 配对正向的实例：to-spec "**Do NOT interview the user**; **just synthesize** what you already know"（`to-spec/SKILL.md:7`——定义约束 + 正向替代同句）；wizard "Where you don't actually know … say so and **ask the user or check the docs: never invent steps that may not exist**"（`wizard/SKILL.md:29`——正向在前，禁令收尾）。
- 纯硬护栏的低频实例：to-tickets "Do NOT close or modify any parent issue"（`to-tickets/SKILL.md:67`）；resolving-merge-conflicts "Do **not** invent new behaviour. **Always resolve; never `--abort`**"（`resolving-merge-conflicts/SKILL.md:10`——正向动作与硬护栏成对）；triage 的 KB 分工护栏"do **not** write to `.out-of-scope/`"并附理由（that KB is for *rejected* requests，`triage/SKILL.md:83`）；teach "**Never trust your parametric knowledge**"（`teach/SKILL.md:30`）。
- 正向动作序列为主干的范本：implement 全文 5 句全动词开头（`implement/SKILL.md:7-15`）；to-spec 步骤链 "Explore → Sketch → Write → Publish"（`to-spec/SKILL.md:13-19`）。diagnosing-bugs 连工具偏好都是正向排序：debugger 优先、targeted logs 次之、最后才是 "Never 'log everything and grep'"（`diagnosing-bugs/SKILL.md:106-108`）。
- 观察结论：正式桶否定句密度低，且几乎都满足"配正向或属硬护栏"二选一；理论文档（writing-for-agents 自身）通篇正向。

## 7. 两种负载与信息层级（渐进披露）

**机理**：文档与指针花的是两种预算——**context load**（常驻材料每回合的窗口成本）与 **cognitive load**（人记住哪些文档、何时取用的人力成本）；"The human is the index"，且认知负荷不是要最小化的成本，而是人类能动性的价格——花在人的判断要紧处，别处移除（writing-for-agents/SKILL.md:20-27）。只经指针触达的材料免除 context load、付指针自身一行；完全无指针的材料全押认知负荷。

- description 的定位由此而来："The description is the skill's top-level context pointer, **forced to stay loaded at all times**: permanent context load in exchange for discoverability"（SKILL-MECHANICS.md:9）；user-invoked 是零 context load、全付认知负荷的交换（:10）。
- **信息层级三级**：in-file step（主层，按序的动作）→ in-file reference（按需查阅，扁平同级是正当形态不是坏味道）→ disclosed reference（推到独立文件、指针后按需加载）（writing-for-agents/SKILL.md:31-37）。**progressive disclosure** 是沿梯子下移以保住顶层可读，"Not primarily a token optimisation: it is how the hierarchy is protected"；**分支是最干净的披露测试**——每个分支都需要的内联，只有部分分支触达的推到指针后（:39）。
- **context pointer 的措辞定律**：指针的 wording（而非 target）决定触达时机与可靠性；"A must-have target behind a weakly worded pointer is a **variance bug**: sharpen the wording first, and inline the material only if sharpening fails"（writing-for-agents/SKILL.md:12）。指针两职：陈述材料是什么 + 列出应触发触达的**分支**；常驻指针的每个词每回合都付费，所以比正文剪得更狠——front-load 领先词、一分支一触发词（同义词=同一分支写两遍）、砍掉正文已携带的身份信息（:14-18）。
- **co-location** 是文件内伴随原则：一个概念的定义、规则、告诫共居一个标题下（:41）；**sprawl** 是失败模式——每行都活但文档过长，注意力摊薄（:43）。
- 落地实例：teach 的五份格式文件各由一行指针携带（`teach/SKILL.md:14-19`）；wizard 把整个 UX 库外包给 template.sh——"**Your job is only to scope the procedure and author its stages**"，库代码"never hand-edit"（`wizard/SKILL.md:10,35`）；共享参考若两个 user-invoked 技能都需要则谁也够不着谁，只能推到技能体系外的普通文件（SKILL-MECHANICS.md:14）。

## 8. 剪枝纪律（single source of truth / environment / no-ops / sediment）

**机理**：四条互补的删减纪律，全部写在 writing-for-agents/SKILL.md:76-81——

- **单一事实源**：一个含义只在一处权威存在，改行为=改一处；duplication 的代价是维护、token，还把该含义在层级上抬高到超出其真实地位（:78）。与领先词是刻意的互逆：领先词重复的是 token 从不是含义。
- **环境即真相源**：`package.json` scripts、config、目录布局、`--help` 都是事实源，复述它们的文档是 **cache**——只在查找昂贵时才值得。"Cache what the agent cannot find by looking: the unwritten convention, the reason behind a choice, the gotcha no config confesses"（:79）。
- **逐行相关性检查**：一行因从不论及任务（纯铺陈/应披露的分支）或因世界变化而失 relevant；"Shorter documents are easier to keep relevant"。无剪枝纪律的默认命运是 **sediment**：因"加感觉安全删感觉危险"而沉积的陈旧层，直到必须向下凿穿层层沉积才能找到还活着的内容（core down through them）（:80）。
- **no-op 猎杀**：默认已遵守的指令白付负荷；判定测试"does it change behaviour versus the default?"是 **model-relative** 的——分歧靠跑文档而不是辩论解决；失败句子整句删除而非削字；对 leading word 同样适用，太弱压不过默认的词的修法是更强的词（:81）。
- 落地实例：handoff "Do not duplicate content already captured in other artifacts … Reference them by path or URL instead"（`handoff/SKILL.md:12`）；wayfinder 的 map 是 index 不是 store——"a decision lives in exactly one place, its ticket, so the map never restates it, only gists it and links"（`wayfinder/SKILL.md:23`）；CONTEXT.md 把已解决的歧义记档防回潮（`CONTEXT.md:27-30`）；变更历史全库不进 SKILL.md（changeset + CHANGELOG 承担，见 §14）。

## 9. 词汇治理（CONTEXT.md 模式）

**机理**：共享语言是机制，不是副产品——词汇表词条自带定义 + **_Avoid_ 清单**，词汇表技能显式禁用同义词，消费侧技能开场先读词汇表。

- CONTEXT.md 四个领域词条各带 Avoid："**Issue tracker** … _Avoid_: backlog manager, backlog backend, issue host"（`CONTEXT.md:7-9`）、Issue（:11-13）、Decision ticket（:15-16）、Triage role（:18-19）；词条关系单列（:21-25）；已裁决的歧义进 Flagged ambiguities 防回潮（:27-30）。
- codebase-design 整个技能就是一部词汇表："Use these terms exactly: **don't substitute** 'component,' 'service,' 'API,' or 'boundary.' Consistent language is the whole point"（`codebase-design/SKILL.md:12`）；八词条（Module/Interface/Implementation/Depth/Seam/Adapter/Leverage/Locality）中 Module/Interface/Seam 三条带 _Avoid_（:14-28）；还有 **Rejected framings** 节显式列出被拒绝的错误框架及理由（:106-109）。
- 消费侧义务：tdd 与 diagnosing-bugs 开场都要求读 CONTEXT.md 使命名贴合领域语言（`tdd/SKILL.md:10`、`diagnosing-bugs/SKILL.md:10`）；to-spec/to-tickets 要求工单标题用领域词汇表并尊重 ADR（`to-spec/SKILL.md:13`、`to-tickets/SKILL.md:21`）；wait-what 要求用 CONTEXT.md 的通用语言重述（`wait-what/SKILL.md:7`）。
- 词汇表的**维护**是主动技能 domain-modeling：挑战与词汇表冲突的用词、把模糊词逼问成精确的规范术语、用具体场景压测边界、与代码交叉验证，术语敲定就地更新 CONTEXT.md——"Don't batch these up"；且 CONTEXT.md "should be totally devoid of implementation details … **a glossary and nothing else**"（`domain-modeling/SKILL.md:44-64`）。被动读词汇表不算该技能——那是一行习惯（invocation.md:24-27）。
- 文档站侧的词法补充：页面必须用技能的 leading words，术语统一到 AI Coding Dictionary 并首现加链（writing-docs.md:76-77）。

## 10. 失败路径 fail-fast

**机理**：异常路径写成显式步骤而非例外注脚——坏输入在派发与深挖**之前**失败，失败时给出路（问用户/换法/停），从不假装不知道。

- 派发前预检的范本："Before going further, confirm the fixed point resolves (`git rev-parse`) and the diff is non-empty. **A bad ref or empty diff should fail here, not inside two parallel sub-agents**"（`code-review/SKILL.md:23`）。
- 造不出反馈环就停在环上："Stop and say so explicitly. List what you tried. Ask the user for: (a) access … (b) a redacted captured artifact … (c) permission to add temporary production instrumentation. **Do not proceed to hypothesise without a loop**"（`diagnosing-bugs/SKILL.md:53-55`）。
- 前置缺失显式兜底：五个工程技能同款一句"tell the user to run `/setup-matt-pocock-skills`"（§2 锚点）；wayfinder 无 tracker 时降级默认 local-markdown（`wayfinder/SKILL.md:25`）。
- 不诚实即失败：wizard "Where you don't actually know the current UI or the exact command, say so and ask the user or check the docs: never invent steps that may not exist"（`wizard/SKILL.md:29`）；prototype 问题真歧义且用户不可达时，走默认分支并**声明假设**（`prototype/SKILL.md:17`）；research 每个论断回溯到拥有它的源（`research/SKILL.md:10`）；diagnosing-bugs 脱敏后不足以定位时"say so and ask the user"（:16）。
- 顺序护栏：grilling 依赖本轮未决问题的问题"belongs to a _later_ round, not this one"（`grilling/SKILL.md:24`）；diagnosing-bugs "If you catch yourself reading code to build a theory before this command exists, **stop**"（:66）。

## 11. 子代理派发纪律

**机理**：子代理不是随手派——隔离、供给、聚合三段都有成文规则。

- **隔离**：code-review 两轴并行子代理，"so they don't pollute each other's context"（`code-review/SKILL.md:11`）。
- **供给（brief 自带全量材料）**：子代理无法访问主上下文，所以 brief 要贴入全部所需——"plus the smell baseline from step 3 **pasted in full (the sub-agent has no other access to it)**"（`code-review/SKILL.md:63`）；brief 里写明报告格式、判定规则与字数上限（"Under 400 words"，:64,70）。
- **聚合纪律**：两份报告原样并排呈现，"Do **not** merge or rerank findings"——重排正是双轴分离要防止的掩蔽（:76-78），设计理由成文（§ Why two axes，:80-87）。
- **后台与并发**：research 派 background agent 保持主会话工作（`research/SKILL.md:6`）；implement-spec 沟通靠 context pointer 保持稀疏，实现者子代理各占 worktree 追求 maximum concurrency（`in-progress/implement-spec/SKILL.md:13-15,21-29`）；wayfinder 图谱定型后批量点火 research 子代理，产物落一次性分支并从工单留指针（`wayfinder/SKILL.md:115`）。
- **事实下放子代理、决策留给用户**：grilling "dispatch a sub-agent to find it; don't ask the user for anything you could look up yourself"（`grilling/SKILL.md:26`）。

## 12. 路由分层与上下文卫生（router skill / main flow / phase boundaries）

**机理**：技能多到人记不住时，认知负荷由 **router skill** 治理——一个 user-invoked 技能点名其余技能与各自的触达时机，"It can only hint, never fire them"（SKILL-MECHANICS.md:20-22）。ask-matt 是该理论的完整落地。

- 流程分层：main flow（grill-with-docs → to-spec → to-tickets → implement → code-review）+ 三条 on-ramp（triage、diagnosing-bugs、wayfinder；原文自称 "two on-ramps" 却列三项，见 §17.5）+ vocabulary underneath（domain-modeling、codebase-design 两个 model-invoked 词汇层"run *beneath* the other skills"）+ standalone（`ask-matt/SKILL.md:11-86`）。
- **上下文卫生成文**：步骤 1-3 保持一个不破的上下文窗口（compact/clear 都等到 to-tickets 之后）；每个 implement 从工单冷启动。窗口极限有名字——**smart zone**（约 150k token 内模型推理仍然锋利），逼近时"don't push on degraded; `/compact` at the nearest phase boundary"（`ask-matt/SKILL.md:30-32`）。
- **相位边界决策树**：五个选项（Continue / clear / handoff / Subagent / compact）各有适用条件，handoff 窄化为四种场景；决策只发生在边界处，mid-phase 要么继续要么拆子代理（`ask-matt/SKILL.md:61-71`）。
- 同一 primitive 多入口：grill-me（无工作目录）与 grill-with-docs（有工作目录）跑同一个 grilling，差别只在是否留纸（:17,77）。
- 会话量约束：wayfinder "**never resolve more than one ticket per session**"（`wayfinder/SKILL.md:105`）；charting 会话"hand-resolves nothing"（:116）。

## 13. 模板内嵌与防陈旧

**机理**：产物模板随技能内嵌（`<spec-template>`、`<local-ticket-template>` 等标签包裹），模板里显式写入防陈旧条款——文件路径与代码片段禁止入册，因为它们腐烂得最快。

- to-spec 模板："Do NOT include specific file paths or code snippets. **They may end up being outdated very quickly**"（`to-spec/SKILL.md:55`）；唯一例外是原型产出的决策密集片段（状态机/reducer/schema/类型形状），内联并注明来源，裁剪到只剩决策（:57）。to-tickets 尾部同款条款（`to-tickets/SKILL.md:105`）。
- 产物形态纪律：本地 tracker 严格"one ticket per file, never a single combined file"，按依赖序编号（`to-tickets/SKILL.md:62`）。
- 交互格式模板化：grilling 的回合格式逐字符给出（`grilling/SKILL.md:10-22`）；triage 的 AI 免责声明是强制前缀（"must start with this disclaimer"，`triage/SKILL.md:13-17`），needs-info 模板要求问题"specific and actionable, not 'please provide more info'"（:94-108）；resuming 时先读旧 notes、不重问已答问题（:110-112）。
- 状态资产的模板边界：handoff 写到 OS 临时目录而非工作区（`handoff/SKILL.md:8`）；teach 的学习工作区五类文件各有格式指针（`teach/SKILL.md:14-19`）；domain-modeling 文件惰性创建——有内容才建文件（`domain-modeling/SKILL.md:40`）。

## 14. 格式与结构纪律（frontmatter / YAML / 桶分层）

**机理**：格式错误不是审美问题——会**静默丢失技能**；仓库为格式事故专门发过两个 patch，并把防线写进 CLAUDE.md/AGENTS.md。

- **YAML 引号事故**：em-dash 清扫留下的未引号冒号使 6 个技能（to-spec、code-review、setup-matt-pocock-skills、writing-fragments、writing-shape、wait-what）frontmatter 变非法 YAML，"skills.sh **skipped all six during discovery** and they couldn't be listed or installed"（`.changeset/fix-yaml-frontmatter-colons.md`）。
- **em-dash 全仓清除**：手工重写每个句子（逗号/冒号/句号/括号/连词）而非机械替换字符，并在 CLAUDE.md/AGENTS.md 写入禁令防回潮（`.changeset/remove-em-dashes-repo-wide.md`）。
- **桶分层**：只有 engineering/productivity 是 promoted 桶（有文档站页面）；misc/in-progress/deprecated 无页面——草稿与实验不占用正式注意力（writing-docs.md:3,7）。
- 双 harness 元数据同步：每技能伴生 `agents/openai.yaml`，分流状态两侧必须一致（invocation.md:10）。
- 变更历史不进 SKILL.md：全库 37 个 SKILL.md 无一携带历史节，演进记录由 changeset/CHANGELOG 承担（对照 §8 的 sediment 纪律）。

## 15. 状态机与并发（triage roles / claim / fog of war / plan-don't-do）

**机理**：多会话协作的流程状态不靠心照不宣——角色是显式状态机，并发抢票有 claim 原语，未知区有专门的记账形态，规划与执行在会话层面分离。

- **triage 状态机**：2 个类目角色（bug/enhancement）+ 5 个状态角色（needs-triage/needs-info/ready-for-agent/ready-for-human/wontfix），每个 issue 恰好一类一态；转换路径与回退成文；非典型转换要 flag 并先问（`triage/SKILL.md:26-45`）。canonical 角色名与实际 label 字符串解耦，映射由配置提供（:43）。
- **claim 原语**：wayfinder 工单开工前先 assign 自己——"**first**, before any work, so concurrent sessions skip it. That assignee _is_ the claim"（`wayfinder/SKILL.md:67`）；blocking 用 tracker 原生依赖关系，因为"it renders the frontier _visually_ in the tracker's own UI"（:69）；整张图预期多会话并发编辑（:128）。
- **fog of war**：看不清的未知区有专门账本（Not yet specified），门票测试是"能否现在精确说出问题"而非能否回答——"Ticket when the question is already sharp, even if it's blocked"；前景推进时雾 graduate 成新票（`wayfinder/SKILL.md:82-93`）。scope 与 sharpness 分开记账：超目的地的进 Out of scope，永不毕业（:95-101）。
- **plan-don't-do**：wayfinder 默认只产决策不产交付物，"The pull to just do the work is usually the signal you've reached the edge of the map and it's time to hand off"（:11-13）；charting 模式第 6 步就是 Stop（:116）。
- **push right**（in-progress/loop-me，草稿但理念清晰）：把检查点推到尽可能晚——"Do maximal work before involving the human, so they are asked once, late, with everything prepared"（`in-progress/loop-me/SKILL.md:22-23`）。
