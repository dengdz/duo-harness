# 工具注册与执行管线（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 02（T-06）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；循环衔接见 [../Agent循环与会话/Agent循环与状态机.md](../Agent循环与会话/Agent循环与状态机.md)。

## 机制全貌

三层分工：**registry** 管注册/别名/模型契约投影（registry.ts:30-130）；**scheduler** 把一批 toolCall 依依赖拓扑排序、按并行安全判定分组成 `parallelGroups`（scheduler.ts:60-83）；**executor** 按「校验→hook→权限→超时→handler→序列化/hook→结果事件」执行单个调用（call-runner.ts:85-638），批次层 `executeSchedule` 逐组并行（batch-runner.ts:56-160）。衔接：turn 循环在收齐模型 tool_use 后先 `scheduleTools`（RT/methods/tools.ts:40-62，从 registry metadata 组装 ToolDependency），经 turn 状态机再 `executeTools` 消费 `executeSchedule` 的 batch_start/batch_complete 事件（RT/methods/turn-tools.ts:145,180）。

## 关键流程

① **注册与别名**：`register` 先清理指向本名的旧 alias（canonical 永不被 alias 遮蔽，R:34-45）；新 alias 若撞 canonical/已有 alias 则**拒本保已**并告警（R:56-69）；`get` 一跳 alias 解析（R:88-90）；`toContracts` 过滤 `providerVisible!==false`，并投影 readOnly/destructive/concurrentSafe/permission/resultBudget 等（R:104-129）；描述可附加 modelInstructions 生成 Usage 块（R:132-139）。

② **调度**：`schedule`→拓扑排序（Kahn，残留即抛 `InvalidStateTransition` 环错，S:138-149）→`groupByParallel` 按依赖层级分层，同层内 canRunParallel 者并入组、上限 maxConcurrency（S:154-202）→`validateNoCycles` 二次校验组内依赖（S:204-226）。`canRunInParallel` 四条判定（S:85-103）：destructive→否；concurrentSafe===true→是；===false→否；readOnly（含 READ_ONLY_TOOLS 兜底，S:233-243）→是；否则仅 sideEffectScope==="none"→是。`executeSchedule` 逐组 yield batch_start/complete，遇 `turnControl.stopTurnAfterResult` 将剩余组工具批量置 ToolCancelled 并 break（B:92-128）；单组失败不再阻断后续组（B:130-156）。

③ **单工具执行**：registry miss/空名→ToolNotFound 且补发 ToolCallError（C:121-153）；initial 校验→工具专属 `validateInput`（必须在 hook 前，C:187-202）→`resolveInput` 归一化为「执行事实」（置于 hook 之前使 hook/权限/确认窗/handler 同字节，C:204-230）→PreToolUse hook（deny/preventContinuation 即拒，C:232-267；改输入后需再校验，C:268-287）→`resolveToolPermission`（allow/ask/deny，C:289-323）→ToolCallStarted（附按执行入参解析的能力旗标）→`resolveTimeoutMs`+`ToolDeadline`（准入排队时暂停计时，T:19-91）→`executeWithTimeout` 包 handler（超时→ToolTimeout 并 abort；外部 abort→ToolCancelled，T:93-179）→validateOutput→serialize（resultBudget 截断/artifact）→PostToolUse hooks→emitToolCallResult+后台任务跟踪（C:442-543）。失败路径跑 failure hook、追加 additionalContext、区分 cancelled/failed 遥测（C:559-634）。

④ **结果与预算**：`ToolResultBudget{maxInlineBytes,maxModelBytes,strategy:truncate|artifact,preview,artifact}`（contracts/src/tools/contract.ts:126-151）；序列化默认 maxModelBytes 100_000、超限截断或落 artifact（executor/result-serialization.ts:35-36,78-86,178）。

## 接口与参数要点

- `ToolContractDeclaration`（contract.ts:168-196）：capability/inputSchema/outputSchema/strict/permission/resultBudget/timeout/cancellation/trace。
- `DEFAULT_MAX_CONCURRENCY=10`（S:48，executor 侧同默认，executor/impl.ts:82）。
- 超时三参：`defaultMs`（兜底 metadata.timeoutMs→deps.defaultTimeoutMs 300s）、`maxMs` 封顶、`allowCallOverride` 允许 `input.timeout_ms` 覆盖；`cleanupGraceMs` 附加到墙钟但用户可见超时不变（T:181-204）；`kind:"none"` 无墙钟仅留 abort 监听。
- 别名规则：canonical 压 alias、冲突 alias 被拒、unregister 连带清 alias（R:73-86）。

## 边界与坑

- 环检测两处抛不可恢复错（S:138-149,204-226）；未注册工具名遥测统一落 "unknown" 桶防基数爆炸（C:77-79）。
- scheduleTools 里 readOnly 需 `readOnly && sideEffectScope==="none"` 联合成立（RT/methods/tools.ts:53-56）。
- timeout 错误 context 携 `cancellation: cleanup ?? "none"` 与 `queuedMs` 区分「慢/等」（T:135-147）；abort（ToolCancelled，recoverable）与超时（ToolTimeout）分流，`signal.aborted` 前置检查省掉整条链（C:157-164）。
- 早退路径（miss/schema 失败）必须补发 ToolCallError，否则 UI 工具行停在 streaming（C:140-142,179-184）。

## 对 duo 的启示

duo 现状=三段管线+虚拟线程并发+isConcurrencySafe+模型序提交（ADR-0018）。对照三条：

1. **调度语义升级**：ZCode 的拓扑排序+分层分组把「依赖」从提交顺序中解耦，且组间 fail-soft（单组失败不截断）；duo 按模型序提交虽保序简单，但可借鉴分层并行提升多工具吞吐，同时保留组内 maxConcurrency 闸。
2. **并行判定应多维声明驱动**：duo 仅 isConcurrencySafe 布尔；ZCode 用 destructive/readOnly/concurrentSafe/sideEffectScope 四元组（含 Bash 按执行入参判只读），误判面更小，值得在 duo 的 ToolSpec 落地。
3. **次序即安全**：ZCode 把输入归一化置于 hook 之前（hook/权限/确认/handler 同字节），PreToolUse deny 先于权限流；duo 若补 hook 层，务必前置覆盖权限并复用归一化输入做策略判定。
