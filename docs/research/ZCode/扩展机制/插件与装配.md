# 插件与装配（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 15（T-19）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；hooks 来源见 [hooks.md](hooks.md)、skills 来源见 [skills与命令.md](skills与命令.md)。

## 机制全貌

ZCode 插件=一个目录包（根下 `.zcode-plugin/plugin.json`，兼容 `.claude-plugin`/`.codex-plugin` 路径，marketplace.ts:54-56），manifest 声明 skills/commands/agents/hooks/mcpServers/userConfig/dependencies（contracts/src/plugins/index.ts:141-161；channels/lspServers/outputStyles/settings 仅告警不支持，marketplace.ts:64、adapters/plugins/index.ts:373）。本地落在 `<storage>/cli/plugins/`（bootstrap/src/app/paths.ts:9-11）：`known_marketplaces.json`、`installed_plugins.json`、`marketplaces/<id>/marketplace.json`（目录缓存）、`cache/<marketplace>/<name>/<version>/`（安装体，marketplace.ts:1064、1208）、`data/<id>` 用户数据（bootstrap/plugins.ts:802）。安装源六种：url/github/git/npm/file/directory（contracts:69-75）。plugin host 不是常驻 daemon：官方插件的 MCP server 在 seed 时被改写为 `command=process.execPath, args=[__zcode-plugin-host, dist/mcp/server.js]`（bootstrap/src/app/official-plugin-runtime.ts:65-79），由主进程 MCP 管理器按 stdio spawn 子进程；SEA 单文件二进制无法解释 Node 旗标，故用隐藏子命令自 re-exec、在 parseArgs 前分派（contracts:10-20），plugin-host-command.ts:49-63 动态 import server.js 并调 main()，凭据恢复在 import 前 fail-closed 校验（:83-106）。

## 关键流程

① **安装链**：`marketplace add` 先 persist:false 解析 manifest，校验 id 保留/匹配（marketplace.ts:356-372），source tree 与 manifest 同一 staging 后一次 rename 激活（:385-400），失败双 activation 回滚（:421-441）；`install` 取依赖闭包（:602-609）→ 逐插件 resolvePluginSourceRoot（git clone/url zip/file 拷贝）→ 原子激活到 cache + ensure manifest（:1140-1151）→ 写 installed_plugins.json，异常按逆序回滚（:632-644）。bootstrap 层加 `withPluginStorageLock` 串行化（bootstrap:757），装完写 User config 默认启用（:736-743）。

② **发现/启停**：`resolveZCodePlugins`（bootstrap:250-267）→ discoverNodePluginsSync 按 enabledPlugins/defaultEnabled 门控（index.ts:175-193），插件以 priority 递增注入 skillRoots/commandRoots/hooks/mcpServers（:350-363），与用户自有 skills/commands/hooks 同一扫描管线；停用插件组件清空但 metadata 仍权威枚举（:315）。防撞：skill qualifiedName=`${pluginName}:${skill}`（adapters/skills/index.ts:261）、MCP=`plugin:${name}:${server}`（mcp.ts:67-69）、agent=`${name}:${agent}`；两个 enabled 插件同名 → conflictingPluginIds fail-closed 禁选（contracts:226-230）。

③ **host**：仅官方插件 MCP server 走 host 前缀（注入不可伪造 ZCODE_PLUGIN_ID，official-plugin-runtime.ts:78），生命周期随 stdio 会话，崩溃隔离=子进程边界。

④ **更新/卸载**：update=先刷新 marketplace 再重装（bootstrap:829-857）；uninstall 删记录+cache，`--keep-data` 留数据；内置插件 uninstall 只写 suppressedBuiltins、restore 反向恢复（:644-654、913）。

## 接口与参数要点

- marketplace.json 拉取：≤10MiB、重定向≤5、180s（marketplace.ts:50-52）；zip：下载≤200MiB、解压≤500MiB、≤2 万条目、单文件≤50MiB（zip-source.ts:14-18）；git clone 3 次重试、单命令 90s、退避 1s×attempt（marketplace.ts:58-60、1668-1684，仅网络型错误重试）。
- 名称正则 `[a-z0-9][a-z0-9._-]{0,127}`（:61-62）；`zcode-plugins-official` id 保留，第三方市场禁用该名（:356-360），workspace 声明保留 id 被忽略（bootstrap:1344-1350）。

## 边界与坑

- github 归档仅限公共 HTTPS github.com 仓、拒绝带凭据/query（github-archive-source.ts:41-75）；检出 submodule/LFS 指针会产出「表面成功」的坏缓存，故检测后回退完整 git clone（:129-153）。
- hook/mcp/skills 声明路径用 resolveInside 防逃逸并拒绝 symlink（hook-sources.ts:48-58、index.ts:427-433）。
- 安装失败回滚靠 staging+backup+cacheTransactionId 崩溃恢复（atomic-directory.ts），但**三方插件 hook 默认直接放行执行是主动放弃的信任边界**（index.ts:366-371）。

## 对 duo 的启示

duo 现状：M1 插件=yml 行装配，无市场、无动态安装。对照三条：

1. ZCode「技能+命令+agent+hook+MCP **一包一 manifest**」是组件化插件包的核心价值，duo 若把 yml 行升级为可整体启停的包，可低成本复用该形态（无需市场，先做 local directory 源）。
2. host 子进程隔离在 ZCode 只为官方重负载 MCP 插件服务且成本不低（SEA re-exec、凭据 fail-closed、manifest 改写），duo 纯内容型技能包用不上，隔离收益不抵复杂度。
3. marketplace 的市场/商店 listing/CDN 分片对个人工具属过度设计，但 **known/installed 两个 JSON + 原子激活 + 保留名命名空间**的「最小安装协议」值得借鉴。
