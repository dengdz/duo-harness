# 只读命令识别与规则（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 08（T-12）产物，五段统一模板——**本项为 ZCode 单侧深析**（DSH 无对应物，见文末对照位；DSH 侧注记见 [../../DSH/交互与呈现/只读命令识别与规则-DSH注记.md](../../DSH/交互与呈现/只读命令识别与规则-DSH注记.md)）。接口参考见 [../模块手册.md](../模块手册.md)；权限档位见 [../沙箱与权限.md](../沙箱与权限.md)。M23 权限深化的核心蓝本。

## 机制全貌

三层架构：① `core/tool/handlers/bash-command-parser.ts` 基于 `unbash` 库把 shell 命令解析为结构化命令列表（`analyzeBashCommand`，:51-90），支持 Statement/AndOr/Pipeline 嵌套（`&&`/`||`/`|`/`|&`/`;`）、重定向、env 赋值前缀；② 只读策略表（`bash-readonly-policy-*` 共 20 文件）对每条命令产出三态 `true/false/undefined`；③ 上层 `isRuntimeReadOnlyBashCommand`（`bash-semantics.ts:39-66`）聚合为两态并 fail-closed，`resolveBashPermissionCapability`（`bash.ts:77-95`）据此改写 Bash 的权限 capability，使 plan/build 档免审批；另有前缀规则评估器负责 `Bash(prefix:*)` 匹配与规则建议。要点：解析失败/不支持语法/动态词一律不视为只读。

## 关键流程

① **解析**：输出 `BashCommandAnalysis`（`bash-command-parser.ts:39-46`）：`commands[]`（argv/name/redirects/envAssignments/operatorBefore）、`hasParseErrors`（>10k 字符或抛错，:48,:56-60）、`hasUnsupportedSyntax`（background 等 `SUPPORTED_CONTAINER_NODES` 之外的节点，:49,:115-117,:263-275）、`hasDynamicWords`（命令替换/进程替换/参数·算术·花括号展开等，:216-242）。`isBashCommandPermissionSafe`（:92-94）= 三者皆无。

② **判定序**（`bash-semantics.ts:39-66`）：permission-safe → 命令数>0 → 含 git 且含 cd/pushd/popd 即拒绝（`bash-git-runtime-safety.ts:26-39`，因 git 会在目标目录加载 hooks；纯 `cd && grep` 放行）→ 含 git 且 `isGitRuntimeContextUnsafe` 拒绝（:71-96：realpath 规范化 cwd，逐级父目录检查 `.git`——symlink/gitfile(worktree) 校验 gitdir 指向不得在 cwd 内且须含 `.git` 段、裸仓库 objects/refs 指示器、HEAD 格式与 4096B 上限、拒 commdir）→ 逐命令：`hasKnownBashWriteOption`（sed -i、find -delete/-exec、tree -o、git -C/-c 等危险全局旗标，`bash-readonly-policy-argv.ts:55-63`）拒绝；`evaluateBashReadonlyPolicy`（:25-53）三态：env 赋值仅白名单约 40 变量（`argv-io.ts:3-49`）、重定向仅输入侧+`>/dev/null`+fd 复制、禁 `/dev/tcp` 与 Windows UNC（:51-73）；剥 `command/builtin/noglob` 包装；git 走子命令最长前缀表；再试精确 argv（`ip addr`、`node -v`、printf 格式串校验、find 逐词扫描、docker images/ps 带危险回调，`argv-direct.ts:69-146`）→ 多词前缀表（docker inspect/logs、gh auth status、gh pr/issue/run 等 21 条，`multiword-core.ts`/`multiword-gh.ts`）→ 任意参数集（basename/cat/df/du/head 等 30+）→ 单命令策略表 51 条（ls/find allowAnyArgs；grep/rg safeFlags；jq/ps/ss 带危险回调）。`undefined`（未知命令）→ 整体 false。

③ **消费**：`bash.ts:77-95` 命中只读即返回 `{readOnly:true, destructive:false, needsApproval:false, riskLevel:"low", sideEffectScope:"none"}`，经 `executor/permission-capability.ts:6-22` 覆盖静态 metadata；`permission/service.ts` 中 plan 档 `mode.plan.readOnly` 放行（:408-415）、build 档 `mode.build.readOnly` 放行（:456-463），跳过 critical/high ask（:465-481）与副作用 ask（:497-508）。`resolveToolCallCapabilityFlags`（`permission-capability.ts:28-39`）把 readOnly 旗标挂上 `ToolCallStarted` 供订阅者预判。

④ **规则**：`bash-command-permission-policy.ts:85-124` 只对「prefix 安全」分析（无重定向/动态词/静态赋值，:169-181）生成建议；`resolveStableCommandPrefix`（:187-238）剥 sudo/env/nohup/time 包装（深度≤2）、排除高危根命令（`HIGH_RISK_ROOT_COMMANDS` :19-36：bash/sh/zsh/rm/chmod/dd/mount/mkfs 等）、借助命令注册表跳过已知选项后取 action token（含 aws/az×2、gcloud×3、kubectl config、docker compose、`npm run <script>`、make/just 目标、`python -m` 等深度覆盖 :68-83,:298-319）；建议规则超 5 条则退化为整串精确规则（:16,:135-157）。匹配语义（`bash-command-rule-evaluator.ts:40-50`）：`prefix:*` 等于 subject 或其后跟空格/tab；deny 检查全部命令，allow 只查非只读命令。注册表 `generated/bash-command-registry.ts`（1.8MB）由 `apps/zcode-cli/scripts/generate-bash-command-registry.mjs` 从 `@withfig/autocomplete@2.692.3` 确定性生成，带版本+hash 常量（:5-8）。

## 接口与参数要点

- 签名：`analyzeBashCommand(command): BashCommandAnalysis`；`isRuntimeReadOnlyBashCommand(command, context?: {workingDirectory?, workspaceRoot?}): boolean`；`evaluateBashReadonlyPolicy(invocation): boolean | undefined`；`isGitRuntimeContextUnsafe(context): boolean`；`resolveBashPermissionRulePolicy(input, context?)`。
- 策略族归类：git 子命令（core+history 两组：status/log/diff/show/rev-parse/ls-remote 等）；gh 多词 21 条；docker 多词+前缀；文本/文件类（grep/rg/cat/head/tail/sort/wc…）safeFlags 带值类型（none/string/number/char/{}/EOF，`argv-flags.ts:165-182`）；进程类 ps/pgrep/netstat/ss 带回调。
- fail-closed 出口全录：解析错误/超长/不支持语法/动态词；git+cd 组合；git 运行时上下文不安全；已知写选项；非白名单 env/重定向；UNC 与 /dev/tcp；未知命令（undefined）；策略 regex 不匹配；xargs 目标不在白名单。

## 边界与坑

- 追不上的 shell 语义：后台 `&` 直接记 unsupported（fail-closed 但可用性受损）；`$VAR`/`$(...)`/算术展开全算 dynamic 拒绝，`FOO=$BAR cmd` 也进不来；alias 展开不可见。
- 误判面：`allowAnyArgs` 依赖回调补丁（jq/ps/ss/docker 危险参数识别各一套 regex，`bash-readonly-policy-callbacks.ts` 354 行）；printf 格式串校验逻辑复杂（`argv-direct.ts:110-134`），精度靠正则维护。
- git 上下文安全是**同步文件系统探测**（realpath/lstat/readFileSync），每次判定都跑，且只保证判定时刻状态。
- 维护成本：20+ 策略文件 + 1.8MB 生成注册表钉死 fig 版本，升级需重新生成；规则 subject 保留 raw+stable 双份兼容历史 wildcard（`bash-command-permission-policy.ts:129-132` 注释自证踩过坑）。
- 与 `dangerouslyDisableSandbox` 正交：只读判定只改审批，不改沙箱——`bash.ts:298`、`:429`。

## 对 duo 的启示

- duo 现状=read-only 档 bash 一律 ask。引入「只读 bash 免审批」的工程量：解析器（含动态词检测，ZCode 276 行）+ 聚合判定约 300-400 行可控；大头是策略表（ZCode 约 2500 行/20 文件）。建议 duo 首期只做：30 个 allowAnyArg 只读命令 + git status/log/diff/show 四件套，先不碰 safeFlags 值类型体系。
- fail-closed 落地形态：三态策略表聚合为两态，`undefined`→ask；**git 命令必须叠加运行时上下文检查**（cwd `.git` 信任分类），否则 plan 档放行的 `git -C /anywhere log` 是逃逸口。
- 与 M23 权限深化的关系：ZCode 的正确缝口是「运行时 capability 覆盖静态 metadata」（`permission-capability.ts:11` `entry.resolvePermissionCapability?.(...)`），mode 检查只读 capability 字段——duo 的 M23 可复用该 seam，且规则建议（`Bash(prefix:*)` + 高危根命令排除 + 上限 5 条）可直接嫁接同一解析器。

## DSH 对照位

DSH 无此实现：其 read-only 档下 Bash 不做只读命令识别，一律走审批/沙箱路径。
