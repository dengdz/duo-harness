# 任务编排 workflow（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 05（T-09）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；子代理域见 [子代理.md](子代理.md)。

## 机制全貌

动态工作流 = 模型写 TS 脚本（facade：`agent/ask/report/artifact/log/phase/world.run/args`，B/dynamic-workflow/src/facade/dts.ts:65-424），编译期在虚拟 compiler host 内对内嵌 facade .d.ts 严格 typecheck（`noEmit`、`types:[]`，编译即纯度契约，compiler/compile.ts:35-55）；lowering 按站点表把每个 facade 调用改写为 `__host.*`（lowering/lower.ts:25-40）。harness 把 lowered+args 内嵌成自包含 ESM 入口文件写到 `<cwd>/.zcode/workflow-runs/<runId>.mjs` 并 spawn node 子进程 vm 沙箱（dynamic-workflow-runtime/src/harness.ts:218-253、child-entry-file.ts:47）。子进程经 stdio NDJSON 桥接父进程的 `WorkflowEngine`——零 I/O 确定性状态机，决策全由 journal 固定（engine/engine.ts:1-17）；engine 经 driver 把每次 ask 变成子代理会话 turn（bootstrap/app/workflow-driver.ts:275）。core 工具族（CreateWorkflow/AmendWorkflow/SaveWorkflow/GetWorkflowRun/ResolveWorkflowQuestion 等）只是薄壳：编译诊断+确认窗+调 bootstrap 的 RunPort（core/src/tool/handlers/create-workflow.ts:131）。journal 落 SQLite 三表 dwf_run/dwf_node/dwf_event，事件双写 journal+emit（engine.ts:640-644）。

## 关键流程

① **创建执行**：handler 先 analyzeScript，编不过直接回诊断不弹窗（create-workflow.ts:94-112）；干净→确认窗→`port.submit`，run service 算 sha256 scriptHash、「编译一次」同交 scriptText+lowered（dynamic-workflow-run-submit.ts:574）→spawn→子进程 create-actor 即发即忘 local#N，父按 stdio FIFO 同步建映射（protocol.ts:14-17）；ask 走 request/response，engine.ask 经调度器准入→driver.startAsk 起 turn，typed ask 附 schema 尾注，submit 由引擎 accept/reject/nudge（workflow-driver.ts:322-347）；report/declare-artifact/phase 走事件通道（harness.ts:460-473）；complete→settleCompleted，error-complete→failed。

② **amend/resume**：停前驱→bootstrap/app/dynamic-workflow-import.ts:121 读前驱 journal 建 ImportedRunCache（运行期按 actor 名+persona、{op,args}+序匹配，engine/imported-cache.ts:154）→新 run 带 resumedFrom+inheritedTokens 启动，命中 (siteId,ordinal) 短路回放；脚本须与建 run 逐字节同（engine.ts:302-314），子代理改写工作区或 live world.run 即关缓存门（engine.ts:181）。

③ **协议**：child→parent 四类 create-actor/request/event/complete，parent→child 仅 response（protocol.ts:158,174）；payload 走入口文件 JSON 而非 argv/base64url——Windows 命令行 32,767 上限（child-source.ts:9-13）。

④ **治理**：Caps.maxConcurrency 建 run 时固定（engine/types.ts:115），天花板=min(16,核数-保留)（bootstrap/app/workflow-concurrency-ceiling.ts:12）；abort 唯一真取消，reason 分流 user/model/interrupted/superseded（harness.ts:344-366）；GUI 中枢经 runtime method `startSavedWorkflowRun` 绕权限直启（core/src/runtime/methods/dynamic-workflow-run-start.ts:51）。

## 接口与参数要点

- CreateWorkflow 入参 `script|path|saved`、`args`、`name`、`max_concurrency`、`subagent_model`，恒 backgrounded+劝阻轮询（create-workflow.ts:185）；AmendWorkflow 多 `run_id`，脚本可省略继承前驱（amend-workflow.ts:112-117）。
- facade：`agent(name?,persona?)→Agent`、`recv.ask<T>(instr)`、`report(item,artifactId?)`、`artifact.file/markdown`(await)/`chart/table/metrics/board`(void)、`world.run` 效应单列 journal（engine-world.ts:67-68）、`args` 浅冻结。
- journal 事件 RunEvent 约 24 种（engine/types.ts:604-786）。

## 边界与坑

- harness 不校验 scriptText/lowered 对是否自洽（harness.ts:57-61）；脚本抛错→failed（终态）vs 子进程崩溃/超时/NDJSON 损坏→stopped(interrupted) 可 resume（harness.ts:165-170）。
- single-writer finalize 必 kill 子进程防孤儿（harness.ts:314-321）；模型侧 provider 错误不过界给脚本——runtime 内重试或 stopRun 整 run 停（protocol.ts:26-30）。
- 入口文件是 protocol 手写镜像、childMain 须自包含且内层函数匿名，esbuild keepNames 会踩雷（child-source.ts:28-30,250-256）。

## 对 duo 的启示

1. **「编译成文件再 spawn」形态**：脚本以 JSON 内嵌入口文件落 `.zcode` 下、argv 只剩路径，规避命令行长度限制，且产物可留档重放——duo 若做编排可直接借鉴。
2. **NDJSON 桥协议**：同步 create-actor+即发即忘 vs 需应答 request 的二分、事件通道靠 stdio FIFO 保序（declare 先于 report），是跨进程编排的轻量可靠范式。
3. **journal 重放/缓存导入**：确定性引擎（站点序号+inputHash 短路）+ amend 把已完成 ask 当缓存导入、脚本哈希门禁，使长跑工作流可修订可崩溃恢复——duo 引入编排时的持久化底座样板。
