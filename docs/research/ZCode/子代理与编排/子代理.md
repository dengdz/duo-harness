## 机制全貌

子代理完全由 profile 驱动：`AgentProfile`（profile.ts:21-38）含内置 general-purpose（tools:`["*"]`、injectAgentsMd，profile.ts:115-130）与 Explore（只读工具集，profile.ts:66-80）两个预设；项目 `.zcode/agents/*.md`、用户 agents 目录经 bootstrap 加载（bootstrap/src/subagents.ts:54-57），`normalizeAgentProfiles` 用 Map 按名后写覆盖内置（profile.ts:109-111）。`SubagentPort` 是 contracts 抽象，缺省实现 `createExploreSubagentPort`（runner.ts:131），由 runtime 装配为 `createDefaultSubagentPort`（runtime/methods/subagent.ts:59）。Agent 工具 handler 调 `subagentPort.launch`（tool/handlers/agent.ts:174-222）；Task 是 Agent 的 `providerVisible:false` 兼容别名（agent.ts:287-300）。子代理是**独立持久化 session**：childSessionId=`subagent_<agentId>`（runner.ts:806），构造独立 `AgentRuntime` 并先落库再发布（subagent.ts:239,378），child 事件按自身 sessionId 持久化，仅少量工具事件镜像回父会话（subagent.ts:332-362）。

## 关键流程

① **spawn**：Agent→launch，`run_in_background||profile.background` 决定 run/start（runner.ts:145-170）。run：registry 注册→写 metadata→activity watchdog（默认 600_000ms，runner.ts:214；contracts/config/index.ts:284）→`runExploreAgent` 组装 child runtime：模型选择 profile>父>override（subagent.ts:100-111）、toolset explore/main（:279）、maxTurns 默认 4（:269）、工具 allowlist 与父可见工具求交并强制附加 RespondToCoordinator（:490-548）；前台结果为 completed output（正文+usage），后台为 `async_launched`（runner.ts:1476-1492）。

② **项目 profile**：`parseAgentProfileFromMarkdown`（profile.ts:154-227）解析 frontmatter；项目级 permissionMode 直接剥离（profile.ts:185；subagents.ts:115-124）。

③ **通信**：SendMessage→running 时经 messageSink `steerTurn(guide, coordinator_steer)` 注入活跃 turn（message-steering.ts:24-40），失败排队、下轮 flush（runner.ts:936-953,1415-1442）；terminal 子代理→`resumeTerminalAgentInBackground` 后台 resumeFromStore 续跑（runner.ts:955-1062）。RespondToCoordinator 仅 subagent scope，经 coordinatorResponsePort enqueue 回父 runtime（respond-to-coordinator.ts:30-49；subagent.ts:308-314）。submit_result 属 workflow actor 终态提交，与 SubagentPort 无关（submit-result.ts:34-67）。

④ **查询与停止**：TaskOutput 按 task_id/block/timeout 查询，block 时 100ms 轮询至终态（task-output.ts:229-243）；TaskStop→`stopBackgroundTask`→registry 置 killed+abort 中止链+向父队列发 stopped 通知（task-stop.ts:50-56；runner.ts:547-566,1655-1739）。ReadSessionContext 跨会话：读 sessionStore 历史，lite 模型按 relevant/handoff 策略抽取（read-session-context.ts:38-144）。

## 接口与参数要点

- Agent/Task 入参：`description`（3-5 词）、`prompt`、`subagent_type?`、`run_in_background?`（contracts/tools/agent.ts:18-33），无 model 参数（agent.ts:25-26 注释：由 Settings/profile 统一决定）。
- SendMessage：`to/summary(≤200)/message(≤20000)`；TaskOutput：`task_id/block(默认true)/timeout(默认30s,≤600s)`；TaskStop：`task_id|shell_id`；ReadSessionContext：`sessionId/query/strategy/maxTokens`。
- maxTurns 默认 4（subagent.ts:269）；inactivity 默认 600s；`autoBackgroundMs` 可配置前台自动转后台（runner.ts:291-329）。
- frontmatter 全字段：name/description（必填）、tools、disallowedTools、skills、mcpServers、maxTurns、memory(user/project/local)、color、permissionMode(auto/plan)、background、injectAgentsMd、model（profile.ts:206-226）。

## 边界与坑

- 同名覆盖：项目/用户 md 可整体顶替内置 Explore/general-purpose（profile.ts:109-111）；插件裸名禁撞保留名（subagents.ts:47,160-174）；近规范化重名会报 ambiguous（runner.ts:767-784）。
- permissionMode 剥离后项目 agent 沿用父 mode，但内置 Explore 无 permissionMode 时强制 "yolo"（subagent.ts:473-488）——两套默认行为不对称。
- borrowed-mcp-port：child 只借用父连接启动快照，禁 lifecycle 变更、close 不传播、scope 外 server 调用报错（borrowed-mcp-port.ts:34-70）。
- persistent-memory：仅当 `profile.memory` 且 `tools` 已定义才补 Write/Edit（persistent-memory.ts:39-47，tools 未写则静默不注入）；user→storageRoot/agent-memory，project→`.zcode/agent-memory`，local→`agent-memory-local`；注入 MEMORY.md 索引 prompt。
- SendMessage 闲时轮被直接拒绝（send-message.ts:50-53）；前台 modelOverride 的 agent 禁止转后台/自动后台（runner.ts:150,294）。

## 对 duo 的启示

- **profile 文件驱动 vs duo yml 模板**：ZCode 的 `.zcode/agents/*.md` frontmatter（background/maxTurns/tools/disallowedTools/memory）是「模板 opt-in」的成熟形态——`profile.background:true` 让模板自身决定后台，而非调用点硬编码，duo 模板可对照补齐（ADR-0017 的 withSkills/withAgentsMd 未实现项有了参照形态）。
- **run_in_background 子代理**：ZCode 用 registry+metadata/output 落盘+`enqueueParentTaskNotification` 同步入父命令队列保证通知不丢（runner.ts:105-117），TaskOutput 轮询 100ms+notified claim 防重复；duo M15 已有后台异步，可补「完成通知必达+TaskOutput 阻塞读」组合。
- **跨会话引用**：ReadSessionContext 的 lite 模型分块抽取+handoff 胶囊策略（read-session-context.ts:212-267）可作 duo 跨 session 引用工具的参考实现（对应 backlog 的 @session 项）。
