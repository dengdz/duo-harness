# 任务管理（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 06（T-10）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；后台 bash 全链见 [../工具系统/本机执行工具族.md](../工具系统/本机执行工具族.md)。

## 机制全貌

ZCode 的「任务管理」分三层面：会话内 todo（TodoWrite→sqlite todo 表→快照 plan 投影到 UI 状态面板）、跨会话定时自动化（CronCreate/Update/Delete/List 四工具→AutomationService→tasks-index 库→常驻 scheduler 进程认领派发→host 起/复用会话执行）、闲时（off-peak）队列任务（服务端取号排队+本地轮询晋级派发）。另有 plan mode（EnterPlanMode/ExitPlanMode 会话级只读规划态）。要点：

- todo：整表替换、session 作用域、无审批（`core/src/tool/handlers/todo.ts:130-198`）。
- cron：workspace 持久化、创建即算 next_run_at、scheduler 20s 轮询认领（`packages/desktop/src/scheduler/index.ts:33,87-118`）。
- off-peak：取号成功才落库，schedulable 晋级才可派发（`packages/services/src/session/offPeakTaskService.ts:167-268`）。
- plan mode：runtime executionState.planEnabled 布尔位，与权限 mode 解耦（`core/src/runtime/session-mode-port.ts:9-33`）。

## 关键流程

① **TodoWrite**：zod 校验 status∈{pending,in_progress,completed}、priority∈{high,medium,low}、content 非空（`contracts/src/tools/todo.ts:27-29`）。语义是**整表替换**：handler 先读 oldTodos，`updateTodos` 事务内 delete-by-session 后按 position 重插并 touchSession（`adapters/.../repositories/todos.ts:24-52`），返回 old+new+四态计数。UI 经 V4 快照 `plan` 字段（`packages/shared/src/zcode-protocol-v4/snapshot.ts:443-447,500`）投影，面板刻意保留权威顺序、完成不重排（`packages/ui/src/v4/conversationStatusPanelModel.ts:173-186`）。

② **cron**：automation turn 内禁止再写 cron 工具防递归（`core/.../cron.ts:39-58`）；CronCreate 固定绑当前 sessionId、模型取 runtime 而非入参（`cron.ts:104-109`）。Service 层：delayMinutes 1–525600 且强制一次性；intervalUnit+interval carrier（1–200）归一化为权威 scheduleRule、cron 仅作兼容展示；「每 N 分钟」cron 也补创建时刻锚点防墙钟提前触发（`packages/services/src/session/automationService.ts:144-231`）。computeNextRunAt 只用 croner 算时间不做调度（`automationCron.ts:59-63`）；scheduler 事务认领（BEGIN IMMEDIATE + running 0→1），派发请求发 main→host：有 targetTaskId 则 resume 原会话注入 prompt，否则 createTask 新会话（`packages/desktop/src/host/index.ts:849-948`）。错过的触发：next_run_at 落后 now 超 5min 视为 misfire，记 skipped 不补跑，一次性任务直接终态（`scheduler/index.ts:38,138-160`）；一次性固定日历目标刚过期 <1min 立即补执行、1–30min 拒绝创建（`automationCron.ts:90-121`）。失败按 transient 退避重试。

③ **off-peak**：与 cron 的本质差别是**无本地时点承诺**——创建即向服务端 POST /ticket 取号（3101 资格/3103 配额类型化错误），落库后由轮询（5s–5min 自适应）发现 schedulable=ready 才派发（`offPeakTaskService.ts:167-268,528-593`）；错过的窗口「顺延不丢弃」，无 misfire-skip（`scheduler/index.ts:8-9`）；调度侧 quota 由服务端票据控制，本地单会话仅允许一个未终态绑定任务（`offPeakTaskService.ts:199-211`）；票过期自动同 task_id 重取号续跑（3102）。派发轮隐藏 CronCreate/OffPeakCreate 防后台再造任务，idle 模型只 execution 作用域注入（`host/index.ts:655-672`）。

④ **plan mode**：EnterPlanMode 免审批进入（policy 恒 allow，`core/permission/plan-mode-policy.ts:23-29`）；ExitPlanMode 需审批、非 plan 态拒绝（InvalidStateTransition，`plan-mode.ts:64-78`），退出前先把 plan 落盘 `plans/plan-<sessionId>.md` 并注入 plan_file_reference（`plan-mode.ts:210-242`、`runtime/helpers/plan-file-continuity.ts:25-26`），模型侧收到「## Approved Plan」+提示先更新 todo 列表（`plan-mode.ts:272-283`）。

## 接口与参数要点

- TodoWrite：`todos[]`（content/status/priority），整表替换；无 maxBytes 外限制（模型字节 100k）。
- CronCreate：cronExpr（5 段，本地时区，勿转 UTC）、prompt/title 非空（title 须保留原时间短语）、recurring 默认 true、maxRuns 仅 recurring=false（缺省=1）、delayMinutes 或 intervalUnit+interval(1–200) 互斥（`contracts/src/tools/automation.ts:39-108`）。
- OffPeakCreate：title/prompt/workspacePath/permissionMode（yolo|plan|edit|auto|autoEdit|build）+modelSelection 必填。
- EnterPlanMode 无参；ExitPlanMode：`plan`（非空 markdown）+`allowedPrompts`。

## 边界与坑

- 闲时任务不保证开始时间，位次/晋级全凭服务端票；暂停票留队、续跑票废则手动重取消耗额度（`offPeakTaskService.ts:298-346`）。
- cron 时区语义：按用户本地时区解释；模型自算「现在」常陈旧——一次性绝对时刻刚过会静默滚一年，故相对延迟强制走 delayMinutes（`cron.ts:197-207`）。
- `*/N` cron 墙钟对齐与创建时刻锚定不一致；每 N 单位超 cron 步长上限必须走 carrier（`automationCron.ts:222-236`）。
- misfire 不补跑 vs off-peak 顺延，两套语义并存；todo 完成时 UI 重排会破坏快照权威顺序；automation turn 写工具须 executor 层终拒（provider denylist 只是可见性）。

## 对 duo 的启示

duo 现状：todo_write（M17）已有，无 cron/off-peak/plan 硬禁。对照三条：

1. duo 的 backlog @schedule 若要升级为「会话内定时提醒」，应学 ZCode **双形态拆分**——相对延迟（「8分钟后」）由 host 真实时钟锚定一次性规则，绝不信任模型换算的绝对时刻；重复间隔用结构化 carrier 而非让模型写 cron，可规避步长上限与时区坑。
2. duo todo 的 UI 投影应学「权威顺序保留」+整表替换事务（delete+reinsert by position），避免增量合并产生顺序漂移。
3. automation turn 内拒绝写 cron 工具的「本轮事实终拒」模式，对 duo 防止定时任务递归自建直接可搬。
