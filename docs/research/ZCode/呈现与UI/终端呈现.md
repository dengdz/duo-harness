# 终端呈现（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 17（T-21）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；审批执行链见 [../交互与呈现/审批与提问交互.md](../交互与呈现/审批与提问交互.md)。

## 机制全貌

TUI 基于 `@mbears/opentui-core/opentui-react`（自绘终端渲染器 + React 19 reconciler），`createCliRenderer` 以 `targetFps:30` 帧循环绘制（tui.tsx:49），组件树全部用 `React.createElement("box"/"text")` 声明布局。`TuiApp`（app.tsx:48）是唯一根组件，集中持有 messages/draft/busy/approvalQueue 等约 30 个 state，并装配控制器：审批（app-permission.ts:31）、subagents（app-subagents.ts）、workflow 镜像（app-workflow-controller.tsx）、sidebar（app-sidebar-layout.ts）、mode/model/effort/slash 补全控制器（app.tsx:124-126）。事件通路：CLI 侧 `promptHandler.subscribeSessionEvents`（tui-command.ts）订阅 contracts 会话事件流，`useSessionEventApplier`（app.tsx:197）把 SessionEvent 逐条归约为 React state；模型流事件由 app-model-streaming.ts 按 `text_delta/reasoning_delta/tool_call/finish` 分派。非 TUI 面：`app-server/agent-server` 走 `runZCodeProtocolAgent` 协议服务器（run.ts:525-533，stdin/stdout JSON 协议，供 desktop host）；`--prompt/--target` 为 headless 单轮，text/json/stream-json 三种输出（prompt-command.ts:45-51）。

## 关键流程

① **启动**：非 TTY 直接拒绝——`!stdin.isTTY || !stdout.isTTY` 写 stderr 提示并 `return 1`（tui.tsx:14-18）。先渲染 `TuiStartupScreen`，监听首个 `FRAME` 后才 `loadStartupOptions`（会话元数据/斜杠命令/git branch）并挂载 `TuiApp`（tui.tsx:113-140），保证首帧不被阻塞；终端主题探测并发进行（最多 600ms，tui.tsx:141-145）。

② **输入**：`useKeyboard` 单回调分派（app-keyboard.ts:136），优先级为 只读视图→审批首项吞掉全部键（:169）→selection→sidebar 快捷键→ctrl+c（双击退出守卫，:201-225）→mode 切换键先于 @ 补全（:250，注释明确 Tab 余量留给文件补全）→`@` 面板 escape/up/down/tab/return（app-file-mentions.ts:115-140）→tab 补全 model/effort/mode/slash→escape 关建议或 abort→up/down 历史（draft 非空时守卫，app-keyboard.ts:333）。slash 过滤仅在草稿以 `/` 开头且无空白（app-input.ts:31-42）。

③ **审批/提问**：请求追加进 `approvalQueue`，默认 `selectedDecision:"deny"`（app-permission.ts:101）；面板显示 reason/input/权限 scope/三个决策行，「Up/Down choose, Enter confirms, Esc denies」（app-approval-panel.tsx:133）；escape=deny 语义硬编码（app-approval.ts:49-51）。AskUserQuestion 解析为 QuestionPanel：j/k、数字 1-9、`o` 自定义答案、`s` 跳过、multiSelect 用 space 勾选（app-question-state.ts:67-107），答完进入 reviewing 再 return 提交 `decision:"modify"`；escape 整体 deny。CreateWorkflow/AmendWorkflow 在 CLI 自动放行（记录在案的旁路，app-permission.ts:23-49）。

④ **模式切换与子代理视图**：plan→build→edit→yolo 循环（app-mode.ts:5），乐观 `setMode(next)` 后异步调 `setModeHandler`，失败回滚 previousMode 并报错（app-mode.ts:44-55）。子代理视图：选中后只读，`readSubagentTranscript` 快照 + onEvent 按 `event.sessionId===childSessionId` 过滤增量（app-subagents.ts:133-141），liveModelText 以 streaming 消息拼在尾部（app-subagent-view.tsx:24-29），escape 返回。

⑤ **流式呈现**：文本走 opentui `markdown` 组件（探测渲染能力降级 code/plain，app-markdown.tsx:27-33），按 assistantMessageId 增量追加保持文本/工具交错顺序（app-model-streaming.ts:52-64）；diff 用 `ShikiDiffView`，宽 >120 列 split 否则 unified，shiki 异步高亮带 cacheKey（app-shiki-diff-view.tsx:7,61-78）。

## 接口与参数要点

- `targetFps:30`、`exitOnCtrlC:false`、`useMouse`+mouse movement、console 复制键 ctrl+y（tui.tsx:26-49）。
- 审批面板预览截断 120 cells、回退宽 80（app-approval-panel.tsx:20-23）；面板优先级=审批>selection>快捷键>补全>历史。

## 边界与坑

- 非 TTY exit 1（tui.tsx:14）；exitSignals 自定义剔除 SIGPIPE——会话替换关 MCP 管道会触发它，OpenTUI 默认信号表会整个销毁 TUI（tui.tsx:29-31）。
- stderr 纪律：错误/用法一律 ctx.stderr，正常输出/help 走 ctx.stdout，headless 下 stream-json 的 result 行是流终止符、其后不得再冒事件行（prompt-command.ts:326）。
- 启动失败经 startupError 于 DESTROY 后重抛（tui.tsx:118-122,148）；模式切换乐观更新必须回滚；ctrl+c 单击清草稿、双击确认退出防误伤长会话（app-keyboard.ts:216）。

## 对 duo 的启示

duo 现状是 CLI REPL 纯文本叙述行 + readLine 阻塞式 y/n。对照三条：

1. opentui-react 这类「终端里的 React」需自绘渲染器+帧循环+键盘事件体系，引入门槛高（依赖 custom fork、主题/宽度/信号全套适配），但换来 markdown 实时渲染、diff 分栏高亮、多面板同屏——duo 可先低成本借鉴其「**事件归约到 state 再渲染**」的分层，把 M11 叙述行改为订阅会话事件流的纯函数 reducer，为后续 TUI 化留口。
2. **审批形态**：ZCode 用 Promise 化审批队列（每请求挂 pending Promise、FIFO、escape=deny、allow_project 持久化规则），且工具无关地复用同一面板承载提问/多选——duo 的 readLine y/n 可升级为「决策枚举+Esc 兜底 deny+abort 信号移除队列项」的小队列，不必先上 TUI。
3. **模式切换的乐观更新+失败回滚**、以及「补全面板打开时键位让位」的优先级链，是 duo 增加 slash/模式交互时直接可抄的交互纪律。
