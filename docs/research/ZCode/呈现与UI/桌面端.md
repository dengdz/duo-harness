# 桌面端（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 18（T-22）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；Web 面见 [Web呈现.md](Web呈现.md)；cron 调度见 [../子代理与编排/任务管理.md](../子代理与编排/任务管理.md)。

## 机制全貌

Electron 五进程面：main（`index.ts`，编排所有 OS 集成与 IPC）、preload、renderer、host 业务进程与 scheduler 进程（后两者均为 `utilityProcess.fork` 的 Node 子进程）。业务 RPC 不走 Electron ipcMain，而是 main 用 `MessageChannelMain` 造一对端口：port2 随 InitLocal 发给 host，port1 经 `webContents.postMessage` 发给 renderer（desktopHostProcess.ts:562-575）；host 侧 `wrapElectronPort` 适配后建 `ChannelServer+Logging/NetworkTelemetry 包装`，`services.exposeOnChannelServer` 暴露全部服务（host/index.ts:1971-2024），renderer 用 rpc 包 `ChannelClient` 对连。跨 workspace 协作靠 `BroadcastHub`：Renderer A→RPC→Host A→parentPort→Main 中转→postMessage→Host B/C→RPC event→Renderer B/C，并带 claim/reservation 原子去重（broadcastHub.ts:12-22,109-153）。窗口由 primaryWindowCoordinator 单飞：`pendingEnsurePromise` 收敛 ready/activate 并发，防冷启动双窗；复用前检查 `isRendererCrashed`，崩溃窗口 `destroy` 后走重建（primaryWindowCoordinator.ts:40-45,77-93）。每窗口一个 host；强制升级 gate 通过 `canCreateWindow` 统一阻断 activate/dock/tray/open-url 各入口（:61-64）；退出时 host 强杀兜底 ≥3.5s，防 agent 子进程成孤儿（desktopHostProcess.ts:644-646）。

## 关键流程

① **启动与窗口**：`requestSingleInstanceLock(deepLink数据)` 单实例，二次启动由 `second-instance` 转发 URL（index.ts:1816-1826）；macOS `open-url` 先于首窗时记入 `startupOpenWorkspaceRequest` 并触发 `ensurePrimaryWindow`（:1803-1811）。`zcode://` 路由四类：`workspace/open?path=`（外部目录需弹窗确认且确认先于 statSync，UNC 网络路径在任何 fs 探测前拒绝，desktopOAuthDeepLink.ts:264-287）、`oauth/callback`（state↔window 注册表路由）、`payment/callback`、`share/import`；renderer 未 ready 一律 pending 缓存等 `rendererReadyWebContentsIds` 上报（:206-220,42-51）。

② **host 进程**：fork 时注入 provider config、灰度快照、macOS CUA launcher pid；main 侧消息路由器分发 Log/遥测/agent 进程生命周期/BrowserExecuteRequest/cron 结果/本地媒体授权等十余类（desktopHostProcess.ts:284-547）。

③ **内置浏览器**：`BrowserGuestManager`（browserGuestManager.ts:431）以 WebContentsView+CDP debugger 挂载实现 IAB，能力含 attachGuest 门禁（window/session/workspace/remoteSession/residency 五重匹配，:522-660）、Playwright locator 执行与 DOM 快照（browserPlaywrightExecutor.ts）、截图面协调（surface coordinator+透明窗）、webm 录屏、tab residency 协调器（按 window 隔离的上限与 victim 淘汰，browserTabResidencyCoordinator.ts:21）。它就是 agent 的 browser-use 工具后端：host 收到浏览器命令→`BrowserExecuteRequest`→main `handleBrowserExecuteRequest` 执行→`BrowserExecuteResult` 回传（desktopHostProcess.ts:411-457）；缺实现时回 `backend_unavailable`。CUA（macOS 辅助功能点控）是另一条链路，与 IAB 并列。

④ **OS 集成**：托盘仅 Windows，菜单随 locale 重建、更新入口按产品 flavor 裁剪（desktopTray.ts:21-107）；任务通知由 host 结果驱动，点击回聚焦发送窗口（desktopNotifications.ts:123-155）；Chrome cookie 迁移跨三平台解密（mac Keychain safe storage/Windows App-Bound/Linux helper），node:sqlite 快照+AES-128-CBC，明文用后清零（chromeCookieManager.ts:82-100）；本地媒体协议在 app ready 前注册 `standard+stream` 特权 scheme（MP4 moov/seek 依赖），复用原生 file loader 处理 Range（localMediaPreviewProtocol.ts:137-153）；autoUpdater 基于 electron-updater+ManifestUpdateProvider，`checkForUpdatesInFlight` 去重、flavor 可禁用（autoUpdater.ts:22,41,62）。

⑤ **scheduler**：独立 utilityProcess 常驻，只持有 tasks-index 轮询派发；`cron-dispatch-request`→main `resolveDispatchHost` 选 host→`CronRun` 转发，结果原路回 scheduler 结算，无 host 则 transient 退避重试；off-peak 独立通道；manual run 落库后 `wake()` 即时唤醒（desktopCronScheduler.ts:3,106-192,207）。

## 接口与参数要点

- Deep link：scheme `zcode`，host/path 为 `workspace/open|oauth/callback|payment/callback|share/import`，参数 `path/code/state/provider/channel/status`；argv 提取支持 3 轮解码+相邻 argv 拼接候选（desktopDeepLinkUrl.ts:105-146,191-199）。
- IPC：`InternalChannels.ServicePort/ScopedServicePort` 传端口；`PlatformChannels.OpenWorkspacePath/PaymentCallback/ShareImport/BrowserView{...}`。
- 浏览器：viewport 限制常量、`clientMode: desktop-continuous|web-remote-replayable`、截图 pending 去重+abandoned 上限熔断（browserGuestManager.ts:1550-1590）。

## 边界与坑

- AppImage/xdg 二次启动：协议回调可能被多次编码或拆成多段 argv，候选集+`isCompleteDeepLinkUrl` 兜底防丢 query（desktopDeepLinkUrl.ts:155-205）。
- cookie 迁移是隐私重区：跨平台解密+临时快照必须同一事务边界（chromeCookieManager.ts:1-3）；被解密的宿主 cookie 可复用于登录态，属高敏能力。
- BrowserView 隔离：guest 用独立 `EMBEDDED_BROWSER_PARTITION` 会话（index.ts:1875），attach 五重门禁防跨窗/跨会话劫持；本地媒体旧实现「信任 renderer 传任意绝对路径」已改为 main 侧精确 realpath 授权表（TTL 30min、上限 256、symlink 失效即回收，localMediaPreviewProtocol.ts:43-70）。
- 崩溃坑：renderer crash 后窗口存活但白屏，必须 destroy 重建（primaryWindowCoordinator.ts:41-43）。

## 对 duo 的启示

duo 无桌面端。对照三条：

1. 桌面壳的**不可替代能力是「受控宿主」**——IAB（WebContentsView+CDP 让 agent 可看可操作浏览器且有截图/录屏/隔离会话）、托盘与通知（长时任务的到达通道）、单实例 deep link（外部拉起工作流）；CLI+Web 均给不了这些。
2. **最小壳形态应是「main 编排+utilityProcess 业务 host+MessagePort RPC」**而非把业务塞进 main：进程隔离使 agent 崩溃不拖垮壳，BroadcastHub 模式可天然扩展多窗。
3. **值不值的判据是自动化宿主需求**：duo 若需 cron/off-peak 类常驻调度，scheduler 独立进程+无 host 退避重试（desktopCronScheduler.ts:119-130）是可直接借用的成熟范式；若只是 CLI 封装，桌面壳溢价不足。
