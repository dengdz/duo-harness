# ZCode（zai-org/ZCode）项目总览

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验，github 离线未 pull；v3.14.0，开源快照仅 2 个提交、历史压缩、测试近乎全剥离）。本文为五批次全景探查（结构/功能/设计/UI/路由交互）的汇总，结论只对该锚点负责；出处均为 ZCode 仓库内路径。沙箱与权限域另有专册 [沙箱与权限.md](沙箱与权限.md)。

## 一句话定位

TS pnpm monorepo 的全形态 agent 产品：Electron 桌面端（React 19 + 32 万行组件库）+ 薄 Web 前端 + 终端 CLI（opentui-react TUI）+ 可远程部署的 server，agent 内核走 ports & adapters 六边形架构，SQLite 事件存储 + v4 协议投影；全仓约 83 万行 TS（根 54.5 万 + CLI 圈 28.9 万）。

## 1. 代码结构与模块划分

- 单仓双圈：根 `packages/`（桌面/Web/服务端产品线）+ `apps/zcode-cli`（自带 lockfile 与 turbo.json 的 CLI 子仓）；`harness/remote` 仅 3 文件（SSH docker 容器）。
- 根 packages：`ui`（React 19 组件库兼应用主体，323k 行全仓最大，radix/lexical/dnd-kit/tailwind v4）、`services`（session/storage/node-pty/cron/undici，88k）、`desktop`（Electron 41 壳，61k）、`shared`（zod 契约 + zcode-protocol-v4，38k）、`server`（Hono HTTP/WS + stdio，11k）、`rpc`（VS Code 式 IPC 抽象）、`provider`/`provider-node`（模型抽象与 Node 实现）、`web`（3 页薄前端）、`zcode-cua`（官方声明 placeholder 桩）、`formal-proof`、`model-option-map`。
- CLI 圈：`contracts` 21k（类型枢纽）/ `core` 96k（领域）/ `adapters` 52k（实现）/ `bootstrap` 64k（装配）/ `cli` 11k / `tui` 14k / `dynamic-workflow` 20k / `telemetry`（OTel）/ `node-repl-host` / `debug`（React 调试台）。
- 依赖方向：cli→bootstrap→{adapters,core}；adapters→contracts；core→contracts(+dynamic-workflow)；**contracts 不依赖任何内部包**。`architecture-policy.yaml` 强制 forbidCycles / forbidDeepImports / 单文件 ≤400 行 / 公有方法 ≤12，`scripts/architecture/architecture-check.mjs` AST 检查（但存量 13 模块标 managed:false，纪律是新码门禁）。
- 构建：根包逐包 tsc、desktop 用 Vite、CLI 圈 turbo 依赖图 + esbuild 打包 + **Node SEA 单文件**分发；oxlint/oxfmt + husky + knip。测试近乎为零（全仓仅 4 个 .test.ts，`apps/zcode-cli/README.md:20` 仍宣称 npm test 但 tests/ 目录不存在）。
- 进程模型：桌面 Electron 三进程（main/preload/renderer + host 进程）；CLI 单进程按需派生（workflow 子进程 `__zcode-dwf-child`、plugin host 子进程、MCP stdio 子进程）。

## 2. 核心功能与业务逻辑

- **agent 运行时**：`core/src/runtime/methods/turn-loop.ts` `runRegularTurnLoop`（while(true)：abort 检查→drain runtime commands/steer→`turn-model-step` 发请求→工具调度→compact/rapid-refill 判定）；状态机 `agent/turn-machine.ts` + `turn-state.ts`（phase 迁移/终态判定）；`AgentRuntime` 单类 + `deps.ts` 约 30 个可选端口注入（「端口在场即功能门」），方法拆 `runtime/methods/` 97 个自由函数文件（签名收 `AgentRuntimeInternal`）；流式经 `model-streaming-event-queue`（有序写队列，高水位 128）+ `streaming-tool-coordinator` 流中工具调用协调。
- **工具系统**：handlers 全景——bash（readonly 判定拆 20+ 个 `bash-readonly-policy-*` 文件）、read/write/edit、glob/grep、webfetch/websearch、todo、node-repl、skill、agent 族（send-message/submit-result/task-output/task-stop）、read-session-context、plan-mode、ask-user-question、cron/off-peak/escalate/list-models、workflow 族（create/amend/save/get-run）。zod schema 在 contracts，注册/别名 `tool/registry.ts`，执行管线 `tool/executor/`（permission-flow、hook-flow、timeout、batch-runner）。**后台 bash**：`run_in_background` → `bash-background-lifecycle` → `background-task-registry`，task-output/task-stop 读/停。
- **会话与存储**：SQLite（node:sqlite DatabaseSync）22 个迁移（0001_base…0022：session/message part/todo/permission/workflow+dwf journal/usage/input ledger/model selection），migration-runner WAL busy 指数重试 + 启动锁；恢复 `resumeFromStore` + history hydrator；压缩 `core/src/compact/`（policy/prompt/rounds/microcompact，summary 单独请求）。
- **LLM provider**：Vercel AI SDK 封装（`adapters/src/model/runner-stream.ts` streamText + StreamingToolCallAssembler 归一流式工具入参）；provider kind 三值 openai/anthropic/openai-compatible，注册表在根 `packages/provider`；reasoning：anthropic thinking providerOptions + 历史回填归一；重试 `retry-policy`（retry-after 上限 5min）+ idle 超时自适应抬高。
- **上下文与记忆**：系统提示 `core/src/context/builder.ts` + sections（memory、AGENTS.md 注入、git 快照）；memory 域（directory/extraction/recall/memory-agent-loop）+ 写侧加固（memory-file-permission 限制写入 memory root）。
- **子代理**：项目 `.zcode/agents/*.md` profile（frontmatter 解析 + 信任检查 + 权限加固剥离）+ runner spawn（general-purpose/explore 预设、borrowed-mcp-port、persistent-memory）；dynamic-workflow：TS 脚本 compiler/lowering/engine，产物写 `.zcode/workflow-runs/<runId>.mjs` spawn 子进程 + NDJSON `__host.*` 桥接回父进程；debug 调试台（模型 IO 记录 + vis-timeline）。
- **技能与命令**：skills 扫描（SKILL.md 根/子目录 + symlink 信任规则）；slash 命令内置/保留名 + 自定义命令；@文件补全在 TUI。
- **MCP**：`ProcessTreeStdioClientTransport` 扩展官方 SDK + 进程树清理（Windows job object）+ 连接池 + OAuth 全家桶。
- **扩展**：plugin host 以 MCP server 形态独立子进程承载插件（源/市场/github 归档下载）；hooks（PreToolUse/PostToolUse/PostToolUseFailure 等，workspace 信任链，执行经 `tool/executor/hook-flow`）；node-repl-host 独立 JS 运行时宿主（桥接 browser/cua 工具）。
- **遥测**：OTel 深度可观——`agent-trace-runtime`（1674 行，span 工厂 + causation）、`model-api-recorder`、`agent-metrics`、OTLP exporter、error-sanitizer；TraceContext 从 contracts 贯穿 core。

## 3. 整体设计与架构风格

- **ports & adapters 六边形**：contracts 25 个 port 文件为唯一类型枢纽（零内依赖），adapters 约 22 个适配族一一实现，core 纯领域零 adapters 依赖；纪律由 `architecture-policy.yaml` + AST 检查器执行——**把层次规则做成可执行策略**是全仓最值得借鉴的机制（但存量未达标，managed:false 普遍）。
- **组合优于继承的内核**：AgentRuntime 构造注入 + methods/ 自由函数模块（零 this 绑定）；代价是 924 行 types.ts 聚合 `AgentRuntimeInternal` 巨型内部接口，上下文靠参数巨对象传递，认知成本高。
- **schema 全栈 zod**：配置/工具/协议三层统一（contracts zod 3 + adapters zod 4）；zcode-protocol-v4 是会话投影协议族（v4-gateway：per-session TopicPublisher + CommandInbox + 投影/replay/local-ttft，不做网络 IO）。
- **事件投影**：`contracts/events/event-reducer.ts` 从约 25 种 SessionEventType 纯投影 SessionProjection；流式侧 promise 链式有序写队列（fail-fast + 显式 drain）+ 流式工具入参小状态机。
- **存储**：SQLite 单文件事务 + 迁移即代码（SQL 内嵌 TS），换投影查询与结构化回填（对照 JSONL 派：DSH 走日志溯源）。
- **错误与重试**：闭合枚举取向——`ExecutionFailureType` 六值分类（spawn_error/timeout/cancelled/sandbox_violation/output_limit/unknown，含已撤除沙箱的残留值）+ 可归因遥测字段；empty-completion-retry、idle 超时自适应。
- **配置**：scope 压栈 System→User→Project→Env→Cli 后者覆盖前者；插件另设 user|workspace scope；项目级权限模式持久化 SQLite。
- **进程模型取舍**：SEA 单文件换零安装分发（资产内嵌管线复杂）；plugin host / workflow / MCP 各自子进程 + NDJSON 桥，进程树清理跨平台（Windows job object）。
- **三标签与评价**：「契约优先的六边形纪律」（25 port + 门禁脚本）、「组合优于继承」（deps 注入 + 函数模块）、「事件溯源投影 + 遥测深可观测」。最值得借鉴：architecture-policy 可执行架构门禁。最重负担：methods/ 97 文件 + 巨型内部类型的认知成本。**快照剥离的影响**：行为正确性完全不可验证（「可读不可验」），cua/swift-bridge 为 fail-closed 占位桩——端口接缝仍诚实，可插拔性由占位包自证。

## 4. UI 界面与组件

- **组件库**：`packages/ui`（React 19）既是组件库也是应用主体——根级应用组件（App/TaskList/SettingsPage/WelcomeScreen/Terminal/PreviewPane/WorkspaceSidebar/LexicalChatInput/ToolCallBlocks）+ `app-shell/`（侧栏/工作流侧面板）+ `settings/`（约 50 文件：MCP/插件商店/Automations/OffPeak）+ `components/ui/`（约 45 个 shadcn/radix primitives）+ `components/ai-elements/`（约 45 个，vercel ai-elements 派生）+ `workflow-graph|timeline`（@xyflow/react）+ prompt-editor + terminal + i18n。
- **设计系统**：Tailwind v4 CSS-first（无独立 config，:root/@theme CSS 变量 + `.dark` 类）；主题 light/dark/zai-light/zai-dark/system（localStorage + 多窗口同步）；平台 variant（mac/linux/windows-desktop）。
- **对话界面**：markdown 用 streamdown（remark/rehype + CJK/代码/数学/mermaid 插件）；代码高亮 shiki 4；工具卡 `ToolCallBlocks.tsx`（393 行）+ renderers 注册表按 toolIdentity 分发（edit/agent/execute/cua/mcp/workflow…）；审批 PermissionDialog + ElicitationDialog；计划 ai-elements/plan + PlanDetailSidePane；输入框 Lexical（SlashCommandPlugin + mentions）；diff 用 @pierre/diffs（Shadow DOM MultiFileDiff）；预览 PreviewPane 八种内容（md/代码/pdf/office/图片/patch）；终端 xterm；git 面板。
- **桌面端**：Electron main 深度 OS 集成——托盘、deep link（zcode:// + OAuth 回调）、内置浏览器（Playwright 执行/截图/录屏/tab residency，30 文件）、Chrome cookie 迁移、本地媒体协议、窗口 vibrancy、通知、autoUpdater；桥接 `packages/rpc`（VS Code 式 PersistentProtocol/MessagePortMain）。
- **Web 前端**：3 页薄壳（Root + OAuth 回调 + 会话分享落地页），复用 @zcode/ui 与 connectViaWebSocket。
- **TUI**：非 ink——`@mbears/opentui-react`（React 19 自绘终端渲染器，30fps + mouse）+ shiki/web-tree-sitter；86 个 app-* 文件（审批面板/模式切换/@补全/输入历史/问题面板/shiki diff/侧栏/子代理视图）。
- **i18n**：自研轻量 Intl（zh-CN 6190 行/en-US 扁平 message 表 + useZCodeIntl）。
- **工程化**：oxlint + tsc + knip；**UI 测试仅 1 个文件**，质量靠类型与 lint。

## 5. 页面路由与交互流程

- **无 router**：`App.tsx`（1280 行）shell 编排，主视图 `workspaceMainView` state 仅三值（chat/automations/plugin-store）；窗口由 tabStore 管理（tab 仅 workspace/settings 两种），设置内容（MCP/技能/插件）以 settings tab 打开；侧栏/终端/预览/Git 走 side-pane tab + paneLayoutStore；命令面板 CommandCenterDialog。
- **桌面进程流**：单飞主窗（primaryWindowCoordinator 复用/崩溃重建）；main `utilityProcess.fork` 起 host 进程（业务 RPC 服务端）；renderer↔main↔host 走 rpc ChannelClient + MessagePortMain；跨 workspace 广播 Renderer→Host→Main→其他 Host→Renderer；deep link 首窗前经确认门；secondary instance 转发 deep link。
- **连接流**：web `connectViaWebSocket`（raw WS → ChannelClient）→ server `/ws`（"web-remote-replayable" 带重放缓冲）；`/ws/host` 为 trusted-host capability token 通道；远程后端经 `/api/connect-remote` 一次性桥接；会话索引/切换在 UI 侧 store（sessionsIndexStore/workspaceConnectionRegistry）；**web 端 onClose 为空——无自动重连**。
- **消息链路**：LexicalChatInput（@mention/斜杠在 mentions 插件）→ `v4/commandFactory`（uuidv7 commandId + 持久化 clientId + baseRevision CAS）→ pendingCommandRegistry 乐观记录 → agentConversationTransport 下发 → topic 订阅（=sessionId）wire 帧 base64 分片重组 + ack barrier + TTFT 校准 → `conversationProjectionStore`（snapshot + optimisticCommands + loadingOlder）→ `useConversationProjection`（useSyncExternalStore）→ ConversationTimeline 渲染 → 工具卡 resolveRenderer 分发 → 审批 interaction 经 pendingInteractionAdapter 转 PermissionDialog，应答以 resolveInteraction 命令回传（列入可重放命令）；断线由 staleAuthorityRecovery/pendingCommandRecovery 恢复。
- **TUI 交互**：模式 plan/build/edit/yolo 循环切换（乐观 setMode 失败回滚）；审批队列 setApprovalQueue → app-approval-panel（不落持久规则）；@ 补全面板；斜杠过滤 + /model、/effort、/variant 补全面板；子代理专门视图（app-subagent-view + 侧栏）。
- **多会话/多任务**：支持真并行——workspace 多 tab + `workbenchGroupStore/paneLayoutTree` 分 pane，每 pane 独立 SessionPane 绑定会话（placement 持久化）；任务列表虚拟化分组 + 拖拽分组；子代理以 side-pane tab 打开 + ModelTrajectoryPane 轨迹查看。
- **分享流**：桌面端 ConversationShareMenu 生成 → web 落地页（登录/过期/跨平台状态机）→ 只读渲染复用 ConversationShareReadonlyTimeline（明确禁止 Desktop 宿主依赖）。
