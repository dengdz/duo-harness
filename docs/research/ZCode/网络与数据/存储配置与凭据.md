# 存储配置与凭据（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 20（T-24）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；SQLite 会话库锁语义见 [../Agent循环与会话/会话事件模型与持久化.md](../Agent循环与会话/会话事件模型与持久化.md)。

## 机制全貌

配置是六层 scope 压栈合并：ConfigScope 定义 System/User/Project/Session/Env/Cli，优先级 0/10/20/30/40/50（contracts/src/config/index.ts:157-175）；config-factory 实际只压 System→User→Project(多个文件)→Env→Cli，Session 留给运行时（apps/zcode-cli/packages/adapters/src/config/config-factory.ts:129-210）。合并算法（config-merger.ts:26-154）：按优先级升序 Object.assign 整体覆盖标量，随后对嵌套对象做一层 spread 深合并；mcp.servers 按服务器名整体替换；plugins 按 pluginId/optionKey 合并、dirs 数组去重并集；hooks.events 为跨来源追加而非覆盖，enabled 取任一来源为 true（config-merger.ts:170-196）。凭据存单一 JSON 文件，值用 AES-256-GCM 加密，key 为 sha256(secret)，secret 取 `ZCODE_CREDENTIAL_SECRET` 否则回退 `platform:homedir:username` 派生（auth/credential-cipher.ts:4-8, 87-101）。所有写路径经进程内 FIFO + OS 排他文件锁保护完整读改写，写完以 allSettled 广播 onDidChange 监听者（auth/shared-credentials.ts:316-331）。workspaceIdentity 是可选的「工作区身份键」：本地为 resolve(cwd)，远程为 `remote:ssh|wsl|docker:<authority>:<path>` 结构串（packages/shared/src/remote-workspace-identity.ts:46-61），用途是把 memory 目录、hook trust 快照与磁盘路径解耦。

## 关键流程

① **配置发现与合并**：loadProjectConfigs 从 cwd 向上逐级找 `.zcode/config.json`/`zcode.json`，遇 `.git`（文件或目录）哨兵即停，reverse 后按根→cwd 顺序装载，显式 projectConfigPath 追加并按 canonical path 去重（packages/shared/src/workspace-hook-config.ts:207-221, 335-343）。每个文件 JSON.parse 后经 ZCodeConfigFileSchema.parse（zod）校验，失败产出 diagnostics 并 warn（config/schema.ts:286-391；config-factory.ts:400-428）。Env 覆盖是白名单映射：仅 ZCODE_STORAGE_DIR/SESSION_DB/HTTP_PROXY/LOG_FORMAT/MAX_TOOL_CONCURRENCY 等少量键，非法数字归 0（env-config.adapter.ts:14-63）。

② **凭据**：createSharedZCodeCredentialStore 的 save/load/delete 族全部走 mutateRawCredentialRecord = withFileLock（进程内 FIFO 串行 + acquireFileLock，重试 25→400ms，上限 8s）→ 读改写 → atomicWritePrivateTextFile（0600 权限 tmp+rename，EPERM/EBUSY 重试）（packages/shared/src/node/privateFilePersistence.ts:51-121）。密文格式 `enc:v1:<iv b64url>.<tag>.<ct>`，IV 12B、tag 16B。损坏处理：JSON.parse 失败时先 backupCorruptFile——以内容 sha256 前 24 位命名 `<file>.corrupt-<hash>.bak`，`wx` 排他创建并 chmod 0600，多进程重试收敛为一份证据——然后抛错拒绝服务，**绝不静默清空重建**（shared-credentials.ts:303-313）。监听分发：per-filePath 的 Set，写盘后 Promise.allSettled 逐个触发（shared-credentials.ts:187-198, 327-330）。

③ **local_setting**：SQLite 表以 (scope, scope_id, namespace, key) 为主键，writeLocalSetting 用 `insert ... on conflict do update` upsert（storage/session-store/repositories/local-settings.ts:107-139）。项目级 permissionMode 即 namespace='permission'/scope='project'/key='mode'，由 bootstrap session-facade 写入（session-facade.ts:428）；migration 0003 从旧 permission 表回填。

④ **workspace**：resolveProjectMemoryRoot 以 workspaceIdentity(trim) 或规范化 workspacePath（win32 转小写）为键源，sha256 取前 16 位 hex 作目录名；有 identity 时 slug 固定 "project"，否则用 basename 清洗（core/src/memory/project-root.ts:10-33）。消费点：create-app 透传 memory.workspaceIdentity（bootstrap/app/create-app.ts:160,260）、MCP pool snapshot（core/src/runtime/methods/mcp.ts:78）、hook trust 快照键（config-factory.ts:220-228）、resume 会话复写（runtime/methods/resume.ts:127）、CUA 远程判定（create-app.ts:768）。

## 接口与参数要点

- `createConfig(options)` → {configPort, config, sources}（config-factory.ts:129）。
- 默认用户配置 `~/.zcode/cli/config.json`（file-config.adapter.ts:443-445）。
- 凭据路径 `$ZCODE_DATA_BASE_DIR || ~` + `.zcode/v2/credentials.json`（shared-credentials.ts:280-290）。
- 加密参数：aes-256-gcm、IV 12B、tag 16B、key=sha256(secret)、前缀 `enc:v1:`（credential-cipher.ts:4-7）。
- 锁参数：重试 25/50/100/200/400ms、maxWait 8s、ownerless grace 100ms（privateFilePersistence.ts:7-9）。
- 凭据条件事务：deleteManyIfValue（guard 匹配才整批删）、saveReplacing（写新删旧）（shared-credentials.ts:46-66, 137-165）。

## 边界与坑

- 损坏凭据文件被读时抛错且留 .bak，调用方必须显式恢复；但同步入口 loadSharedZCodeCredentialSync 吞掉一切错误返回 undefined 且不加锁（shared-credentials.ts:275-277），仅适合非关键读取。
- MCP servers 的 user 遮蔽 project，与全局「project 高于 user」相反（config-factory.ts:391-394）；project 层 extraKnownMarketplaces 在合并时被剥离（config-merger.ts:34-41）。
- project hooks 只作 pending-trust 候选进快照，不进可执行 merge（project-config.adapter.ts:63-71）；显式配置重复加入会使既有 trust stale（config-factory.ts:163-166 注释）。
- workspaceIdentity 变化会连带 memory 目录、hook snapshot bundleDigest、远程判定全变，resume/信任记录随之失效；非法 remote identity 解析返回 null 回落本地路径（remote-workspace-identity.ts:64-68）。
- Env 只覆盖极小键集，密钥类凭据绝不走 env-config。

## 对 duo 的启示

- **scope 压栈合并**：duo 现状是 yml 一次性引导，可演进为 System→User→Project→Env→CLI 的 RuntimeConfigPatch 压栈 + 显式优先级表；关键是**逐字段声明合并语义**——标量覆盖、对象一层深合并、数组分「按名替换」（mcp.servers 式）与「追加」（hooks 式），并在合并层强制不变量（hooks 追加 + enabled 或运算）。
- **凭据加密最小形态**：无需引入 KMS——单 JSON + withFileLock 包住读改写 + 0600 原子 rename + 内容哈希 .bak 损坏备份，即达成 ZCode 同级安全；加密用 AES-256-GCM，secret 优先 env、回退用户/机器派生，可平滑替换 duo .env 中的明文 token。
- **workspaceIdentity 增强 M12 root**：duo 的 workspace root 可改为「显式 identity || realpath(cwd) 归一（win32 小写）|| .git 哨兵根」，哈希 16 位作隔离键，memory/快照/trust 与物理路径解耦，天然支持远程/容器工作区；且快照 digest 必须复用同一键源，避免 ZCode 曾出现的 toggle/review 各自推导导致 mismatch 的教训。
- **local_setting 模式**：项目级偏好（如 permissionMode）适合 namespace/scope 四元组主键 + upsert 的通用键值表，与业务 schema 表分离，迁移成本最低。
