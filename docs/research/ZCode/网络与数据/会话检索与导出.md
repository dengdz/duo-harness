# 会话检索与导出（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 21（T-25）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；子代理 profile 见 [../子代理与编排/子代理.md](../子代理与编排/子代理.md)。

## 机制全貌

跨会话读取是模型工具 ReadSessionContext：从本地 SqliteSessionStore（`apps/zcode-cli/packages/bootstrap/src/app/session-store.ts:2`）取历史→查询词打分选段→超预算时用辅助 lite 模型分块抽取→返回有界摘录。会话分享是独立链路：桌面端选区生成投影 rows+artifact→服务端 capabilities/prepare/upload/confirm 换 share_url→web 只读落地页拉 preview 渲染。ZCode **无 /export 类本地导出命令**（全仓 grep 无果）；对照 duo：M21 session_search 是「用户/模型共用的检索」，ReadSessionContext 是「模型专用、lite 模型二次加工」的读取，ZCode 把「导出」外包给了分享发布。

## 关键流程

① **ReadSessionContext**：入参 `sessionId(sess_*)+query(≤4000字)+strategy+maxTokens`（`contracts/src/tools/read-session-context.ts:12-38`）。消息先去重、剔除 model-only 用户消息成 snippet（`core/src/session-context/read-session-context.ts:157-166`），按 query 评分：整句命中+20、词命中+3+min(频次，5)，中文做二元切词（:191-237）。**relevant**：取 score≥3 的 snippet（否则末尾 12 条）按分排序装到字符预算（:249-259）；**handoff**：直接取尾部预算内连续片段（:262-272）——前者「按相关性检索」，后者「无条件保尾部」。lite 路径：全文≤80k 字符则一次抽取；否则按 28k 字符切块，relevant 取「top4 评分块+始终保留最后一块」、handoff 取最后 5 块（:310-324），每块 lite 调用（perChunkTokens=clamp(maxTokens/2, 800..2500)，`handlers/read-session-context.ts:230-237`），空/NO_RELEVANT_CONTEXT 跳过，多块结果再合成一次（:258-266）。lite 不可用或出错时回退本地拼装，source 标 "local"/"fallback"、truncated=true（:94-143）。归属校验：仅 `session.context.read` 权限（:175-177），读本机 sqlite；session 不存在返回结构化 not_found 而非抛错（:59-65）。用户输入 `#sess_*` 时 turn 注入 reminder 提示模型主动调本工具（`session-context/references.ts:12-30`、`runtime/methods/turn.ts:869-871`）。

② **分享链**：桌面顶栏按钮进入选区 dock，默认全选、可 partial 勾选（`ui/ConversationShareMenu.tsx:38-53`），权限三档 private/link-viewer/link-editor。服务编排 preflight→prepare→逐 artifact 上传→confirm 轮询（`services/conversation-share/conversationShareService.ts:664+`），HTTP 端点 `/shares/capabilities|preparations|preparations/{id}/artifacts|confirm|{code}/preview|{code}/continuation`（`conversationShareHttpClient.ts:244-332`）；confirm 提交 rows 投影+双 sha256+`acknowledged_no_secret_detection:true` 披露确认（`shared/src/conversation-share.ts:310-327`），返回 share_code/share_url/expires_at（:239-244）。服务端实现不在开源快照内，仅契约可核实。web 落地页状态机 loading/ready/login_required/error（`web/src/share/ConversationShareLandingPage.tsx:29-34`）：有 token 先带鉴权请求，authentication_required/not_found 匿名时转 login_required；错误码映射 401→需登录、404/403→not_found（**存在性隐匿**）；continuation 是反向导入：web→桌面落盘只读副本（`conversation-share.ts:379-399`）。

③ **导出**：无本地写盘导出，仅分享/导入复制路径。

## 接口与参数要点

- maxTokens 默认 6000、上限 12000（contracts:5-6），换算字符预算 ×4 并 clamp 到 [4000,48000]（session-context:144-147）；lite 输入 80k 字符/块 28k/最多 5 块（:18-20）；工具输出上限 80k 字节、超时固定 5 分钟不可覆盖（handlers:33-35,194-198）。
- share schema：capabilities 含 ttl_ms/max_rows/max_payload_bytes/max_artifact_*（shared:159-166）；access_mode 三态（:53-57）；preview 的 rows 线上为 unknown[]，逐行降级解码并计数 unsupportedRowCount（:92-112,349-361）；schema_version>本端即「请升级」。

## 边界与坑

- **token 成本**：handoff 大会话最多 5 块×抽取+1 次合成共 6 次 lite 调用，每次输出最多 12k tokens，最坏五分钟挂起；relevant 也可能被低质评分 snippet 塞满预算。
- 分享：ttl/expires_at 服务端控制、artifact URL 带 url_expires_at 短时效；404 是刻意的存在性隐匿；出站 strict、入站宽容的双向纪律（shared:132-148）；未做密钥检测，靠用户勾选披露确认兜底。
- 历史内容被 system prompt 标记为不可信背景，防注入（handlers:285-289）。

## 对 duo 的启示

1. **分工**：duo 的 session_search 同时服务用户搜索框和模型，ZCode 拆成「用户侧 UI 检索」与「模型侧 ReadSessionContext（带 lite 抽取+预算）」——duo 模型侧可借鉴 query 打分+分块+NO_RELEVANT_CONTEXT 哨兵控制 token 成本。
2. **handoff/relevant 双 strategy 值得抄**：续做场景「尾部优先」比相关性排序更符合直觉，duo 导出的 handoff 包可复用其提示词结构。
3. **分享链路重**（capability 发现/双摘要/披露确认/存在性隐匿），duo 的 /export 本地写盘是零服务端成本的替代；若做分享需至少补 expires_at 与逐行降级解码，避免新 row kind 打死老客户端。
