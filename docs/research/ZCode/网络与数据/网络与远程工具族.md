# 网络与远程工具族（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 19（T-23）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；SSRF 既有防线对照见 [../沙箱与权限.md](../沙箱与权限.md) 与 duo `docs/research/DSH/web工具族/`。

## 机制全貌

ZCode 的网络工具分两层：`WebFetch`/`WebSearch` handler 在 core 定义语义与限额，真正出网走 `HttpClientPort` 适配器；适配器内建「public egress」策略（DNS 解析后校验目标必须公网）+ WebFetch 自有的字面量 IP 拦截。`SessionMailboxPort` 是跨会话异步消息的文件信箱：发送方写入 `<root>/<toSession>/unread/*.json`，接收会话在 UserPromptSubmit/PostToolUse/Stop 三个 hook 上 drain 并注入上下文。远程面由 `packages/server/src/remote` 的 SSH/Docker/WSL 三种 backend 抽象为 `IRemoteBackend`（detect/upload/exec/exists/readFile），把 server bundle 与 agent runtime 部署到远端 `~/.zcode/server` 后远端执行、stdio 回传；mailbox 仍在本地文件系统，**远程化的是运行时而非信箱**。

## 关键流程

① **webfetch**（core/src/tool/handlers/）：`normalizeWebFetchUrl`（webfetch-url.ts:10-45）限 URL≤2000 字符、仅 http/https、禁内嵌凭据、http 强制升级 https，并做形态过滤（localhost/.local、非公网 IP 字面量）。每次真实 GET 前 `assertWebFetchLiteralEgress`（webfetch-egress-guard.ts:14-28）拦截字面量私网/环回目标，含 IPv4-mapped 与 DNS64 well-known 前缀还原、198.18.0.0/15 与 5 段 special-use IPv6 排除（:5-12,77-87）；**普通域名不做 DNS preflight**（性能原因，:24-25）。重定向手动跟随，最多 10 次；跨 host/降协议/带凭据的重定向不跟随，返回终端结果让模型重调（webfetch-url.ts:63-81、webfetch.ts:128-159）。HTML→markdown 是**手写正则转换器**（webfetch-content.ts:59-85），非第三方库；仅接受 text-like MIME（:103-115），>100k 字符落 artifact 并截断。限额：60s 超时、10MB 响应、缓存 15min/50MB（webfetch-constants.ts:2-9）。

② **websearch**（websearch.ts:60-127）：无独立爬虫，走 **provider-native** `web_search`——把请求包成单工具 `streamText` 调用（需 `supportsNativeWebSearch`，:71）；入参 query + allowed/blocked_domains，maxUses=8、60s 超时（:31-32）。特别处理 BigModel Anthropic 兼容端点：强制 tool_choice 会 1210 报错故用自动选择，且必须流式（:94-105 注释）。

③ **http 适配**（adapters/src/http/）：`egressPolicy:"public"` 时先 `assertPublicEgressDestination` 预检（DNS all 解析后逐地址校验公网，public-egress-policy.ts:79-119），再把 `createPublicEgressLookup` 挂为 Node lookup 在建连时二次校验（:34-77，防 DNS rebinding TOCTOU）；public egress **禁用代理**（代理侧 DNS 无法验证，http/index.ts:272-281）；DNS 预检继承请求 abort signal（:151-165）。trace 头 `x-zcode-trace-id`（:31,305-311）；错误码含 egress_blocked/timeout/too_large 等。webfetch 错误消息会把「resolved to…」内网 IP 细节抹掉防泄漏（webfetch-network.ts:252-259）。

④ **mailbox**：目录 `<root=ZCODE_MAILBOX_ROOT|~/.zcode/mailbox>/<sessId>/{unread,read}/*.json`（adapters/src/mailbox/index.ts:13-36；create-app.ts:359-367）；`drainUnread` 排序取前 20 条（默认），校验 envelope v1 后 `rename(unread→read)` 原子确认。hook 注入 `<session-message>` 并附「仅供参考，需核对原始来源」（core/src/hooks/session-mailbox.ts:20-72）。发送侧：桌面 main 经 `taskRealtimeBus.handleSessionMessageSendRequested` 按 sessionRoutes 路由到目标 host 子进程投递（taskRealtimeBus.ts:920-975）。

⑤ **远程 backend**：`createRemoteBackend` 按目标分发 ssh/wsl/docker（create-backend.ts:6-31）。SSH 用 ssh2 Client，支持私钥/密码（keyboard-interactive）/agent，SFTP 上传带进度与 abort，ready 后 error/close/end 统一上报一次断连（ssh-backend.ts:100-190）。Docker 即 `docker exec -i` 进容器；WSL 经 wsl.exe，特殊点是把 Windows 侧 loopback 代理换成宿主网关 IP（backend.ts:33-34）。部署：server bundle + agent runtime 上传到 `REMOTE_BASE=~/.zcode/server`（deployShared.ts:7）；remoteAssetInstaller 按组件装到 `asset-cache/components/<platformArch>/<id>/`，带 `.ready` 标记、lock+心跳、sha256 校验、>24h 才清理他人 staging（remoteAssetInstaller.ts:82-94,812-853）。会话数据在远端侧产生，本侧只收 stdio。

## 接口与参数要点

- WebFetch 入参 `url+prompt`；WebSearch 入参 `query, allowed_domains?, blocked_domains?`。默认值：webfetch 60s/10MB/100k 模型字节/10 重定向/15min 缓存；http 适配 180s/10MB；websearch 60s/8 次/20k 输出。
- mailbox 参数仅 `sessionId+limit(默认20)`；remote 配置按 target 类型（ssh: host/port/username/私钥或密码；docker: 容器名；wsl: distro/user）。

## 边界与坑

- WebFetch 对**普通域名不做 DNS 解析校验**，只挡字面量 IP——若 NO_PROXY 直连场景域名解析到内网，需靠代理 allowlist（`x-proxy-error: blocked-by-allowlist`）兜底；严格防线在 HttpClientPort 的 public egress（预检+建连双查）。
- 重定向同 host（去 www）+同协议同端口才自动跟随，否则返回给模型；`TooManyRedirects` 上限 10。
- mailbox 防路径逃逸：sessionId 白名单 `^sess_[A-Za-z0-9._-]+$` + `relative()` 越界检查（mailbox/index.ts:39-50）。
- 远程断连：SSH ready 后的抖动只上报一次 disconnect 防宿主崩溃；dispose 后迟到的 ready/connect 被拒绝防旧凭据复活（ssh-backend.ts:148-172）。
- 信箱投递有超时与 failed 回执，但依赖桌面 main 在线路由，headless CLI 场景发送侧缺位。

## 对 duo 的启示

- **出网策略**：duo 的 web_fetch 已对齐 ADR-0021，但 ZCode 的双层结构（工具层字面量拦截 + 适配层 public-egress DNS 双查、禁代理）比单一防线细；duo 三道防线可对照补「**建连时二次 DNS 校验**」与「DNS64/IPv4-mapped 还原」这类绕过面。
- **mailbox 形态**：文件信箱 + 三 hook drain + rename 原子确认，是 duo 子代理/多会话通信的低成本参考——无需消息中间件，天然持久、可审计；duo 可复用「unread→read + 注入 additionalContext」语义。
- **远程部署价值**：SSH/Docker/WSL backend + 组件化资产安装工程量大，适合团队级远程执行；对个人工具收益有限，duo 若无远程跑 CLI 需求可只借鉴 `IRemoteBackend` 的窄接口（detect/upload/exec）与断连单次上报语义。
