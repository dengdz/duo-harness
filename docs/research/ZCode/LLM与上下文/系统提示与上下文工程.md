# 系统提示与上下文工程（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 10（T-14）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；压缩治理见 [压缩治理.md](压缩治理.md)。

## 机制全貌

`ContextBuilder.build()`（builder.ts:82-223）把约 14 类 section 按「节声明 → 注入位置（system|meta_user）× 缓存提示（stable|dynamic）」四象限组织（types.ts:52-54），最终产出三条各带 `cacheControl: ephemeral` 的 system message（builder.ts:230-277）：① cli_prefix；② stable body（identity/desktop/workflowActor/customSystemPrompt）；③ 全部 dynamic 段（含 `\n\n` 左边界，builder.ts:271）。meta_user 节另拆成两个 user 附件（skills_listing、context_prefix，builder.ts:279-307），不打缓存断点。memory 域分两层：system 只注入「如何写 memory」的规范段，MEMORY.md 索引走 meta_user。

## 关键流程

① **节组装**：cli-prefix → identity|customSystemPrompt|workflowActor 三选一（workflowActor 与 customSystemPrompt 同在即 throw，builder.ts:93-97）；customSystemPrompt 跳过全部动态段（130-173）；workflowActor 跳过 cli-prefix/desktop/dynamicBehavior/sessionGuidance、保留 memory 及其后（103-149）。

② **request-user-context**：`NodeContextSourceAdapter.resolveContextSources`（adapters/context/index.ts:38-68）解析 AGENTS.md——user 级 `~/.zcode/AGENTS.md` + workspace 级自 cwd 向上找到 projectRoot（94-129、204-243），100KB 截断（25、175），多源 join 合并（187-202）。输出固定标题 "# agentsMd" + OVERRIDE 强调语（request-user-context.ts:63-70），并拼接 MEMORY.md 索引（去 frontmatter、200 行/25k 字符截断+警告，index-content.ts:6-36）。

③ **memory**：system 规范段要求每事实一文件+frontmatter（user/feedback/project/reference）+MEMORY.md 一行指针（memory.ts:25-49）。turn 成功结束调 `scheduleProjectMemoryExtraction`（turn.ts:699-703；headless/remote/extractionEnabled=false 跳过，project-memory-extraction.ts:36-43）；scheduler 以 cursor 去重，直接 memory 写或无≥3 词用户散文则 skip（extraction.ts:68-83）；抽取子代理 5 turns、工具限只读+memory 目录内 Edit/Write/rm（memory-agent-loop.ts），prompt 携带按 mtime 排序、上限 200 文件的 manifest（manifest.ts:13-34）。

④ **git 快照**：`resolveGitSnapshot`（git-snapshot.ts:27-62）抓 inside-work-tree、branch、main branch（origin/HEAD 优先+main/master 探测）、user.name、`status --short`（2k 字符截断，157-170）、`log -5`，会话开始并入 EnvInfo（adapters/context/index.ts:76-84），以 system_context 段注入并声明「会话开始快照、不会更新」（env-info.ts:21-22）。

⑤ **cacheControl**：三块 ephemeral 按「身份前缀/稳定身份/易变动态」划分；stable 仅 identity/desktop/workflowActor/customSystemPrompt（各文件 cacheHint 字段）。runner-options.ts:89-90 仅声明 system-message 构造归 core/context 所有；断点透传与非 system 剥除在 provider-request-messages.ts:197-198、329-330。

## 接口与参数要点

- `addSection(section)`：省略 chars/tokens/injectionTarget/cacheHint，默认 system/dynamic（builder.ts:65-77）；`setEnvInfo(envInfo)` 替换 config（54-60）；`setToolRegistry` 兼容 no-op（50-52）。
- Config 关键参数：memoryRoot、memoryIndexContent、userInstructions、skills、guidanceToolNames、customSystemPrompt、workflowActor、presentationSurface（types.ts:102-128）。
- 节序表（source→target/hint）：cli_prefix sys/stable；identity、desktop sys/stable；dynamic_behavior、session_guidance、memory、env_info、output_style、context_management、system_context、current_date sys/dynamic；skills、request_user_context meta_user/dynamic（orderSectionsForInjection 重排，builder.ts:310-325）。

## 边界与坑

- setToolRegistry 是 no-op，工具说明走 tools 字段不镜像进 prompt（builder.ts:47-52）。
- dynamic system block 的 `\n\n` 左边界是 by design（builder.ts:270-271），空内容节不得让左边界单独成块（subagent/context-builder.ts:106-108）。
- `SubagentContextBuilder` 继承但完全 override build()：每段 system 独立打 ephemeral 断点、不走主 builder 三段组装（45-66）。
- skills 段要求 guidanceToolNames 含 "Skill"，缺席（测试/旧调用方）才保留（builder.ts:179、225-228）。
- 旧 EnvInfo 可能带历史 model 字段，渲染只读本步骤 Model（env-info.ts:76-79）；MEMORY.md 索引注入条件是 `memoryIndexContent !== undefined`（request-user-context.ts:77）。

## 对 duo 的启示

1. **三段 cacheControl 划分**：duo 可借鉴「cli 前缀/稳定身份/动态段」三级 ephemeral 断点，静态 prompt 注册表归 stable、M21 运行时注入归 dynamic，避免任一处变更打散全量缓存。
2. **meta_user 通道**：duo 现仅 M7 把 AGENTS.md 拼进 system；ZCode 把项目指令+memory 索引放 user 级 context_prefix 附件并附「可能不相关」免责语（builder.ts:330-335），system 级只留稳定规范——duo 最小改造即把 AGENTS.md 迁 meta_user。
3. **memory 域最小形态**：system 规范段（怎么写）+ meta_user MEMORY.md 索引（读什么）+ turn 末后台抽取子代理（何时写），三者解耦；duo 无 memory 域，可先落规范段+索引注入两件套，抽取调度后置。
