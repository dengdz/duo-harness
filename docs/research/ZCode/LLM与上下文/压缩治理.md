# 压缩治理（ZCode）

> 源锚点：`872ad960de7ec172591f7e1952f7849229f94521`（2026-09-21 本地核验）。M22 探测里程碑工单 11（T-15）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；上下文工程见 [系统提示与上下文工程.md](系统提示与上下文工程.md)。

## 机制全貌

ZCode 的压缩分三层：auto-compact（turn 循环内每次模型步前判定，超阈值发独立 summary 模型请求重写历史）、manual `/compact`（独立 turn，走同一 summary 链路）、microcompact（纯本地裁剪旧工具结果为 `[Old tool result content cleared]`，零模型调用）。三者最终都汇聚到 `compactActiveConversation`（manual/reactive 全量），microcompact 则独立于它。与 turn 循环的挂点：每步先 `microcompactIfNeeded` 再 `autoCompactIfNeeded`（turn-loop.ts:69-90）；rapid-refill 熔断（3 工具轮内连环压缩≥3 次）时抛 `CompactRapidRefillError` 中止 turn（turn-loop.ts:91-98，turn-loop-state.ts:21-22）；compact 取消时关 `queueAutoDrain` 暂停队列（compact.ts:150-154）。compact 落 5 种事件（session.events.ts:158-162），checkpoint 载荷携带 `compactBoundaryId`，rewind 目标被 compact 覆盖时对话回退只能 fork（rewind/index.ts:40，helpers/rewind.ts:309-310）。

## 关键流程

① **auto-compact**：`shouldAutoCompact` 判定序=disabled→消息不足（<2 轮或无 assistant）→熔断（连续失败≥3）→低于阈值（policy.ts:124-154）。token 优先用 provider usage 锚点+本地增量（compact.ts:313-340）。阈值=有效窗口（200k−min(输出预留,21k)）−buffer 13k，即 200k 模型约 155k 触发（policy.ts:67-88）。触发后同步压缩并把压缩后 entries 写回本 turn 继续跑（compact.ts:258-292），失败则 `autoCompactConsecutiveFailures++` 且 turn 继续。

② **summary 请求**：`buildCompactPrompt`=禁工具前言+9 段结构（用户意图/技术概念/文件代码/错误修复/全部用户消息/待办/当前工作/下一步，要求保留安全约束原文，prompt.ts:14-117），输入=去掉 system/`<system-reminder>` 前缀的全部轮次，末尾保留最近若干组原样（compact-selection.ts:40-56）。超窗时先增多保留组重选、manual 再截断重试，`MAX_COMPACT_PROMPT_TOO_LONG_RETRIES=3`（manual.ts:55）；Auto 外层最多 3 次尝试并发 `Retrying` 时间线事件（compact-active.ts:72,640-668）。成功后发 `ModelComplete`+`CompactBoundary`+`CompactCompleted`，历史替换为「summary 用户消息+plan/read-state 提醒+保留段」（compact-active.ts:495-624），并 `readFileState.clear()`。

③ **manual /compact**：`parseCompactCommand` 解析可选附加指令（commands.ts:5-15），turn.ts:240-257 分流到 `executeManualCompact`：StandaloneTurn 阶段、`TurnStarted` 标 `inputVisibility:"model-only"` 不渲染用户气泡（compact.ts:69-81）；历史不足时发 `CompactCompleted(skipped)` 健康空转（compact-active.ts:217-238）。

④ **microcompact**：触发=距上次 assistant 完成>60min（TimeBased）或估算≥阈值（TokenPressure，默认 min(0.9×autoThreshold， autoThreshold−2000)，microcompact.ts:77-81,171-195）；按 assistant 轮分组收集可压缩工具结果（Read/Bash/Grep 等 9 种），保留最近 5 组，其余替换为清除标记；节省<256 token 放弃（below_min_savings）；媒体块与错误结果默认豁免。

⑤ **rewind 交互**：checkpoint 记录 boundaryId；被 compact 覆盖的消息不可直接对话回退，须 fork 新会话，工作区文件回退不受影响。

## 接口与参数要点

- 阈值：contextWindow 200k、输出预留 32k（决策夹 21k）、buffer 13k、summary maxOutput=min(模型上限， 20k)（compact-active.ts:716-725）；microcompact keepRecent=5、idle=60min、minSaving=256、ratio=0.9、buffer=2k。
- 事件 5 种：compact_started/completed/failed/boundary/microcompact_boundary；时间线状态 6 种；trigger 5 种（Manual/Auto/Partial/Reactive/SessionMemory）、phase 4 种、reason 4 种（contracts/compact/index.ts）。
- summary 模型=会话当前选中模型（compact-active.ts:174-178）；工具>100 个时 summary 请求不带工具（compact-active.ts:255-257）；流式失败且未提交 content block 时降级非流式（compact-summary-model-request.ts:258-300）。

## 边界与坑

- **熔断恢复**：仅成功 compact 清零计数（compact.ts:282,437）；熔断后 auto 静默跳过、turn 照常跑（可能直至 provider overflow 走 Reactive 补救），manual `/compact` 不受熔断约束。
- **summary 自身预算隔离**：独立 `context_compaction` operation、独立 maxOutputTokens 夹 20k，避免占用正常请求 32k 预算；但输入侧无独立预算，超窗依赖重选/截断兜底。
- microcompact 不动最近 5 组工具结果与任何含 image/video/file 的结果，保证视觉上下文不被误清（microcompact.ts:249-256）；`isError` 默认豁免。
- **preflight 夹 21k 的原因**：provider 窗口 input+output 共享，压缩只能让出输入侧；若按完整输出预留（旧 legacy=完整窗口）会过早压缩，统一夹到 21k 与正常请求预算收敛（policy.ts:75-82 注释）。
- token 估算须计入 assistant toolCalls JSON 与 reasoning 块，否则大型工具入参计 0（manual.ts:102-138）。

## 对 duo 的启示

- 对照 M9-M11（阈值 yml、压缩点事件化、投影拼接）：ZCode 的 **microcompact 是免模型本地裁剪**，把「清旧工具结果」从 summary 请求中剥离，省一次昂贵调用且可幂等重放（清除标记防重复清）；duo 投影拼接可先落这层。
- 对照 M19 `/compact`：ZCode **连续失败熔断（3 次）+rapid-refill 防连环**，避免「压缩失败→每步重试→雪崩」；duo 压缩点事件化后应配同类计数器。
- **summary 单独请求的预算隔离**（独立 20k 输出上限+独立 operation 追踪）与 provider-usage 锚点决策（base+本地增量，避免纯估算误判）值得 duo 的 summary 模型请求直接借鉴；`willRetriggerNextTurn` 字段提前告知压缩后仍超阈，便于 UI 预警。
