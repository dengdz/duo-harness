## 一、核心循环与会话

### agent-loop（`packages/core/agent-loop`）
- **用途**：创建/恢复 agent，驱动 turn→step 循环：组装提示→模型流→工具→事件落库。
- **核心接口**：`AgentLoop`（src/index.ts:359，inject=['agents','sessions','llm','tools','systemPrompt','sessionProjections']:360）：`create/createAgent/resume`（:704/:766/:859）；`ReactLoopAgent`（src/agent.ts:72）：`send`(:128)、`followup`=next-turn 唤醒(:137)、`steer`=next-step 唤醒(:141)、`inject` 不唤醒(:145)、`cancel(cause,{keepInbox})`(:149)、`whenIdle`(:211)、`runMaintenance`(:157)。
- **关键参数**：`maxParallelToolCalls=10`（src/constants.ts:6，经 `agent-loop` settings 段热生效 index.ts:300,396-411）；声明式 agents[] id/provider/model 必需，sessionId 与 resumeSessionId 互斥（index.ts:341-356）。
- **调用方式**：构造时注册 turnBoundary/inbox 投影、`ctx.agents.setFactory(this)`、注册 provider/model/cwd 变量（index.ts:416-424）。
- **依赖**：←session/tools/system-prompt/session-projection/persistence；被 bundle/sdk 挂载。
- **注意**：`agent/turn-stopping` 串行瀑布仅当后续队列空才派发（agent.ts:316-319）；取消保留已流出文本，中断步落 assistant/attempt 或截断 assistant/message（agent.ts:400-440）；resume 先抢写柄排除并发、仅 NotFound 才回退新建（index.ts:481-500,894）；disposed 唤醒不入 latch（agent.ts:188-198）。

### agent（`packages/core/agent`）
- **用途**：agent 活注册表、创建工厂委托、进程内 initiator 归因；不含具体循环。
- **核心接口**：`AgentRegistry`（src/index.ts:245）：`setFactory`(:355，重复注册抛错)、`create/resume`(:388/:407，委托工厂)、`register`(:434)、`enter/announce`(:456/:534)、`get/isOwnedBy/list/roots`(:563/:575/:583/:593)、`withInitiator/withoutInitiator/currentInitiator`(:324/:339/:292)；`AgentHandle{agent,dispose}`(:160)；`AgentFactory{createAgent,resume}`(:171)。
- **调用方式**：loop 构造时 `ctx.agents.setFactory(this)`（agent-loop index.ts:421）；消费方走 `ctx.agents.create()`。
- **依赖**：←scope/session；被 agent-loop、ACP 等依赖。
- **注意**：owner 上下文决定生命周期归属（:190-202）；created/disposed 严格配对，announce 前回滚不发 disposed（:494-507）；initiator 仅同进程归因、非授权（:239-243）；unload 时 drain 返回的 Promise 边界（:599-617）。

### session（`packages/core/session`）
- **用途**：事件溯源会话：append-only 日志、内存 store、派生消息史；持久化是插件事。
- **核心接口**：`Session`（src/index.ts:446）：`append(type,data,opts?)`(:719，seq=log.length，返回冻结事件)、`deriveMessages()`(:841)、`requestHeader()`(:785)、`seq/firstLiveSeq`(:678/:497)；`SessionStore`(:908)：`create`(:969)、`prepare/enter/announce`(:1001/:1068/:1123)、`flush(session)`(:1177)、`fork(source,boundary?,childId?)`(:1236)。
- **事件词表**：turn/start|end、step/start|end、system|user|assistant message、tool/result、assistant/attempt、request/header(context)、agent/inbox/spliced、session/end-seed（surface 事件必须带 surfaceOp/sourceEventSeqs，:693-717）。
- **依赖**：←llm/scope；被几乎所有包依赖。
- **注意**：append 后即提交，监听器失败被容纳（:687-690）；data 须无损 JSON 否则原地抛（:729-736）；append 期间禁止重入（:737-740,751）；fork 边界不得落在开 turn（:1287-1294）；`session/created` 同步抛即否决（:1134-1146）。

### tools（`packages/core/tools`）
- **用途**：工具注册表与 pre/guard/around/post/finalize/notify 执行管线及并行调度。
- **核心接口**：`ToolRuntime`（src/index.ts:789）：`register(def)`(:1043，`run_code` 名保留:1060)、`restrict({allow,deny})`(:1077，仅 scoped、空 filter 抛)、`guard(fn)`(:1116，单调只可拒)、`presentAs(mode)`(:954)、`get/schemas`(:1210/:1240)、`executionMode`(:1282)、`execute(input)`(:1348)；`defineTool`（src/schema.ts:545）。
- **关键参数**：`mode='native'`（native|ptc|both，:793）、`maxParallelSubCalls=10`（:794,777-783）；`timeoutMs` 由外层策略执行、不下发模型（:249）。
- **六段管线**：`tools/pre-execute` 瀑布(:146)→guard(:713)→`tools/execute` around(:157，仅可换 signal)→`tools/post-execute`(:169)→定义 `finalizeContent`(:241)→`tools/result` emit(:191)。
- **并发**：`isConcurrencySafe` 仅严格 `true` 并行，其余/抛错 fail-closed 为 exclusive 屏障（:251-263,1282-1291）；上限读 loop 的 maxParallelToolCalls（agent-loop tool-calls.ts:132,200）。
- **注意**：ptc 下模型直呼非 run_code 记 UNKNOWN_TOOL（:1327-1332）；restrict 不过滤本 scope 自注册（:1158-1199）。

### system-prompt（`packages/core/system-prompt`）
- **用途**：有序 section/动态 context/工具 schema/变量注册与每次装配。
- **核心接口**：`SystemPrompt`（src/index.ts:406）：`section({name,order,text,interpolate?,complete?})`(:455)、`context`(:490)、`tools(provider)`(:522)、`variable(name,provider)`(:538)、`suppressRuntimeContext`(:507)、`assemble(context?)`(:559)；纯渲染 `renderPrompt`(:280)。
- **关键参数**：Config 默认 `includeHarnessIdentity=true`、`includeRuntimeContext=true`、personaPrefix/Suffix=''（:407-414）；order 中心位表 SECTION_ORDERS(:125)，如 TOOLS_SDK=5000；同 order 按名排序（:238-240）。
- **调用方式**：各插件经 ctx（或 agent.ctx）注册；装配后走 `system-prompt/assemble` 瀑布(:31)。
- **注意**：`{{var}}` 严格插值：未知/未定义值抛错，名字须 `[a-z][a-z0-9_]*`（:186,326-363）；toolOrder 必含 `<unlisted-tools>`（:192,198-209）；多个 complete section 装配失败（:597-600）；scoped 同名遮蔽 global（:575-577）。

### scope（`packages/core/scope`）
- **用途**：给 Cordis context 打不透明 scope 标签并构造路由事件载体，支撑注册表分层遮蔽与事件沿链上行。

- **调用方式**：ReactLoopAgent 构造 `createScope(loopCtx,this)`（agent.ts:104）；各注册表经 `ScopedLayers.effect` 挂层（store.ts:226-266）。
- **依赖**：←cordis；被 agent/session/tools/system-prompt 依赖。
- **注意**：父链成环抛错（:54-59）；事件只上行不下行（:161-165）；`peek` 故意链盲只看本 scope（store.ts:180-183）。

## 二、LLM 层

### llm（`packages/llm/llm`）
- **用途**：provider 无关流式调用 seam：adapter 注册表 + `llm/stream` 瀑布。
- **核心接口**：`LlmRuntime`（src/index.ts:336）：`stream(options)`(:1110)、`prepareCall(config,signal?)→PreparedLlmCall`(:920，一次性且 config 须一致否则 INVALID_PREPARED_CALL:947-957)、`registerAdapter(providers,adapter)`(:390，DUPLICATE_ADAPTER 全有全无)、handle`.replace()` 原子换路由(:291-309)、`registerConfigurableProviders`(:484)、`discoverModels`(:590)；抽象 `LlmAdapter`（:203，仅 `stream` 必需:284）。
- **请求冻结**：loop 构造的请求 `markAgentLoopRequest`+deepFreeze，内容纯由日志派生，监听器只读（:60-70）。
- **依赖**：←cordis；被 agent-loop/deepseek/pi-ai 依赖。
- **注意**：`prepareCall` 绑定注册代际，HMR 不串代（:912-919）；adapter 选择/迭代失败转终止 error/aborted finish chunk，中间件失败仍抛（:1010-1014,1127-1136）。

### llm-retry + token-meter（`packages/llm/llm-retry`、`packages/llm/token-meter`）
- **用途**：provider 重试策略执行器；token 计量（usage 优先、估算兜底）。
- **核心接口**：llm-retry `apply(ctx)`(:123) 挂 `agent/request-error` 监听(:243)；token-meter `TokenMeter.measure(session,requestHeader?)`(:146) 返回基线。
- **关键参数**：默认 `maxRetries=5、initialDelayMs=500、maxDelayMs=10000、jitterRatio=0.1`，可重试码 EMPTY_RESPONSE/RATE_LIMIT/SERVER/TIMEOUT/TRANSPORT（llm/src/retry-policy.ts:14-24）；`mode:'always'` 无界重试（:49-54）；延迟=指数退避×对称抖动封顶（llm-retry/src/index.ts:59-64）；Retry-After 优先但超上限时 normal 放弃、always 本地退避（:227-236）。token-meter Config 拒绝任何键（:88-92）。
- **注意**：每次重试先 append `llm/retry` 再可取消等待（:188-190）；maxRetries 计数按 provider+policy 键存投影，step/turn 边界清零（:130-137）；meter 按 provider usage 匹配 header 锚点，否则启发式估计（:156-181）。

### llm-deepseek（`packages/llm/llm-deepseek`）

## 三、会话持久化与投影

### session-persistence + jsonl（`packages/session/session-persistence(-jsonl)`）
- **用途**：持久化 seam（读/写柄、单写者互斥）与 JSONL+zstd 后端。
- **核心接口**：`SessionPersistence`（src/index.ts:135）：`create(header,opts)`(:147)、`open(id,'read'|'write')`(:162)、`flush()`(:175)、`stat/list`(:191/:198)；`SessionHandle{read/append/flush/close}`（src/handle.ts）。
- **关键参数**：jsonl `root` 必填无默认、`compression='zstd'`（jsonl/src/index.ts:236-239,66）。
- **共享契约**：seq 连续、append 尽力而为、**flush 才是持久化屏障**；未知非 ignorable 事件 fail-closed（storage-contract.ts:69-104,145-151）。
- **注意**：惰性物化——create 即本进程可见，首次 append/flush 才落盘，崩溃前未物化=从未存在（:229-233）；fsync 语义：创建=临时写+fsync+link+目录 fsync（:1097,1145,1229）、append 后 fsync、部分写失败截回原偏移（:1242）、打开时撕裂尾截断（:1286）；同 id 跨项目目录重复即抛错（:1404-1407）。

### session-projection（`packages/session/session-projection`）
- **用途**：投影注册表：纯同步 fold 单元在每条已提交事件上被推驱动，附客户端视图与检查点。
