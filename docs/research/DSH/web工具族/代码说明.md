# DSH web 工具族代码说明

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-20 pull，release 0.1.6-alpha.2）。出处均为 DSH 仓库内路径，路径前缀 `packages/web/` 省略时指该目录下。配套：[架构设计.md](架构设计.md)、[细节备忘.md](细节备忘.md)。

## 关键实现逻辑

### 一、web_fetch 执行流（tool-web/src/fetch.ts + web-fetch-http）

1. **入参与选路**：`applyWebFetchTool(ctx, timeoutMs, maxOutputChars)` 注册 `web_fetch`（`fetch.ts:447-517`）；inputSchema 仅 `url: string` required（`fetch.ts:462`）——超时是部署策略挂在工具定义的 `timeoutMs` 上交 timeout-policy 强制（`fetch.ts:98-101`），不暴露给模型。execute 调 `ctx.web.fetch({url}, exec.signal)`（`fetch.ts:503-506`）。
2. **URL 字面预检**（`web-fetch-http/src/policy.ts`）：仅 `http:`/`https:`（32-34 行，`file:`/`ftp:`/`data:` 等一律 `WEB_INVALID_URL`）；内嵌用户名/密码拒绝 `WEB_BLOCKED_URL`（35-37 行）；URL 长度 ≤ 2048（12,50-53 行）。无端口限制、无 allowlist/denylist 配置——策略硬编码，配置面只有 limits + UA（`index.ts:32-51`）。
3. **DNS 解析后公网校验**（`network.ts`，不是字符串判断）：非字面量 hostname 用 `lookup(host, {all:true, order:'verbatim'})` 取**完整地址集**，IP 字面量直接构造（80-84 行）；**答案集中任意一个地址非公网 → 整体拒绝** `WEB_BLOCKED_URL`（100-102 行，防部分记录投毒）。公网判定 `isPublicIpAddress` = ipaddr.js `range() === 'unicast'`（54-64 行）——拦回环、RFC1918、链路本地、组播、保留段；IPv4-mapped IPv6 按内嵌 IPv4 判定；另有 NAT64/DNS64 检测（RFC 7050，经 `ipv4only.arpa` 哨兵发现前缀，翻译出非公网 IPv4 也拒绝，37-39,91-105,113-146 行）。
4. **连接 pinning 防 DNS rebinding**：校验后的地址集经自定义 undici Agent 的 `connect.lookup` 回调喂给连接，连接层**不再二次解析** hostname，Host/SNI 仍用原域名（191-212,260-285 行；注释 177-189）。**pinning 是每请求的**（每请求 `new Agent(...)` 用毕 `close()`），不做进程级——否则打死 loopback 上合法服务（如本机 MCP/model endpoint）的解析（176-189 行）。
5. **重定向控制**：`redirect:'manual'` 自行跟（206 行）；每跳 (a) 重跑完整 `validateFetchUrl`（`provider.ts:93`），(b) 强制**同源**（scheme+host+port，94-99 行；`policy.ts:65-67`），跨源 → `WEB_REDIRECT_BLOCKED` 并提示模型直接请求该 URL，(c) 每跳重新 DNS 解析+校验+pin（70-71,138 行）。跳数上限默认 5（`index.ts:49`；`provider.ts:76-79`）。代理路径例外：走代理的 hop 跳过本地解析/pinning（由代理做 DNS），但**非公网 IP 字面量绝不发往代理**（`provider.ts:126-137`；`network.ts:171-174`）。
6. **content-type 分类与解码**（`provider.ts` + `policy.ts`）：`text/*`、`application/json`、`application/xml`、`+json`、`+xml` → `kind:'text'` 原样透传（`policy.ts:78-84`）；**PDF/图片/二进制/无 Content-Type → 读 body 前直接拒** `WEB_UNSUPPORTED_CONTENT_TYPE`（`provider.ts:148-153`）；charset 按 Content-Type 声明用 `TextDecoder` 解码（默认 utf-8），声明了不认识的 charset 报错而非乱码（`policy.ts:96-118`；`provider.ts:158-164`）。所有错误路径 `response.body?.cancel()` 防 socket 泄漏（77,84,101,104,151,162 行）。
7. **限额三层**：① 字节——provider 读流上限 `maxResponseBytes`（默认 5MB），Content-Length 超限直接报 `WEB_FETCH_TOO_LARGE`（无部分内容），流式超限截断并置 `truncated`（恰好填满不算截断，207-216 行）；② 字符——解码后 `maxBodyChars`（默认 100k）slice（167-168 行）；③ 输出——`fetchMaxOutputChars`（默认 200k）既限转换前源字符数（`fetch.ts:243`）也限完整输出（header+正文+footer，328-337 行），被截时追加固定 footer "(Content truncated. Fetch a more specific URL or section for the full text.)"（265 行）。
8. **HTML→Markdown 转换**：`turndown` + `@joplin/turndown-plugin-gfm`，配置 `headingStyle:'atx', codeBlockStyle:'fenced', bulletListMarker:'-'`（25-30 行）；自定义 `removeNonVisibleContent` 剔除 `SCRIPT/STYLE/NOSCRIPT/TEMPLATE/IFRAME/OBJECT/EMBED`、`hidden` 属性、`aria-hidden="true"`、`type=hidden` input、内联 `display:none`/`visibility:hidden|collapse`（31-49 行）——**nav/header/footer 不剔除**；表格有专门规则防 colspan/rowspan 展开爆炸（51-95 行）。
9. **转换安全护栏**：嵌套深度 > 512 的 HTML 不转换，返回占位 `'[HTML content omitted: unable to convert safely.]'`（120,156-223,247 行）——深度护栏必须**先于**转换执行，否则 domino/turndown 深度超线性耗时（512≈0.15s、20000≈5s）会饿死协作超时（110-119 行注释）；turndown 抛异常同样返回占位符而非源码（248-255 行）。
10. **渲染与呈现**：模型可见文本 = `Fetched <最终URL> (HTTP <状态码>)\n\n` + 不可信数据声明 + 正文（+截断 footer）（`fetch.ts:329`；notice 定义 `trust.ts:7`）；结构化 output value `{url, statusCode, body{kind,content}, truncated}`（schema `fetch.ts:464-494`）；UI 元数据 `presentationMeta{url, statusCode, truncated}` 供 fetch 卡片回放（392-394,423-435 行）。渲染结果按 `(result, maxOutputChars)` 用 WeakMap 记忆化，转换只跑一次（302-318 行）。

### 二、web_search 执行流（tool-web/src/search.ts）

1. **入参**：唯一参数 `queries: string[]`（1–`searchMaxQueries` 项，默认上限 4，常量 `WEB_SEARCH_MAX_QUERIES` 于 22 行）；无 count/freshness/domain 模型可见参数（freshness 只存在于 perplexity 的 provider 配置）。`parseSearchArgs` 校验非空数组、逐项非空白，按首次出现顺序去重（39-51 行）。
2. **多 query 并发**：单 query 直接透传；多 query 并发执行、任一失败 abort 兄弟并等全部 settle 后重抛第一个错误；按名次轮询合并、URL 去重、截到 `maxResults`，各 query 的 answer 以 `### query` 标题拼接（`runSearchQueries`/`mergeSearchResults`，231-293 行）。
3. **格式化**（`formatSearchOutput`，73-94 行）：防注入 notice → provider answer（可选）→ `Sources:` 下 `- [title|hostname](url) — snippet (publishedAt)` 列表 → 截断提示 "(Showing the first N sources. Refine the query for more.)" → 固定句 "Cite the relevant URLs above as markdown links in your answer."。空结果渲染 `No results found.`（87-88 行）。
4. **工具声明**：`isConcurrencySafe: () => true`（364 行）；`timeoutMs` 挂工具定义交 timeout-policy（362 行；bundle 对 search 放宽到 60s——deepseek 搜索是一整次辅助模型请求）。

### 三、provider 选路与三实现（web/src/index.ts + web-search-*）

- **执行期选路**见架构设计.md；seam 回程 `capSources` 按 `maxResults` 强制截断 `sources[]`（140-147,196-200 行）——截断权归 seam 不归 provider，三 provider 恒返回 `truncated: false`。
- **deepseek-official**：Anthropic 兼容 Messages + 原生 `web_search_20250305` server tool，请求体 `{model: deepseek-v4-flash, max_tokens: 4096, messages:[user "Perform a web search for: X"], tools:[{type: web_search_20250305, max_uses: 5}]}`（`provider.ts:207-215`）；鉴权同时发 `x-api-key` 与 `Authorization: Bearer`（227-236 行）；归一化取 `web_search_tool_result` 块，snippet 由 text 块 `citations[]` 按 URL join（120-173 行）。**每次搜索 = 一次完整模型推理**。key 解析链：settings `apiKey` 字面量 → credentials service → 进程 env `DEEPSEEK_API_KEY`，缺 key 抛 `WEB_PROVIDER_CREDENTIAL_MISSING` 且报错文本点名三种补 key 途径（286-308 行）。
- **exa**：`POST {base}/search`，`{query, type:auto, contents.highlights.highlightsPerUrl:1, numResults?}`（`provider.ts:110-115`）；**无 highlight 的条目整条丢弃**——"inventing one would lie"（47-58 行注释），可能出现有命中但零 source。
- **perplexity**：OpenAI 兼容 `chat/completions`（sonar 模型），answer → `content`，sources 优先 `search_results[]`、回退 URL-only `citations[]`（56-83 行）。
- **无 key 行为分两派**：exa/perplexity key 为空 → `available()` false → 选路期即报 `WEB_PROVIDER_UNAVAILABLE`；deepseek 恒有 resolver thunk、`available()` 恒真 → key 缺失推迟到执行期才暴露（与另两家不对称）。
- 三 provider 均 `redirect:'error'`（重定向即失败）；provider 自身不设 HTTP 超时，统一靠工具层 timeout 经 AbortSignal 协作取消，取消映射 `WEB_ABORTED` 而非 provider 错误（各 provider catch 里重查 `signal.aborted`）。
- **审计旁路**：deepseek 每次派发前经 session 事件 `web/deepseek-search-llm-request` 记录无密钥请求，记录抛错则阻止派发（79-84,216-220 行；`index.ts:115-120`）。

## 依赖关系

- **被依赖**：`web`（seam）被 `tool-web` 与三个 provider 包依赖；三者互不依赖、均不依赖 `web-fetch-http`。
- **外部库**：`tool-web` → `turndown@^7.2.4`（自带 domino DOM）+ `@joplin/turndown-plugin-gfm@^1.0.67`；`web-fetch-http` → `ipaddr.js`（IP 分类）、undici（Node 原生 fetch 的 Agent 定制）。
- **装配**：dsh-base patch 四行（见架构设计.md）；Web 应用按 agent preset 每会话重述 `tool-web` 行，web service 与 provider 留宿主组合。
- **测试**：`tool-web/tests/tool-web.spec.ts`（含无 provider 注册、多 provider 歧义等选路用例）、`web-fetch-http/tests/fetch-http.spec.ts`（重定向/限额/content-type/超时）。
