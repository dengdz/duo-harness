## 边界条件

- **恰好填满不算截断**：流式读 body 只计被丢弃的字节，exact-at-cap 置 `truncated:false`（`web-fetch-http/src/provider.ts:207-216`）。
- **深度护栏先于转换**：嵌套 >512 层的 HTML 直接返回占位，不进 turndown（domino 深度超线性，512≈0.15s、20000≈5s 会饿死协作超时，`tool-web/src/fetch.ts:110-119`）。
- **body.cancel() 纪律**：所有错误路径（含 charset 解析失败、content-type 拒绝）先 cancel response body 防 socket 泄漏（`provider.ts:77,84,101,104,151,162`）。
- **pinning 每请求独立**：直连路径每请求 `new Agent` 用毕 close；绝不能进程级 pin——否则打死 loopback 上合法服务（本机 MCP/model endpoint）的域名解析（`network.ts:176-189`）。
- **非公网 IP 字面量不过代理**：代理路由判定前先拦（`provider.ts:135`；`network.ts:171-174`）；回环 host 永远 bypass 代理。
- **多 query 去重**：按首次出现顺序去重后并发；合并按名次轮询（保公平）再 URL 去重（`search.ts:39-51,231-293`）。
- **渲染记忆化**：fetch 的转换/渲染按 `(result, maxOutputChars)` WeakMap 缓存，重放只跑一次（`fetch.ts:302-318`）。

## 异常处理

错误统一 `WebError`（机器可路由 code），工具层转为 `isError` 结果 + `error.info.code`（`packages/core/tools/src/index.ts:1877-1883`）：

| 场景 | code | 备注 |
|---|---|---|
| 整体 deadline 超时 | `WEB_FETCH_TIMEOUT` | 连接与读 body 同一 deadline |
| 调用方取消 | `WEB_ABORTED` | catch 里重查 `signal.aborted`，避免 body 阶段误报为 HTTP 错误 |
| DNS 解析失败/连接失败/重定向缺 Location | `WEB_PROVIDER_ERROR` | |
| 非公网 IP（含 NAT64 翻译出私网） | `WEB_BLOCKED_URL` | URL 带凭据也是此码 |
| 非法 scheme / URL 超长 | `WEB_INVALID_URL` | |
| Content-Length 超字节上限 | `WEB_FETCH_TOO_LARGE` | **无部分内容**；流式超限则不报错、截断+truncated |
| 不支持的 content-type / 未知 charset（含 PDF、图片、无 Content-Type） | `WEB_UNSUPPORTED_CONTENT_TYPE` | 读 body 前拒绝 |
| 跨源重定向 / 超跳数 | `WEB_REDIRECT_BLOCKED` | 提示模型直接请求目标 URL |
| provider 零可用 / 配置 id 未注册 / 配置 id 不可用 / 多可用歧义 | `WEB_PROVIDER_UNAVAILABLE` / `_CONFIGURED_MISSING` / `_CONFIGURED_UNAVAILABLE` / `WEB_PROVIDER_AMBIGUOUS` | 选路期 |
| deepseek key 缺失（执行期） | `WEB_PROVIDER_CREDENTIAL_MISSING` | 报错点名三条补 key 途径 |

**刻意不是 error 的**：非 2xx 状态码（结果携带 `statusCode`，错误页正文照常渲染，`types.ts:69-73`）；超深/转换失败的 HTML（占位文本 + truncated，`fetch.ts:247-255`）；搜索空结果（渲染 `No results found.`）。

## 已知坑

1. **deepseek provider 每次搜索 = 一次完整辅助模型推理 + 最多 5 次服务端搜索**（`max_uses: 5`），延迟显著高于纯搜索 API——bundle 为此把 searchTimeoutMs 放宽到 60s；且无 `web_search_tool_result` 块时抛错而非返回空（"may not have triggered native web search"，`provider.ts:149-154`）。
2. **exa 无 highlight 的结果整条丢弃**——可能出现"有命中但零 source"（`provider.ts:47-58` 注释 "inventing one would lie"）。
3. **available() 语义不对称**：契约是"廉价本地检查、禁止网络调用"（`types.ts:104-105`），exa/perplexity 缺 key 即 false（选路期报错），deepseek 恒 true（key 缺失推迟到执行期）——同一"无 key"事实在两派 provider 上报错时机不同。
4. **多可用 provider 不钉 id 会 `WEB_PROVIDER_AMBIGUOUS`**：设计上拒绝隐藏优先级链，部署装多个 provider 必须显式点名。
5. **gzip 无显式处理**——undici fetch 按 spec 自动 `accept-encoding` 并透明解压；Java 侧用 JDK HttpClient 需自行显式处理压缩。
6. **Node timer 上限 2^31-1 ms**：超配会被强制成 1ms，故配置期拒绝该值域（`web-fetch-http/src/index.ts:63-69`）。
7. **`nav/header/footer` 不剔除**：DSH 的 HTML 清洗只去不可见节点，导航/页眉文本会进 Markdown——对 token 是噪音源，参照实现时需自行裁定是否加强剔除。
8. **fetch 工具零模型可见策略参数**：超时/格式/深度全是部署配置——模型面保持最小，策略面归部署者；这是"enablement 与 availability 解耦"之外的第三条解耦（策略与模型面解耦）。
