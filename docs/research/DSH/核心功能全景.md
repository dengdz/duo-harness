# DSH 核心功能全景

> 源锚点：`c291e7961a515f6d7af9304e7fd1d257929aef26`（2026-09-10，release 0.1.5-rc.2，pnpm monorepo 60+ 包 `@deepseek-ai/dsh-*`，架构基座 Cordis 插件容器）
> 本文是功能清单级全景（"它能让用户做什么"），架构与插件化机制见 [总览.md](总览.md) 与 [插件化架构/](插件化架构/)。事实与出处为准；采纳决策走 ADR，不在本文发酵。

## 一、Agent 循环与能力

| 功能 | 说明 | 落点 |
|---|---|---|
| agent 主循环 | call model → run tools → repeat；每步派生历史 + 可见工具 schema；工具经守卫管线执行 | `packages/core/agent-loop/` |
| 流式输出 | token 级 chunk，必以 terminal finish 结尾；取消时已送达文本保留 | `packages/llm/llm/` |
| 并行工具调用 | `maxParallelToolCalls`（默认 10）限制并发，exclusive 调用作顺序屏障 | agent-loop 配置 |
| LLM 请求重试 | `llm-retry` 在持久 agent-step 边界按 provider 策略重试；错误码稳定（RATE_LIMIT / CONTEXT_WINDOW_EXCEEDED 等） | `packages/llm/llm-retry/` |
| 失控防护 | **无内置 turn 预算**，靠 guard 补位：`repeat-tool-reminder`（同调用连读 3/5/8 次逐级提醒）+ `timeout-policy`（超时返回明确错误） | `packages/guard/` |
| steering / inbox | 运行中 `agent.steer()` 注入下一条用户消息（如 `/plan <msg>`） | agent-loop |
| 每步检查点 | session-checkpoint-policy：模型请求与顶层工具副作用前先落盘 | `packages/session/session-checkpoint-policy/` |
| 声明式 + 编程式 agent | 配置 `agents[]` 开机自启；`ctx.agents.create()/resume()` | agent-loop |

## 二、内置工具清单（`docs/tool-catalog.md` 生成并校验）

- **默认启用**：`read` / `read_image` / `write` / `edit`（fs）、`glob` / `grep`（内置 ripgrep）、`bash`/`pwsh`、`web_search` / `web_fetch`、`todo_write`、`skill`、`subagent` / `subagent_fork` / `send_message` / `interrupt_agent` / `list_agents`、`job_list` / `job_output` / `job_kill`、`create/get/update_goal`、`workflow` / `ralph`（脚本化多子 agent）、`exit_plan_mode`
- **opt-in**：`str_replace_editor`、持久 shell、`terminal_*` 六件套（交互式 PTY）、`ask_user_question`（模型问人）、`present`（交付快照）、`lsp`、`session_search` 等 5 个会话查询、`schedule_*`、`cordis_*` 七件套（运行时自改，刻意不出厂）
- **run_code（PTC）**：程序化工具调用传输，模型写代码并发调工具，嵌套调用重入守卫管线

## 三、交互与 HITL（人机协同全景）

**形态**：DSH **没有终端 REPL**——交互式使用全部在浏览器 GUI（或 Electron 桌面壳）；自动化场景走 headless（一次性）/ ACP / SDK。

| 机制 | 语义 | 落点 |
|---|---|---|
| 审批 seam（`ctx.approval`） | 敏感动作前 one-shot allow/reject；策略 `ask`（默认，走 answerer waterfall）或 `never`（无头确定性拒绝）；无 answerer 时 **fail-closed**；`approval/asked` + `approval/decided` 全程审计；**无"永久放行/remember"** | `packages/interaction/user-approval/` |
| 权限预设 | 三档打包（沙箱模式 + 审批策略）：`read-only`(ask) / `workspace-write`(ask，默认) / `danger-full-access`(never)；`/permission` 查看/切换，env 可改默认 | `packages/interaction/permission-presets/` |
| 模型问人 | `ask_user_question` 工具：模型暂停等待人选选项/自定义输入，返回 JSON answers；schema 验证（id/question/options/multiSelect/intent）；子代理调用被拒 | `packages/interaction/tool-ask-user/` + `user-questions/`（answerer waterfall） |
| plan 模式 | `/plan` 进入，agent 完成后调 `exit_plan_mode` 呈交计划，用户 Approve / Keep planning；**引导而非限制**（工具全可见，靠指导文本约束）；单一 log 事件状态，resume 后恢复 | `packages/plan/plan-mode/` |
| 斜杠命令 | **插件代码注册**（`ctx.commands`）而非 markdown 文件；直接作用于 agent、不进模型历史；`command/run`+`command/done` 审计；已注册 `/compact` `/plan` `/permission` `/model` `/goal` `/export` `/feedback` | `packages/interaction/commands/` |
| 设置 | 插件注册带 schema 的 namespace；解析层级 schema 默认 < 部署 < 用户 override（单一 `settings.yaml`，热重载）；Web 设置页 schema 驱动表单 | `packages/settings/` |
| 人工授权流程 | 凭证获取需人完成时（OAuth/一次性码），attempts 只发给发起它的界面 | `packages/credentials/authorization/` |

**用户被叫到的时刻**：① 审批 seam ask 弹 allow-once/reject；② 模型 `ask_user_question` 或 `exit_plan_mode` 计划复核；③ 用户主动斜杠命令/设置页/凭证授权。自动化客户端可代答或 `never` 直接拒。

## 四、会话与上下文

- **JSONL 事件溯源**（与 duo-harness M4 同构）：append-only、类型化 SessionEvent、LLM 消息历史纯派生；工业级强化——Zstandard 校验帧压缩、v0→v3 不可变代际迁移链、flock 跨进程单写、torn-tail 崩溃恢复、按归一化 cwd 分项目目录、无删除 API（`packages/session/`）
- **resume 语义修复**：崩溃中断的 turn 追加合成闭合事件；无结果的持久调用标 `TOOL_OUTCOME_UNKNOWN` 提示模型只重试只读/幂等操作（agent-loop）
- **compaction**：默认 80% 窗口触发（`thresholdRatio`），保留近端 16%；摘要 = 固定 8 段 Markdown checkpoint（Primary Request / Key Concepts / Files and Code / Errors and Fixes / Pending Jobs / Current Work / Next Step / Critical Context）；溢出（CONTEXT_WINDOW_EXCEEDED）绕阈值最大削减并重试；`/compact` 手动；前置 `tool-result-pruner`（超 8K 字符结果先头尾修剪，可能免掉摘要调用）（`packages/compaction/`）
- **spill**：超 `maxInlineBytes`（默认 50KB）的工具结果卸载到 store，给模型"头尾预览 + 定位符 + 检索指引"；失败保留原结果（`packages/spill/`）
- **上下文注入插件**（纯上下文、无工具）：AGENTS.md/CLAUDE.md 链加载（64KB 预算，去重）、`@file`/`@session` 引用、time-context——注入以 user-role 消息持久进历史（`packages/context/`）
- **附件**：内容寻址去重、持久存 `~/.dsh/attachments`、永不自动删除（`packages/attachment/`）

## 五、扩展生态

- **skills**：`<name>/SKILL.md`（YAML frontmatter name+description）；发现根优先级 `.dsh/skills`(100)→`.agents/skills`(200)→自定义(300)→`~/.dsh/skills`(400)→`~/.agents/skills`(500)→bundled(600)；Chokidar 热加载；触发三路：目录注入模型 / `skill` 工具按名加载 / 用户 `/name` 直调（`packages/skill/`）——与 Claude Code 同构
- **subagent**：spawn（全新）/ fork（父历史播种，KV-cache 友好）；后端 6 种含**跨 harness 委派**（把真实 Claude Code、Codex 作为子 agent 运行）；控制面 `send_message`/`interrupt_agent`/`list_agents`（`packages/subagent/`）
- **hooks**：**直接复用 Claude Code/Codex 的 hooks 配置**而非新协议；钩子点映射到内部扩展点（PreToolUse→tools/pre-execute 等）；exit 2 阻断并把 stderr 给模型；opt-in（`packages/hooks/`）
- **bundle vs preset**：bundle = 应用形态装配（`dsh --profile web/headless/sdk`，补丁层叠加）；preset = 单会话 agent 组成（**一个 preset 目录装配该会话的工具 + prompt 段 + skills + persona**）（`packages/bundle/`、`packages/preset/`）
- **goal / todo / schedule / jobs**：目标持久化（变更需人类根权限）、任务清单、会话内定时提醒（普通消息投递，永不离开会话）、后台作业三工具

## 六、LLM 适配

- 双适配器：`llm-deepseek`（thinking + reasoningEffort 分级，图像 Files API，100 万窗口）+ `llm-pi-ai`（多 provider 目录路由，OAuth 登录）
- 路由 = provider 路由名 + model id；`agent-default-model` 进程级默认；**无自动跨 provider 降级**——失败交给 llm-retry
- reasoning 内容逐字回传后续请求（与 duo-harness BUG-05 修复的 reasoning_content 同语义）；session-title 用途强制关 thinking 省 token
- `systemPromptUpdate: in-history` 保持前缀缓存（prompt 更新以历史消息形式追加而非替换 system）

## 已知限制（DSH 自己承认的）

- 审批无"永久放行"（ui-approval Known Limitations：persistent permission 仍属 Host 侧策略包）
- 无终端 REPL/TUI（`--profile tui` 仅为示例占位）
- 无专用 git 工具（走 shell）；`@file` 索引不支持 .gitignore 语义
- 斜杠命令不能靠 markdown 文件定义（必须插件代码注册）
- MCP 仅桥接 Tools 能力（resources/prompts 不支持），默认不启用
