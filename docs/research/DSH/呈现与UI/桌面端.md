# 桌面端（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 18（T-22）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；Web 面见 [Web呈现.md](Web呈现.md)。

## 机制全貌

三进程形态且**渲染不走外部浏览器**：Electron main（壳）内 BrowserWindow（sandbox+contextIsolation，`main.ts:134-140`）加载自定义特权协议 `dsh-app://app/`（`main.ts:70-80,222`）；该协议 handler 对静态路径直接回打包的 `dsh-web-frontend/dist`，其余请求带认证 cookie 转发给 host 的 `127.0.0.1:19387`（`main.ts:398-411`），WS 请求在 `onBeforeSendHeaders` 里重写 origin/cookie（`main.ts:431-442`）。host 进程是 `ELECTRON_RUN_AS_NODE=1` 的 Electron 自己（`host-process.ts:115-128`）跑 `desktop-host/lib/index.js`，经 `runProfile` 启动 cordis runtime+webserver（`desktop-host/src/index.ts:5-36`）。main↔host 用 Node IPC，协议版本号 4（`host-protocol.ts:4`）。更新=electron-updater（generic feed，channel nightly）+独立强制更新策略服务。

## 关键流程

① **启动链**：单实例锁→main 创建主窗口先载 `dsh-app://app/` 静态加载页→spawn host→host 报 `ready{url,injections}`（`desktop-host/src/index.ts:73-74`）→main 换取认证 cookie（303 set-cookie，`web-document.ts:53-63`）→renderer 经 `dsh-desktop:boot` IPC 拿 injections+streamBaseUrl 完成启动注入（`main.ts:415-420`）。

② **host 协议**：host→main `ready/fatal/shutdown-complete/update-tasks`；main→host `shutdown/update-tasks{inspect|lock|unlock}`（`host-process.ts:18-23`）；stderr 只留尾部 64Ki 字符（`host-process.ts:25,131`）；stop 10s→SIGTERM→5s→SIGKILL（`host-process.ts:200-207`）。

③ **更新**：electron-updater autoDownload=false、channel='nightly'、禁降级（`update-coordinator.ts:65-70`），仅打包且存在 app-update.yml 才启用（:53）；feed 检查由 `DesktopUpdateSchedule` 指数退避轮询（`update-schedule.ts:22-38`）。强制更新是独立策略服务：轮询 `/api/v0/check_client_update`，响应 `code===40005` 即 blocking（`mandatory-update-policy.ts:105-118,176`）；blocking 时弹模态子窗 `dsh-app://shell/mandatory-update.html`（`mandatory-update-window.ts:46,151-157`），关闭窗=退出应用。安装前须 inspect→用户确认→lock 排空在途请求→优雅停 host（`main.ts:366-383`），lock 实现拒绝新请求并检查 agent/job 活跃任务（`desktop-host/src/update-tasks.ts:12-46`）。update-attention：下载就绪未聚焦时 Win `flashFrame`/mac `dock.bounce`+Notification（`update-attention.ts:37-40`）。

④ **directory-picker**：web 侧是 cordis 服务缝，能力判别 `native|browse`（`directory-picker/src/index.ts:20-58`）；`auto` 在 boot 时定后端——bind 非 127.0.0.1、经 SSH、Linux 无 zenity/kdialog 或无 DISPLAY 一律 browse，darwin/win32 native（`directory-picker-auto/src/resolve.ts:50-54`）；native 后端 mac 用 osascript、win 用子进程 COM IFileOpenDialog（`directory-picker-native/src/index.ts:5-10`）；Desktop 下渲染器走 Electron 原生 `dialog.showOpenDialog`，并发共享一个对话框（`apps/desktop/src/directory-picker.ts:12-29`）。

## 接口与参数要点

- 打包：`package-target.ts` 各目标产物，mac 签名/公证脚本、Windows 对第一方 runtime 未签名 PE 补签；更新配置：policy JSON 从打包 manifest 的 `dshMandatoryUpdatePolicy` 注入（`electron-builder-config.mjs:80`），HTTPS origin、intervalMs 默认 600s、退避上限 1h。
- 端口 19387 写死在 host argv（`desktop-host/src/index.ts:24`），可用 `webserver.config.port` patch 覆盖。

## 边界与坑

- host 崩溃→fail 回调进原生恢复对话框（`main.ts:64-68`）；更新失败且曾停 host 会重启 host 并重新导航（`main.ts:298-317`）；EADDRINUSE 有专门文案提示退出其他实例。
- 单实例锁在访问 profile 前获取，second-instance 仅聚焦（`main.ts:774`、`single-instance.ts:20-24`）。
- 恢复对话框诊断限 1200 字符/8 行，防 credentials 泄漏（`host-process.ts:210`）；Desktop 与 Web 端口隔离（19387 vs 3080），profile 独占 `$DSH_HOME/profiles/desktop` 不与 CLI 共享包状态。

## 对 duo 的启示

1. 「Electron 壳+同 exe Node 模式 host 进程+壳内自定义协议渲染」对 duo 当前（纯 CLI+内嵌静态单页）**非必需**：DSH 引入 host 隔离主要是为独占 profile/依赖树与更新排空；duo 单进程即可，除非要免装 Node 分发+代码签名。
2. **最小 host 协议只需 4 条消息**：`ready{url,injections}`/`fatal`/`shutdown`/`shutdown-complete`（外加就绪前 URL 传递），易复刻。
3. **更新通道成本高**：generic feed+nightly channel+策略服务+任务排空+dock bounce 全链路（约 15 个源文件）是 DSH 更新最重资产；duo 若做桌面化，建议先只做 feed 检查+提示，不做强制更新窗。
4. 目录选择「native/browse/**auto 三形态**按 bind host/SSH/display 降级」的模式值得 duo 的 Web 静态页借鉴——远端场景天然只能 browse。
