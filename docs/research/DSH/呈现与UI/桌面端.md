## 机制全貌

三进程形态且**渲染不走外部浏览器**（模型未变，参数大变）：Electron main（壳）内 BrowserWindow（sandbox+contextIsolation，`apps/desktop/src/main.ts:229-237`）加载自定义特权协议 `dsh-app://app/`——静态路径直接回打包的 `dsh-web-frontend/dist`，其余带认证 cookie 转发 host（`main.ts:662-677`；另有 `dsh-app://shell/` 壳自有文档路由 `main.ts:665`），WS 在 `onBeforeSendHeaders` 重写 origin/cookie（`main.ts:710-721`），认证 cookie 经 303 set-cookie 换取（`web-document.ts:43-50`）。host 进程仍是 `ELECTRON_RUN_AS_NODE=1` 的 Electron 自己（`host-process.ts:189-201`，环境注入统一 `node-environment.ts:15`）跑 `dsh-desktop-host/lib/index.js`（目录已从顶层 `desktop-host/` 迁至 `apps/desktop-host/`）。**端口从写死 19387 改为 OS 分配**（ecd9bf9273，动机：Windows Hyper-V/WinNAT 保留动态端口段导致 bind 失败）：host argv `--port 0`（`apps/desktop-host/src/index.ts:30`），就绪后以 `ctx.webServer.port` 拼真实 URL 放进 `ready.url`（`:103-104`），main 存 `hostUrl` 供协议转发/WS 匹配（`main.ts:671-676,711-720`）。main↔host 用 Node IPC，协议版本号仍 4（`apps/desktop/src/host-protocol.ts:4`），但消息集已扩展（见关键流程②）。更新=electron-updater（generic feed）+独立强制更新策略服务（链路保留、身份头重构，见③）。**壳能力大扩**：原生菜单管理 CLI 命令安装、原生 welcome 登录窗、login shell 环境探测、崩溃报告落盘、Windows 关窗入托盘、`dsh://` 深链、自定义 NSIS 品牌安装器、嵌入式 Platform 视图与 Sidebar webview 宾客。

## 关键流程

① **启动链**：单实例锁→main 创建主窗先载 `dsh-app://app/` 静态加载页→spawn host（`--port 0`）→host 报 `ready{url,injections}`（`apps/desktop-host/src/index.ts:103-104`）→main 换认证 cookie→renderer 经 `dsh-desktop:boot` IPC 拿 injections+`streamBaseUrl = new URL(hostUrl).origin`（`main.ts:685-690`）。GUI（Dock/Finder）启动时异步探测用户 login shell 环境（`login-shell-environment.ts:8-13,65-69,96-103,172-185`：`shell -ilc 'command env -0'`、候选 userInfo().shell→/bin/zsh→bash→sh、10s 超时按进程组 SIGKILL、DISABLE_AUTO_UPDATE/ZSH_TMUX_AUTOSTARTED 防 rc 卡死、DSH_*/ELECTRON_* 不被覆盖），结果合并进 host 环境（`main.ts:327-338`）；Windows 直接跳过（`:176`）。

② **host 协议（4 条 → 扩展集）**：host→main `ready/fatal/shutdown-complete/update-tasks/platform-session`；main→host `shutdown/update-tasks{inspect|lock|unlock}/quit-inspection`。`platform-session` 推嵌 Platform 视图凭据（origin/token 白名单校验，`host-process.ts:21-24,61-79`；`desktop-host/src/index.ts:100-102`）；`quit-inspection` 请求/应答 2s deadline，超时按「有任务」处理（`host-process.ts:49,254-258`）；控制消息统一 requestId 关联+超时（`host-process.ts:260-280`）；`fatal` 增 `diagnostic` 字段承载完整 inspect 错误（上限 64Ki，与 stderr 分通道，`host-process.ts:14-19`）。stderr 仍只留尾部 64Ki（`host-process.ts:51,204`）；stop 10s→SIGTERM→5s→SIGKILL（`host-process.ts:295-301`）。

③ **更新**：electron-updater 链保留（generic feed、禁降级，仅打包且存在 app-update.yml 才启用）；强制更新策略链保留——blocking 判定仍 `code===40005`（`mandatory-update-policy.ts:115`）、轮询 600s/退避上限 1h（`update-schedule.ts:20-21`）、policy JSON 经打包 manifest `dshMandatoryUpdatePolicy` 注入（`scripts/electron-builder-config.mjs:105`）、安装前 inspect→确认→lock 排空→优雅停 host（`main.ts:584-638`）。变化：身份头从固定 identity 改 per-check `platformClientHeaders(platform, client())`（win32/darwin+活动 UI 语言/UTC 偏移/版本），新增 `allowedAuthOrigins` 与认证 401 重登（`mandatory-update-policy.ts:4,158-160,189`）；装更新前须等 CLI 操作空闲（`main.ts:587`）与嵌入式 Platform 视图 `closeAndWait`（`main.ts:616-617`）；update-attention 的 Win flashFrame/mac dock bounce+Notification 保留。

④ **directory-picker**：native/browse/auto 三形态与降级规则逐字未变（`directory-picker-auto/src/resolve.ts:50-54`）；Desktop 渲染器仍是 Electron 原生 `dialog.showOpenDialog` 并发共享单对话框（`apps/desktop/src/directory-picker.ts:12-29`）。

⑤ **CLI 命令管理（新增）**：应用菜单项→`DesktopCommandManager`（`main.ts:956-957,389-397`）→独立 worker 进程（打包 Node 跑 `runtime/cli/command-manager.js`，JSON over stdout，`command-management.ts:138-141`）。所有权模型：目标旁 receipt `.dsh-desktop-command.json`（schemaVersion 1，记录 launcher+symlink 指纹=sha256(lstat 字段+target)，`command-installation.ts:55-57,116-128`）；确认指纹绑定用户所见状态，变更即 `ESTALE` 拒绝；备份 `.dsh-command-backup-<uuid>`+失败回滚+只删自己装的条目（`command-installation.ts:185-268`）。macOS 目标 `/usr/local/bin/dsh`，EACCES 时 osascript 提权重跑（`command-management.ts:143-147`）；mac 上 Node `link()` 会跟随 symlink，需 `linkat` C 助手保 symlink 身份（`cli/link-entry.c`；`command-installation.ts:159-163`）；装前用用户 login shell 跑 `command -v dsh` 检测遮蔽（`command-management.ts:112-121`）。Windows 固定 PATH 目录+`dsh.cmd`，PATH 修改由 PowerShell 脚本完成（`command-manager-entry.ts:23-35`）。

⑥ **bundled CLI 启动链（新增）**：`cli/bin/dsh`（sh 脚本）以 `ELECTRON_RUN_AS_NODE=1` 重入 Electron 自身跑 `desktop-host/lib/cli.js`→`runCli({manageDesktopProfile:true})` 用打包 pnpm 管理独占 profile（`desktop-host/src/cli.ts:11-37`）；Windows 对应 `cli/dsh.cmd`，控制台信号经 koffi `SetConsoleCtrlHandler` 转 SIGINT/SIGBREAK（`windows-cli-signals.ts:12-24`）。

⑦ **登录流程（重做）**：未登录且无 API key 才弹 welcome 窗（`welcome-api.ts:73-75`）——本地静态页 `renderer/welcome.html`+受限 IPC（`welcome-window.ts:59-132`）；登录态由 host 侧 account 后端推送，`waiting-browser` 阶段 `shell.openExternal` 跳系统浏览器授权 URL（附 theme 参数），成功 `credential-stored` 进工作区，signed-out/session-expired 回弹 welcome（`main.ts:460-495,1136-1211`）；登录无响应错误码 `no-response` 被接受（dff4dfbe75）。

## 边界与坑

- **退出语义已变**：主窗 close 仅隐藏（Windows 入托盘，`main.ts:1071-1081,984-991`）；退出前经 quit-inspection 后端探活弹确认（`quit-confirmation.ts:18-27`；`main.ts:1259-1281`）；安装器接管退出走 `shellInstallerOwnsQuit` 旁路（`main.ts:1260-1271`）；session-end 免确认退出（`main.ts:1082-1091`）。
- 固定端口的教训：Windows Hyper-V/WinNAT 保留动态端口段，即使无进程占用 bind 也会失败（ecd9bf9273 动机）。
- mac symlink：Node `link()` 跟随 symlink，装命令须 `linkat` 保身份；`/usr/local/bin` 需提权。
- host 崩溃→fail 回调进原生恢复对话框，支持「禁用全部插件/重启」（`main.ts:93-105`）；崩溃报告落 logs 目录（renderer console 尾部+host diagnostic+环境快照，`main.ts:107-130`）；更新失败且曾停 host 会重启 host 并重新导航。
- 单实例锁在访问 profile 前获取，second-instance 仅聚焦（`main.ts:1336`）；EADDRINUSE 仍专门文案。
- 嵌入式 Platform 视图（WebContentsView 使用/充值页，`platform-view.ts:41-59`）在更新停 host 前必须 closeAndWait 换凭据；Sidebar webview 宾客主进程托管，webviewTag 仅主窗开启（`main.ts:235`）。

## 对 duo 的启示

1. **动态端口必须学**：固定端口在 Windows 会撞 Hyper-V/WinNAT 保留段。Java 侧 `new ServerSocket(0)` 后把实际端口写进启动就绪消息，壳只信任该消息——一行设计消灭一整类用户报障。
2. **CLI 安装的所有权范式最值得抄**：receipt+内容指纹+确认时指纹比对+备份回滚+「只动自己装的条目」，是把可执行命令装进系统 PATH 而不踩坏用户环境的安全全套；duo 若随桌面端分发 `duo` 命令（内嵌 JRE 版）可直接套用。mac symlink 语义坑（`link()` 跟随、`/usr/local/bin` 提权）DSH 已踩平。
3. **mac GUI 启动无 shell 环境**：桌面 app 若依赖 PATH 里的 java/mvn，必须做 login-shell 探测（或干脆内置运行时不依赖用户环境——DSH 两条都做了，内置优先）。
4. **退出确认走后端探活**：`quit-inspection`（2s deadline，超时按有任务）是「后端还有活就别退」的最小协议扩展，比轮询简单。
5. **更新链可分级**：强制更新策略（纯 HTTP+错误码 40005）与 electron-updater 完全解耦，duo 可先只做「策略检查+提示」；安装前排空（lock）+unclean-exit 拒装是防更新损坏的关键闸门。
6. **最小 host 协议仍够用**（ready/fatal/shutdown/shutdown-complete），但 fatal 应带结构化 diagnostic（与 stderr 分通道防竞态截断）；requestId 关联+超时是控制消息的成熟形态。
7. **登录窗与工作区窗分离**：welcome 是本地静态页+白名单 IPC，凭据操作全经后端 RPC，浏览器 OAuth 外跳+深链唤回——比把登录页塞进 Web UI 更安全且不依赖后端已就绪。
