# 终端呈现（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 17（T-21）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；Web 面见 [Web呈现.md](Web呈现.md)。

## 机制全貌

DSH 的 `dsh` CLI（apps/cli）被裁定为纯 profile 启动器：bin.ts:34-51 按 mode 分派 profile/plugin/dump-config，launcher 只认自家旗标，第一个不认识的 token 起的参数原样交给树内 app 插件自解析（args.ts:4-15,145-152）。所以终端上没有 TUI——出厂 profile 仅 acp/web/headless/sdk/sdk-minimal（packages/boot/app-boot/src/profile.ts:135-150）；GUI 在 loopback web（web-app），终端面实际是三种非交互/半交互协议面：

- **headless**：一次性任务驱动器，消费者是脚本与 CI；`--json` 时 stdout 是 NDJSON 事件流。
- **acp**：面向可信程序化客户端的 Agent Client Protocol stdio 桥，「自动化专用……呈现与人际交互留给 UI 模块」（acp/src/index.ts:1-10）。
- **web**：浏览器托管形态，终端只负责打印 URL 与拉起默认浏览器。

## 关键流程

① **headless**：输入为 positional task（多词拼空格），`-` 独占读 stdin，交互式 TTY 无 task 即 usage error（headless/src/startup.ts:96-106）；`--session-id` 恢复既有会话。json-stream 投影词汇（json-stream.ts:257-318）：开场 `session{sessionId,cwd}`（先写后订阅，:318）；`status`(phase=turn_start/step_start/step_end/turn_end，step_end 汇总跨 attempt 的 usage，缺样本则整项省略，:278-288)；`thinking`/`text` 仅在 `assistant/message` 提交时发射（commit-point，模块头注：1-8）；`tool_call{callId,tool,input}`、`tool_result{callId,status,error|completed,result}`（只投影 surfaceOp==='append'，:303）；`error`（含 commander 语法错误覆写，startup.ts:83-94）；终帧 `final{text}` 承载无损答案、刻意不 bounding（:322-326）。Bounding：单字符串/键 8KB、单行含换行 32KB（json-stream.ts:16-19），超限打 `truncated:true`，行超长降级为标量字段、再退化为 `{type,truncated}`（:132-149）。退出码：turn/end reason.kind==='completed'→0 否则 1（runner 内 index.ts:380）；launcher 层 SIGTERM→0、SIGINT→130（apps/cli/src/profile-boot.ts:290-291）。resume 有护栏：拒绝 preset/subagent/fork/cwd 不匹配/不存在的 id（index.ts:211-230,291）。

② **acp**：stdio NDJSON JSON-RPC（index.ts:374-377），方法=initialize/authenticate/session/new/list/resume/close/setConfigOption/prompt + 通知 session/cancel（:379-390）；capability 含 mcp http、prompt image（探测后宣告）/audio:false/embeddedContext:false、session close/list/resume（:179-189）。事件投影只取已提交事件（session.ts:345-389）：`assistant/message`→agent_thought_chunk/agent_message_chunk（含图片内容）+usage_update（updates.ts:16-102）；`tool/call`→tool_call(status in_progress)，`tool/result`→tool_call_update(completed|failed)，ToolCallContent 为 `{type:'content',content}`（updates.ts:52-85）。permission：approval/request 先 drainUpdates 再向客户端 session/requestPermission，选项仅 allow-once/reject-once，一次性、绝不从应答推断持久授权（index.ts:152-173）。stopReason 映射（codec.ts:14-34）：completed→end_turn、max-tokens→max_tokens、interrupted→cancelled、aborted/blocked/error→end_turn。resume 校验 cwd realpath 一致、非 subagent/fork、未激活（index.ts:239-290）；stdin EOF 绑定有界关停（acp-app/src/index.ts:44）。

③ **cli 启动**：profile 选择→`dsh.profile.bundles` 层叠合成（profile-boot.ts:1-11,199-215）；web 面 webserver 起来后等 Loader settle 再 announce：打印 `dsh web: <带鉴权 URL> (LAN: …)`，随后经 `open` 包拉默认浏览器，SSH 启动则抑制 handoff，失败打印手动 URL 提示（web-app/src/index.ts:229,252-299）。分叉点：headless 与 web 各自是独立 bundle，同一 launcher 以 inner args 区分。

## 接口与参数要点

- json-stream 字段：session{sessionId,cwd}；status{phase,turn,step?,usage?,reason?}；thinking/text{text}；tool_call{callId,tool,input}；tool_result{callId,status,result}；error{message}；final{text}；统一可选 `truncated:true`。
- headless 旗标：task positional、`-`（stdin）、`--json`、`--session-id <id>`（startup.ts:38-53）。
- ACP 方法清单见上；additionalDirectories 明确不支持（:516-525）。
- cli 旗标：--profile/--from-default-profile/--patch(可重复)/--dump-config/--dump-default-config/plugin（args.ts:153-157）；web 面 --host/--port/--no-open/--trusted-host，--host 0.0.0.0 因 RCE 风险禁用（web-app/src/startup.ts:51-76）。
- 退出码：0=completed/SIGTERM；1=错误或非 completed 终止；130=SIGINT。

## 边界与坑

- headless 无任何中途交互（无 y/n、无进度询问），诊断全走 stderr、stdout 只留答案/事件流；`final` 不 bounding 但中间行严格 8KB/32KB——消费者必须容忍行降级与 `truncated` 标记。
- ACP 明确不承载 UI 与人际交互，permission 仅一次性、无持久授权；事件只来自 commit 点，live attempt 重试不会泄漏进流。
- headless --session-id 的 typo 会报错而非新建空会话（index.ts:286-292）。

## 对 duo 的启示

1. duo 的 CLI REPL 是一等呈现位，但可补一条 **headless 式 `--json` NDJSON 通道**：以 commit 事件为唯一投影源、final 帧无损豁免 bounding、退出码=turn 结果，自动化消费者即可不碰 TUI 拿到稳定词汇（status/text/tool_call/tool_result/error/final）。
2. duo 对接外部客户端可参照 ACP 形态：stdio JSON-RPC + 会话 new/resume/list + 有序 SessionUpdate 流 + 一次性 permission 应答，呈现责任留在客户端侧；stopReason 词汇需显式映射表而非直通。
3. 事件词汇与退出码是跨进程契约，DSH 为此做了系统性纪律：usage 缺样本宁缺勿假（json-stream.ts:283-286）、SIGTERM=0/SIGINT=130 固定、bounding 降级路径固定——duo 的叙述行/流式 print 词汇在对外发布前同样需要冻结与降级约定。
