## 关键实现逻辑（按流程分节）

### 1. 插件加载全流程

插件形状：`Plugin<T>` = `Plugin.Function | Plugin.Constructor | Plugin.Object`（`vendor/cordis/src/registry.ts:92-133`）。公共元数据 `Plugin.Base`：`name?`（诊断名）、`Config?`（StandardSchemaV1 校验器）、`inject?`、`provide?`、`intercept?`。Function 形态 `(ctx, config) => any`，返回值即 effect body——返回函数 = disposer，返回 Promise\<函数\> 或可迭代 disposer 流也接受，其他非空值 throw `TypeError('Invalid effect')`（`vendor/cordis/src/fiber.ts:83-108,356-400`）。

`ctx.plugin(X, config)` 步骤（`vendor/cordis/src/registry.ts:316-336`）：

1. `resolve(plugin)`：function 直接用，object 取 `.apply`，解析不出即 throw（`registry.ts:222-228`）。
2. `ctx.fiber.assertActive()`：父 fiber 已销毁则拒绝挂子插件（`fiber.ts:351-354`）。
3. 取/建 `Runtime{fibers, callback, Config}`——**以回调函数身份为 key**，同一插件多次 plugin() 共享 runtime、各得一个 Fiber。
4. `new Fiber(parentCtx, config, Inject.resolve(plugin.inject), runtime)`（`fiber.ts:222-333`）：uid 自增 → `ctx = parent.extend({fiber})` → inject 配置写入子 context intercept 表 → 组 runner（构造器形式 `new callback(ctx, config)` + `@Inject` 钩子；函数形式直接调用）→ **把自己注册成父 fiber 的 effect**（父子级联销毁的根，`fiber.ts:265-297`）→ 同步 emit `internal/plugin` → 对每个 inject 名 `_checkImpl` 后 `_refresh()`。
5. 返回包成 PromiseLike 的 fiber：`await ctx.plugin(X)` 即等加载 settle。

依赖等待到 apply 运行：`_refresh()`（`fiber.ts:611-623`）算 epoch = 各依赖 `impl.fiber.uid` 拼串；任一缺失 → INACTIVE；epoch 变化触发 `_setEpoch` → `_reload()`（`fiber.ts:646-673`）：config 先过 `internal/config` waterfall（loader 做 !!js 插值）再 schema 校验（失败 `ValidationError`）→ 真正调用插件回调收集 disposer → 成功置 ACTIVE；异常记 `_error` 置 FAILED。服务缺失时 fiber 停在 PENDING **等待而不报错**，由 boot 终审兜底。

`ctx.inject(deps, cb)` 只是 `plugin({inject, apply: cb})` 的语法糖（`registry.ts:300-302`）。

### 2. Fiber 状态机与生命周期

六态：PENDING → LOADING → ACTIVE → UNLOADING → DISPOSED，LOADING/ACTIVE 可转 FAILED（`vendor/cordis/src/fiber.ts:147-154`）。派生规则 `_getState()`（`:574-579`）：uid===null → DISPOSED；有 `_error` → FAILED；epoch 非 INACTIVE → ACTIVE；否则 PENDING。所有迁移经 `_updateState` emit `internal/status`，跨 ACTIVE 边界时对自己 provide 的每个服务 `reflect.notify`。

| 迁移 | 触发 |
|---|---|
| PENDING→LOADING | 全部 inject 依赖 impl 就绪 |
| LOADING→ACTIVE | `_reload` 成功 settle |
| LOADING→FAILED | config 校验或 apply 抛错 |
| *→UNLOADING | 依赖消失 / restart() / dispose |
| UNLOADING→LOADING | 卸载期间依赖回来 |
| *→DISPOSED | dispose 回调把 uid 置 null |

**dispose 清理序**（`fiber.ts:265-297`）：uid=null → emit `internal/plugin`（uid 已清）→ 从 runtime.fibers 移除（最后一个 fiber 时删 registry 条目）→ `_setEpoch(INACTIVE)` 触发 `_unload` → await 全部迁移排空。`_unload()`（`:675-696`）：`_disposables.clear()` 后 **Promise.all 并行**执行全部 disposer（每个错误包装后仅 logger.error，不中断兄弟清理）；fiber 级并行、单个 `effect()` 内部逆序串行（后注册先释放，`fiber.ts:431-441`）。

**update(config) 热更语义**（`fiber.ts:736-753`）：默认 = **整体重启不是增量**——先跑 `internal/update` waterfall（监听者可否决或替换重启行为，Loader 持久化钩子与 HMR 挂这里）→ 校验 → `restart()` = 卸载全部 disposer + 用新 config 重跑 apply。

**epoch 机制**：依赖集合指纹变化即触发 reload/unload——依赖来了自动启动、走了自动卸载、换提供者自动重启（`fiber.ts:611-639`）。

### 3. 服务解析（ctx.xxx 的实现）

三层设计：Proxy 运行时解析 + 声明式依赖等待 + 声明合并类型增强。

- **发布**：`ReflectService.provide(name, value, check?)`（`vendor/cordis/src/reflect.ts:277-305`）——包在 `ctx.fiber.effect` 里：登记 props → 按 isolate symbol 写全局 store + provider fiber 快照 → provider 已 ACTIVE 则 `notify`。disposer：删 store → notify → **await 所有依赖者完成重载** → 最后删 provider 自己快照（清理期间依赖者仍可读旧值）。`Service` 子类构造即 provide（`service.ts:57`）。
- **驱动**：`notify(names)`（`reflect.ts:314-336`）遍历全部 runtime.fibers，对声明了该服务且 isolate 匹配的 fiber 重查 impl（含 `impl.check()` 谓词）→ `_refresh()`。
- **读取**：Proxy get trap（`reflect.ts:135-171`）——特殊属性直通 → 内置服务 → accessor → 插件 fiber 走 `internal/get` waterfall 默认解析：沿 fiber 父链查激活期快照 `fiber.store[prop]`，**每步校验 isolate symbol 一致**，到 root 未声明 inject 即抛 `cannot get property without inject`。
- **隔离**：寻址键 = (服务名, isolate symbol)（`reflect.ts:209,286-293`）。编程式 `ctx.isolate(name, label?)`；配置式 entry `isolate: {svc: true|label}`（LocalRealm `#entryId` 私有 / GlobalRealm `@label` 共享，`vendor/loader/src/config/isolate.ts:26-68`）。
- **配置注入**：inject 表可带 intercept 配置，服务用 `resolveConfig` 沿原型链收集合并（根侧优先级低，`service.ts:86-102`）——"依赖方给服务传参"是一等能力。

### 4. 事件分派（五种模式）

`vendor/cordis/src/events.ts:32` DispatchMode = `emit | parallel | serial | bail | waterfall`。

| 模式 | 行号 | 语义 |
|---|---|---|
| emit | :194 | 同步逐个、忽略返回值 |
| parallel | :183 | `Promise.allSettled` 并发，有 rejected 抛 AggregateError |
| serial | :204 | 顺序 await，`isBailed`（非 null/false/undefined）即停 |
| bail | :217 | 同 serial 但同步 |
| waterfall | :234 | 最后参数为最内层 `next`；监听器外层先跑，收 `(...args, next)`；**不调 next 即否决链（含内置行为）**；返回最外层返回值——天然洋葱模型 |

监听器绑定：`on()` → `ctx.fiber.effect(注册/解绑)`（`events.ts:254-260`）——fiber 卸载自动摘除。派发按 `ctx[Context.filter]` 做上下文过滤（isolate 匹配）。框架把 get/set/config/update/listener/dispatch 全开成 `internal/*` 事件允许再拦截（`events.ts:329-352`）。

### 5. Loader / Entry / Include

- **Entry**（`vendor/loader/src/config/entry.ts`）：`init()` → `tree.import(name)`（`cordis:` 查 builtins 表，否则动态 import）→ `registry.plugin(plugin, config)` → `await fiber.await()`（`entry.ts:277-302`）。`update()`（`:142-246`）事务性更新：deepEqual 算 diff；diff 不含 name/inject/group 时走 **config-only 热更**（`fiber.update(config, noSave=true)`）；含则重 import + 换插件，失败回滚重启旧插件。disabled getter 级联祖先判定（`:88-98`）。
- **EntryGroup**（`config/group.ts:59-106`）：整组事务——逐行 create、删旧有新无的 id、任何失败回滚（删新增、按旧列表重建）、错误聚合。
- **Include**（`vendor/include/src/index.ts:174-375`）：`Service.init` 读文件（ENOENT + initial 写模板）→ stop disposer → `enqueue` 串行化 apply（防初始 apply 与 watcher 初扫竞态）→ `applyEntryPatches` → `EntryGroup.update`。写回走 tmp 文件 + rename（EACCES/EBUSY 重试 10×50ms）。
- **applyEntryPatches**（`:58-128`）：`structuredClone` 输入（永不突变）→ buildMap 按 id 索引（递归进 group）→ 逐 patch 按列表顺序（后写胜出）：insert 分支（带 id 插指定 group 尾部 / 不带追加根；**insert 行即时入索引**，后续 patch 可引用）→ 覆盖分支（查不到 warn 跳过；name 不匹配 warn 跳过；逐字段浅覆盖，config 整行替换）。
- **Loader**（`vendor/loader/src/index.ts:65-200`）挂四钩子：`internal/config`（!!js 插值）、`internal/update`（持久化写回 + reload 日志）、`internal/plugin`（给 fiber 挂 entry；区分用户 self-dispose → 写回 disabled 与 HMR 删除等 7 种 case，`:117-157`）、`[Service.check]`（loader 有未完成任务时依赖者保持 PENDING，实现 boot 排序）。

### 7. 工具注册与执行管线

**注册** `ToolRuntime.register(definition)`（`packages/core/tools/src/index.ts:1037-1062`）：校验 output 形状 + JSON Schema 支持 + timeoutMs 正有限；保留名 `run_code` 注册即 throw；`layers.effect(...)` 进 ScopedLayers（scope=agent；同层重名 throw；返回精确 disposer；触发 `tools/change`）；scoped 注册遮蔽全局同名。

**ToolDefinition 形状**（`:222-288`）：`{ name, description, parameters, output{schema,render}, execute(args, exec), finalizeContent?, timeoutMs?, isConcurrencySafe?(args), presentCall?/presentResult? }`。模型可见面仅 name/description/parameters（`:1256-1267`）。

**执行管线**（`execute :1342` = prepareExecution `:1463` → dispatch `:1569` → finalize `:1609` → finish `:1631`）：

1. createExecution：token + 参数 deepFreeze + 登记上下文；code-mode collapse 在可扩展策略之前终局拒绝为 UNKNOWN_TOOL。
2. `tools/pre-execute` waterfall（默认 allow；决策 allow/deny/ask）→ ask 走 `ctx.get('approval')` 可选服务，缺失降级 deny。
3. guard 门：`guardReason(exec)` 有 reason → 拒绝。
4. `tools/execute` waterfall（around-dispatch，超时/重试/指标包装在此；wrapper 只能替换 exec.signal）→ `dispatchToolBody`：`tool.execute(args, exec)` → 成功结果过 output.schema 校验（违规 throw ToolOutputError）→ render 投影 → deepFreeze。
5. 结果归一化：wrapper 自造结果必须重过 output 契约。
6. `tools/post-execute` waterfall（默认 accept）：accept 可换 content 或换 value（重新过契约）；block 把纠正反馈变 isError 结果。
7. finish：materialize → tool 自有 finalizeContent → emit `tools/result`。

**restrict vs guard**（两个治理钩子的区别）：
- `restrict(filter)`（`:1071-1098`）= **静态可见性**：allow/deny 名单编译为 Set，多条 restriction 相交；只过滤继承面（全局+祖先层），本 scope 自己的注册不受过滤——保证子代理上报工具不被能力过滤器剥掉。只允许 scoped context 调用。
- `guard(fn)`（`:1110-1128`）= **动态调用期**：`(execution) => string | undefined`，**单调否决**——返回 reason 即拒绝、没有 allow 结果、顺序无法翻回；时机在 pre-execute waterfall 之后、body 之前。普通 ctx 注册全局生效、agent.ctx 注册只对该 agent 生效。

### 10. HMR 机制

`vendor/hmr/src/index.ts`（inject `['loader','timer']`，要求 Node `--expose-internals`）：

- **监听**：主 watcher chokidar `watch(root, {ignored: ['**/node_modules','**/.*','cache','data'], ignoreInitial:true, debounce:100ms})`（ignoreInitial 防初始扫描重放 boot 刚消费的文件造成 teardown 死锁）；`registerConfig` 精确监听配置文件（用户 patch 层热更走此通道：重读 patch → `entry.update` → Include 重应用）。
- **变更路由**（`onChange :244-271`）：配置文件 → `include.refresh()`（config-only 热更）；externals（CLI 依赖闭包）→ `loader.exit()` 进程全量重启；ESM loadCache 内 → debounce 后 `partialReload`；其他 → emit `hmr/change`。
- **partialReload**（`:400-549`）：沿反向依赖链分类 accepted/declined → 定位受影响插件（**原子重载单位 = 插件入口文件**）→ 清 ESM loadCache + CJS require.cache 双缓存 → 重新 import → `registry.delete(oldPlugin)` + 对每个旧 fiber 在其 parent 上 `registry.plugin(newPlugin, oldFiber._config)` 并**继承 entry 关联与原 config** → 失败回滚。
- HMR 删除与 Loader 联动：loader 的 `internal/plugin` case 凭 `registry.has(callback)===false` 识别 HMR 删除，不误写回 `disabled: true`。

## 依赖关系

**框架层内部**（单向）：cosmokit ← schemastery ← cordis ← loader ← include/group/hmr（hmr 还依赖 timer）。

**产品插件 → 框架**：所有产品包 peer 依赖 `@deepseek-ai/cordis`（且镜像进 devDependencies，`scripts/check-workspace-constraints.ts:336-342` 强制）；seam 定义包是其实实现者的 peer、从不是普通 dependency（out-of-tree 插件直接 import 它们，profile 的 pnpm 解析必须含 peerDependencies 闭包，`packages/boot/app-boot/src/profile.ts:229-247`）。

**插件运行时零包间直接调用**：一切经 Context 服务注入与事件。被依赖关系（谁消费这些机制）：

- `ctx.plugin` / Fiber / effect：全部 225 个产品包的加载地基。
- `ctx.tools` + `tools/*` waterfall：mcp-client、tool-fs、tool-bash、tool-web、spill-policy、timeout-policy 等。
- loader 树 + `internal/plugin`：client-modules（增量扫描）、plugin-inventory（状态投影）、HMR（重载定位）。
- `loader.await()` + 审计：boot 的唯一 settle 判据。
