## !!js 表达式与动态配置

- 表示法：YAML 标签 `!!js` 解析为 `{__jsExpr: string}` 节点（`vendor/include/src/index.ts:12-14`）；dump 工具复用同一 schema 保证往返不漂移。
- 求值器：`new Function('ctx','expr','with(ctx){return eval(expr)}')`（`vendor/loader/src/config/utils.ts:5-9`）。**无沙箱**——表达式拥有完整宿主权限；信任模型 = 配置文件与代码同级可信。
- 求值时机仅两处，其他元数据一律字面（`docs/cordis-primer.md:38`）：
  1. `config`：`internal/config` waterfall 在**声明的 inject 全部激活之后、对插件自己的 ctx** 求值（`vendor/loader/src/index.ts:97-102`）——所以 `config.task: !!js ctx.headlessStartup.task` 合法（`packages/bundle/headless/cordis.patch.yml:27-31`）；每次 fiber 激活（含 reload）重求值；Group/Include 载体的 config 保持字面。
  2. `disabled`：每次 mount 决策对 loader ctx 求值（`entry.ts:89-93`）；平台门控样例 `disabled: !!js process.platform === 'win32'`（`packages/bundle/base/cordis.patch.yml:223-259`）。
- 表达式抛错 = fiber FAILED（同 apply 抛错路径；disabled 表达式抛错另被 boot 审计单列为条目失败）；`--dump-config` 按原样打印不求值（`app-boot/src/index.ts:403` renderConfigDump）。

## 已知坑（作者明确警告）

**加载/时序类**
- entry 并发启动，**行序对加载顺序零保证**，顺序只由 inject 决定（tutorial/01:31；base patch:12-13）。
- 模块解析失败只走 logger，早期日志可能丢——新 entry 无声无息先查拼写（tutorial/01:91；ddefc45f 起初始 import 失败也走同路）。
- PENDING 是合法静默态：不报错不保活；HMR 自己 inject `timer`——没挂 timer 插件则 HMR 永久 PENDING 无提示（tutorial/06:42,63）。
- 时序问题用声明式 inject 解，不写 boot 顺序；可选依赖用 `ctx.get(name)` 使用点探测（tutorial/03:80-90）。tools 对 ptcRuntime 刻意不用静态 inject（b150a551 时叫 codeRuntime）：否则 native 模式下所有工具插件被可能不存在的后端劫持（`packages/core/tools/src/index.ts:930-936,1026-1028`）。
- **apply 必须显式 `async`**：带 prototype 的普通函数被当 constructor，其返回的 Promise 不算 startup work（`packages/mcp/mcp-client/src/index.ts:154` apply 本体即 async）。

**配置/patch 类**
- patch 替换整行 config 不合并，覆盖行必须重述全部键（base patch:5-13）。
- 无 `id` 的 entry 在文件任意编辑后 remount（tutorial/06:59）。
- **waterfall 纪律**：只观察/注解的 listener 必须调 `next()`；忘调 = 静默吞掉默认行为（tutorial/04:138）。
- const enum 镜像：Cordis `FiberState` 无运行时对象可 import，多处手抄数值镜像并要求保持对齐——ddefc45f 起镜像增 `FIBER_DISPOSED = 4`，且 tool-cordis 的 fiber-state 副本已删（不再列对齐对象），只对 `packages/client/web/src/loader-status.ts`（`app-boot/src/index.ts:679-684`）。

**HMR 限制**
