### bundle patch yml 结构

出处：`vendor/include/src/index.ts:144-156`（类型）、`58-128`（算法）。**只有两种操作，没有 insert/delete/replace 三语法**：

| 操作 | 语法 | 语义 |
|---|---|---|
| 覆盖 | `{ id, name?, ...任意 entry 字段 }` | 逐字段浅覆盖（id 跳过）；**config 整行替换而非深合并**（`packages/bundle/base/cordis.patch.yml:5-9` 注释明示）；**没有 delete——删除行 = `disabled: true`** |
| 插入 | `{ insert: [entry...] }` 可带 id 指定 group | 无 id 追加根列表；**insert 行即时进入 id 索引**，同列表后续 patch 可引用（`:96-101`） |

## !!js 表达式与动态配置

- 表示法：YAML 标签 `!!js` 解析为 `{__jsExpr: string}` 节点（`vendor/include/src/index.ts:9-15`）；dump 工具复用同一 schema 保证往返不漂移。
- 求值器：`new Function('ctx','expr','with(ctx){return eval(expr)}')`（`vendor/loader/src/config/utils.ts:5-9`）。**无沙箱**——表达式拥有完整宿主权限；信任模型 = 配置文件与代码同级可信。
- 求值时机仅两处，其他元数据一律字面（`docs/cordis-primer.md:38`）：
  1. `config`：`internal/config` waterfall 在**声明的 inject 全部激活之后、对插件自己的 ctx** 求值（`vendor/loader/src/index.ts:92-101`）——所以 `config.task: !!js ctx.headlessStartup.task` 合法（`packages/bundle/headless/cordis.patch.yml:38-40`）；每次 fiber 激活（含 reload）重求值；Group/Include 载体的 config 保持字面。
  2. `disabled`：每次 mount 决策对 loader ctx 求值（`entry.ts:104-108`）；平台门控样例 `disabled: !!js process.platform === 'win32'`（`packages/bundle/base/cordis.patch.yml:180-186`）。
- 表达式抛错 = fiber FAILED（同 apply 抛错路径）；`--dump-config` 按原样打印不求值（`app-boot/src/index.ts:357-358`）。

### isolate / Realm

- 何时需要：同一服务名多实例并存（两个 group 各挂一套 shell）；agent preset 给会话换服务实现时服务行需要 realm（`docs/architecture.md:114`）；**provider 与 consumers 必须同 group、同 label 才互相可见**（`app-boot/src/index.ts:506-509`）。
- 注入地址：`Realm.access` 把服务名变 `Symbol(name+suffix)`，ReflectService.store 以该 symbol 为 key；跨 realm 读取沿父链时每层校验 symbol 一致，不一致即抛增强版错误（`vendor/cordis/src/reflect.ts:153-167`）。
- 运行时改 isolate 配置：`loader/patch-context` 七步事务（新 map → diff → swap → reload → 迁移 impl symbol → notify → 清理），服务实现可在 realm 间搬家（`vendor/loader/src/config/isolate.ts:96-153`）；realm 表随 `loader/partial-dispose` GC（`:155-172`）。
- 冲突：同 scope 同名服务二次 provide 抛 `service "x" has been registered at <fiber>`（`reflect.ts:289-291`）。

### MCP

- 首连语义：apply await `connection.ready`；`failOnStartupError: true` 失败即 throw 让 fiber 回滚；false 仅日志进重连循环（`packages/mcp/mcp-client/src/index.ts:172-180`）。初始同步 `registrationFailure:'throw'`，后续 re-sync 一律 contain（`connection.ts:130-136`）。
- 世代护栏：`GENERATION_CLOSE_TIMEOUT_MS = 5000`；旧代超时未关则 **fail-closed 停止重连**，宁可无服务不重叠子进程（`connection.ts:47-50,285-292`）；dispose 时同样等关闭 + quiesce（`:327-349`）。
- 工具列表变化：`ToolListChangedNotification` → 重新 enqueueSync；**syncChain 串行化所有同步**（初始/通知/跨代）防 double-dispose/泄漏（`:158-170`）；fetch 失败保留上一份好列表继续服务（`:264-268`）。
- 命名清洗是全部 sanitize 逻辑：非法字符替换 + 64 字符截断 + `SHA-256(serverName\0raw)` 前 12 hex 后缀防碰撞（`tools.ts:97-117`）；wire 只发 rawName，public name 永不反解析（`:8-10`）。

### 双面模块 wire（BootManifest）

- JSON 结构：`window.__DSH_BOOT__ = {rev, entries: WebBootEntry[]}`；行字段 `id`/`url`（`/plugins/<id>/client.js?rev=`）/`rev`/`inject?`（信息性包名边，权威边在包声明）/`external?`（**约束代码到达顺序**——浏览器 require 是同步的）/`immediately?`（stage-one 预取）（`packages/client/modules/src/client/manifest.ts:44-50,51-108`）。

## 已知坑（作者明确警告）

**加载/时序类**
- entry 并发启动，**行序对加载顺序零保证**，顺序只由 inject 决定（tutorial/01:31；base patch:12-13）。
- 模块解析失败只走 logger，早期日志可能丢——新 entry 无声无息先查拼写（tutorial/01:91）。
- PENDING 是合法静默态：不报错不保活；HMR 自己 inject `timer`——没挂 timer 插件则 HMR 永久 PENDING 无提示（tutorial/06:42,63）。
- 时序问题用声明式 inject 解，不写 boot 顺序；可选依赖用 `ctx.get(name)` 使用点探测（tutorial/03:80-90）。tools 对 codeRuntime 刻意不用静态 inject：否则 native 模式下所有工具插件被可能不存在的后端劫持（`packages/core/tools/src/index.ts:1002-1009`）。
- **apply 必须显式 `async`**：带 prototype 的普通函数被当 constructor，其返回的 Promise 不算 startup work（`packages/mcp/mcp-client/src/index.ts:132-137`）。

**配置/patch 类**
- patch 替换整行 config 不合并，覆盖行必须重述全部键（base patch:5-13）。
- 无 `id` 的 entry 在文件任意编辑后 remount（tutorial/06:59）。
- **waterfall 纪律**：只观察/注解的 listener 必须调 `next()`；忘调 = 静默吞掉默认行为（tutorial/04:138）。
- const enum 镜像：Cordis `FiberState` 无运行时对象可 import，多处手抄数值镜像并要求保持对齐（`app-boot/src/index.ts:666-673`）。

**HMR 限制**
- 需 `--expose-internals` 否则构造即抛；externals 内文件变更 = 全量重启无部分替换；Node 22/23/24 ESM loadCache 与 CJS require.cache **双缓存都要清**，loadCache 在 24 是子类 Map 须 `Map.prototype.delete.call`（`vendor/hmr/src/index.ts:446-459`）；主 watcher `ignoreInitial: true` 防 include 回滚与刷新互等死锁（`:228-240`）；include 组级事务不可重入，所有 apply 过 applyQueue 串行化（`vendor/include/src/index.ts:216-229`）。

**peer 依赖约束（seam 包零运行时依赖的原因）**
- 规则：`@deepseek-ai/cordis` 必须同时在 peerDependencies 与 devDependencies 且范围一致；唯一允许进 dependencies 的是 schemastery（`scripts/check-workspace-constraints.ts:336-342`）。
- 实证：seam 包 `packages/fs/fs/package.json`、`packages/shell/shell/package.json` 的 dependencies 均为空；`packages/core/tools` 仅 schemastery 一个 runtime dep。
- 原因：out-of-tree 插件经 pnpm 解析必须共享**单一份 cordis 实例**；Service Definition 包是其实实现者的 peer、从不是普通 dependency；seam 包带 runtime 依赖会在每个消费者处分叉实例，破坏"一次 provider 替换改变整个产品"的语义（`packages/boot/app-boot/src/profile.ts:229-247`；`docs/architecture.md:98-104`）。
- 命名：服务名单 app 扁平命名空间；harness 占用 `tools`/`llm` 等裸名，第三方服务要加前缀（tutorial/03:94）。
