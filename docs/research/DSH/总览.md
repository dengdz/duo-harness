# DSH（deepseek-harness）项目总览

> 源锚点：`b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`（本地 `/Users/zhangyl/IdeaProjects/deepseek-harness`，2026-08-24 已 pull）。本文结论只对该锚点负责；出处均为 DSH 仓库内路径。

## 一句话定位

deepseek-harness（DSH）是一个 TypeScript monorepo 的 AI agent harness：Node 进程承载宿主侧（agent 循环、工具执行、会话持久化），内嵌 HTTP 服务向浏览器提供 Web UI，全部能力以 Cordis 插件形式组装，运行形态由 profile → bundle 补丁层合成。

## 总体架构理念

三条主线贯穿全库（`docs/architecture.md:5-45`）：

1. **一切皆 Cordis 插件**。DSH 没有单体核心，而是跑在 vendored 的 Cordis 插件容器（`@deepseek-ai/cordis`，DI + 事件框架）上。每个能力包（llm、tools、compaction、web…）都是一个插件，通过 service 注入（`ctx.llm`、`ctx.tools`…）和事件瀑布（waterfall）协作。
2. **无特权核心、逐层可 patch**。运行中的 `dsh` 是 boot 时按 profile → bundle 层序合成的插件树：`dsh-base` 是所有 profile 的第一层核心补丁，`dsh-web-app` 叠加浏览器面，`dsh-headless` 是无服务一次性 runner（`packages/bundle/*/cordis.patch.yml`）。
3. **框架层自有化**。Cordis 框架 9 个包整体 vendored 进 `vendor/`，重命名进 `@deepseek-ai` scope——harness 完全拥有框架层，可审计、可打补丁、可锁版本（`vendor/README.md:3-5`）。

## 模块调用关系

### 静态依赖结构（关键事实）

插件包之间的依赖声明在 **peerDependencies（`workspace:^`）**——这是 Cordis 插件惯例，同包 devDependencies 重复声明用于本地解析（`packages/core/agent/package.json:39-47`）。硬 dependencies 只出现在装配层（apps/cli、bundle/*、python/sdk-runtime）。

核心 peer 依赖边：

```
dsh-agent        → invariants, llm, scope, session, system-prompt, typert-protocol, cordis
dsh-agent-loop   → agent, llm, scope, session, session-persistence, system-prompt, tools, settings
dsh-tools        → agent, code-runtime, llm, scope, session, system-prompt, user-approval
dsh-llm          → attachment, brand, invariants, timeout
dsh-app-boot     → cordis-plugin-{group,hmr,include,loader}, home-paths, system-prompt
```

装配链：`dsh-base`（约 80 包）→ `dsh-web-app`（叠加 client ui-* 与 host/*）→ `apps/cli`（dsh-base + dsh-web-app + dsh-headless + 工具包）。几乎每个包都 peer 依赖 `dsh-invariants` 与 `cordis`。

### 运行时协作

运行时不存在包间直接调用，一切经 Cordis Context 的 service 注入与事件：

- **Service（`ctx.<name>`）**：`ctx.llm`、`ctx.tools`、`ctx.systemPrompt`、`ctx.sessions`、`ctx.apiProxy`、`ctx.web`、`ctx.lsp`、`ctx.sandboxPolicy`、`ctx.settings`、`ctx.approval`…
- **Waterfall（可拦截管线）**：`agent/pre-step`、`agent/request`、`llm/stream`、`tools/pre-execute`、`tools/execute`、`tools/post-execute`、`approval/request`…
- **事件 firehose**：`session/event`（会话事件流，UI 与持久化都订阅它）

扩展接入模式（mcp/lsp/terminal 为代表）：能力包不侵入主循环，只通过 `ctx.tools.register(definition)` 把自己注册为普通工具，再挂一段 system prompt 提示（如 `tool:lsp`）。

## 启动链路

1. **CLI 入口**：`dsh` bin → `apps/cli/src/bin.ts` 解析模式，profile 模式动态 import `runProfile`（bin.ts:27-38）。
2. **profile 组合**：`composeProfile()` 加载 `$DSH_HOME/profiles/<name>`，按序叠加补丁层：bundle 层（dsh-base + dsh-web-app）→ profile 自有 `cordis.patch.yml` → home 层 → `--patch` overlay → telemetry（`apps/cli/src/profile-boot.ts:142-171`）。
3. **boot()**：`new Context()` → `ctx.plugin(Loader)` → `mountRootInclude()` 交出全部 patch → `loader.await()` 等插件树 settle → 审计所有条目激活（`packages/boot/app-boot/src/index.ts:757-802, 692-725`）。
4. **插件树内容**：由 `packages/bundle/base/cordis.patch.yml` 的 insert 序列定义（timer/hmr/llm/session/agent/agent-loop/tools/system-prompt/sandbox/tool-bash/tool-fs/web/compaction/subagent…）；web profile 叠加 webserver、apiproxy、connection 与浏览器端插件名单（`packages/bundle/web-app/cordis.patch.yml`）。
5. **进入运行态**：无传统 REPL。web profile 下 webserver 监听（默认 127.0.0.1:3080），`web-runtime` 打印 URL 并开浏览器（`packages/bundle/web-app/src/index.ts:186,217-230`）；headless profile 答完一个 task 即退出。用户 patch 层支持 config-only HMR。

## Agent 循环（核心运行时）

核心类 `ReactLoopAgent`（`packages/core/agent-loop/src/agent.ts:64`），工厂服务 `AgentLoop` 提供 `create/createAgent/resume`（`packages/core/agent-loop/src/index.ts:296,589,606,653`）。一轮 turn：

1. **入队**：`send/followup/steer` 把 `UserMessage` 放进 `Inbox`（`nextTurn`/`nextStep` 双队列），`wakeDriver()` 启动 `while (await this.turn())` 循环。
2. **preStep**：领取消息 → `systemPrompt.assemble()` 组装 → runtime context 投影成 durable user 消息 → `agent/pre-step` waterfall（插件可改写/拒绝）。
3. **step**：`buildRequest()`（`agent/request` waterfall 定 provider/model → `ctx.llm.prepareCall()` 冻结配置 → 记 `request/header` 事件）→ 流式 `ctx.llm.stream()` → 逐 chunk `session.append('assistant/chunk')` + BlockAssembler 聚合 → 完成 `assistant/message` → 有 tool-call 则进入工具调度；无 tool-call 则 turn 结束。
4. **工具调度**（`tool-calls.ts:59-101`）：按 `ctx.tools.executionMode()` 分组——并发安全工具进并行滚动池（上限 `maxParallelToolCalls`），独占工具是屏障；结果严格按 model 序提交；`tool/call` 与 `tool/result` 事件成对写入。
5. **执行管线**：`tools/pre-execute`（allow/deny/ask → `ctx.approval` 审批）→ `ToolGuard`（只能拒绝）→ `tools/execute`（超时/重试/spill 包装）→ `tools/post-execute` + `tools/result`。

会话状态即事件日志：`Session.append()` 唯一写入，核心事件词汇 `turn/*`、`step/*`、`user/message`、`assistant/chunk|message`、`tool/call|result`、`request/header|context`（`packages/core/session/src/types.ts:236-336`）；`deriveMessages()` 按有序 surface 投影出下一请求的 messages。

### Compaction（上下文压缩）

`BasicCompactionEngine` 三种触发：token 压力（`agent/pre-step`，阈值 0.8 × contextWindow）、上下文溢出恢复（`agent/request-error` 且 `CONTEXT_WINDOW_EXCEEDED`）、手动 `/compact`。机制：选一段 tool call/result 配对完整的 surface 范围 → LLM 摘要 → 写 `compaction/start|summary` + 带 `surfaceOp: replace` 的 checkpoint——模型历史删旧 span，日志本身 append-only 不删（`packages/compaction/compaction-basic/src/index.ts:103,147-200`、`region.ts:447-463`）。另有工具结果前置修剪（阈值 8192 字符，`tools/post-execute` 阶段）。

## 一次请求的端到端数据流（web UI）

```
浏览器 ui-conversation (React)
  │ HTTP fetch POST /api/<method>
  ▼
WebServer /api 路由（浏览器信任栅栏）→ toFetchHandler(apiProxy)
  │ apiProxy.prompt() → agent.steer/followup，立即返回 {accepted:true}
  ▼
ReactLoopAgent Inbox（内存 UserMessage 队列）
  ▼ preStep：systemPrompt.assemble() → runtime-context 投影 → session.append('user/message')
  ▼ buildRequest：agent/request waterfall → llm.prepareCall → session.append('request/header')
  ▼ llm.stream()（llm/stream waterfall）→ DeepSeekAdapter fetch SSE → StreamChunk 流
  │   每 chunk：session.append('assistant/chunk') + BlockAssembler
  │       ├─→ session/event firehose → apiproxy mux 帧 → WebSocket /api/events.mux → 浏览器流式渲染
  │       └─→ persistence write-behind 缓冲 → JSONL 落盘
  ▼ 有 tool-call：executeToolCalls → ToolRuntime 管线 → 工具体（bash/fs/MCP/PTY/LSP）
  ▼ session.append('tool/result') → 回到 preStep 下一 step，直到无 tool-call → turn/end
```

前后端通信形态：上行 HTTP RPC（fetch `/api`），下行 WebSocket 聚合流（`/api/events.mux` 全 session 事件 + approval/question/inbox/jobs 控制帧）。浏览器端不是静态页面——`AppWebEntry` 在浏览器里再起一棵 Cordis 树装载客户端插件（`packages/client/web/src/boot.ts:22-158`）。

## 关键设计速览（供 duo-harness 借鉴时定位）

- **Seam + 实现 + 工具**三包模式：每个能力域拆为抽象 seam 包（`ctx.web`/`ctx.lsp`）、后端实现包（`web-fetch-http`/`lsp-stdio`）、模型侧工具包（`tool-web`/`tool-lsp`）——同一个 seam 可换后端，工具层独立演化。
- **事件溯源会话**：`append()` 单写原语 + surface 投影（`deriveMessages`）+ surfaceOp replace（compaction 不改日志），回放/检索/压缩都建立在同一份日志上。
- **双面插件（host/client）**：`dsh.client` 双面模块系统让一个包同时声明服务端与浏览器端插件。
- **peer 依赖 + 装配层硬依赖**：插件包零运行时依赖，版本约束全部由 profile/bundle 装配决定，支撑"逐层 patch"的形态合成。
- **权限三态 + fail-closed 并发**：read-only / workspace-write / danger-full-access 三态策略，仅 `isConcurrencySafe === true` 的工具进并行池。
