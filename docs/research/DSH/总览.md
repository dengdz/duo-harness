# DSH（deepseek-harness）项目总览

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验，github 离线未 pull；release 0.1.6-alpha.2）。本文为五批次全景探查（结构/功能/设计/UI/路由交互）的汇总，结论只对该锚点负责；出处均为 DSH 仓库内路径。沙箱与权限域另有专册 [沙箱与权限.md](沙箱与权限.md)。2026-09-21 全景探查版，取代 b150a551 旧版总览。

## 一句话定位

TypeScript pnpm monorepo 的 AI agent harness：Node 宿主承载 agent 循环 / 工具执行 / 事件溯源会话，Cordis 插件容器组装一切能力，React SPA 经 loopback webserver 提供 GUI；规模约 87.6 万行 TS（packages 内，含测试）。

## 1. 代码结构与模块划分

- 顶层：`packages/`（59 域 × 291 子包，两层「域/包」结构，域目录纯容器；`scripts/check-workspace-constraints.ts:16`）、`apps/`（cli / web / desktop / desktop-host）、`vendor/`（cordis 框架 9 包整体自有化）、`native/`（Rust/C 启动器独立 workspace + 四平台预编译包）、`docs/`（架构文档 + 生成型目录）、`snapshots/`（111 场景录制回放基线）、`benchmarks/`（性能门禁）、`website/`（文档站）、`python/`（SDK）。
- **seam 三元组规律**：每能力域 = `<域>`（Service Definition seam，仅依赖 cordis，如 `packages/fs/fs`）+ `<域>-local/-sandbox/-ssh/-e2b`（provider 实现）+ `tool-<域>`（consumer 工具）；`docs/capability-seams.md` 由脚本生成并 `--check` 门禁。
- 体量分布：core/ 51k 行、api/ 48k 行、client/ 241k 行（78 个 ui-* 包，占全仓 27%）、experimental/ 69k 行；最大单包 `client/ui-conversation` 25.4k。
- apps/cli 只是 profile 启动器（bin `dsh`，非 TUI，全仓无 ink）；GUI 全在 web，dist 由 cli 的 host webserver 托管。
- 依赖方向：util→seam→impl→tool/bundle→apps 单向；`scripts/verify-package-dependencies.ts` 按 client-only / client-host / configured-host 三角色校验 npm 段；TS project references DAG 兜底，无循环依赖。
- 构建与工具链：tsc 双 face（host/client）聚合 + tsdown 产 ESM（`DSH_BUILD_FACE` 切换）；Vitest 七车道（单测 per-file 100% 覆盖门禁 / e2e 真 API / expected / snapshot / web / web-perf-stress / bench）；lefthook + oxlint；CI 24 workflow（GitHub）+ GitLab 镜像。

## 2. 核心功能与业务逻辑

- **agent 循环**（`packages/core/agent-loop`）：call model → run tools → repeat；inbox 收件箱按 `next-turn`/`next-step` 两类目标消费 steer/wake；工具并发池 `maxParallelToolCalls`（缺省 10）+ exclusive 屏障；无内置 turn 预算（外部经 `agent/turn-stopping` 生命周期点取消，取消保留已流出文本）；`core/agent` 提供 follow-up/steer/inject-context API。
- **会话与事件**：append-only 事件溯源（60 余种事件词表，`core/session/known-event-types.ts`，未知类型须 `ignorable` 标记）；`session-persistence-jsonl` 每会话一个 `.jsonl.zstd`（每批 fsync、committed 永不重写、撕裂尾帧截断恢复）；格式迁移链 v0→v1→v2→v3 显式版本包；投影急切派生（todos/goal/stats/turnBoundary）+ 快照水位 + 冷读「checkpoint+尾部重放」；标题生成 newest-wins、不进模型输入。
- **上下文治理**：`context/`（AGENTS.md/CLAUDE.md、@file、跨会话引用、时间上下文等无工具型注入，以 user 消息入日志可重放）+ `compaction/`（token 压力自动摘要 + `/compact` 手动 + 工具结果预裁剪/图片卸载；被遮蔽内容留日志保证确定性重放）+ `spill/`（超限结果落盘 locator + 有界预览，全文可回读）。
- **LLM 层**：`llm` seam 请求深冻结不可改写、每流=一次尝试、可由日志重建；`llm-retry` 重试、`token-meter` 计量；适配器 `llm-deepseek`（Messages/Chat 双协议）与 `llm-pi-ai`（多 provider/自定义网关，可 dormant 挂载）并存路由。
- **工具系统**：固定管线 pre-execute（allow/deny/ask 瀑布）→ 单调 guard → execute（超时/重试包装）→ post-execute（改写）→ finalizeContent → result（只读）；失败返回结构化错误不断 turn；`restrict` 按 agent 收窄。工具域全景：fs（read/glob/grep/str-replace-editor）、shell（bash/pwsh + persistent 常驻会话）、web（fetch + deepseek/exa/perplexity 搜索）、lsp（只读）、terminal（PTY 持久终端六件套接 jobs）、browser-use/computer-use、document、deliverables（交付声明 + git 工作区变更快照）、attachment、session-query（SQL 查历史）、mcp-client、ask-user、subagent、skill、todo/goal/jobs。
- **子代理与任务分解**：subagent 委派 seam（in-process spawn / fork 复制父上下文 + ACP/Claude Code/Codex/DSH-SDK 外部后端）+ control（列举/操控）+ report；todo=轮内清单、goal=单目标 CAS 续跑（256 轮 cap + 竞态防护）、plan=执行前审批——三域分立。
- **扩展机制**：hooks（Claude Code/Codex 双格式桥，command 钩子可拦 prompt/tool call）；skills 多源注册表；workflow（模型写 JS 编排脚本 `agent()/parallel()/pipeline()/phase()`，跑在 code-runtime worker 线程）+ ralph（fresh-agent 循环）；PTC `run_code` 程序化工具调用（生成 SDK）。
- **交互面**：user-approval（ask/never 一次性审批，fail-closed，全程审计）、user-questions 答案者瀑布、permission-presets、斜杠命令、api/gateway（Typert RPC 双端 + WS 多路复用流）、ACP stdio（自动化协议）、headless `--json` 事件流。
- **MCP 与远程**：mcp-client（工具命名 `mcp__server__tool` 直注册）+ mcp-resources；ssh 域（OpenSSH 别名 + fs/subprocess/sandbox 三远程 provider）；e2b 云适配器——均与本地 provider 同 seam 可互换。
- **出厂装配**（`packages/bundle/base/cordis.patch.yml`，87 行插件单次 insert）：llm 双适配器、session 全家、沙箱域、fs/shell 工具、skills、goal/plan/compaction、subagent、workflow、spill、todo/goal/ralph/jobs/web 工具、mcp-resources、user-approval/questions；web-app/acp-app/headless/sdk-app/sdk-minimal 各 bundle 按 patch 叠加。

## 3. 整体设计与架构风格

- **DI/插件模型**：vendored cordis（Service/Context/Fiber；五类事件派发，waterfall 即 around 中间件）；装配 = profile→bundle patch yml 层序（按 id 覆写行配置 / insert 插行 / `!!js` 表达式），bundle 列表→profile patch→home patch→`--patch`；`ctx.*` 经 TS declaration merging 挂载（237 文件）。
- **seam 模式与不可变纪律**：seam/provider/consumer 三元组由生成文档 + `--check` 强制，consumer 只 import seam 包，seam 契约测试（如 `runPersistenceContract`）钉死 provider 行为；请求/消息深冻结（`agent.ts:521,603` deepFreeze + frozenMessages WeakSet）、registry 内部可变/公开只读双视图。
- **事件溯源与确定性**：append-only + 投影派生 + 快照水位；持久化指纹目录（每事件类型 SHA-256 指纹，注释/别名不敏感、字段序敏感，`verify-persistence-catalog` 门禁；历史代际只增不改）。
- **错误哲学**：`HarnessError` code（稳定机读，"route on this, never by parsing message"）与 message（人读）分离；对 provider 模糊失败保留正则分类兜底；模型只见渲染结果 + name/code，stack 不外泄；`docs/defensive-patterns.md` 把真实事故沉淀为规则（postmortem 制度）。
- **并发模型**：cordis fiber + 异步 Promise；工具并发池 + exclusive 屏障；`isConcurrencySafe` 元数据不进模型视野；子进程树收割（managed-owner/kill 升级链，dispose 必须等到子进程静默）。
- **配置体系**：cordis.yml 行配置（部署组合）→ settings seam（命名 namespace + schema，用户 YAML 覆盖 live 生效）→ credentials 独立；schemastery + zod + StandardSchema 三重校验；`DSH_*` 环境变量约定；spawn 前 env 脱敏（`*KEY*/*SECRET*/*TOKEN*/*PASSWORD*`）。
- **测试哲学**：七层（单测含 HMR dispose 测试 → 100% 覆盖门禁「未覆盖行=删代码信号」→ 真 API e2e → keyless expected → 性能门禁 → snapshot → web 快照）；快照录制回放：真 API 录制产父子代际 JSONL，replay 无 key，「验世界不验自述」（外部重读文件、字节级比较）。
- **文档工程**：生成型文档（capability-seams / graph-atlas / persistence-catalog，头部 "Generated do not edit"，CI `--check`）+ AGENTS.md 文档宪法（教程/参考二分、doc-budget 上限、postmortem 制度）+ 每文档 i18n 同步税。
- **三标签与评价**：「一切皆插件」（无特权核心，产品本体全是可 patch 的行）、「契约可校验」（catalog/指纹/`--check` 把架构约定变 CI 事实）、「防御性工程」。最值得借鉴：seam + patch 装配模型（能力可换而消费者不动）；最重负担：文档/指纹/i18n 的维护税（对迭代速度构成显著成本）。

## 4. UI 界面与组件

- 形态：React 18 SPA + Vite 壳（apps/web 只是 boot kernel）；CSS Modules + `--dsw-*` 设计 token（ui-theme 注入 pre-plugin bootstrap 保首帧主题，light/dark/system，字号 12-17px）；无 tailwind。
- 基础层：ui-primitives（零 cordis 原子组件：Button/Modal/Menu/DiffBlock/ReadBlock/JsonTree/HoverCard…）/ ui-slots（slot 注册表纯核）/ ui-renderer（挂载 + selector hooks）/ store（Zustand+Immer snapshot，localStorage 持久化）/ locale（zh/en 类型化命名空间词典，插件可注册语言）/ ui-theme。
- 壳布局：ui-layout（三栏 AppFrame + 面板几何）/ ui-dockkit（可分裂/反转 tabbed pane 停靠树 + 浮动层）/ ui-sidebar 家族（browser/documentpreview/files/right/terminal）。
- 会话域：ui-conversation（事件/视图注册表 + SubmitMachine 输入状态机）/ ui-chat / ui-tool（`tool.call.toolview` 键控插槽的工具卡树，未注册工具 generic 卡）/ ui-trajectory（turn 级事件台账 + 时间轴）/ ui-message-feedback / ui-commands。
- 交互域：ui-approval（权限应答）/ ui-user-questions（ask_user 的 composer 接管卡 + plan-review 审批卡）/ ui-permission-presets / ui-input-trigger / ui-plan（composer 状态 chip）。
- 周边域：ui-settings 全家（general/models/plugins/plugin-inventory/unarchive…）/ ui-plugin-manager（全局面）/ ui-model-selection / ui-agent-preset / ui-session / ui-workspace / ui-goal / ui-jobs / ui-schedule / ui-skill / ui-subagent / ui-workflow-run / ui-deliverables / ui-directory-picker。
- 富文本：markdown + TeX（katex）+ **shiki** 代码高亮；不可信输出禁 raw HTML、限链、解析 ANSI。
- 桌面端：apps/desktop Electron 壳（窗口/IPC/宿主进程协议/强制更新窗/更新注意用 dock bounce，无系统托盘）；apps/desktop-host 私有 Node 宿主跑 runtime + webserver；packages/host 组（webserver SPA fallback / frontend-static / apiproxy / directory-picker）。
- 工程化：client 角色门禁（verify-package-dependencies）+ 浏览器纯净性 spec；测试走 vitest.web 构建产物交互快照（`DSH_SNAPSHOT=refresh/replay`）+ web-stress / web-perf 车道。

## 5. 页面路由与交互流程

- **无 URL 路由**（无 react-router/pushState）：三栏壳 + slot 注册（`ctx.slots.inject('main'/'sidebar.panellist')`）+ dockkit 停靠树驱动导航；全局面（插件管理等）注册为 main 面板；右栏 ui-sidebar-right 每会话一个 docking surface（push/fullscreen 两种呈现）。
- **传输**：POST JSON RPC（/api）+ WS 多路复用流（`/api/remote.mux`，ping/pong 心跳）；ConnectionController generation 循环 + 指数退避 + network online/offline 感知 + 手动 reconnect。
- **会话流**：session-controller 目录（host 目录 + 显式 retain）+ 每会话 journal follow；恢复 = snapshot-first 开窗 + ordered baseline 合并 + `loadOlder/loadThrough` 回翻；断线保留旧投影、重连替换；列表/新建在 ui-sidebar（按 workspace 优先级），切换即换 scoped 会话绑定。
- **消息链路**：composer SubmitMachine 纯状态机（busy-Enter→queue/steer 决议）→ `session.beginSubmission()` 本地回显（requestId 去重）→ `session.prompt()` RPC → journal append（user/message）+ assistant-stream 帧 → store 投影 → ui-chat 节点渲染 → 工具调用经 conversation 注册表派发 ui-tool 键槽卡。
- **审批/提问**：host 以 waterfall Remote 事件（`approval/request`、`user-questions/request`）前转 → client 按会话 owner scope 消费 → `registerPendingInteraction` → composer 接管卡（ApprovalPanel）→ 应答经 listener 返回值回传 host；无人应答 `next()` 委托/降级 'unavailable'。
- **steer**：提交模式决议为 'steer' 时打断当前 turn；队列项可升级为 steer；关闭窗口的 steer 由 AgentLoop 落回 queue。
- **其他流**：斜杠命令三类（popupSelect/action/execute）+ 逐会话目录；compact 以折叠标记呈现（不替换被阴影行）；子代理 ui-subagent 父头目录导航 + 只读执行记录可续跑；ui-trajectory turn-aware 台账。
- **多会话**：中央单焦点 + host 并行多会话（running 徽标 / completionUnread）——「并行运行、单焦点呈现」；右栏 dock 每会话独立 surface，子代理各自续跑。
- headless `--json`：durable 事件的有序投影流（仅提交点内容，8KB/串、32KB/事件上限，terminal `final`）；ACP：会话 create/list/resume/close + MCP attach + 模型选项 + prompt/cancel + 语义更新流 + permission 应答的 stdio JSON-RPC。
