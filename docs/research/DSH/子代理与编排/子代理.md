# 子代理（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 04（T-08）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；编排见 [任务编排.md](任务编排.md)。

## 机制全貌

核心是 cordis 服务 `SubagentRuntime`（挂为 `ctx.subagents`，subagent/src/index.ts:198）：一个**命名 provider 注册表**+能力校验的启动门面。spawn-in-process、fork-in-process、acp 等后端各自 `registerProvider`（index.ts:544）注册，事件 `subagent/provider-added/removed` 驱动工具的挂/卸（tool-subagent/src/index.ts:580-594）。两后端本质差异只在**种子**：spawn 全新子 Agent——自有 session、自有系统提示、零父上下文（spawn-in-process/src/index.ts:49-59）；fork 以父日志「最后一个 turn/end（含）」为前缀做种子，进行中回合不可回放（fork-in-process/src/index.ts:48-55），无已完成回合则退化为 fresh（:81）。子会话持久化 lineage/depth/delegationDepth（child-agent.ts:139-157），审计靠作用域化事件 `subagent/start`/`end`（index.ts:163-172）与三个 session projection。工具面：`subagent`（委托，tool-subagent）、`send_message`/`interrupt_agent`（tool-subagent-control/src/index.ts:28/76）、`list_agents`（list-agents.ts:92）；另有仅存编译产物的 `report`（见边界）。

## 关键流程

① **spawn/one-shot**：工具 execute 组装 request（label=description、prompt 文本块、parent、persona/toolFilter/maxDepth，tool-subagent/src/index.ts:515-524）→ `subagents.start`（index.ts:591）做能力断言（agentOptions/outputSchema/depthLimit/toolFilter/persona，:676-692）→ `startInProcessRun`（in-process-driver/src/index.ts:96）：resolveChildDepth（child-agent.ts:50-59，超限抛 SubagentDepthError）→ 首个 await 前捕获策略快照 → 建子 Agent、首 turn 内追加 descriptor → 结果按 stopReason 映射（completed/aborted/error/max-tokens/refusal，tool-subagent:157-174），非 completed 连同 partial output 回流父会话；前台用完即 dispose（settleForegroundRun:208-238）。后台 one-shot 走 jobs 返回 jobId；continuable 模式 `startContinuable`（continuation.ts:96-176）在 inbox 受理即返回 durable childId，**settled 时由运行时向父推 settlement notice**（含结果与最终 assistant 消息，tool-subagent:387、continuation-messages.ts:135）。

② **fork**：`completedTurnPrefix` 用 `findLast(turn/end)` 切点，seq=数组下标保证种子从 0 连续；continuable 的种子**创建时一次性固化**进子转录，冷恢复重放前缀而非重新 fork（fork:85-91）。

③ **send_message/interrupt**：sendMessage 校验「精确活体 sender」，住民子可发直接父，否则仅限直接 continuable 子、缺失子冷恢复；running 目标走 steer（最近步界注入），idle 起 turn（continuation.ts:194-232，continuation-activation.ts ChildLock:152 串行化）。interrupt 为 fire-and-return：先验权（user 按父 header、ancestor 按 WeakSet 活体祖先，:283-326）再 `cancel({keepInbox:true})`，返回时目标可能仍在跑；已消失/已完成是 no-op；竞态窗口由 `inbox.closing` 检查+per-child 锁收窄。

④ **回收**：前台 run 由工具 dispose；目录写失败则弃 run（index.ts:604-619）；registry 在 ctx 卸载时先 drain 再放 scope（continuation-activation.ts:216-225），父 dispose 触发 `drainContinuableDescendants` 子优先释放（index.ts:343）；容量由 ActivationPool 共享槽位管理（:41-57）。

## 接口与参数要点

- `subagent` 工具：`description`（3-5 词展示标签）、`prompt`（必填；文案随 provider 的 inheritsParentContext 切换：fork 版明说「已见已完成回合，只写增量」，spawn 版要求自包含，tool-subagent:252-277）、可选 `provider/model/reasoning_effort`、`run_in_background`（默认随模式：one-shot 前台、continuable 后台，:288-306）。
- control 工具：`send_message{agent_id,message}`（仅回执不回答案）、`interrupt_agent{agent_id}`（接受≠静止）、`list_agents{scope?:children|descendants}`（one-shot 子被隐藏，深层条目只可 interrupt，list-agents.ts:77/106）。
- 默认：`maxDepth=1`、`maxActiveSubagents=8`（subagent/src/index.ts:194/201，settings 可调）；`maxDepth:'provider-managed'` 时 `resolveMaxDepth` 返回 undefined 不传 cap（index.ts:248-251）。
- 后端注册 API：`ctx.subagents.registerProvider(provider)`（effect 域，HMR 安全，index.ts:544）；provider 声明 `capabilities` 与 `inheritsParentContext`。

## 边界与坑

- **fork 只支持活会话**：种子来自 `parent.session.snapshotEvents()` 的内存日志，且切点不得落在开 turn（无 turn/end 即空种子）。
- **depth=provider-managed**：仅适用于递归预算归子运行时的进程外 provider；数值 cap 挂载时强制要求 provider 有 depthLimit 能力，否则 fail loud（tool-subagent:330-335）。超限不隐藏工具——「运行时策略负责拒绝」（:97-99）。
- **report 未核实**：tool-subagent-report 仅有 lib 编译产物，其调用的 `ctx.subagents.reportFrom` 只存在于 subagent/lib/types/*.d.ts，src 无实现——属未合入/前瞻产物。
- 嵌套由 depth 账本禁止（默认 1）；子权限在委托时刻固化（approval 钉 'never'，child-agent.ts:246-253），并注入「不可扩权」声明（SUBAGENT_DELEGATION_CONTEXT，:172-218）。
- 双 one-shot 同名 toolName 的晚挂载碰撞是已知 TODO（tool-subagent:575-579）。

## 对 duo 的启示

- **fork 形态**：DSH 的 fork=父已完成回合前缀一次性固化，且工具描述随 inheritsParentContext 自动换文案（父见历史/子自包含）。duo 若做 fork，切点约束（不落开 turn）与「种子固化防冷恢复再 fork」两点可直接借鉴；withSkills/withAgentsMd 类 opt-in 在 DSH 对应 persona/toolFilter 的 scoped shadowing，做法是子创建窗内 `applyChildComposition`（child-agent.ts:200-218）。
- **多活跃并发**：DSH 用 maxActiveSubagents=8 的共享池 reserve/拒绝（continuation-activation.ts:45-56），达上限对模型抛 ACTIVATION_LIMIT_REACHED 等待语义，**不做摘要回流**；duo「达上限回流摘要」是更强的产品化选择，但可借其「父链共享槽位」定义何为一棵树。
- **控制面对位**：duo 的后台治理可对位三件套——`send_message`（steer/起 turn 双投递+邻接校验）、`interrupt_agent`（仅停当前 turn、队列保留、火后即返）、`list_agents`（running/idle/ready 三态与诊断行）；再补 settlement notice（run 结束运行时主动推父），即可覆盖 duo「同步等待不做」前提下的闭环。
