# 任务编排 workflow（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 05（T-09）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；子代理域见 [子代理.md](子代理.md)。

## 机制全貌

DSH 的编排 = 模型写 JS 脚本、引擎跑在 PTC 子进程里、`agent()` 落到 subagent 域。分层：① seam 包 `packages/workflow/workflow/src/index.ts:157` 定义抽象 `WorkflowEngine`（挂 `ctx.workflowEngine`）与 6 个 `workflow/*` 事件（start/phase/log/agent-start/agent-end/end，index.ts:43-89）；② 实现包 workflow-ptc：`PtcWorkflowEngine`（`workflow-ptc/src/index.ts:102`）注入 `['subagents','ptcRuntime','sandboxPolicy']`，强制要求 Node TS 版 PTC 运行时（index.ts:117）；③ 工具入口 tool-workflow/tool-ralph 只管模型面。执行形态（`workflow-ptc/src/host.ts:26`）：宿主把 guest 代码（生成产物 `guest-source.ts:1`，含 runtime.ts/guest.ts/realm.ts 打包）以 data: URL 塞进 PTC 程序，在子进程 `node:vm` context 中跑 `WorkflowExecution`。脚本宿主 API 仅 6 个：`agent/parallel/pipeline/phase/log/args`（`runtime.ts:85-93`，冻结函数）。子代理经 `ctx.subagents.start(provider,{prompt,parent,signal,outputSchema,agentOptions})` 发布（`host.ts:200-211`）。与 PTC run_code 同源：二者共用 `ctx.ptcRuntime`，run_code（`core/tools/src/ptc.ts:23`）绑定工具注册表，workflow 只换了一组 `workflowHost` 绑定（host.ts:276-283）。code-runtime（`packages/code-runtime`）是另一条 seam（CodeRuntime，worker_threads 后端，见 lib/types/index.d.ts），workflow 不依赖它。

## 关键流程

① **工具调用**（`tool-workflow/src/index.ts:271-329`）：入参 script/meta/args → `ctx.workflowEngine.start()`；start 先 `validateMeta`（meta.ts:23，name/description 必填、拒绝未知字段）+ 宿主侧 vm 仅解析不执行，并禁止 `export const meta`（index.ts:48-64）；`run.result` 永不 reject，非 completed 映射 isError（:303-307），finally 必 `dispose()`；recorder 把 agent-start/end 投影成会话 `tool-workflow/*` 事件（:94-115）。

② **agent()**（runtime.ts:163-229）：prompt 非空→总帽检查（:168，AGENT_CAP 致命）→FIFO 并发槽（:143）→host `startChild`→subagents.start；child 正常结束但有 schema 而 structured 缺失→null（:211），非 completed→null（:222）；只有基础设施拒绝升级为致命 AGENT_RESULT（:205）——即「脚本得 null」语义，脚本侧 `.filter(Boolean)`。

③ **上限执行点**：`maxConcurrentAgents` 槽在 guest runtime.ts:144；`maxTotalAgents` 在 runtime.ts:168（请求值≤引擎帽，index.ts:82-94）；`maxItemsPerCall` 在 `assertItemCap`（runtime.ts:342）；`syncTimeoutMs` 是 vm 首个同步切片超时（runtime.ts:107）；引擎级 `timeoutMs:null`（host.ts:281，无墙钟帽，取消只靠 signal）。

④ **ralph**（`tool-ralph/src/index.ts:88` 固定脚本）：每轮起一个全新结构化子代理，report{status continue/complete/blocked, summary, evidence, nextSteps, blocker}，轮间只传序列化后的 `previous` 交接（受 maxHandoffChars 限制），工作区=长期记忆；`maxTotalAgents=maxRounds`（:450），宿主再防御性校验 report（readReport :245）与终值（:281）。

⑤ **run_code**：绑定由工具注册表生成、子进程隔离（`ptc-runtime-node/src/launch.ts:24` bootstrap 经继承控制通道起 Node 子进程），与 workflow 共享同一 PtcRuntime 进程池与 JSON wire。

## 接口与参数要点

- 工具入参：`script`（纯 JS 体+顶层 await+return JSON）、`meta{name,description,whenToUse?,phases[{title,detail?,provider?,model?}]}`、`args`。
- `agent(prompt,opts?)` 仅支持 `label/phase/schema/provider/model`（runtime.ts:33），`effort/isolation/agentType` 显式拒绝（:35）；schema 只收 type/properties/required/additionalProperties/items/enum/const/oneOf 子集（无 pattern/format/数值界）。
- 默认值：provider `spawn`、`maxConcurrentAgents=0`→`min(16,max(1,cores-2))`、`maxTotalAgents=1000`、`maxItemsPerCall=4096`、`syncTimeoutMs=5000`（index.ts:105-111,141）；tool 侧 `maxResultChars=50000`；ralph `maxRounds=256`、handoff/result 各 `16384`（tool-ralph :33-38）。
- PTC 进程级：`timeoutMs=120000`、`maxTimeoutMs=600000`、`maxOutputBytes=64MiB`、`maxMessageBytes=128MiB`、`maxPendingCalls=128`、`graceMs=3000`（ptc-runtime-node/src/index.ts:55-61）。

## 边界与坑

- 脚本无文件/网络/定时器/Node API（工具描述：149 明示），vm context 为空对象无 require；syncTimeout 只覆盖首个同步切片，await 之后的异步段无超时，只能靠取消。
- progress 通道失败会把整次 run 判 error（guest.ts:69）；`agentsStarted` 在终止路径退化为宿主计数（types.ts:79-86）。
- 致命/普通错误纪律靠宿主 realm 的 `instanceof WorkflowError`（不可伪造，runtime.ts:300）；meta 必须走参数而非代码。
- 未核实项：`packages/workflow/workflow-worker-thread`（lib/worker.cjs 等）与 `packages/code-runtime`、tool-*/lib 均只有编译产物无 src，相关结论仅据 .d.ts/lib 反推。

## 对 duo 的启示

1. **引擎放子进程而非线程**：照抄「宿主进程 + Node 子进程 + JSON wire 控制通道 + vm context」形态，取消/清理归宿主、脚本只跑 vm——duo 现无任何编排能力，backlog 的 workflow/ralph 可直接以 DSH 为参照，且 guest 可做成自包含 bundle 由 data: URL 注入，免去产物分发。
2. **宿主 API 面最小集就 6 个**：`agent/parallel/pipeline/phase/log/args`，配四帽（并发/总量/单次条目/同步超时）+ 无 IO 的空 realm + 强制 JSON 返回值（materializeFromRealm 白名单原型链）；致命错误与 per-item null 的二分是脚手架可用性的关键。
3. **与子代理治理衔接**：`agent()` 直接落 ctx.subagents.start、父归属+signal 贯通+对象 JSON schema 子集做结构化输出；ralph 作为「固定脚本+数据入参」的特例跑在同一引擎上，模型只给 objective 不改循环——duo 引入时优先做引擎+ralph，模型自写 workflow 可后置。
