# 任务管理（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 06（T-10）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；后台任务与编排见 [子代理.md](子代理.md)、[任务编排.md](任务编排.md)。

## 机制全貌

四域各管一面，全部落在会话日志（事件溯源）+投影上：**todo**=轮内清单投影，`todo_write` 整表写 `todo/write` 事件，UI 从事件重放（packages/todo/tool-todo/src/index.ts:210,134）；**goal**=每会话至多一个持久目标，`goal/change` 事件+`goal` 投影，goal-round-driver 驱动同会话自动续跑（packages/goal/goal/src/domain.ts:66, types.ts:107）；**plan**=执行前审批态，`plan/mode` 事件折叠成 `{active,pending}` 投影，只改提示词不改工具目录（packages/plan/plan-mode/src/index.ts:47,15-17）；**jobs**=纯内存后台作业面（bash/subagent 两 kind），不落盘、随进程消亡（packages/jobs/jobs/src/types.ts:17-26）；**schedule**=会话内持久提醒，`schedule/change` 事件+到期定时器投递普通消息（packages/schedule/schedule/src/types.ts:213-219）。

## 关键流程

① **todo**：整表替换校验（非空、去重、默认单 in_progress，index.ts:91-111）→ append 事件 → 投影取最新表、下一 `turn/start` 清空（turn/end 保留完整清单供查看，index.ts:131-144）；重启后由日志重放恢复。

② **goal**：`GoalRef{id,revision}` 做 CAS，每次变更 revision+1，过期引用报 `GOAL_STALE_REVISION`（goal/src/types.ts:20-25, index.ts:456-465）；`roundsStarted` 由 goal 来源的 `user/message` 事件推进（index.ts:146-159）。driver 在 agent idle 且 armed 时保留下一轮：达 `maxGoalRounds` → block('round-limit') 停机；否则渲染 `<goal_round>` 提示经 `followup()` 入队，pre-step 双重校验防串轮（goal-round-driver/src/index.ts:164-204,360-425）；宿主 pause 会 cancel 运行中回合，模型自 pause 则正常收尾（index.ts:288-291）。重启/加载后默认 disarm，人发 `/goal resume` 或模型 `update_goal resume` 重新武装（index.ts:429-432）。人侧 `/goal [<objective>|clear|edit|pause|resume]`，complete 态可重建（command-goal/src/index.ts:16,144-159）。

③ **plan-mode**：`/plan [message]` 进入（steer 附带消息）→ 模型探索 → `exit_plan_mode{plan}`（须 # 开头）触发 Approve/Keep planning 用户问询 → 打回则报错带回反馈继续规划，批准则挂 pending intent，在下一个被接受的 in-turn pre-step 落 `plan/mode{active:false}`（plan-mode/src/index.ts:289-348,414-449）。未决选择不落盘会随进程丢，但已提交态在投影里、resume/fork 存活（index.ts:132-164）。

④ **jobs**：bash `run_in_background:true` → `jobs.start({kind:'bash'})` 得 `bash-N` id（shell/tool-bash/src/index.ts:348-365）；`job_output`（`wait:true` 阻塞至终态或超时，超时返回 running 不报错）、`job_list`、`job_kill`（请求取消→stopping→killed）；`read` 消费游标读取增量（jobs-local/src/index.ts:205-228）。完成通知 first-wins（settle 只记首个终态，index.ts:416-440），owner idle 时 `followup` 开新回合（wake），busy 时 `inject` 进本回合收尾；每人连续 wake 预算 3 次，用户消息 claim 即重置（tool-jobs/src/index.ts:278-299,223-229）。

⑤ **schedule**：三规则 after_seconds/at/every_seconds（≥300s，domain.ts:25）；到期判定取最早到期 one-shot 或整批 every（runtime.ts:35-69），经 `runMaintenance` 空闲投递 `[SCHEDULE REMINDER]` 防注入框架消息（domain.ts:806-814），随后 append `dispatch` 事件推进/删除记录；timer 上限 2^31-1 分段唤醒（runtime.ts:22,179）。每次驱动前后 `sessions.flush` 持久化屏障，重启由 JSONL 重放恢复（persistence.ts:22-31）。

## 接口与参数要点

- todo_write：`todos[{content,status}]`，`allowParallelInProgress` 部署必选。
- goal 工具：`get_goal()`/`create_goal{objective,max_goal_rounds?}`/`update_goal{goal_id,revision,action:edit|pause|resume|complete|blocked,...}`；`defaultMaxGoalRounds=256`（goal/src/index.ts:244），`blockedAfterConsecutiveRounds=3`（tool-goal/src/index.ts:32）；blocked 须在 ≥3 轮后且必带 reason。
- jobs：`waitTimeoutMs=30s`、`maxWaitTimeoutMs=600s`、`maxConsecutiveWakes=3`、`completionDelivery=wakeup`、每 owner 并发 10（tool-jobs/src/index.ts:48-51；jobs-local/src/index.ts:28）。
- schedule：`schedule_create{prompt, after_seconds|at|every_seconds 三选一}`、`schedule_list`、`schedule_delete{id}`。

## 边界与坑

- plan 只注入引导段，沙箱/审批策略独立、不读 plan 态（plan-mode/src/index.ts:3-7），无硬禁工具。
- goal 只记账不跨进程调度——activation 进程本地不持久，resume/fork 后必 disarm；模型不能 resume paused 目标（tool-goal/src/index.ts:280-285）；paused 后取消的回合被围栏钉到精确 revision 防误再暂停（goal-round-driver/src/index.ts:263-278）。
- jobs 通知 first-wins、teardown 一律标 reported 防每层 teardown 烧一次模型请求（jobs-local/src/index.ts:507-531）；jobs 不跨重启。
- schedule 严格 session-local：原会话不 live 就不投递（types.ts:111），出 session 不可见。

## 对 duo 的启示

duo 现状=M17 todo_write 分解抓手、无 goal/schedule、后台任务无 job 面（M23 候选）。对照三条：

1. **goal 的 CAS（GoalRef revision）+轮上限 256+轮内 authority**（complete/blocked 仅限 goal-round 或真人回合，tool-goal/src/authority.ts:100-118）是「持久目标+自动续跑」的成熟形态，M23+ 若做自主长任务可直接平移。
2. **schedule 的最小实现**=会话日志存规则事件+空闲时 followup 投递防注入框架消息，成本低、不引跨会话调度。
3. **jobs 的 `wait/kill/output` 三工具+完成通知 wakeup 预算限流**，正是 duo M23 后台任务缺的模型侧接口面，且 bash `run_in_background` 返 job id 的接缝已在 DSH 验证。
