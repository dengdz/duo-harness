## 功能一句话

DSH 拥有完整的 OS 沙箱子系统：`SandboxProvider` seam + 四平台方言链（bwrap / Landlock / Seatbelt / Windows 受限令牌）+ fail-closed（沙箱缺席即拒绝执行、无 unconfined 回落）+ 沙箱内命令免审批、仅升级时审批。它是 duo 曾规划 M22 沙箱实现时的头号实现参照。

## 架构：confine = spawn 前的 argv 前缀替换

沙箱介入点在**进程创建之前**：`ctx.sandbox.confine(argv, policy)` 把「runner 可执行文件 + profile 参数 + `--` + 原命令 argv」的包裹结果交回，执行器照常 spawn 包裹后的 argv——进程创建层零注入、无 fork 级钩子。

| 包 | 职责 |
|---|---|
| `packages/sandbox/sandbox` | seam：`SandboxMode`（`read-only` / `workspace-write` / `danger-full-access`）、`confine()` 抽象（`src/index.ts:176`）、`ConfinedArgv`、`writableRoots`（`src/roots.ts`）、升级词汇与编排（`src/escalation.ts`）、拒绝分类（`src/diagnostics.ts`） |
| `packages/sandbox/sandbox-local` | 平台 runner 链选择、探测、profile 构造（`src/profiles.ts`、`src/index.ts`） |

## 可写范围：writableRoots 是「档位含义的唯一家」

`packages/sandbox/sandbox/src/roots.ts:52`：`workspace-write` 的可写集 = **workspace 根 + `/tmp` + `os.tmpdir()`**（各自 `realpathSync.native` canonical 化——darwin 上 `/tmp` 就是 `/private/tmp`，按字面授权会匹配不到；解析失败原样返回，缺失根保守地匹配不到任何路径），去重。`read-only` → 空集。

该模块注释把设计意图说得很直白：Seatbelt profile 与进程内 fs fence **共用这一份推导**，使「write 工具不能写 /tmp 而 bash 能」的漂移无从产生；bwrap / Landlock 各按自己的方言拼法表达，**parity 靠测试钉住**。

值得注意的负空间：**没有 extra 可写路径配置**——`~/.m2`、`~/.npm` 等构建缓存在 `workspace-write` 档下一律拒绝，模型撞墙后的正路是升级审批。

## 四方言要点

- **Seatbelt（darwin 唯一候选，选中不探测）**：`sandbox-exec -p` 内联 SBPL（`sandbox-local/src/profiles.ts:51`）——`(version 1)(allow default)(deny file-write*)(allow file-write* (literal "/dev/null"))`，再对每个可写根追加 `(allow file-write* (subpath "…"))`。profile 只碰 `file-write*`，**网络不限制**。探测 = `sandbox-exec -p <profile> -- true`，退出 0 即可用（`sandbox-local/src/index.ts:85`）；Apple 已弃用该 CLI，注释明示若消失即 unusable（fail-closed）。
- **Landlock（linux 链第二位）**：外部 C11 启动器 `landlock-run`（`native/system/packages/entry/src/main.c`，298 行，仅依赖 libc，静态 musl 编译，per-platform npm 预编译包分发）——**self-restrict-then-exec**：裸 syscall 444/445/446、按 ABI（1/2/3/5）缩放 handled-access 掩码（`fs_mask_for_abi`，`main.c:185`）、`--ro` 授权只给 read+execute、`prctl(PR_SET_NO_NEW_PRIVS)` 后 `landlock_restrict_self` 再 `execvp`（`restrict_self`，`main.c:230`）。ENOSYS/EOPNOTSUPP 直接退出不 exec（fail-closed）；`--probe` 模式输出 `fully enforced` / `partially enforced (older ABI)`——旧 ABI 是全系统唯一「继续用但报 partial」的情形。JS 契约侧（`native/landlock-run/packages/entry/lib/index.js`）：launcher 路径从平台包解析、**禁止环境变量覆盖**（`:12-15`，防 ambient env 决定哪个二进制来做限制）、launcher 失败退出码约定 125。
- **bwrap（linux 链第一位）**：`--ro-bind / / --dev /dev --unshare-pid --proc /proc --die-with-parent`，workspace-write 追加 `--tmpfs /tmp --bind ws ws`（`profiles.ts:16`）。
- **Windows 受限令牌**：WRITE_RESTRICTED 令牌 + workspace 写 SID 白名单 + `CreateProcessAsUserW`，固有 `partial`（Everyone 必须留在 restricting list）。

链选择：`PLATFORM_CHAINS = { linux: ['bwrap','landlock'], darwin: ['seatbelt'], win32: ['windows-acl'] }`（`sandbox-local/src/index.ts:159`）；单候选免探测直接选中，多候选按序功能探测仲裁；`runnerCommand` 配置覆盖 = operator 断言 full enforcement、跳过探测（`:320`）。

## 失败与拒绝语义：fail-closed，没有 unconfined 回落

- 平台无链或候选全 unusable → `SandboxUnavailableError`（code `SANDBOX_UNAVAILABLE`），命令**拒绝执行**，不回落裸跑（`sandbox-local/src/index.ts:497`）。
- runner 启动失败归类为不可用（runner 失败 > 拒绝分类——命令根本没跑成）；命令跑了但被内核拒 → 按 `DENIAL_SIGNATURES`（`index.ts:205`）分类，结果带 `sandbox: {mode, denied, enforcement}` 戳（`bash-sandbox/src/index.ts:117-127`）。
- 模型面统一 marker：`[sandbox: file access denied under <mode> mode]` + 同轮升级提示（`escalation.ts:71`，两个执行族共享同一词汇）。
- 事故复盘 `docs/postmortem/0004`：Landlock partial 通知曾被误分类为子进程失败——runner 输出分类是需要独立测试的细节坑。

## 审批联动：双旋钮正交，沙箱内免审批

- 两个正交旋钮：`SandboxMode`（文件效果）× `ApprovalPolicy`（`ask` / `never`，**无 always**；`user-approval/src/index.ts:60`）。用户面预设 = 旋钮打包：`read-only`+ask / `workspace-write`+ask / `danger-full-access`+never（`permission-presets/src/index.ts:185`）；出厂缺省 `workspace-write`（schema 缺省是 `read-only` 的 fail-safe，bundle 盖掉；env `DSH_PERMISSION_MODE` 可改）。
- **沙箱内命令免审批**：confined bash 直接执行，预设里的 `ask` 只作用于升级请求；`danger-full-access` 完全绕过 confine 也不审批（`bash-sandbox/src/index.ts:92`）。
- **升级 = 被拒后的一次性重试**：工具 schema 仅在执行器 confining 时才登 `sandbox_permissions`（enum = `ESCALATION_TARGETS`）与 `justification` 两参数（`tool-bash/src/index.ts:258`，描述明写 "Only valid as a one-shot retry of a command the sandbox just denied"）；两参数成对校验、justification 非空句（`escalation.ts:51`）；目标档必须在 `WIDER_MODES` 严格更宽阶梯内（read-only→[ww, dfa]；ww→[dfa]，`escalation.ts:28`）；审批经 `ctx.approval` 通道，执行前完成；approval=never 时确定性拒绝并告知模型勿再设该参数。
- 执行器不带沙箱能力（裸 `LocalBashExecutor` 组合）时，permission-presets **拒绝挂载**（`permission-presets/src/index.ts:214`）——预设功能整体 fail-closed。
- 会话事件 `sandbox/mode`、`approval/policy`、`permission/preset` 均 log-only 投影态。

## e2b 的定位

`packages/e2b/{e2b, fs-e2b, subprocess-e2b}` 是 E2B 云 microVM 的**远程 fs/subprocess 适配器**：替换整个能力 seam（命令不在本机跑），而非本地 OS 沙箱的一种方言。

## 测试形态

真实内核 e2e + probe 自跳过：`bash-sandbox/tests/` 三套（landlock / bwrap / seatbelt，`describe.skipIf(!usable)`，断言文件世界效果 + 结果戳）；partial-landlock 与 runner 失败分类的快照与单测；Windows FFI 层注入绑定跑纯逻辑；CLI e2e 覆盖 escalation 审批链路。

## 对 duo 的启示

1. Seatbelt 路对 duo 成本最低：`sandbox-exec -p` 外部命令包裹与 Java `ProcessBuilder` 同构、零新依赖；SBPL profile 与 `WorkspacePolicy` canonical 语义可对齐（`realpath` 等价物）。
2. Landlock 路的重量级证词：连 TS 生态都绕开 FFI 用独立 C 启动器 + 预编译分发——duo 零 native 红线下该路的成本画像由此坐实。
3. fail-closed（缺席即拒跑）与升级词汇（`WIDER_MODES` 阶梯、一次性重试、`justification` 必带）是成熟设计，若 duo 未来重启沙箱可整体借用。
4. `writableRoots` 单一推导家 + 无 extra 配置——极简但构建缓存场景靠升级审批救济。

- 审批无 `always` 档；bash 无 per-command 路径白名单（`tool-bash/src/index.ts:6` 注记 `TODO(permissions): deployment policy belongs in tools/pre-execute`）。
