# 系统提示与上下文工程（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 10（T-14）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；压缩治理见 [压缩治理.md](压缩治理.md)。

## 机制全貌

DSH 是两层上下文模型：`packages/core/system-prompt` 是注册表（section→system 消息；context→持久 user 角色快照），`packages/context/*` 是无工具型注入插件。section/context/variable/tool 均分全局层+agent 作用域层，scoped 遮蔽同名全局项；内置位由中心位表分配（index.ts:125-169）。context 插件：agent-instructions（dsh-base 默认含，可被 profile patch 禁用）、session-reference、file-reference(-local)、time-context、tmux-context，其余需主动启用（context/README.zh.md）。注入的指令与引用以 user 消息进历史，「持久、可回放、可压缩」。AGENTS.md：候选 AGENTS.md/CLAUDE.md + 本地覆盖 AGENTS.local.md/CLAUDE.local.md（config.ts:12-13），外加 $DSH_HOME/AGENTS.md 全局文件（render.ts:98）。

## 关键流程

① **装配**：`assemble()` 合并 scoped 遮蔽全局→按 order 升序、同序按名称 code-unit 排序→求值 text 提供方→跑 `system-prompt/assemble` waterfall→complete section 在 waterfall 后恢复为唯一提示词（index.ts:559-635）；`renderPrompt()` 严格插值 `{{var}}`（280-363），变量由 agent-loop 注册 provider/model/cwd（agent-loop/src/index.ts:422-424）。运行时 context 渲染为带 `source:{kind:'plugin',form:'snapshot',sections}` 的 user 快照，头部声明「本快照取代更早快照」（runtime-context.ts:147-158；index.ts:304-308）。

② **AGENTS.md**：项目根按 `.git` 标记自 cwd 上溯（files.ts:181-196），user-global→root→cwd 链逐目录加载（272-314）；单文件超 `maxSourceBytes`（默认 1MiB，config.ts:14）直接忽略（files.ts:344）；渲染预算 `maxBytes`（必填）确定性降级：整体→丢最宽→二分截断最具体文件（render.ts:275-332），成文包 `<system-reminder>` 帧（242），以 `source:{kind:'agent-instructions',baseline:true}` user 消息折入 claimed 批次之后（index.ts:177-186,338-340）；read/write/edit 触碰文件后增量调和进 inbox（74,343-359）。

③ **@file**：DSH 只注入路径不注入内容——FILE_REFERENCE_PROMPT 明示「@ 是用户引用的路径…需要内容时用 read 工具」（file-reference/src/index.ts:17）；文法 `@path`/`@"含空格"`（grammar.ts:26-55）；section 挂 FILE_REFERENCE=900 位，read 工具缺席时输出空文本（file-reference-local/src/index.ts:70-74）。64KiB/上下文窗口 20% 预算与 spill 截断属于 session-reference 而非 @file。

④ **session-reference**：提及解析→读快照→按预算保留（单源默认 64KiB 或 `max(64KiB, contextWindow×4×0.2)`，index.ts:368-385；config.ts:4-8，每消息≤3 源），JSON 包 `<referenced-sessions>` + 不可信声明（index.ts:58-65），快照消息紧跟引用它的消息（154-178）；截断时经 spillStore 存全量转录（spill.ts:23-50）。

⑤ **time-context**：prepend 的 pre-step 监听（index.ts:181-221），`refreshIntervalMs` 节流（189-194），追加带 `source:{kind:'plugin',plugin:'time-context'}` 的 user 消息。

## 接口与参数要点

- API：`section()`/`context()`/`variable()`/`tools()`/`suppressRuntimeContext()`（index.ts:455/490/538/522/507）。
- 配置：includeHarnessIdentity=true、includeRuntimeContext=true、personaPrefix/personaSuffix=''、toolOrder（248-269）；agent-instructions：maxBytes 必填、maxSourceBytes=1MiB、rootMarkers=['.git']；session-reference：maxReferences=3、candidateLimit=50、referenceContextFraction=0.2；time-context：timeZone、refreshIntervalMs（0/省略=每步注入）。

## 边界与坑

- 插值失败即抛：格式错误组、未注册名、已注册无值（index.ts:339,353,357），不发送畸形提示词；多个 complete section 使 assemble 失败，且 waterfall 监听器无法增删它（597-599,26-27）。
- 注入内容是持久 user 消息——可重放、可压缩，但也意味着重复注入需自行去重（agent-instructions syncInbox、time-context 投影态）。
- 单文件超 1MiB 是「忽略」而非截断，且无聚合预算（TODO，files.ts:340-342）；`includeRuntimeContext:false`/suppressor 清空全部动态快照（629-634）。
- KV cache 以渲染逐字节稳定为前提。

## 对 duo 的启示

duo 现状：M7 AGENTS.md 最小链（全局+项目根、64KB）、M21 @file 零内容注入（system 指南+模型自 read）、prompt 注册表仅静态片段。对照三条：

1. **order 中心位表**：DSH 用具名常量表+`getSectionOrder()` 集中分配内置位，外部插件任意有限值即可插入，避免片段间 order 冲突——duo 注册表可预留具名槽位。
2. **注入以带 source 的 user 消息入日志**：结构化归因（kind/plugin/sections）使历史可回放、可压缩、UI 可归属；duo 注入 AGENTS.md/@file 内容时可附带 source 元数据而非裸文本。
3. **动态 context 的节奏控制**：time-context 的 refreshIntervalMs 节流+「本快照取代早前快照」语义是注入易变事实（时间等）的成熟范式；duo 若引入动态上下文应同帧具备节流与取代声明，否则污染 KV 前缀。
