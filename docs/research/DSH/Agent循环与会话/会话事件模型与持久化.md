# 会话事件模型与持久化（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑第 4 批产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；循环语义见 [Agent循环与状态机.md](Agent循环与状态机.md)。

## 机制全貌

三层：`core/session` 内存事件日志 → `session-persistence` 后端无关 seam → `session-persistence-jsonl` 磁盘后端。`Session` 是类型化事件的仅追加日志（`packages/core/session/src/index.ts:446`），持久化是插件关注点：监听 `session/event` 复制事件、`session/flush` 做等待式持久屏障（index.ts:72,81）。seam 定义抽象 `SessionPersistence` 服务与 `SessionHandle`（`packages/session/session-persistence/src/index.ts:135`），JSONL 后端把每个会话存为 `<root>/--cwd--/<id>/session.v3.jsonl[.zstd]`（`session-persistence-jsonl/src/format.ts:57`）。完整路径：append 快照冻结 → log.push → 包容式派发 session/event → 后端路由进句柄缓冲 → 固定批窗排空 → 写文件+fsync。

## 关键流程

① **append**：`snapshotJsonValue` 单遍读取+校验+复制，防有状态 getter 两面值（index.ts:729）；seq=log.length（:743）；重入直接抛（:738）；`surfaceManager.validateNext` 先规划后入栈，失败不半改（:749,584）；监听器快照在 push 前解析、push 后调用，观察者异常逐个容纳不影响提交（:756-762）。`store.flush()` 并行等待所有监听器、全部结算后抛首个失败（:1177）。

② **创建**：`create`=`prepare`+`enter`+`announce` 折入单个 effect（:969-980）。prepare 校验 id/cwd 并构造 header（:1001）；enter 安装发布钩子、复查同 id、返回 detach disposer（:1068）；announce 先置 announced 再派发 `session/created`，同步抛出否决创建并经 detach 回滚（:1123-1131）。

③ **fork**：要求源是 store 内活实例（SESSION_NOT_LIVE）、boundary 是已存在连续 seq（INVALID_BOUNDARY）、前缀不得停在开放 turn（findLast turn/start 未闭合→OPEN_TURN，:1287-1294）；seed 复制、`inheritedEventCount=seed.length`、header 标 isSeeded/parentSession，子会话构造器在切点追加 `session/end-seed{inherited:true}` 标记（:615-619）。`firstLiveSeq`（本进程构造边界）与 inheritedEventCount（持久 fork 切点）是两个不同概念（:474-497）。

④ **jsonl 文件协议**：延迟实体化——create 零磁盘写入；首次 append 走 temp(wx)+fsync→`link()` 发布（不用 rename，EEXIST 防同 id 竞态互踩）→逐级目录 fsync（index.ts:1097-1157）；后续批次 append+fsync，写/同步失败截回原长度再抛（:1246-1284）。zstd：每批次一个带校验和独立帧，`scanZstdFrames` 纯结构扫描定位撕裂尾帧起点（`zstd.ts:48`），`ZSTD_e_flush` 前缀解码抢救完整记录（:154），scanner 以 committedBytes 给出安全截断偏移（`format.ts:448-473`），写路径下次 append 前先截断+持久重写恢复事件（`storage.ts:326-341`）；完整帧校验失败=损坏拒绝。跨进程写互斥：`session.lock` 非阻塞 flock(2)，Windows 用命名信号量（`lease.ts:40`）。

⑤ **迁移链**：`SESSION_FORMAT_VERSION=3`（`core/session/src/types.ts:88`）；chain 强制相邻 vN→vN+1、完整无重复（`session-format/src/chain.ts:50-77`）；读路径先按首行 version 分类，外来版本在结构校验前拒绝为「请升级 harness」而非「损坏」（`format.ts:339`）；读 open 单遍解码+迁移+校验不发布；写 open 准备→分片编码同目录 temp→Worker 校验→复查源 revision→link 独占发布后继（`generation.ts:814-940`），旧 generation 文件逐字节保留。

## 接口与参数要点

- 事件词表 `SessionEventMap` 可合并扩展；`KNOWN_SESSION_EVENT_TYPES` 生成式清单 57 项（`known-event-types.ts:22`）。
- 信封 `ignorable?: true` 是唯一兼容机制——未知非 ignorable 类型读端 fail-closed（:11-20）。
- surface 事件（system/user/assistant message、tool/result）必须带 `surfaceOp`+`sourceEventSeqs`，replace 仅接受 `{startSeq,endSeq}`；TS 层面 opts 参数仅对 SurfaceEventType 存在（index.ts:719-722）。
- 写柄单写者：`create`/`open(id,'write')` 进程内认领，二次写打开抛 `SessionAlreadyOwnedError`；读柄可共存。
- 配置仅 `root`（必填无默认）与 `compression:'zstd'|'none'`。

## 边界与坑

- append 重入禁止；载荷须无损 JSON（BigInt、-0、稀疏数组、异种原型在追加点拒绝）。
- 监听器失败被容纳但 `session/created` 同步抛仍否决；同 id 已有磁盘日志 loudly 拒绝物化「open it instead」（index.ts:1182）。
- 已退役 PTC 标签/`header.system` 即使在畸形行之后也整体拒文件，绝不当撕裂尾截断（`format.ts:488-495`）。
- append 尽力而为、只有 flush 是持久性承诺并实体化空会话；seed 事件不发 session/event；fork 只支持活会话稳定边界，不支持未加载的持久会话。

## 对 duo 的启示

duo 现状：`~/.duo/sessions/<id>.jsonl` 单文件，`FileChannel.tryLock` 双层互斥、append 后 `force(false)`（`duo-harness-session/.../Session.java:409`），CoW 快照发布。对照三条：

1. **撕裂恢复值得抄**——duo 崩溃后半行无处理也无校验和；DSH 仅靠「换行=已提交字节游标+截断重写」即可低成本获得崩溃安全，配合每批次 checksum 更稳。
2. **格式版本化**——duo 文件无版本头；学 DSH 首行 `{type:'session',version}` + 相邻迁移链，未来 schema 演进可升级而非作废。
3. **ignorable 标记**——duo 读端遇未知事件类型宜区分「带 ignorable 可跳过/无标记拒绝加载」，避免新旧版本互读出错误会话；`surfaceOp`/replace 的投影思路对 duo 后续做上下文压缩也有参考。
