# 投影、恢复与分页（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 01（T-05）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；循环语义见 [Agent循环与状态机.md](Agent循环与状态机.md)、持久化见 [会话事件模型与持久化.md](会话事件模型与持久化.md)。

## 机制全貌

DSH 把「会话派生状态」收敛到一个 merge-extensible 投影层：`SessionProjectionRegistry`（packages/session/session-projection/src/index.ts:199，下称 index.ts）订阅 `session/event`（index.ts:220），每条已提交事件驱动全部注册单元的纯折叠 `apply`，并维护每会话每单元的 watermark cell；载体经 `stateOf`/`snapshot` 同步读一致切面。`SessionProjectionCache`（packages/session/session-projection-cache/src/index.ts:92，下称 cache.ts）把各单元 checkpoint 落到 `session_projcache` 域（每会话一文档，cache.ts:105-109），为冷读提供「缓存种子+尾部重放」加速。会话读取链在 api 侧：客户端 `SessionEventStream extends RemoteJournalStream`（packages/api/session-controller/src/client/transport.ts:137；抽象在 packages/api/gateway/src/client/journal-stream.ts:90），journal 开窗快照自带 `projections` 基线（transport.ts:44-47）。标题 `title` 只是投影表里的一个 key（packages/session/session-title/src/index.ts:263-275，下称 title.ts），随同一套 wire/缓存/列表机制分发。

- 投影层=权威内存态；cache=可丢弃捷径，永远不领先日志。
- journal 流=事件窗口（cursor+page），与投影基线在 opening 快照合流。

## 关键流程

① **投影注册与推进**：`register` 是 effect（disposer 挂调用 fiber，index.ts:253-293）；`session/created`（seq=0）为各单元建 cell 并 init（index.ts:209-219）。`drive`（index.ts:657-704）：cell 已达该 seq 则跳过；缺 cell 惰性 buildCell 折历史；`apply` 同引用（Object.is）=零下游工作；仅 wire 结果引用变化才 view+notify。`stateOf`/`snapshot` 先 materializeCells 再读，`asOfSeq=cursorBefore(session.seq)`（空日志 -1，index.ts:177-179,319-352）；`cachedSnapshot` 只读已物化 cell（index.ts:362）。

② **checkpoint/restoreFloor/restore/hydrate**：`checkpoint` 输出每单元 `{ver,seq,val}`（structuredClone 分离拷贝，index.ts:396-407）。`restoreFloor` 取「最低可用行 watermark+1 再减一」的锚点（index.ts:425-435），使尾部重放能证伪缩短的日志；`restore` 行可用条件=ver 匹配且 `seq>=beforeBase` 且 `seq<=endSeq`（index.ts:510-513），不可用且 baseSeq>0 则 throw 要求从 seq 0 全量重读（index.ts:514-518）。cache 写点=创建/`turn/end`/disposed 强制+count/interval 节流（cache.ts:301-352），`write` 先 flush 日志再落盘（持久屏障，cache.ts:246-262）；coldSnapshot 失败软回写（cache.ts:277-296）；hydratePrepared 异常退化为全量 hydrate（cache.ts:230-234）。记录以 identity（formatVersion/createdAt/cwd/isSeeded/inheritedEventCount）绑定生命周期（cache.ts:395-443）。

③ **读取开窗**：首开 `open({maxMessages:50})`（session-controller/src/client/sessions/session.ts:602、51），snapshot-first：首帧 `opened{cursor,page}` 发布 replace（journal-stream.ts:289-303）；重连保留旧窗口，resumed cursor 落后即协议违规（journal-stream.ts:269-286）；entry 须 `follows(last,first)` 连续，出 gap 走 `replaceThrough` 拉页并合并排队 entry/通知（journal-stream.ts:305-395）。回翻：`loadOlder`→`prepend({beforeSeq:baseSeq,maxMessages:50})`（session.ts:391-407、journal-stream.ts:188-212，过滤重叠、断页抛违规）；`loadThrough` 循环翻页至覆盖目标 seq，带重定向与 no-progress 守卫（session.ts:410-453）。列表合并用 `mergeOrderedBaseline`（session-controller/src/client/ordered-baseline.ts:11-43）：既有相对序不动、baseline-only 按最近后继插入、消失 id 移除。

④ **标题链**：`user/message`→onUserMessage（title.ts:499-523）：user rename 钉住（不再自动生成）；满足 cadence（all-prompts 或首条）记 pending{throughSeq}；pending 等 `request/header` 事件拿到主请求 route（provider/model）才 startPending 提交（title.ts:526-536）。文本经 `normalizeSessionTitle`（去 OSC/CSI/ESC/控制/方向字符+UTF-8 字节截断，session-title/src/normalize.ts:57-60）后 append `session/title`；投影 apply=latest-wins（title.ts:268-270）；client rename 用响应 `{title,seq}` 高 seq 赢先落 cell（session.ts:357-363）。

## 接口与参数要点

- `ProjectionDefinition`（index.ts:48-93）：key / stateSchema（持久态校验）/ init(header,inheritedEventCount) / apply（纯同步、同引用免发布）/ wire{viewSchema,view}（可选客户端视图）/ stateVersion（序列化字段或折叠语义变化必 bump，非负整数）。
- checkpoint 行=`(sessionId,key,ver,seq,val)`；`asOfSeq` 为已反映的最后事件 seq，快照取全单元公共 watermark。
- checkpoint 存 `session_projcache` per-record 域；节流参数 `writeEveryEvents`/`writeIntervalMs`（cache.ts:63-73）+三个强制写点。
- journal 参数：首窗/上翻 50 条（PAGE_MESSAGES），跳转 200 条（JUMP_PAGE_MESSAGES，session.ts:51-54）。
- title 三限：fallbackMaxWords/fallbackMaxBytes/maxTitleBytes，且 fallbackMaxBytes≤maxTitleBytes（title.ts:297-323）。

## 边界与坑

- apply 对不关心的事件必须返回同一引用；object 值 wire view 也须复用引用，否则内部态变化误发布。
- 注册即 effect：插件卸载即 key 从快照消失，客户端读作能力缺失；同键共享按 refs 计数，且共享键必须同 stateVersion（index.ts:169-174,279-290）。
- checkpoint 行非权威：restore 行不可用且非全量重读直接 throw；缓存写失败 fail-soft 只损失回放长度；**先日志后缓存的次序保证缓存永不超前日志**。
- journal 断页/缺口修复不到位抛 protocolViolation；loadThrough 无进展即停，防空转。
- 缓存行按 identity 绑定生命周期，跨生命周期/换库的旧行一律拒用。

## 对 duo 的启示

duo 现状=M13 尾窗快照+向上分页、M10 SSE 游标回放、标题一次生成+改名。可转译：

1. **watermark 语义**：尾窗快照携带「截至 seq」水印，回放/推送按 higher-seq-wins 合并而非到达顺序，rename 等可像 DSH 一样用响应 seq 先行落定、后到推送变 no-op。
2. **checkpoint+尾部重放**：派生状态按 (ver,seq,val) 冷缓存，冷启动从 floor 锚点重放尾部；ver 不匹配或尾部证伪日志缩短时全量重读——避免每次冷启动全量折叠。
3. **回翻 ordered baseline 合并**：向上分页与实时 SSE 竞争时，用 mergeOrderedBaseline 语义（保持既有相对序、新 id 按最近后继插入、消失 id 移除）消除列表跳动；配合 gap 修复「替换整窗」而非增量缝补。
