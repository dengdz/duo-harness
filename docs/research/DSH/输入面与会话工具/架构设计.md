# DSH 输入面与会话工具架构设计

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-20 pull，release 0.1.6-alpha.2）。出处均为 DSH 仓库内路径。配套：[代码说明.md](代码说明.md)、[细节备忘.md](细节备忘.md)、[../核心功能全景.md](../核心功能全景.md)。

## 功能一句话

DSH 的输入面与会话工具 = **附件内容寻址库**（图片/文件、SHA-256 硬链接去重、永不删除）+ **read_image 多模态链路**（存储规范化 / 请求变体 / Files API 三层增强、非视觉模型三层降级）+ **@file 路径提及**（补全索引 + system 指南，零内容注入）+ **会话查询/导出**（FTS5"服务在、索引熄火" + /export ZIP 流式下载）。

## 核心类与接口

| 接口/类型 | 职责 | 出处 |
|---|---|---|
| `PromptContentPart` | wire 契约：`text \| {type:'image', mediaType, data(base64), name?}`——所有附件入口共用的形态 | `attachment/src/types.ts:100-107` |
| `AttachmentStore`（服务名 `attachments`） | `saveImage` / `admitEncodedImages` / `admitEncodedFile` / `readImageRequest`——准入后持久化、按需读请求变体 | `attachment/src/index.ts:46-50` |
| `LocalAttachmentStore` | 内容寻址实现：`objects/<2位>/<sha256>` 规范对象、0400 只读、硬链接去重、tmp 暂存 fsync | `attachment-local/src/store.ts` |
| `ImageReadValue` | read_image 结构化产物：`{path, image:{attachmentId, mediaType, bytes, w, h, name?}}` | `tool-fs/src/read-image.ts:84-100` |
| `FileReferenceService` | @file 补全候选：`activeAtToken` grammar + 工作区索引（路径 only，不读内容） | `file-reference/src/grammar.ts`、`file-reference-local/src/search.ts` |
| `SessionQueryService`（服务名 `sessionQuery`） | 检索 + exact reads + 标题 + lineage；`openAt` 三态控制索引开关 | `session-query-sqlite/src/index.ts:88-89,333-344` |
| `WebError` 系列 | 机器可路由错误码（`IMAGE_TOO_LARGE`、`SESSION_QUERY_SEARCH_DISABLED`、`SESSION_REFERENCE_BUDGET_EXCEEDED` 等） | 各域 types |

**选路/准入口径**：

- 图片准入批校验：`maxImagesPerMessage` / `maxMessageImageBytes` / mediaTypes 白名单（`attachment/src/index.ts:77-91`）。
- 附件引用进入会话日志 = **只存 `{attachmentId, mediaType, bytes, name}` 元数据，不存字节**（session-format 校验器冻结字段集，`session-format-v2-to-v3/src/payload.ts:187-206`）；客户端渲染走授权读取端点（先验证日志确实引用了该 id，`session-controller/src/commands.ts:394-407`）。
- 模型侧唯一附件写入口 = `read_image`（全仓 `saveImage` 非测试调用点仅此一处，`tool-fs/src/read-image.ts:275`）；wire 调用者"永远无法引用未上传的附件"（types.ts:94-99 设计注释）。

## 数据流向

### 图片（用户拖拽/粘贴 或 read_image）

```
base64 图片 → admission 规范校验（批量 limits）
  → LocalAttachmentStore：解码规范化（长边受限/8-bit sRGB/≤4MiB）
  → 规范化字节 SHA-256 → tmp fsync → 硬链接 objects/（EEXIST 即去重）→ 0400
  → 会话日志记 {attachmentId, mediaType, bytes, name}（无字节）
  → 请求组装：非视觉模型 → 抛 UNSUPPORTED_CONTENT 或投影占位文本
             视觉模型 → readImageRequest（variantId=sha256(附件+目标+编码版本)，
                        sharp 长边缩放+质量阶梯，缓存 cache/attachments/request-images/）
             → Messages: handle 文本 + {type:image, source:base64|file_id}
             → Chat-Completions: 默认 Files 上传换 file_id（本地索引去重/配额回收/失效重传），失败回退 base64 data URI
```

### @file

```
用户输入 "@src/foo.ts" → grammar.activeAtToken 识别（@ 前须行首/空白；引号形式 @"...）
  → Web 补全：file-reference-local 索引（路径 only；mtimes 增量；symlink 不跟随；越界返空）
  → mention 字面文本原样进 user 消息（服务端零改写）
  → system 指南（仅 read 工具在册时注入）：@ 是路径、要内容调 read、未 read 不得声称看过
```

### 会话检索与导出

```
检索：JSONL → extractSessionEventText（user/assistant 文本、tool 名+参数、tool 结果、todo、turn 错误；
      reasoning 不入）→ FTS5 persisted_docs + temp.live_docs（live 优先）→ search（整串短语、highlight 裁 snippet）
      → 模型工具 session_search（cwd 授权过滤）/ Web 侧栏搜索（never 时退化为标题匹配）
导出：/export（无参数）→ flush 持久化屏障 → 规范 JSONL + subagents/ 后代 + 引用附件字节
      → fflate 流式 ZIP → GET /api/session.export 浏览器下载；失败弄断下载而非给截断包
```

## 值得定位的差异点（事实记录，决策走 ADR）

- @file 是**纯路径提及**：索引 only、选中候选不读不附内容（包头注释原话）；"内容注入"是 ADR-0016 措辞侧的误记。
- 附件**永不自动删除**是"无任何 GC 代码"的物理事实，非策略声明； unreachable 对象留待未来 retention policy。
- 会话检索是**双层深 opt-in**：sqlite 包挂载但索引熄火（保 exact reads/titles/lineage 可用）+ 模型工具插件无 bundle 挂载。
- /export 是 **ZIP（JSONL+附件）** 而非 Markdown/JSON 文件；命令不产生持久审计事件，真正下载是同源浏览器 GET。
