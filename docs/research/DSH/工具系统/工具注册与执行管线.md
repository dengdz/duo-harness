# 工具注册与执行管线（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 02（T-06）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；并发循环侧见 [../Agent循环与会话/Agent循环与状态机.md](../Agent循环与会话/Agent循环与状态机.md)。

## 机制全貌

`ToolRuntime`（`packages/core/tools/src/index.ts:789`）是 cordis 服务，内含 `ScopedLayers` 分层注册表（全局层+作用域链，`index.ts:813`）与一个仅供调度器用的分阶段接口 `TOOL_RUNTIME_SCHEDULER{prepare/dispatch/finalize/finish}`（`index.ts:798`）。六段管线全部挂在作用域过滤事件上：`tools/pre-execute` 瀑布（allow/deny/cancel/ask，`index.ts:146`）→ 单调 guard（无 allow，只能否认，`index.ts:713`）→ `tools/execute` around 瀑布（可换 signal、做超时/重试，`index.ts:157`）→ 工具体 → `tools/post-execute`（accept/block，`index.ts:169`）→ 定义私有 `finalizeContent`（`index.ts:241`）→ `tools/result` emit（冻结快照，`index.ts:191`）。与 agent-loop 的分工：注册表管「单次调用的策略与语义」，`tool-calls.ts` 只管「一批 model tool-calls 的并发编排」，通过 scheduler 四段接口把管线的 pre（串行、按模型序）与 dispatch（可并行）拆开（`packages/core/agent-loop/src/tool-calls.ts:170-184`）。

## 关键流程

① **注册**：`defineTool` 把参数/输出 spec 编译为 JSON Schema（`packages/core/tools/src/schema.ts:566-567`），包装 `execute` 先校验参数抛 `ToolArgsError`（`schema.ts:585-589`），presenter/isConcurrencySafe 软校验失败降级（`schema.ts:598-615`）；`register` 校验 output 形状、schema、timeoutMs，拒绝保留名 `run_code`，同名冲突报错并提示走 `agent.ctx`（`index.ts:1043-1068,728`），名字原样保留；`presentAs` 仅限 scoped ctx、一 scope 一声明（`index.ts:954-964`）。

② **单次执行序**：`execute`（`index.ts:1348`）先 createExecution：快照+冻结参数、提前快照 finalizeContent（`index.ts:1415-1425`）；ptc 折叠调用在策略管线**之前**直接 `final-result`（带 reachableFrom 的 UNKNOWN_TOOL，`index.ts:1430-1450`）；随后 pre-execute 瀑布→ask（无 approval 服务降级为 deny，`index.ts:1702`）→guard；deny/guard 拒绝产出 `post-result`（仍过 post-execute，`index.ts:1496-1508`）；dispatch 段 `tools/execute` 瀑布包住工具体，工具体抛错→结构化 error result（`toolErrorResult`，`index.ts:1879`），body 启动后取消→`ABORTED`、启动前→`ABORTED_BEFORE_DISPATCH`（`index.ts:466-469`）；未知名在 dispatch 段抛 `ToolNotFoundError`（`index.ts:1555`）。成功值须过 `output.schema` 校验+render 快照（`index.ts:1802-1823`）。

③ **并发**：`runGroup` 用 `inFlight` Map+`Promise.race` 滚动补位，上限 `maxParallelToolCalls`（`tool-calls.ts:200,222`）；启动前重读 `executionMode`，后续调用变 exclusive 则 break 等池排空，下一组成屏障（`tool-calls.ts:203-205`）；提交严格按模型序：`commitReady` 只推进连续槽位（`tool-calls.ts:147-161`），每批前先重分类（`tool-calls.ts:86`）。

④ **restrict** 只过滤**继承面**（全局+祖先链交集），本层自有注册豁免，`run_code` 追加在最后不可过滤（`index.ts:1172-1197`）；scoped 注册遮蔽全局（`index.ts:1184-1188`）。

⑤ **超时**：工具只声明 `timeoutMs`（`index.ts:249`），由独立插件 `packages/guard/timeout-policy/src/index.ts:56-74` 以 `tools/execute` wrapper 用 `deadline()` 协作式实现，超时产出 code=`TOOL_TIMEOUT` 的结构化错误（`timeout-policy:25,41`）；取消为协作式：注册表不抛弃已启动 promise，只换最终结果（`index.ts:1538-1541`）。

## 接口与参数要点

- `defineTool` 字段：name/description/parameters/output{schema,render,presentationMeta?}/execute/timeoutMs?/isConcurrencySafe?/finalizeContent?/presentCall?/presentResult?（`schema.ts:483-536`）。
- 监听签名：pre `(exec,next)→PreToolDecision`、execute `(exec,next)→ToolExecutionResult`（wrapper 只可换 `exec.signal`，`index.ts:388`）、post `(exec,result,next)→PostToolDecision`、result 为只读 emit。
- `isConcurrencySafe` 仅精确 `true` 入并行池，异常/非 true/隐藏一律 exclusive（fail-closed，`index.ts:1282-1291`）；`presentAs: native|ptc|both` 决定模型所见面（`index.ts:653`），ptc 下模型直呼非 run_code 即 UNKNOWN_TOOL（`index.ts:1330`）。

## 边界与坑

- exclusive 调度是 fail-closed 屏障；调度器内部失败 `allSettled` 排空后**原样抛出、不伪造 tool result**（`tool-calls.ts:232-236`），但 abort 会对未启动调用补合成 `ABORTED_BEFORE_DISPATCH` 结果保证回放完整（`tool-calls.ts:238-243`）。
- deny/guard 裁决走 post-result 而非 final-result——拒绝结果仍受 post-execute 管辖（「拒绝也是结果」）。
- 重名/保留名注册即抛；`finalizeContent` 在调用开始时快照、只能改 content 不能动 value/isError（`index.ts:1658-1663`）；post-execute 的 accept 不能同时换 value+content、不能给失败结果换 value（`index.ts:1766-1775`）。

## 对 duo 的启示

对照 ADR-0018（三段管线+虚拟线程并发+isConcurrencySafe+模型序提交）：

1. DSH 的 guard 是 pre-execute 之后的**单调层**（无 allow、序无关）——duo 若把许可判断放进可扩展 pre 阶段，监听器顺序可能把拒绝翻转成放行，值得引入单调终裁。
2. `finalizeContent` 把「呈现改写」从策略瀑布剥离并快照隔离，且只许改 content——duo 的 post 阶段如承担 UI 呈现裁剪，应区分呈现/事实两权。
3. 调度器失败语义：DSH 严格区分「取消（补合成结果保回放）」与「调度器 bug（不伪造结果、向上抛）」——duo 虚拟线程池的中断路径应避免把内部异常吞成正常 tool result。
4. deny 结果仍过 post-execute 的设计，可让 duo 的审计/改写策略统一覆盖被拒调用。
