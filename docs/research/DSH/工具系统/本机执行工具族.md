# 本机执行工具族（DSH）

> 源锚点：`ddefc45fbc7f8e46dd73185e68295696d1297887`（2026-09-21 本地核验）。M22 探测里程碑工单 03（T-07）产物，五段统一模板。接口参考见 [../模块手册.md](../模块手册.md)；管线语义见 [工具注册与执行管线.md](工具注册与执行管线.md)；沙箱包裹见 [../沙箱与权限.md](../沙箱与权限.md)。

## 机制全貌

四包经三层 seam 串联：`LocalFileSystem`（packages/fs/fs-local/src/index.ts:66）以 realpath 为 targetKey 提供 stat/read/stream/write/edit，写与编辑都在 per-key FIFO 锁内走版本守卫+原子发布（index.ts:93,183,238）；`LocalBashExecutor`（packages/shell/bash-local/src/index.ts:102）把 `bash -c` 组装成 spawn spec 交给 `ctx.subprocess`，`subprocess-local` 的 `spawnSubprocess`（subprocess-local/src/spawn.ts:448）以 detached 进程组启动并做 tail 收集/杀树；`TerminalSessionService`（terminal/src/index.ts:105）是 owner 作用域 PTY 注册表，backend `terminal-bash` 出交互 shell，后台化统一走 `ctx.jobs`。于是「读改写」=tool-fs 的 read/write/edit→fs-local，「跑命令」=tool-bash→bash-local→subprocess-local，「长任务」=bash 后台（startArgv，index.ts:284）与 PTY 会话+jobs 回读。

## 关键流程

① **读**：`read` 一次 stat 定路由，size≥10MiB 或未知走 `streamText` 流式（tool-fs/src/read.ts:145-147；fsio.ts:492），全程 8KiB 采样 NUL 判二进制（fsio.ts:17,498）；`buildWindow` 边扫边限：默认 2000 行、单行 2000 字符加 `... (line truncated)` 后缀、输出 50KiB 字节帽置 truncatedByBytes，但扫完全文得精确 totalLines（read-render.ts:11-14,111-144）；footer 三态「续读 offset= / End of file」（read-render.ts:152-161），offset 越 EOF 抛 FS_NOT_FOUND；信封 `<path>/<type>file/<content>`。

② **写/编辑**：`writeFileAtomic`（fsio.ts:588）在同目录建私有 staging 目录（`.{name}.{pid}.{uuid}.tmpdir`，0700）内以 'wx' 0600 建 temp→写→fsync→POSIX rename / Windows `replaceFile` 先拷 DACL；`createIfAbsent` 改走 hard-link no-replace，撞车报 FS_NOT_OBSERVED（fsio.ts:557-569）。`edit` 在锁内 probe 版本→`readForEdit` LF 归一并记 CRLF 风格回写（fsio.ts:725-736,702）→`applyLiteralEdit` 字面替换：空/未命中 FS_EDIT_NOT_FOUND，多命中 FS_AMBIGUOUS_EDIT（fsio.ts:814-833）；`str_replace_editor` 为兼容形态（view/str_replace/insert/create+view_range）。

③ **bash**：`resolve` 填 workdir 与 timeout（默认 120s、上限 600s，bash-local index.ts:107-108）；spec 带 stdin data/ignore、stdout/stderr collect{maxBytes 64KiB, spill 64MiB}、env 覆盖 NO_COLOR/TERM=dumb/PAGER=cat（index.ts:27-32,198）。`OutputCollector` 保尾：内存超帽即把含已收块全量转写 0700 私有 tmpdir spill 文件（output.ts:109-126），总量超 64MiB 则删 spill 只留尾；`readFrom` 起点滑出窗口即 lossy+spillPath（output.ts:160-171）。超时：BASH_TIMEOUT deadline→abort→SIGTERM，graceMs(3s) 后 SIGKILL（spawn.ts:351-362），POSIX `kill(-pid)` 组信号、Windows `taskkill /T /F`（spawn.ts:130-155）；仅自身 deadline 记 timedOut（index.ts:256）。渲染 marker `[timed out after Xms]`/`[killed by signal]`/`[exit code: N]`（tool-bash/src/render.ts:52-58）。

④ **PTY**：六工具 open/send/read/signal/close/list（tool-terminal/src/index.ts:162-400）。owner=精确 Agent 实例，`expectOwned` 拒 NO_SESSION/FOREIGN_SESSION（terminal/src/index.ts:387），id 为 `pty-N`（index.ts:166）；每会话限一个 active send（index.ts:246）。send 轮询判定（terminal-bash/src/session.ts:554-590）：promptSeen 且前台 pgid 回到 shell→stdin_read；`exactProbeAfterMs` 后 inputWaiting→stdin_read；静默 3s(+handoffGrace)→inferred_idle；另有 timeout 30s 与 session_exit。`terminal_read` 翻 scrollback（默认 10000 行/4MiB，config.ts:91-92）；`terminal_signal` 仅五信号且拒对 shell 前台 SIGKILL；`terminal_close` 幂等并等捕获的进程树消亡（index.ts:285-300）。后台 send 经 `jobs.start({kind:'pty-send'})` 返回 jobId，由 job_output/job_kill 回读（tool-terminal index.ts:255-275）。

## 接口与参数要点

- read：file_path/offset(1 起)/limit≤2000；write：file_path/content；edit：file_path/old_string/new_string/replace_all；bash：command/timeoutMs/workdir；terminal_send：sessionId/text/submit(默认 true)/run_in_background；terminal_read：offset(最新相对)/count(默认 500)。
- 输出限额：read 50KiB、bash 单流 64KiB+spill 64MiB、terminal 结果 256KiB（tool-terminal index.ts:30）。
- 编码一律 UTF-8 fatal 解码，二进制/NUL 拒绝（FS_NOT_TEXT）；spill 文件 0600，目录 0700。

## 边界与坑

- 并发写同文件：进程内锁+版本 probe 使败者 FS_STALE_VERSION 强制重读，但**跨进程无防护**。
- 截断与 spill：text 只是尾 64KiB，truncated=true 时头部只能凭 spillPath 找回；超 64MiB spill 被删且不告警、恢复路径消失（output.ts:129-150）；SIGKILL 的宿主进程留下 spill 残渣。
- PTY 泄漏防护：owner dispose effect 全关其会话（index.ts:403-417）、closing fence 防重入、服务 teardown 兜底；`inferred_idle/timeout 不证明前台命令已退出`（系统提示明示）。
- POSIX/Windows：rename vs replaceFile+DACL、kill 组 vs taskkill、env 键大小写不敏感合并（spawn.ts:44-54）、ENOTDIR 在 win32 需 stat 修复（fsio.ts:191）。bash-local 每次新 `bash -c`，cd 不持久（注释 index.ts:176）。

## 对 duo 的启示

duo 现状=fs 工具族（read 三帽/edit LF 归一/bash 120s 杀树）+M21 read_image。对照三条：

1. **流式大文件读**：duo read 可照搬「size≥阈值走流式+8KiB NUL 采样+扫全量得 totalLines」，避免大文件整读且保留精确行号。
2. **bash 输出 spill**：duo spill 无，可引入 OutputCollector 形态——内存保尾（64KiB）+超帽落 0700 spill 并在结果附 spillPath，模型可再 read 头部；这是 duo bash 120s 杀树之外最易移植的一块。
3. **PTY 六件套**：duo 若无交互 REPL/gdb 需求可暂缓全套，但其 owner(精确 Agent)绑定、SEND_ACTIVE 互斥、owner 死亡自动回收、以及 run_in_background→job_output 回读的三方解耦（terminal/jobs/owner）值得作为 duo 后台任务增强的蓝本；轻量替代是 bash 后台句柄+定期 readOutput。
