# 插件包交货指南

> 本文对齐 1.1.0，教程体裁。读者定位：**写了一个插件，想把它作为独立文件交给别人装**的插件作者。插件模型与扩展点见[多插件协同](多插件协同.md)，部署者视角的安装操作见[插件中心](../02-指南/插件中心.md)。

## 交货形态（v1）：一个普通 jar + 一行装配

v1 的插件包就是**你模块的常规构建产物**——`mvn package` 打出的 jar，里面只有你自己的类：

```bash
mvn -pl duo-harness-stats package
# 产物：target/duo-harness-stats-<版本>.jar
```

不需要 shade、不需要 fat-jar、不需要 MANIFEST 声明。你的插件用到的 duo API（`Plugin` / `Context` / 各服务）与公共库（Jackson、slf4j）由**宿主 classpath 供给**——部署者的 duo 进程里都有。

## 为什么包里不能打入宿主的类

装载器是**自优先**的：包内出现的类一律取包内副本，包内没有的才回落宿主。这条隔离规则让多个插件的同名类互不可见——但反过来说，**只要你把宿主供给的类（duo API、Jackson、slf4j……）打进了包**，自优先就会加载你的副本，它与接口签名里的宿主类是不同的 `Class` 对象，调用即撞加载器约束（`LinkageError: loader constraint violation`，实测形态）。

另一个实测教训：Maven shade 的 `artifactSet` 排除**不覆盖被排除依赖的传递依赖**——逐个点名排除（core、tools、agent、jackson、jsoup……）必有遗漏。所以 v1 的推荐就是最简单的：**包里只有你自己的类**。你确实需要宿主没有的独有库时，自行 shade，并把宿主供给面逐件排除（`dev.duo:*`、`com.fasterxml.jackson.*`、`org.slf4j:*` 起步，按你的依赖树核对），打完用 `unzip -l` 自查。

## 装配行：三要素

部署者（或插件中心页面）把你的包装进 `~/.duo/plugins.yml`，一行三要素：

```yaml
plugins:
  - id: tool-stats                      # 稳定标识：审计点名与运行期管理的锚
    name: dev.duo.harness.stats.ToolStatsPlugin   # 入口类 FQCN（公共无参构造）
    jar: /home/me/.duo/plugins/duo-harness-stats-1.0.1.jar   # 包路径
    config: { }                          # 绑定到你的 config record；无配置插件省略
```

- 入口类实现 `dev.duo.harness.core.api.Plugin`（同[多插件协同](多插件协同.md)的模型——inject 声明依赖、`configType` 声明配置 record、`apply` 做一切）；
- `config` 缺省或 `{}` 的语义由你的 `configType` 决定：声明了 record 就必须给全字段（缺字段装载即失败、点名到字段路径）；`configType` 返回 `null` 的插件不要给 config；
- 装载失败（缺包/坏包/类缺失/构造失败）一律点名到行并**整树回滚**——启动期 fail-fast，不会半死运行。

## 从源码到装载的最短路径

以仓库样板 `duo-harness-stats`（`/toolstats` 命令 + `tool_stats` 查询工具）为例：

```bash
# 1. 打包
mvn -pl duo-harness-stats package

# 2. 交付：把 target/duo-harness-stats-<版本>.jar 交给部署者
#    （部署者）放进插件目录
cp duo-harness-stats-1.0.1.jar ~/.duo/plugins/

# 3. 部署者在 Web「插件中心」待装区看到它 → 安装 → 确认 → 生效
```

装载即激活、卸载即干净退场（服务与工具随行摘除、类加载器释放），全程不需要重启。样板模块本身就是双形态：classpath 装配行与插件包装载都可以。

## 装前点名：页面会向部署者展示什么

插件中心安装前会出示：包路径、大小、sha256，以及**候选入口类**（按"类文件引用了 Plugin 接口"的启发式扫描，唯一候选自动预填）。注意两点：

- 点名是**告知义务不是安全审查**——它展示的是依赖声明面（inject / optionalInject / config 类型），你插件 `apply` 里真正注册的工具、命令、监听要装完后在状态页核验；
- sha256 仅供部署者对账，不构成签名或信任锚。

## 卸载与升级语义

- **卸载**：容器拔除（服务注销、依赖方自动回落等待、类加载器释放）+ 装配行删除。同包可重新安装。
- **升级**：停用 → 覆盖 jar 文件 → 启用（或卸载后重装）。没有带外检测——覆盖了文件页面不会自动知道。
- 类加载器泄漏（极少数静态引用钉住）时卸载不彻底：页面与日志提示**需重启生效**，这是兜底口径而非缺陷。

## 逐条自查（交货前）

- [ ] jar 里只有自己的类（`unzip -l` 无 `dev/duo/harness/core|tools|agent`、无 jackson/slf4j）
- [ ] 入口类 public 且有无参构造，`inject()` 声明了全部实际消费的服务
- [ ] `configType` 与文档给的 config JSON 对得上（部署者要照着填）
- [ ] 服务名加了你的前缀（全局扁平命名空间，harness 保留裸名）
- [ ] 交给自己或信任的人——装插件等于装任意代码，这条对作者和部署者同时成立
