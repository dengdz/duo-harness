# 版本与发布

duo-harness 自 1.0 起遵循[语义化版本](https://semver.org/lang/zh-CN/)，承诺 **1.x 内向后兼容**：

| 变更类型 | 版本位 | 例子 |
|---|---|---|
| 破坏性变更 | 主版本（2.0.0） | 配置格式废弃重设计、插件接口不兼容改动、默认行为契约变更 |
| 新功能 | 次版本（1.1.0） | 新工具、新斜杠命令、新配置项、新插件扩展点 |
| 缺陷修复与小改进 | 修订号（1.1.1） | 行为修复、文档修正、依赖升级 |

升级含义：从任意 1.x 升级到更新的 1.y，不需要改配置、不需要改插件代码；只有跨主版本（如 1.0 → 2.0）才可能需要迁移。1.0 之前的版本（0.x）不在此承诺范围内。

## 发版形态

- **按需发版**：不排期，功能或修复就绪即发。
- **CHANGELOG 即账本**：每个版本的用户可见变更逐条记账于 [CHANGELOG](https://github.com/dengdz/duo-harness/blob/main/CHANGELOG.md)，发布时落日期——看某个版本改了什么，以它为准。
- **tag 即发布**：版本分支打 tag（如 `v1.0.0`）即经 CI 自动构建并挂 [GitHub Release](https://github.com/dengdz/duo-harness/releases)，产物为 `java -jar` 直跑的 fat-jar（见[快速开始](/01-入门/快速开始)）。

## 对照系惯例

- **ZCode**：语义化版本做进发版机械——conventional commits（`feat` / `fix` / `!:` 标破坏性）驱动 release-it 自动升档与分节 changelog，当前 3.x。
- **DSH（DeepSeek Harness）**：developer preview 阶段，0.x alpha/rc 预发布流，README 明示「THERE WILL BE COMPATIBILITY-BREAKING CHANGES」。
- **duo-harness**：自 1.0 起给出上表的 1.x 兼容承诺——强于 preview 期的反承诺；升档判定靠 CHANGELOG 记账纪律与发版把关，而非全自动机械。
