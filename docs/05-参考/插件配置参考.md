# 插件配置参考

> 状态：对齐 agent-demo.yml（M12 版）。本文逐行注解 demo 装配里的每个插件行——想组装自己的 agent，从这里抄；机制语义见[设计主线](../04-架构/设计主线.md)，跑现成 demo 见[运行Demo](../01-入门/运行Demo.md)。

## 全量装配示例（agent-demo.yml）

```yaml
plugins:
  # 工具域：一行启用整个域
  - id: tools
    name: dev.duo.harness.tools.ToolsPlugin

  # fs 工具族六件（ADR-0012）：read/write/edit/glob/grep/bash——workspace 约束
  # + 三档权限预设；发布 "workspace" 服务（CLI /permission 查看与切换预设）。
  # attachment 行在场时追加 read_image（视觉模型读图，M21）
  - id: fs-tools
    name: dev.duo.harness.tools.fs.FsToolsPlugin
    config:
      mode: workspace-write   # read-only / workspace-write / danger-full-access

  # 附件库（M21，ADR-0022）：发布 "attachments" 服务——内容寻址图片库
  # （~/.duo/attachments/v1，SHA-256 硬链接去重、0400 只读、永不自动删除）。
  # 行在场即启用 read_image 与 Web 图片上传/渲染；不装零感知
  - id: attachment
    name: dev.duo.harness.attachment.AttachmentPlugin
    config: {}

  # 会话检索（M21，ADR-0022）：行在场即发布 sessionQuery 服务（Web 侧栏搜索框
  # 数据源），tools 服务在册时同时注册 session_search 工具（模型侧）。
  # 索引懒构建——首次搜索才扫会话目录，启动零成本；子代理会话不索引，
  # reasoning 不入索引。config 块须在场（空块 {} 即可），可选字段：
  #   sessionsDir: /path/to/sessions  # 会话目录（省略用 duo home 的 agent-sessions）
  #   maxResults: 8                   # 单次搜索命中上限（省略默认 8，须为正）
  - id: session-query
    name: dev.duo.harness.sessionquery.SessionQueryPlugin
    config: {}

  # prompt 注册表：systemPrompt 为最前用户指令片段（M7 起经插件发布为 "prompts" 服务）
  - id: prompts
    name: dev.duo.harness.agent.prompt.PromptPlugin
    config:
      systemPrompt: "你是在 duo-harness 中运行的助手，回答使用中文并保持简洁。"

  # AGENTS.md 注入：~/.duo/AGENTS.md + 项目根（.git 定根），64KB 预算截断；
  # 注册为 agents-md 片段——行序即组装序（用户指令 → 项目约定 → 技能清单）
  - id: agents-md
    name: dev.duo.harness.agent.prompt.AgentsMdPlugin
    config: {}

  # 技能系统：四根发现（.duo/skills → .agents/skills → ~/.duo/skills → ~/.agents/skills）
  # + 清单片段进 prompt 注册表 + skill 工具挂载；disabled 可点名关闭技能
  - id: skills
    name: dev.duo.harness.agent.skills.SkillsPlugin
    config:
      disabled: []

  # 命令注册表（M19，ADR-0020）：发布 "commands" 服务——斜杠命令统一入口
  # （命令 → 技能直调 → 未知报错）；命令本体由呈现位插件注册，本行零配置
  - id: commands
    name: dev.duo.harness.agent.commands.CommandsPlugin
    config: {}

  # 交互服务：回答者注册表（console / web answerer 随呈现位插件注册）
  - id: answers
    name: dev.duo.harness.tools.InteractionPlugin

  # 档位审批（ADR-0012）：workspace-write 档区内写放行、越界/read-only 档 ask——
  # ask 交回答者瀑布（web 行在前 → 卡片优先呈现；纯 CLI 装配为终端 y/n）
  # ——与 ApprovalPlugin（always-deny / auto-approve）、InteractiveApprovalPlugin
  # （无档位全 ask）三选一挂载
  - id: approval
    name: dev.duo.harness.tools.fs.WorkspaceApprovalPlugin

  # 重复调用提醒：同一工具相同参数连续重复达阈值（3/5/8）时在结果尾部附加提醒
  # （内核约定：声明 config 类型即须提供 config 块——块内字段可省，省略即默认阈值）
  - id: repeat-reminder
    name: dev.duo.harness.example.mcpfs.RepeatReminderPlugin
    config: {}

  # 会话独占：Web 面与 CLI 各自尝试续接最新会话，先到者持锁——后到者收到明确占用提示
  # （CLI 改开新会话继续；Web 面启动失败点名被占会话）。同一会话同一时刻只允许一个属主
  - id: web
    name: dev.duo.harness.web.WebPlugin
    config:
      port: 18080   # 避开本机常用端口（8080/8081 被 duoduo 占用）

  # CLI 呈现位（ADR-0011）：终端 REPL 插件——与 web 对称。
  # 行序即回答者路由：cli 在 web 之后，审批/提问由 Web 卡片优先呈现
  - id: cli
    name: dev.duo.harness.cli.CliPlugin
    config: {}
```

## 逐行注解

| id | 插件类 | config | 作用与依赖 |
|---|---|---|---|
| `tools` | `tools.ToolsPlugin` | 无 | 发布 "tools" 服务（ToolDefinition 注册 + 三段管线 + 审批/guard 挂点）。工具域是 MCP、fs 工具族与 agent 循环的前置 |
| `fs-tools` | `tools.fs.FsToolsPlugin` | `mode`（默认档，缺省 workspace-write）、`root`（workspace 根，缺省进程 cwd） | inject "tools"——注册 read/write/edit/glob/grep/bash 六件（attachments 服务在场时追加 read_image，M21 ADR-0022）+ 发布 "workspace" 服务（三档权限预设 + 路径包含性判定，ADR-0012）。CLI `/permission` 依赖本行 |
| `attachment` | `attachment.AttachmentPlugin` | 附件段（可选，见下） | 发布 "attachments" 内容寻址图片库（M21，ADR-0022）：`~/.duo/attachments/v1`、SHA-256 硬链接去重、0400 只读、无 GC 永不自动删除。行在场启用 read_image 工具与 Web 图片上传/渲染端点；不装零感知 |
| `session-query` | `sessionquery.SessionQueryPlugin` | 检索段（可选，见下） | 发布 "sessionQuery" 检索服务（M21，ADR-0022）：内存倒排索引懒构建（首次搜索才扫 + mtime 增量）、后端无关接口；tools 服务在册时同时注册 session_search 工具。不装零感知 |
| `web-tools` | `tools.web.WebToolsPlugin` | 限额/超时字段（均可省）+ `search` 段（可选，见下） | inject "tools"——注册 web_fetch（行在场即注册）与 web_search（search 段非空且 key 有解才注册，ADR-0021）。SSRF 三道防线拒绝内网目标与跨源重定向；网络读档位：read-only 档 ask、其余档放行 |
| `prompts` | `agent.prompt.PromptPlugin` | `systemPrompt`（可选） | 发布 "prompts" 注册表；systemPrompt 作为最前用户指令片段，全空落内置缺省 |
| `agents-md` | `agent.prompt.AgentsMdPlugin` | `budgetChars`（总预算字符数，缺省 65536） | inject "prompts"——读 `~/.duo/AGENTS.md` 与项目根 AGENTS.md 拼接注入（声明 config 类型即须提供 config 块，字段可省） |
| `skills` | `agent.skills.SkillsPlugin` | `disabled`（可选数组） | inject "tools" + "prompts"——发布 "skills" 注册表：四根发现 SKILL.md、清单片段、`skill` 工具挂载 |
| `commands` | `agent.commands.CommandsPlugin` | 无 | 发布 "commands" 命令注册表（M19，ADR-0020）：斜杠命令统一入口（命令 → 技能直调 → 未知报错），执行落 `command/run` / `command/done` 审计事件；命令本体由呈现位插件注册（CLI 四命令随 `cli` 行） |
| `answers` | `tools.InteractionPlugin` | 无 | 发布 "answers" 交互服务；回答者（console / web answerer）随呈现位插件注册 |
| `approval` | `tools.fs.WorkspaceApprovalPlugin` | 无 | inject "answers" + "workspace"——档位前置裁决：danger 档全放行、workspace-write 档区内写放行、越界写与 bash 及 read-only 档写一律 ask（无人应答 fail-closed）。无 fs-tools 时本插件 PENDING（点名可见），纯交互装配改挂 `InteractiveApprovalPlugin` |
| `repeat-reminder` | `example.mcpfs.RepeatReminderPlugin` | `thresholds`（升序数组，省略即 [3, 5, 8]） | 同一工具相同参数连续重复达阈值时逐级附加提醒（advisory 非 guard） |
| `web` | `web.WebPlugin` | `port`（缺省 8080）、`maxIterations`（缺省 10）、`pageSize`（首屏/每页消息数，缺省 50，M19）、`governance`（可选段，见下） | inject tools + prompts + answers——浏览器对话/状态/HITL 卡片；只绑 127.0.0.1；装配 ask_user 与计划呈交工具（纯 Web 部署 HITL 完整）；接管当前会话独占锁（被占则插件 FAILED 点名会话）；LLM 未配置则整体 FAILED |
| `cli` | `cli.CliPlugin` | `maxIterations`（缺省 10）、`governance`（可选段，见下） | inject tools + prompts + answers + skills + commands + workspace——终端 REPL（/new、/plan、/permission 档位、/技能名直调、审批 y/n、ask 选项；斜杠命令经 "commands" 注册表共享入口）；会话独占（被占则提示并改开新会话）；`/exit` 或 EOF = idle：锁释放、回答者摘除、插件树不受影响（彻底停止交给 Ctrl-C）；LLM 未配置则插件 FAILED 带 yml 示例 |

### maxIterations（web / cli，可选）

单轮对话的迭代上限（每轮 = 一次 LLM 调用往返）：缺省 10（内核常量）。**计划模式等探索型任务**（模型按计划指导连读多份文档/技能再设计）在真实仓库上常超十轮，建议显式调高（如 30）——达上限时循环以"已达最大迭代轮数"异常终止。非正整数启动即 FAILED 点名；防失控硬停在缺省路径上原样保留。

```yaml
  - id: web
    name: dev.duo.harness.web.WebPlugin
    config:
      port: 18080
      maxIterations: 30           # 可选迭代上限（缺省 10）
```

### governance 段（web / cli，可选）

上下文治理六阈值（ADR-0013）：段与字段均可省，省略即内置缺省（0.7.0 行为）；双开部署时 web 与 cli 各自配段、互不同步（已知取舍）。字段未知、类型不符或数值越界（阈值/窗口/折叠数须为正，压缩比例须在 (0,1]，保留比须在 [0,1)）启动即 FAILED 点名：

```yaml
  governance:
    spillThresholdChars: 50000        # spill 卸载阈值（字符，缺省 50000）
    pruneThresholdChars: 8000         # 修剪触发阈值（字符，缺省 8000）
    compactionThresholdRatio: 0.8     # 压缩触发比例（缺省 0.8——窗口 × 比例）
    contextWindowTokens: 128000       # 模型上下文窗口（token，缺省 128000）
    keepRecentRatio: 0.2              # 压缩保留近端比例（缺省 0.2）
    minRemoteMessages: 4              # 压缩最小远端消息数（缺省 4）
```

### subagent 段（M15，ADR-0015）

子代理模板制装配：`templates` 段缺席或为 null 即空集——插件零副作用，spawn/fork/控制面五件工具不出现（未配置部署零变化）。模板结构严格绑定：未知字段、类型不符、模板名空/重复、工具清单空一律启动 FAILED 点名。子代理可用集在装配处再经强制过滤：交互工具（ask_user / exit_plan_mode）与控制面五件配置了也滤除（不可绕过）：

```yaml
  - id: subagent
    name: dev.duo.harness.agent.subagent.SubagentPlugin
    config:
      templates:
        - name: researcher                     # 模板名（spawn/fork 的点名键，配置内唯一）
          tools: [read, glob, grep, write]     # 工具清单（须为在册工具名；未注册工具自然不进集）
          prompt: "你是调研助手……"              # 可选专属提示（叠加在框架基线之后）
          maxIterations: 40                    # 可选迭代上限（缺省 30，高于主对话的 10）
        - name: worker
          tools: [read, write]
```

注意：本插件依赖呈现位发布的 `presenter` 服务（子代理的 LLM 与当前会话来源）——部署必须含 cli 或 web 呈现位，缺失时启动报"永久等待中，缺失服务 [presenter]"。子代理完成/失败/被中止均以 `subagent/completed` 事件回流父会话；子会话存于 `~/.duo/agent-sessions/subagents/`（侧栏不列出），完成后可打开回放。

### web 工具族 config（web-tools 插件，M20，ADR-0021）

fetch 限额与超时全部可省（缺省对齐 DSH）；`search` 段缺席即 fetch-only（web_search 不注册，模型工具清单不出现）。字段非法启动即 FAILED 点名：

```yaml
  - id: web-tools
    name: dev.duo.harness.tools.web.WebToolsPlugin
    config:
      timeoutMs: 30000            # 单次抓取/搜索超时上限，覆盖响应头与 body 两段（连接失败另受 10s 上限且不超过本值；缺省 30000）
      maxResponseBytes: 5000000   # 响应体字节上限（缺省 5000000）
      maxBodyChars: 100000        # 转换后正文字符上限（缺省 100000；后置于转换——head 重量级页面预切会丢整段正文）
      maxOutputChars: 200000      # 模型可见输出上限（缺省 200000）
      maxRedirects: 5             # 重定向跳数上限（缺省 5；跨源强制拒绝）
      userAgent: duo-harness      # 请求 UA（缺省 duo-harness，去版本化）
      search:                     # 搜索段（缺席即 fetch-only）
        type: tavily              # 首发 provider（唯一实现，其他值启动即 FAILED）
        apiKeyEnv: TAVILY_API_KEY # env 名（缺省 TAVILY_API_KEY）；或 apiKey 字面量
        baseUrl: https://api.tavily.com   # 缺省官方端点
        maxResults: 8             # 结果上限（缺省 8）
```

key 解析链：`apiKey` 字面量 → 环境变量兜底 → 皆空视为未配置（不注册 web_search）。红线"key 永不入库"约束的是 git 仓库，部署侧 yml 放字面量不算违规；demo yml 只示范 env 方式。

### 附件段（attachment 插件，M21，ADR-0022）

准入上限全部可省（缺省对齐 DSH 量级）；字段非法启动即 FAILED 点名：

```yaml
  - id: attachment
    name: dev.duo.harness.attachment.AttachmentPlugin
    config:
      maxImageBytes: 20971520            # 单图字节上限（缺省 20MiB）
      maxImagesPerMessage: 20            # 单消息图片数上限（缺省 20）
      maxMessageImageBytes: 104857600    # 单消息图片总字节上限（缺省 100MiB）
      maxImagePixels: 67108864           # 解码像素上限（缺省 64M）
      maxImageDimension: 8192            # 单边长上限（缺省 8192）
      normalizedImageMaxPixels: 4194304  # 入库规范化长边像素预算（缺省 2048²）
      normalizedImageMaxDimension: 8192  # 规范化单边长上限（缺省 8192）
      normalizedImageMaxBytes: 4194304   # 规范化字节预算（缺省 4MiB）
```

### 会话检索段（session-query 插件，M21，ADR-0022）

```yaml
  - id: session-query
    name: dev.duo.harness.sessionquery.SessionQueryPlugin
    config:
      sessionsDir: /path/to/sessions # 会话目录（省略用 duo home 的 agent-sessions；测试/多目录部署用）
      maxResults: 8                  # 单次搜索命中上限（缺省 8，须为正）
```

索引内容为会话正文（消息文本 / tool 调用名+参数 / tool 结果 / todo 内容项 / turn 错误）——reasoning 与治理事件不入；子代理会话（subagents/ 子目录）不索引；查询分词 AND（英文整词 + 中文单字），查询含连续汉字原词时该原词为主排序键、摘录锚定原词首次出现。文件戳（mtime+size）未变的会话不重扫；带外改动的会话文件在下次搜索自动重扫。

### llm 视觉字段（~/.duo/config.yml，M21，ADR-0022）

`llm:` 段（OpenAI 兼容 provider 连接配置所在）新增可选布尔字段 `vision`：

```yaml
llm:
  baseUrl: https://api.deepseek.com
  apiKey: sk-…            # 永不入库（.gitignore 约束 .env；config.yml 在 duo home 天然不入库）
  model: deepseek-flash
  vision: true            # 缺省 false——false 时 Web 收图即拒（409）、read_image 执行前即拒；
                          # true 且 attachment 行在场时，消息附件与 read_image 结果以图片部件进请求
  imageDelivery: files    # 图片投递形态（缺省 inline）：inline = base64 data URI（任何 OpenAI
                          # 兼容端点可用）；files = DeepSeek 形态 Files API 上传换 file_id（省大图
                          # 传输，本地索引去重、配额满回收最旧自有文件、上传失败回退 inline）
```

`imageDelivery` 非 inline/files 的值启动即 FAILED 点名；files 形态仅 DeepSeek 端点可用（其余 provider 保持 inline），见[已知限制](../limitations.md)。

## 通用约定

- **行序即装载序**：依赖别的东西先挂（如 approval 依赖 answers 与 workspace，须排在 answers、fs-tools 之后；cli 依赖 workspace，同理）
- **config 块**：插件声明了 config 类型就必须带 `config:` 行（免配置写 `config: {}`）；字段缺失按严格绑定失败并点名
- **审批策略三选一**：`approval`（档位裁决，ADR-0012）、`ApprovalPlugin`（策略式：always-deny / auto-approve 白名单）、`InteractiveApprovalPlugin`（无档位全 ask）都是审批策略服务，同装会冲突

## 斜杠命令（commands 插件 + 呈现位注册，M19 ADR-0020）

boot yml 装 `dev.duo.harness.agent.commands.CommandsPlugin` 行发布 "commands" 服务（零 config）；**命令本体由呈现位插件注册**（cli 硬依赖本服务）——两呈现位共享同一入口顺序：**命令 → 技能直调 → 未知报错**（斜杠文本永不透传进模型历史）。

内置命令一览：

| 命令 | 面 | busySafe | 说明 |
|---|---|---|---|
| `/permission [档位]` | 双面 | 是 | 查看/切换权限预设（切档落 `permission/mode` 事件，重开会话恢复；新会话回 yml 缺省） |
| `/compact` | 双面 | 否 | 手动压缩上下文（落 `context/compacted` 压缩点，投影按最后压缩点拼接） |
| `/title 新标题` | 双面 | 是 | 改会话标题（latest-wins 覆盖自动标题） |
| `/export [markdown\|json]` | 双面 | 是 | 导出当前会话（M21，ADR-0022）：缺省 markdown 人读记录；json 为日志原样副本。CLI 写盘当前目录 `duo-session-<id>.md/.jsonl`；Web 自动触发浏览器下载 |
| `/new` / `/plan [描述]` / `/exit` | 仅 CLI | 否 | 终端呈现位命令（换绑/计划模式/退出） |

- **busySafe**：agent 执行中 busySafe 命令立即生效（如运行中勒紧权限）；其余回应"执行中，需等待空闲"（fail-closed：说不清就别在运行中动）
- **审计**：命令执行落 `command/run` / `command/done` 两事件（Web 渲染命令行、刷新回放可见；投影排除不进模型历史）
- 插件代码可注册自定义命令（`CommandsRegistry.register(registrant, definition)`：名 + 描述 + 适用面 ANY/CLI/WEB + busySafe + handler，随作用域自动摘除）

## hooks.json（hooks 插件，ADR-0019）

hooks 配置独立于 yml：`~/.duo/hooks.json`（DuoHome 根下），复用 Claude Code/Codex 格式，**Claude Code 的 settings.json 整文件粘贴即用**（未知键宽容忽略、Codex 扁平条目兼容）。boot yml 装 `dev.duo.harness.hooks.HooksPlugin` 行即 opt-in（该行无需 config 块）；不装行零感知，装行而文件缺失/为空 = 插件空转。

```json
{
  "hooks": {
    "PreToolUse": [
      {"matcher": "bash", "hooks": [{"type": "command", "command": "/path/to/guard.sh", "timeout": 30}]}
    ],
    "PostToolUse": [
      {"matcher": "Write|Edit", "hooks": [{"type": "command", "command": "/path/to/audit.sh"}]}
    ]
  }
}
```

- **事件**：一期 `PreToolUse`（映射 tools/pre-execute，可阻断）与 `PostToolUse`（映射 tools/post-execute，结果改写）；其余 Claude Code 事件跳过 + WARN
- **matcher**：省略/`*` = 全匹配；纯字母数字与 `_ - 空格 | ,` = 精确名/多选；含其他字符 = 未锚定正则（`Edit.*` 亦命中 `NotebookEdit`，需整串请加 `^$`）；非法正则条目跳过 + WARN
- **裁定**：exit 2 = 阻断（stderr 回给模型；PostToolUse 为结果改写为错误，不撤销已执行的副作用）；exit 0 时 stdout 输出 JSON 可裁定——PreToolUse 认 `{"permissionDecision": "deny"|"allow"|"ask", "permissionDecisionReason": "…"}`（`ask` = 交审批段裁决，未配置审批策略即拒），PostToolUse 认 deny/block（等价结果改写），均兼容 legacy `{"decision": "block", "reason": "…}`；其余非零退出 = 非阻断 + WARN
- **处理器类型**：仅 `type: "command"`（其余类型跳过 + WARN）；`args` 数组在场 = exec 直启，缺省 `sh -c`
- **超时**：条目级 `timeout`（秒），缺省 600s；超时取消进程、丢弃输出、放行
- **stdin 载荷**（JSON，字段名与 Claude Code 同名）：`hook_event_name`、`tool_name`、`tool_input`、`cwd`（PostToolUse 增 `tool_response`）、`presenter_id`（M19：发起呈现位标记 `cli`/`web`，agent 循环执行时携带）；环境变量注入 `DUO_HOME`。`session_id` / `transcript_path` / `tool_use_id` 仍不提供（管线无会话与调用标识，见 backlog"钩子载荷上下文透传"）
- **失败语义 fail-open**：钩子超时、崩溃、路径不存在一律放行 + WARN——**钩子不是执法边界**；"绝不放行"的硬闸门用 guard（进程内单调否决）或审批承担
- **与审批的顺序**：钩子与审批策略同在准入段，先到先决——钩子 deny 占先即省掉审批交互；钩子无"跳过审批放行"能力（只收不放）
- 配置解析失败（非法 JSON / 结构不符）→ hooks 插件 FAILED 并点名文件位置，不连坐 boot 树其他插件

## 不在 yml 里的挂载（编程形态）

| 能力 | 挂载方 | 等价 yml 形态 |
|---|---|---|
| `ask_user` / `exit_plan_mode` 交互工具 | 两个呈现位插件装配链各自查重注册（先到先得） | 无独立插件行——随 `web` / `cli` 行自动获得 |
| MCP 服务器连接 | `root.plugin(new McpClientPlugin(), config)`：`serverName` + `command` + `args` + `requestTimeoutMs` + `reconnect`（initialDelayMs/maxDelayMs/maxAttempts）——agent demo 默认不挂（本机工具族取代），DemoMain 的 M2 段演示，等价 yml 行见 demo-m2.yml 注释 | `- id: files / name: dev.duo.harness.mcp.McpClientPlugin / config: {...}`（命令与参数随目标服务器而定） |
| console / web answerer | 呈现位组件随装配注册——回答者永远属于呈现位（ADR-0008） | 无 yml 形态（机制在核，呈现属装配） |
| 审计桥 AuditingAnswerer | 包装真实回答者注册——审批请求/决定落会话事件 | 同上，装配层组合关注点 |

## 出错怎么看

- 插件 FAILED：boot 审计输出会点名插件与原因（config 绑定失败带字段路径）
- 服务缺失：依赖方 PENDING，boot 输出列缺失的服务名——按名字检查漏挂的行
- 整树回滚：任一插件启动失败，已启动的按注册逆序回滚，不留半装配状态
