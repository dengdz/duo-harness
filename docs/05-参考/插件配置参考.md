# 插件配置参考

> 状态：对齐 agent-demo.yml（M8 收官版）。本文逐行注解 demo 装配里的每个插件行——想组装自己的 agent，从这里抄；机制语义见[设计主线](../04-架构/设计主线.md)，跑现成 demo 见[运行Demo](../01-入门/运行Demo.md)。

## 全量装配示例（agent-demo.yml）

```yaml
plugins:
  # 工具域：一行启用整个域
  - id: tools
    name: dev.duo.harness.tools.ToolsPlugin

  # prompt 注册表：systemPrompt 为最前用户指令片段
  - id: prompts
    name: dev.duo.harness.agent.PromptPlugin
    config:
      systemPrompt: "你是在 duo-harness 中运行的助手，回答使用中文并保持简洁。"

  # AGENTS.md 注入：~/.duo/AGENTS.md + 项目根（.git 定根），64KB 预算截断
  - id: agents-md
    name: dev.duo.harness.agent.AgentsMdPlugin
    config: {}

  # 技能系统：四根发现 + 清单片段进 prompt 注册表 + skill 工具挂载
  - id: skills
    name: dev.duo.harness.agent.SkillsPlugin
    config:
      disabled: []   # 点名禁用技能，如 ["release-notes"]

  # 交互服务：回答者注册表（console/web answerer 由装配层注册）
  - id: answers
    name: dev.duo.harness.tools.InteractionPlugin

  # 交互审批：写操作被声明"需审批"后由回答者逐次作答（fail-closed，无永久放行）
  # ——与 ApprovalPlugin（always-deny / auto-approve 白名单）二选一挂载
  - id: approval
    name: dev.duo.harness.tools.InteractiveApprovalPlugin

  # 写保护治理插件（示例）：对 write_file 声明 ask + guard 拦截涉密文件读取
  - id: write-protector
    name: dev.duo.harness.example.mcpfs.WriteProtectorPlugin

  # 重复调用提醒：同一工具相同参数连续重复达阈值（3/5/8）时在结果尾部附加提醒
  - id: repeat-reminder
    name: dev.duo.harness.example.mcpfs.RepeatReminderPlugin
    config: {}

  # Web 双面：本地浏览器界面（对话 + 状态 + HITL 卡片），只绑 127.0.0.1
  - id: web
    name: dev.duo.harness.web.WebPlugin
    config:
      port: 18080
```

## 逐行注解

| id | 插件类 | config | 作用与依赖 |
|---|---|---|---|
| `tools` | `tools.ToolsPlugin` | 无 | 发布 "tools" 服务（ToolDefinition 注册 + 三段管线 + 审批/ guard 挂点）。工具域是 MCP 与 agent 循环的前置 |
| `prompts` | `agent.PromptPlugin` | `systemPrompt`（可选） | 发布 "prompts" 注册表；systemPrompt 作为最前用户指令片段，全空落内置缺省 |
| `agents-md` | `agent.AgentsMdPlugin` | `{}` | 读 `~/.duo/AGENTS.md` 与项目根 AGENTS.md 拼接注入（64KB 预算）——声明 config 类型即须提供 config 块，字段可省 |
| `skills` | `agent.SkillsPlugin` | `disabled`（可选数组） | 发布 "skills" 注册表：四根发现 SKILL.md、清单片段、`skill` 工具挂载 |
| `answers` | `tools.InteractionPlugin` | 无 | 发布 "answers" 交互服务；回答者（console / web answerer）由演示入口在装配层注册 |
| `approval` | `tools.InteractiveApprovalPlugin` | 无 | inject "answers"——工具声明 ask 后由回答者逐次作答；无人应答 fail-closed |
| `write-protector` | `example.mcpfs.WriteProtectorPlugin` | 无 | 示例治理插件：write_file 声明 ask + guard 拦涉密读取——写自己的治理插件照此结构 |
| `repeat-reminder` | `example.mcpfs.RepeatReminderPlugin` | `{}`（阈值可省） | 同一工具相同参数连续 3/5/8 次时逐级附加提醒（advisory 非 guard） |
| `web` | `web.WebPlugin` | `port`（缺省 8080） | inject tools + prompts + answers——浏览器对话/状态/HITL 卡片；只绑 127.0.0.1；装配 ask_user 与计划呈交工具（纯 Web 部署 HITL 完整）；接管当前会话独占锁（被占则插件 FAILED 点名会话）；LLM 未配置则整体 FAILED |

## 通用约定

- **行序即装载序**：依赖别的东西先挂（如 approval 依赖 answers；web 依赖 tools/prompts/answers）
- **config 块**：插件声明了 config 类型就必须带 `config:` 行（免配置写 `config: {}`）；字段缺失按严格绑定失败并点名
- **二选一**：`approval`（交互审批）与 `ApprovalPlugin`（策略式：always-deny / auto-approve 白名单）都是审批策略服务，同装会冲突

## 不在 yml 里的挂载（编程形态）

| 能力 | 挂载方 | 等价 yml 形态 |
|---|---|---|
| `ask_user` 提问工具 | 演示入口构造注入交互服务后 `tools.register(root, new AskUserTool(answers))` | 无内置插件——工具注册即三行 Java |
| MCP files 连接 | `root.plugin(new McpClientPlugin(), config)`：`serverName` + `command` + `args` + `requestTimeoutMs` + `reconnect`（initialDelayMs/maxDelayMs/maxAttempts） | 等价行：`- id: files / name: dev.duo.harness.mcp.McpClientPlugin / config: {...}`（命令与参数随目标服务器而定） |
| console / web answerer | `answers.register(root, ...)`——回答者是呈现位组件，永远在装配层注册 | 无 yml 形态（ADR-0008：机制在核，呈现属装配） |
| 审计桥 AuditingAnswerer | 包装真实回答者注册——审批请求/决定落会话事件 | 同上，装配层组合关注点 |

## 出错怎么看

- 插件 FAILED：boot 审计输出会点名插件与原因（config 绑定失败带字段路径）
- 服务缺失：依赖方 PENDING，boot 输出列缺失的服务名——按名字检查漏挂的行
- 整树回滚：任一插件启动失败，已启动的按注册逆序回滚，不留半装配状态
