# 事件快照读侧零拷贝与单趟窗口

Status: 批准（2026-09-16，M14 grill 裁定，四问 + 实测校准）

M14（结构治理与性能）兑现 ADR-0013 决策 2 与 limitations M13#3 留档的两笔承诺：`events()` O(n) 拷贝优化与投影单趟化。grill 期实测修正了认知前提：80K 事件会话下 `events()` 拷贝仅 0.13ms，真正的成本在投影遍历本身（8~9ms/趟）——本决策的定位因此是**兑现债务承诺、消除结构性浪费、基准固化防回退**，不是用户可感的提速（端到端刷新秒级，成本主要在传输与渲染）。关键判断事实：事件日志 append-only（已追加内容永不变更）+ 读多写少（治理每轮、状态面 5s 轮询、回放分页都是读；写仅每消息/工具事件一次）——快照共享的天然前提。

## 背景

roadmap S4：`events()` 每次调用锁内 `List.copyOf` 全量拷贝，消费方横跨读侧——投影（治理每轮 + Web 状态面轮询）、分页定窗（`tailWindow`/`windowBefore`）、Web 回放（单次刷新 2~3 次拷贝）。80K 事件实测（本机、20 轮均值、grill 期临时探针）：`events()` 0.13ms、`deriveMessages()` 8.78ms、`tailWindow(50)` 8.31ms（≈拷贝 0.13 + 三趟遍历 ~8.2，每趟 ~2.7ms）。

## 决策

1. **事件快照读侧零拷贝（CoW）**：Session 维护 volatile 不可变快照引用——append 在锁内追加后重建快照（写侧 O(n)，80K 事件 ~0.13ms，写频率低可接受），`events()` 直接返回共享引用（读侧 O(1)）。读侧对外语义不变：仍是调用时刻的稳定不可变视图，并发安全语义（与 append 的隔离、遍历无 CME）原样保留，只是从"每次新建一份"变"共享同一份"。
2. **消息窗口单趟化**：`messageWindow` 三趟（计数 / 定位 / earlier 统计）收敛——`earlier ≡ tailStart`（未截断时同为 0，截断时起点之前恰有 tailStart 条投影消息），第三趟是恒等冗余，直接消除；起点定位用容量 O(max) 的投影下标滑动缓冲，单趟完成（至多保留两趟兜底）。80K 实测定窗 8.3ms 预期降至 ~3ms。
3. **基准固化**：grill 期临时探针（80K 事件程序化生成 + 计时）不进常规测试套件（拖慢全量）；转正为可手动触发的基准（默认跳过），数字落档本文与验收件，作为达标判定与后续回归参照。
4. **达标线**：80K 事件单次"分页定窗 + 投影回放"总投影成本 ≤ 15ms（现状 ~17-26ms），以落档基准数字判定。

## 拒绝的选项

- **投影结果缓存 / 增量投影**：`deriveMessages()` 的 8.78ms 是单趟遍历 + 对象构造的物理成本，缓存增量续算省的是毫秒级，代价是 Session 引入"缓存 vs 日志"一致性状态管理（哪些事件投影、失效语义、测试面扩大）——记 backlog，等真出现可感卡顿再立项。
- **请求内快照复用**（只合并调用、不动结构）：limitations #3 只算半兑现；且决策 1 落地后拷贝已消失，此优化失去对象。
- **分块不可变日志**（append O(1) + snapshot O(1) 的 Chunked 结构）：为单用户 harness 引入数据结构复杂度，过度设计；写侧 O(n) 重建在可预见规模下无感。

## Consequences

- session 域"事件快照"获得新实现语义：共享不可变视图（CoW）——术语表立"事件快照"词条，与"尾部窗口快照"（ADR-0013，协议层恢复形态）严格区分。
- limitations M13#3（全量投影优化属 M14）同 diff 删除，CHANGELOG 记账。
- 基准数字落档，后续里程碑性能回归有参照锚。
- 写侧每 append 一次 O(n) 重建是新增成本——若未来出现高频写场景（如事件粒度流式入库）需重新评估分块结构。

## 实测验收注记（2026-09-16，M14 工单 04）

基准转正为 `SessionPerfBenchmarkTest`（默认跳过，`-Dperf.benchmark=true` 手动启用；79,200 事件 JSONL 直写 + load 构造，20 轮均值，预热 3 轮不计；首次落档 9.00ms 含计时整数截断偏差，工单 04 审查期修正计时精度后复测如下）。优化后实测（M 系列 Mac）：

| 指标 | grill 基线（优化前） | 实测（优化后） | 变化 |
|---|---|---|---|
| `events()` | 0.13ms | 共享引用（O(1)，无拷贝） | 消除 |
| `tailWindow(50)` | 8.31ms | 2.11ms | -75% |
| `deriveMessages()` | 8.78ms | 7.48ms | -15% |
| 定窗 + 投影 | ~17.1ms | **7.60ms** | **-56%，达标线 15ms ✓** |

达标判定：**通过**。实现说明：单趟化的 earlier 并非严格恒等式——tool/result 回折把调用卡纳入窗口使起点前移，earlier 以 tailStart 为基线、按回折前移跨越的投影消息数扣减（既有窗口回归网当场拦截了初版恒等式假设）。
