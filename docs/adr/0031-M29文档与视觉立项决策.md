# M29 文档与视觉立项决策：版图顺移与范围增项

Status: 批准（2026-09-29，M29 启动 grill 八问逐项裁定；细化 [ADR-0029](0029-M27至1.0版图重排第二弹.md) M29 节并勘误其两处版本号）

## 背景

ADR-0029 版图定 M29=0.24.0（文档与视觉）、M30=0.25.0（发布产物）、M31=1.0.0（收口）。实际执行中插入的 C2 补丁式代码处置批（`.scratch/c2-code-audit/`，全库审计四轴驱动）占用了 0.24.0 并已于 2026-09-29 发版（CHANGELOG 落日期、分支已建），全仓无版图顺移记录在案——M29 启动需先钉版本号。启动 grill（2026-09-29）八问逐项裁定，探索底座：三章素材充足度实测（技能章充足——技能写作规范 190 行 + 16 个实例技能；MCP 与多插件协同散落 7+ 处待聚合，duo-harness-stats 为唯一范例插件但零 README）、Web 前端零构建三文件单页（vendor 直挂与工具卡按 toolName 二次分发均有先例）、ZCode 研究文档机制视角已备而视觉/交互形态视角缺位（呈现与UI 三篇共 122 行讲 wire 帧/投影 store/分发协议）、reasoning 管线全通（ChatMessage/LlmTurn/Message 三层有字段）但会话事件面仅 tool/call 携带（回传 provider 用，assistant 思考内容不进事件流）。

## 决策

### 版图顺移

版本号错位处置：**M29=0.25.0、M30=0.26.0，顺移一档；M31=1.0.0 收口锚点不动**。ADR-0029 M29/M30 节同 diff 原文加注勘误。

### 范围（三章 + 先行研究 + 视觉线四件）

ADR-0029 五件套照单全收，另增思考折叠卡一件；执行中新发现欠账一律登记 backlog 不扩范围（工具名协议化渲染维持留 1.0 后）。

**03-高级三章**（300-600 行/章）：

- **技能编写章 = SKILL.md 技能教程**：以《技能写作规范》为底座教程化 + 补发现/热加载/skill 工具机制侧；不含插件工具编写。
- **MCP 深入章 = 散落素材聚合升格**：连接生命周期与工具同步展开叙述、config 面（编程形态全表）、mcpfs 示例 walkthrough、connectorStatus 状态面消费。
- **多插件协同章 = 「从零写一个插件」端到端教程 + 多插件组装**：duo-harness-stats 四扩展点（事件监听/命令注册/工具注册/服务消费）串一插件为叙事主线；组装侧讲 provide/inject/optionalInject、事件协同、装配序。
- **大纲先行确认制**（ADR-0029 既定）：三章大纲齐出（机制点/示例/引用），载体 `.scratch/m29-docs-visual/outline.md` → 用户确认 → 每章一工单、成章即审查即验收。

**示例标准 = 活体引用**：三章示例锚定真实活体（duo-harness-stats、demo 装配 yml、既有 mcp 插件配置面），关键代码块可复制可编译；不为文档新写 demo 模块。

**视觉线**：

- **ZCode 形态研究（先行工单）**：源码级（本机 `/Users/zhangyl/IdeaProjects/ZCode/`，锚点 872ad960，v3.14.0），补齐现有研究缺的视觉/交互形态视角——思考折叠、分工具卡形态、子代理页、确认交互卡样式四块 + 对 duo 落地清单；产出喂走查与卡片工单。
- **整页走查打磨**：基线 = M8 冻结原型（`prototype.html`）+ 现有 DSH 亮色 token + ZCode 形态参照；打磨不重设计（不加暗色主题、不换色板、不重排布局）；重点区 = 分工具类型展示样式、子代理抽屉、审批/提问/计划卡样式；逐区域截图前后对照 + 用户目测裁定。
- **语法高亮**：highlight.js 全量 vendor 直挂（约 100KB，同 marked 先例零构建链；`/web/` 白名单与 token 注入已实测天然放行，零 Java 改动）。
- **成果卡片**：挂 present 工具卡二次分发（同 ask_user→提问卡、todo_write→todoCard 先例）；卡面 = 成果件数 + 逐行路径点击复制；deliverable/presented 事件保持不渲染（防同动作双卡，事件消费方检索/导出已有着落）；「与导出交付清单联动」= 同源展示，不另加导出按钮。
- **思考折叠卡（增项）**：完成态折叠卡——后端把 assistant 思考内容补进会话事件面（一次补齐），前端折叠卡默认收起、点开全文，回放/实时同源；流式实时思考展示挂 backlog。

## 拒绝的选项

- **回填 0.24.0**：C2 已发版落日期，分支与 tag 均在，历史不可回改。
- **M29+M30 合并 0.25.0 一期发版**：写作/前端/发布性质互异混一期，违背「每期只对一类东西负责」——ADR-0029 拆解动因重演。
- **技能编写章扩为泛扩展编写（SKILL.md + 插件工具都讲）**：与多插件协同章衔接负担重，素材分布不支持。
- **「从零写一个插件」独立成第四章**：超 ADR-0029 三章口径。
- **示例用示意片段 / 活体 + 机械一致性校验**：前者接口演进后文档静默失真（注释失真有既往教训）；后者每章多一道工序收益不足。
- **走查升级含暗色主题 / 只修缺陷**：前者扩范围（新主题非打磨）；后者深度不足背不动「脸面」命题。
- **成果卡挂 deliverable/presented 事件渲染（双卡）/ 卡上放导出按钮**：前者同动作双卡需去重；后者新增卡片交互通道（C2 刚收敛按 id 回填通道，不轻动）。
- **思考折叠流式 + 完成态全要 / 整体入 backlog**：前者视觉期掺纵向技术链（适配器增量上报→agent 透传→增量帧→前端实时渲染），审查面变宽；后者放弃 1.0 前交互亮点，且管线数据全通只差落事件一步。

- backlog 新增「流式思考展示」条目（Web 呈现域节）。
- 术语表 Web 呈现域新增「成果卡片」词条（同 diff）；思考折叠卡词条留 spec 期形态定稿后随首个实现工单同 diff 落表。

- 每期流程不变：grill → to-spec → to-tickets → 逐工单实现 → 四轴审查 → 用户验收 → 发版。
