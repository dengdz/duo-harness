# M31 文档官方化立项决策:文档期插入,收口顺移 M32

Status: 批准（2026-10-01，M31 启动 grill 九问逐题裁定；[ADR-0029](0029-M27至1.0版图重排第二弹.md) 的 M31 节（1.0.0 收口）整体移至 M32——其 M27-M30 各节与横切口径维持有效）

## 背景

ADR-0029 版图定 M31 = 1.0.0 收口（核对与盖章，纯手续期，约 4-5 工单）。M31 启动 grill 首步版图对账通过（CHANGELOG 实发 0.26.0 与版图一致，无顺移争议）；范围确认时用户提出：**文档站需要以官方说明文档的形式呈现，需要一次大调整**。

现状核查（2026-10-01 实测）：文档站已有五段骨架（01-入门 / 02-指南 / 03-高级 / 04-架构 / 05-参考，共 13 篇），但存在两个实质差距——①通篇开发过程叙事：《运行Demo》开头即「状态：M1+M2 一条命令演示全链路可用；M3 聊天 REPL……」的里程碑流水账口吻，首页「文档之外」直挂 research/（参考项目考古）与 agents/（agent 工程设施）等内部材料；②指南层严重单薄：02-指南仅 1 篇，权限审批、会话恢复、斜杠命令、模型档位、导出检索、子代理、hooks、MCP 接入等已交付能力**没有任何一篇「我想做 X 该怎么操作」的指南页**。

硬联动：1.0 判定标准第三项「文档三层齐备」若按现状核对，大改完成后即作废——文档官方化必须在收口核对**之前**完成。另经实测核定：README 与《运行Demo》对演示入口承诺的均为 `mvn exec:java` 形态，`java -jar` 承诺仅覆盖 DuoMain（M30-01 已切资源通道），backlog「演示入口 jar 形态必炸」洞属承诺范围外（见范围排除节）。

## 决策

### 版图第三改：M31 = 文档官方化（0.27.0），收口顺移 M32（1.0.0）

- 文档官方化独立成期（体量 12-15 工单，与 M29 同量级），不与收口手续混装——ADR-0029「每期只对一类东西负责」总纲不变。
- **1.0 锚点只挪期号不取消**：原 M31 收口五件（具名候选终审 / 移出项与 1.0 后菜单终审 / 判定四项出证据 / 1.x 版本策略声明 / 盖章 1.0.0）范围不变，整体移 M32。
- 判定四项证据形态预先裁定（M32 立项时启用）：acceptance.md 核对表四项各一节逐项出示证据 + 盖章时择要并入 CHANGELOG 1.0.0 段（历期验收件先例 + 永久档案轻量并轨）。
- ADR-0029 M31 节同 diff 加指针注，内容保持原样（ADR-0024→0029 先例形态）。

### M31（0.27.0）文档官方化——「官方说明文档形态」

幅度三档中定 **C 档（全面官方化）**，三批：

1. **口吻重写批**（现有 13 篇去里程碑叙事，改产品文档口吻）：首页 index（产品简介 + 快速开始前置，research/、agents/ 内部材料退出站内导航）；01-入门《运行Demo》改写《快速开始》（`java -jar` 一条命令前置，mvn 源码形态与 headless 降为次要小节——现状相反）；02-指南现有篇与 03-高级三章（M29 新交付、锚定源码，预计微调）；04-架构两篇（保留设计叙事，剥离里程碑编号与历期引用）；05-参考六篇（核对补漏）。
2. **指南层新增批**（02-指南 1 → 约 8 篇，每篇 = 「我想做 X 怎么操作」）：权限与审批 / 会话管理与恢复 / 斜杠命令 / 模型与思考档位 / 导出与检索 / 子代理 / hooks / MCP 接入（与《MCP 深入》分工：指南讲配置与使用，高级讲机制）。
3. **参考层新增批**（3 篇）：config.yml 全量字段参考 / CLI 参考（启动参数 + REPL 快捷键 + 斜杠命令清单）/ Web 界面使用说明。

执行形态：

- **大纲确认制沿用**（M29 先例）：全站大纲与篇目清单 = 工单 01 → 用户确认 → 逐篇交付、成篇即审即验；顺序：口吻重写批 → 指南批 → 参考批 → 首页/架构收尾。
- **立产品文档口吻规范**（几十行，落 `docs/agents/`，不进站内公开导航，随工单 01 同批产出）：用户任务视角组织 / 里程碑叙事禁入正文（历史归 CHANGELOG 与 ADR）/ 术语对齐术语表——后续每篇审查的可引用尺子；13 篇重写与 10+ 篇新增若无成文标准，里程碑叙事随时回流。
- 口吻重写剥下的旧叙事材料**直接删除不存档**：完整历史已由 CHANGELOG、ADR、git 历史承载，文档站不承担考古职责。

### 随批落地项

- AGENTS.md 显式命令表 `/grill-me`、`/grill-with-docs` 两行加注「开工先读 duo-workflow 经验档」——逐题提问纪律四犯存证（M23→M24→M27→M30）后的机械强制，本次落（外部 grill 技能漏在红线 8 字面之外，加注补网）。
- `0.27.0` 分支随本 ADR 自 main 切出；发版沿用 release.yml 自动化（tag 即发布，M30 首秀两轮过，不特殊化）。

### 范围排除

- backlog「演示入口缺省资源文件化读取残留（jar 形态必炸）」**维持挂账不入本期**：堵它需给 5 个演示入口类逐个切资源通道，测试成本花在没人承诺过的场景；若日后想将 DemoMain 装进 jar 再立项。

## 拒绝的选项

- **文档官方化并入 M31 双职责**：15-20 工单混装违背「每期只对一类东西负责」，审查与验收质量稀释——正是当初拆解 M27 收口期的动因。
- **A 档（仅口吻重写）/ B 档（+指南扩容）**：指南层单薄是「官方感」的实质缺口；B 档参考层仍缺（config/CLI/Web 三参考是官方文档标配）。用户明示「大调整」，一次定形避免 1.0 后返工。
- **文档官方化放 1.0 后**：官方说明文档是 1.0 脸面的组成部分；先盖章后大改门面，「文档三层齐备」判定即走过场。
- **C 档不分批一次交付**：20+ 篇无大纲确认与逐篇审查，质量必然稀释；大纲确认制是 M29 验证过的文档期交付纪律。

## Consequences

- ADR-0029 M31 节由本决策移至 M32（原文加注不改写）；其 M27-M30 各节、横切口径（理解关卡补考不排期、每期 grill → to-spec → to-tickets 流程）继续有效。
- 1.0 锚点移至 **M32**；0.27.0 照常发版（CHANGELOG 锚点纪律不变）。
- M32 收口时「文档三层齐备」核对对象 = 本次大改后的文档站——判定口径就此钉死为大改后状态。
- 「产品文档口吻」概念随口吻规范入术语表（工单 01 同批）；`docs/agents/` 新增一份面向维护者的写作规范（不进公开导航）。
- backlog「演示入口 jar 形态」条目同 diff 加 grill 裁定注（承诺外维持挂账）。
- AGENTS.md 加注后，此后 grill 类会话的「开工读经验档」由环境提示兜底，不再依赖模型自觉。
