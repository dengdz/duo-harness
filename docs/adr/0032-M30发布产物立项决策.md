# M30 发布产物立项决策：范围锁定与发布形态

Status: 批准（2026-10-01，M30 启动 grill 六问逐项裁定；细化 [ADR-0029](0029-M27至1.0版图重排第二弹.md) M30 节）

## 背景

ADR-0029 版图定 M30=0.26.0（发布产物——「拿得出手」，勘误注在案）。启动 grill 首步版图对账一致：CHANGELOG 顶部实发 0.25.0（tag v0.25.0 已打，即 main HEAD），无错位无顺移议题。搭车件已裁定在先：会话持久化 defer 化工单（2026-10-01 用户裁定归 M30，`.scratch/m30-release/issues/05-deferred-session.md`，自 m30-session-lifecycle 单间目录迁入，研究锚点与 checklist 齐备）。实现面实测四项：全仓无 shade 配置、无 release workflow（ci.yml 门禁 `contents: read` + docs.yml Pages 两件）；README 停在 0.15.0 叙事（演进史三段陈账 + M1/M2 demo 叙事 + 缺快速开始）；**DuoMain 缺省 yml 经 `Path.of(getResource().toURI())` 文件化读取——fat-jar 内资源 URI 为 `jar:` 形态必炸**（`HeadlessArgs` 同型两处），即「`java -jar` 即跑」现状不成立；web 静态资源走 `getResourceAsStream` 天然兼容、`~/.duo/config.yml` 为文件系统路径，均不受影响。缺省装配 agent-demo.yml 为 web + cli 双呈现位（行序契约合规）。

## 决策

### 范围：锁定四件，backlog 不拉项

定版三件（shade fat-jar / CI 挂 GitHub Release / README 重写）+ 会话 defer 化，共四件。backlog 候选项一律不拉：流式思考展示与查阅组卡嵌套的评估点均为「视 M29 使用反馈/观感」，反馈期刚开始；bind 地址配置化属安全面独立议题；Web 斜杠命令异步化触发条件罕见；user.dir 取值提取为工程洁癖项。

### 发布面：GitHub Release + SHA256，Maven Central 有意不做

分发渠道只走 GitHub Release（ADR-0029 定版口径确认）；产物 = fat-jar + `.sha256` 校验和。源码 jar / javadoc jar 为 Central 配套要求，不挂。

### 发版 workflow：独立 release.yml

`.github/workflows/release.yml`，不塞 ci.yml。触发 = push tag `v*`；步骤链 = tag 与 pom 版本一致性校验（`v<pom.version>` 不等即失败）→ 全量 verify（测试不过不发版）→ 生成 SHA256 → 创建 Release 挂 jar + 校验和；Release notes 用脚本从 CHANGELOG.md 对应版本段摘录，不用 GitHub 自动生成（PR 列表与 CHANGELOG 唯一锚点形成两本账）。权限 `contents: write` 仅此文件持有。

### fat-jar：example 模块 shade + 去 example 后缀 + Boot API 资源化

- shade 挂 `duo-harness-example`（唯一聚合全部插件装配的模块），`Main-Class` = `dev.duo.harness.example.DuoMain`，`finalName` 定制为 `duo-harness-<version>.jar`（对外名字不带 example）。
- 缺省 yml 的 fat-jar 兼容改造走 **Boot API 资源化**：给 Boot 装载加资源流通道（新增重载不动旧签名），DuoMain/HeadlessArgs 缺省分支切换到资源装载；`validatePresenterRowOrder` 的预检输入同步适配（InputStream 单次读取，预检与装载的读取顺序 spec 期钉）。
- shade 常规处理：签名文件 exclude、`META-INF/services` merge（MCP SDK 依赖）。

### README：中文为主全新门面 + 验收期全景图

结构 = 一句话定位 → 三行快速开始（JDK 21 前提 + `java -jar` + `~/.duo/config.yml` 最小配置样例【占位符，API key 永不入库】+ 双呈现位第一眼）→ 能力概览（当前版本面，不按版本史）→ 模块表微调保留 → 文档站入口。0.1.0-0.15.0 演进史压缩成一句（CHANGELOG 已是完整账本）；「一条命令看它做什么」demo 叙事段替换为 `java -jar` 快速开始，Demo 降级到文档站「运行 Demo」页。验收期配 web 面全景截图一张（对话流 + 工具卡 + 思考折叠卡）。

### 工单组织：统一目录一本账

建 `.scratch/m30-release/`（spec.md 覆盖发布产物 + 会话生命周期双域），defer 化工单 git mv 迁入（backlog 引用同 diff 更新）——M29 先例：一个目录一本账，收口对账不跨两处。

## 拒绝的选项

- **Maven Central**：GPG 签名 / Sonatype 流程 / 源码与 javadoc jar 配套，发布门槛显著抬高；duo 是本地单用户工具（`java -jar` 即跑、`~/.duo` 本地配置），非被 import 的库定位。
- **校验和省略**：成本约 5 行 workflow，「拿得出手」的门面细节，不省。
- **release workflow 塞进 ci.yml**：`contents: write` 权限放宽到所有 push/PR 门禁触发，职责与权限双混。
- **免 tag-pom 版本一致性校验**：tag 手滑（`0.26.0` 无 v / `v0.27.0` 错位）时 workflow 照发，产物名与 tag 静默错位，fail-closed 值得一步。
- **缺省 yml 临时文件桥接**：classpath 流读出写临时文件再走既有 Path 路径——改动最小但引入临时目录落盘副作用（写权限/清理），且资源装载留为二等路径；Boot API 资源化让资源装载成为内核正门能力（用户裁定）。
- **README 保留 demo 叙事 / 演进史全保留 / 英文重写**：demo 是机制演示非用户入口，docs.yml 触发路径已含 README.md 无部署负担；演进史与 CHANGELOG 双本账；docs 站全中文下 README 独英文形成双轨负担。
- **backlog 拉项（流式思考 / 组卡嵌套 / bind / 斜杠异步化 / user.dir 提取）**：各自评估点未到或主题不符，见范围节。
- **defer 化工单留原地双目录**：收口与 backlog 对账跨两处，违背 M29 一本账先例。

## Consequences

- 版本分支 0.26.0 已自 main 切出（2026-10-01）。
- `.scratch/m30-release/` 立账；defer 化工单迁入，backlog「会话生命周期」条目路径同 diff 更新。
- Boot 资源装载通道为内核接口新增（M27/M28 规范化边界内的增量重载）——实现期同 diff 核查 `Boot.from` 全部消费点（duo-workflow 经验档：接口新增通道须排查装饰/包装实现透传）。
- 发版时序钉死：验收后 14 处 pom 对齐 0.26.0 → CHANGELOG 落段 → 合并 main → 打 tag `v0.26.0` → release.yml 校验发版。
- 术语表：deferred 会话 / draft 等会话域新词条随 defer 化实现工单同 diff 落表（同 ADR-0031 思考折叠卡先例）；引擎/机制采纳类 _Avoid_ 反噬检查不适用（无外部机制名转正）。
- 每期流程不变：grill → to-spec → to-tickets → 逐工单实现 → 四轴审查 → 用户验收 → 发版。
