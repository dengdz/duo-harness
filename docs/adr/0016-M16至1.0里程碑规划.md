# M16 至 1.0 里程碑规划：质量先行、并发居先与 DSH 复审校准

Status: 批准（2026-09-17，M15 发布后规划，经 DSH 功能全景复审校准并经用户三项裁定确认）

M15（0.10.0）发布后，[ADR-0007](0007-里程碑重排agent循环提前.md) 的 M9+ 具名候选期剩余项（并发工具调度、hooks、附件、会话查询/导出、沙箱/权限深化）需要排出具体顺序。本决策给出 M16 至 1.0 的完整版图。事实基础：CHANGELOG 0.1.0-0.10.0 全量、limitations 全部挂账、`.scratch/backlog.md`、双轴质量审查（`.scratch/quality-review-20260917.md`）Top 10 问题、subagent 三方对照差距（[docs/research/subagent-派发与提示词对照.md](../research/subagent-派发与提示词对照.md)），以及以 [docs/research/DSH/核心功能全景.md](../research/DSH/核心功能全景.md)（锚点 c291e796）为对照系的功能复审。

复审对初版规划审出四类校准，均并入本文决策：**重大漏项**——web 工具族（DSH 默认启用 web_search/web_fetch，duo 工具清单零覆盖，且 ADR-0007 具名候选期即未列入）；**三处设计修订**——并发结果提交序、hooks 生态兼容形态、父级 steer 缺位；**鲁棒性缺口**——会话崩溃恢复语义；**优先级再校准**——会话查询/导出降权、todo_write 提前、沙箱研究三路化。

## 决策

排期逻辑：

- **质量先行**：M15 刚发大功能，双轴审查已把设计做完的债（Top 10）先清；CI 建成后 M17 起每期都有回归门禁，复利最高。
- **并发居先、hooks 居后**：hooks 要在并发管线之上设计才不用返工；DSH 的 `isConcurrencySafe` + 独占屏障 + model 序提交词汇直接照搬，消解事件乱序对 M10 游标回放与 M13 单趟定窗假设的冲击——这是本期 grill 主战场。
- **体验还账居中**：M19 集中清掉已点名的交互债（/compact、Web 斜杠、亲和路由）；steer 补齐父子语义不对称。
- **web 工具族入册**：联网是 agent 能力而非工具 UX，DSH 默认启用即优先级证词；插入为独立一期（用户裁定①）。
- **沙箱压轴带出栈阀**：平台依赖最重、唯一重大不确定点；研究结论决定进 1.0 还是出栈（用户保留此弹性）。
- **1.0 判定标准**：具名候选全部 done 或明示出栈；CI 绿为常态且无 S 级质量债；文档三层齐备（含 03-高级）；安全基线闭合（Origin 防护 + 审批钉死 + 沙箱进退决议）。

本决策细化 ADR-0007 的 M9+ 具名候选期排序——其"其余按需逐期，顺序到时再定"自本文起由本表接管；ADR-0007 其余内容（M3-M8 序列、小步渐进原则）继续有效。上下文治理、subagent 两候选已分别于 M9/M15 完成，本表不再列。

## 拒绝的选项

- **守住七期，把会话查询/导出降菜单**：DSH FTS5 默认不启用的证据支持降权，但同期只需与附件拼一期即可两全；联网入册 + 查询留守的八期版图更完整（用户裁定①的对照组）。
- **hooks 自定 yml 钩子协议**：发明新格式割裂生态——DSH 直接复用 Claude Code/Codex 配置，兼容即上手成本归零。
- **M17 结果按完成序提交**：投影与重放需自行消化乱序，冲击 M10/M13 既有算法假设；DSH 证明 model 序提交即可（执行并发、提交有序）。
- **父级 steer 不做（维持 409 单飞）**：与子代理 send_message 语义不对称，运行中纠偏是真实体验伤（DSH steer 验证需求）。
- **沙箱提前**：平台分化最重，未研究先排期是空承诺；e2b 云沙箱作为第三路纳入研究而非预设结论。
- **对齐 DSH 的无 REPL / React 多插件 UI / preset-bundle 层叠**：duo CLI 呈现位是优势形态（DSH 缺位而非方向），静态单页是 M8 裁定，yml 一行装配已覆盖 profile 需求——差异定位不是缺陷，不反向对齐。
- **PTC run_code / workflow-ralph / agent-team / LSP / PTY 持久终端 / 跨 harness 委派后端 / Anthropic-messages 适配等进 1.0 前**：全数入 1.0 后菜单（`.scratch/backlog.md` 已增记），不为 parity 而 parity。

## Consequences

- limitations 指针同步更新：M9-M11#3 手动压缩去向改指 M19；M15#6 分解抓手改指 M17；M12#1 沙箱去向补注 M22（同一 diff）。
- backlog 对账同一 diff：治理阈值 yml 化、分页范式两项销账（0.8.0 已交付）；已入册项标注目标里程碑；新增 1.0 后菜单段。
- 每期启动仪式不变：切版本分支 → grill（+ADR）→ to-spec/to-tickets → 逐工单实现 → 验收 → CHANGELOG/limitations 同 diff 收口 → 双轴审查 → 合并 main；启动时先扫 backlog 挑可搭车项。
- M16 起每期合并前跑双轴审查（M15 起的实践固化为流程）。
- 理解关卡补考挂账至 M23 前集中两场（用户已裁定延后）。
