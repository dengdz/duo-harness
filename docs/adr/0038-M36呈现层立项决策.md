# M36 立项决策：呈现层——主题 token 体系、卡片声明式模板与生态开放面

Status: 批准（2026-10-03，/grill-with-docs 八问逐题裁定，共识纪要经用户确认后落盘；1.0 后轻量里程碑制第四期 M36，兑现 ADR-0037 决策四）

## 背景

M35 已收口（1.1.0 实发，2026-10-03 验收），生态链路在位：插件包装载、插件中心、端点贡献口 `webRoutes`、行级控制 `pluginRows`。M36 兑现 ADR-0037 决策四的呈现层两台阶（主题 token 换肤 + 工具卡片声明式模板，销账「工具名协议化渲染」），并并入 M35 工单 06 验收期用户裁定的「Web 页面全视觉 pass」（backlog 2026-10-03 条：token 化 + 全页视觉 pass + 插件中心精修）。

版图对账：CHANGELOG 实发 1.1.0（tag 在）；ADR-0037 定 M36 = 1.2.0，无错位。分支 `1.2.0` 待 /to-spec 拆工单后自 main 切出。

实现面实测底座（探索代理 smoke 级核查，HEAD 5ba6473e）：

- `theme.css` 头部已有 19 个 token 的 `:root` 块，头注释立约「token 只增不改名」（对外锚点）；无任何暗色机制（`prefers-color-scheme`/`data-theme` 零命中）；`:root` 外约 20 处硬编码色值（扫光动画、子代理八色、diff 红绿、抽屉阴影）+ 鉴权横幅 JS 内联样式，暗色下必漏色；highlight.js 为独立亮色 GitHub 主题文件、与 token 体系脱钩。
- 工具卡片分型是 render IIFE 内的 if/else 工具名链；工具名散布约 20 处、跨 5 类用途（图标/中文名/参数摘要/分型分支/结果特判）；三条魔法串语义判定（`deny` 前缀、`执行被拒绝|执行失败` 正则、`已获批准` 包含）横跨 agent/tools/web 三模块，CLI 测试有耦合断言。
- `webRoutes` 贡献口仅 HTTP 端点通道；静态资源服务、页面结构、SSE 均内核独占，前端无任何插件注入点——主题与卡片模板的贡献需要新开受控口，属架构演进而非前端改造。
- 插件中心抽屉向导为原生 `prompt()`/`confirm()` 对话框驱动，精修 = 重做卡内表单交互流，非 CSS 修改；三列布局为固定像素列宽（220px/1fr/360px）。

## 决策（grill Q1-Q8）

### 一、范围四至（Q1）：三块一体

① 主题 token 体系：收拢颜色/间距/字号为变量集，换肤 = 换一套变量值；顺手修三档视觉债务（鉴权横幅、宽屏三列塌陷、插件中心抽屉表单堆形态）+ 插件中心精修。② 工具卡片声明式模板：分型由注册表驱动，替代前端约 20 处工具名硬编码——销账 backlog「工具名协议化渲染」（含后端魔法串半边，见决策五）。③ 生态开放面：第三方插件可贡献主题与展示型卡片（决策二、四）。明确不做（维持既定）：插件自带页面、整页替换（ADR-0037 拒绝项）；查阅组卡嵌套（backlog 另案，视观感再立项）。

### 二、主题开放面与交付形态（Q2/Q6）

插件可贡献主题：一个主题插件包装上即入主题列表，复用 M35 插件包/插件中心链路（装主题 = 装插件，停/卸 = 回落默认主题）。交付形态 = **token 值集声明**：结构化变量值，前端套到根元素 CSS 变量上——第三方改得了所有变量值、注入不了任意 CSS 规则（改值不改构），与审批槽位开放同构的安全哲学（表达力换安全面）。高亮配色：内置主题自带配套高亮配色（token 联动），第三方主题选内置高亮配套或映射语义色——独立亮色 GitHub 主题文件随本期统一。

### 三、内置主题与视觉语言（Q4/Q5）

单暗色精品：本期只交付一套打磨到位的暗色主题（内置主题是第三方作者的参照系与默认观感的直接决定因素），亮色留给第三方主题或后期——token 集结构与具体值分离，亮色后期零结构成本。气质锚点 = 开发者工具精致风：低饱和深底 + 单一强调色 + 细边框 + 适度留白；色值/圆角/字号细节 spec 期出样式稿截图对照裁定（M35-06 先例），grill 不锁细节。

### 四、卡片模板：开放面与贡献通道（Q3/Q7）

展示卡开放、交互卡独占：第三方插件可贡献/替换**展示型**工具卡的声明式模板；审批/提问/计划卡承载 fail-closed 安全交互语义（点拒绝 = 真实拒绝），留内核独占——一句话边界：改得了长相，改不了交互语义。贡献通道 = **新开呈现贡献口**：Web 域新发注册表服务，与 `webRoutes` 同哲学（申请制 + 同工具名冲突点名拒绝）；先到先得，卸了再装 = 替换语义，不引入后装覆盖。前端声明式注册表在 render IIFE 边界开注册口（M29 边界纪律），内核为全部内置工具注册全量表。

### 五、语义收敛（Q8）：魔法串同批收

后端事件载荷补结构化枚举字段（审批事件补 decision、工具结果补 status），前端改读字段、不再嗅探中文文案；旧文案保留（纯新增，1.x 向后兼容承诺内），CLI 侧耦合断言不动。销账完整性：backlog「工具名协议化渲染」原话含「后端'拒绝'魔法串判定审批语义」半边，同批收敛才销得完整；且卡片模板消费成败语义，模板声明里写文案正则即新债。

### 六、版图（既定确认）

M36 = 1.2.0；分支 `1.2.0` 自 main 切出，开发提交不落 main（红线 7）。

## 拒绝的选项

- **CSS 文件注入式主题**：表达力最强但等于给插件开任意样式注入面——能弱化拒绝按钮、伪造状态色，与「交互卡独占、fail-closed」裁定直接冲突。
- **token 值 + 白名单附加 CSS 段**：折中形态，但白名单边界是长期维护负担，一期不背。
- **仅内置多套主题可切换**：token 化退化为内部工程，「换肤」生态诉求只兑现一半，插件中心装不了主题包。
- **明暗双主题**：两套都调到及格线以上视觉 pass 火力翻倍；亮色半边未被验证的代价由「token 集与值分离」消解，第三方或后期补。
- **终端拟真风 / 出稿再定气质**：等宽排版在信息密度上吃亏；气质不定则 token 分组命名无锚点——细节仍留样式稿对照。
- **工具注册元数据承载卡片声明**：自家工具声明优雅，但「替换别家工具的卡片」绕不通（替换者非工具提供方），且触及工具注册契约，跨模块手术面大。
- **后装覆盖式替换语义**：先到先得 + 卸了再装已覆盖替换诉求，覆盖语义引入顺序敏感的隐式契约。
- **魔法串留后期**：销账半截 + 模板声明写文案正则 = 把新债写进新机制。
- **查阅组卡嵌套入本期**：前端事件流聚合投影是架构级特性，backlog 既定另案。

## Consequences

- 分支 `1.2.0` 于 /to-spec 拆工单后自 main 切出；开发提交不落 main（红线 7）。
- 存量账处置随对应工单同 diff 执行：backlog「工具名协议化渲染」「Web 页面全视觉 pass」两条销账；四处预登记兑现并更新——ADR-0029「协议化渲染留 1.0 后」、扩展点清单「协议化渲染与主题 token 列 M36 呈现层期」行、`WebRouteRegistry` javadoc「呈现层开放的后续台阶」、术语表内核独占面词条预埋「工具卡片模板经声明式模板开放」。
- 术语表同 diff 入册：主题令牌、主题包、呈现贡献口、展示卡、交互卡五词条；内核独占面词条同步改写（本 diff 已落）。
- 文档义务：主题包与卡片模板贡献的作者文档（M35 交货文档续章）；已知限制页补「主题只能改 token 值不能改布局」「交互卡独占」类条目。
- spec 阶段待定细节（非悬置——/to-spec 时定点处理）：主题切换入口与持久化形态（推定状态面板 + localStorage，可改）、主题/呈现两贡献口的服务命名、token 分组命名法、工单拆分粒度、样式稿对照的裁定方式。
