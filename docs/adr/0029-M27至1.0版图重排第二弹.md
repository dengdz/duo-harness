# M27 至 1.0 版图重排第二弹：收口期五段拆解

Status: 批准（2026-09-27，M26 发布后立项 grill 九问逐项裁定 + 终局清单确认；取代 [ADR-0024](0024-M23至1.0里程碑版图重排.md) 的 M27 节——其 M23-M26 各节与 1.0 判定标准维持有效，原 M27 收口内容整体移至 M31）

## 背景

ADR-0024 将 M27 定为 1.0.0 单期收口：03-高级三章、视觉打磨轮、release 产物分发、理解关卡补考（M3-M26）、具名候选终审、1.x 版本策略声明。启动前的事实核查（2026-09-27）显示各子项体量均够独立一期：03-高级目录不存在（全站现有 10 文档共 1670 行，三章各 300-600 行）；release 产物为零（无打包无 GitHub Release，README 停在 0.15.0）；补考欠账约 20 门（M3/M4/M6-M22 + M25/M26，M23/M24 已用亲历验收抵扣）；CI 绿常态与具名候选清账**已提前达成**。用户据此发起拆解，并新增两期质量工程（插件化审查、规范化重构）以确保 1.0 后功能的可演进性。

## 决策

### 排序总纲

**先把代码改对（插件化+规范化），再讲清（文档）、穿上衣服（视觉）、装进盒子（发布）、盖上钢印（1.0）**——每期只对一类东西负责。硬联动依据：03-高级三章讲的就是插件体系（技能编写/MCP 深入/多插件协同），插件化审查若在文档期后，接口变更即致文档返工；规范化大重构后代码方为定稿，文档与产物以定稿为对象。

### M27（0.22.0）插件化审查——「后续功能挂得上」

内核面（Boot/Context/Plugin/Service 边界：新插件能挂什么钩子、能消费/发布什么服务、内核独占面）+ 全仓用法（绕过插件机制的硬连点扫描——已知线索：装配线性增长（chatAgent 全参重载 14 参、全仓最大装配点 CliPlugin.registerCommands 17 参）、三呈现位（CLI/Web/headless）接线同构重复；2026-09-27 M27 启动 grill 实测勘误，立项原文「PresenterAssembly 装配 15 参、双呈现位接线重复」）+ **未来功能挂载点预演**：从 1.0 后菜单挑 2-3 个功能（如 cron/goal）推演"今天做成插件会在哪里卡住"，卡点即真缺陷。审查驱动小步改（接口手术精度，不大拆伤稳）。验收 = **demo 插件**（不动内核一行代码接入新能力）+ 审查报告。

### M28（0.23.0）规范化重构——「代码优雅化」

挂账清偿（Data Clumps 三处同构、user.dir 取值 19+ 处提取、WebFace 大文件拆分、装配 15 参参数对象化——均 review-log 多轮审查验证过的痛点）+ 全仓设计模式审查（命令分发族/provider 映射/装配层等策略-工厂形态的该用未用点）。重构执行期（与 M27 的审查形态相对）。度量轻量做：审查代理前后对比 + 少量脚本统计，**不引入 PMD 等工具依赖**（独立工程化决策，不与重构验收捆绑）。

> 勘误（2026-09-28，M28 启动 grill 实测）：装配参数实测 chatAgent 全参重载 14 参（非 15；全仓最大装配点为命令注册接线 17 参）；user.dir 同形实测 22 处（非 19+）。范围档位、H-03 破坏性变更许可、步子大小红线与完成判据详见 [ADR-0030](0030-M28规范化重构立项决策.md)。

### M29（0.24.0）文档与视觉——「1.0 的脸面与说明书」

> 勘误（2026-09-29，M29 启动 grill 裁定）：版本号顺移一档——M29 实发 **0.25.0**（0.24.0 已被插入的 C2 补丁式代码处置批占用发版）、M30 实发 0.26.0，M31=1.0.0 锚点不动；范围细化与增项（思考折叠卡）见 [ADR-0031](0031-M29文档与视觉立项决策.md)。

03-高级三章（技能编写/MCP 深入/多插件协同）——**大纲先行确认制**：三章大纲齐出（机制点/示例/引用）→ 用户确认 → 逐章交付（每章 = 工单，成章即审查即验收）。视觉三件：整页走查打磨本体（截图前后对照 + 用户目测裁定）、语法高亮（highlight.js ~100KB vendor 直挂，同 marked 先例不引构建链）、present 成果卡片（DSH 形态，与导出交付清单联动）。工具名协议化渲染留 1.0 后。

### 横切口径

- **理解关卡补考**：约 20 门**不排期、用户主动发起**（取代 ADR-0016"1.0 前集中两场"裁定——单场 10 门违背记忆规律，与拆解 M27 的同一逻辑）；闸门口径延续（凭证未发，拆下阶段工单前停下询问）。
- 每期流程不变：grill → to-spec → to-tickets → 逐工单实现 → 四轴审查 → 用户验收 → 发版；CI 绿常态跨期持续观察（判定证据）。

## 拒绝的选项

- **M27 单期内部拆 12-15 工单**：六类性质互异的活（写作/前端/发布/学习/手续）混一期，审查与验收质量稀释——用户发起拆解的动因。
- **文档期先行**：插件化审查若改插件接口，03-高级三章（讲插件体系）即返工。
- **PMD/CPD 等度量工具进构建**：新依赖 + "指标达标"易变数字游戏；重构质量与工具化解耦，后者真需要时单独立项。
- **补考维持集中两场**：20 门的单场高强度学习效果必然差；且质量两期的全仓审查天然是复习材料，绑定本可两全——用户裁定更轻：不排期、主动发起。

## Consequences

- ADR-0024 M27 节由本决策取代并在原文加注；其 M23-M26 各节、移出项清单、1.0 判定标准继续有效（判定核对移至 M31 执行）。
- 1.0 锚点从 M27 移至 **M31**；中间各期版本号 0.22.0-0.25.0 照常发版（CHANGELOG 锚点纪律不变）。
- ADR-0016"集中两场补考"裁定由"不排期、用户主动发起"取代（本文档即为变更记录）。
- 每期启动第一步照旧：从 main 切版本分支（0.22.0 已随本决策切出）。
- backlog 对账（同 diff）：「视觉打磨」「03-高级」「语法高亮」三词条目的建议时机由 M23(旧口径) 更正为 M29；「present 渲染」评估点提前至 M29（原 07 评估或 1.0 后）。
