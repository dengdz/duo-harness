# CLI 插件化：呈现位对称、通用启动器与 idle 语义

Status: 批准（2026-09-14，M11 grill 裁定）

修正 CLI 的架构定位：从"example 模块里硬编码的入口程序"升级为与 WebPlugin **对称的呈现位插件**。修正 M8 起形成的"一条命令 = CLI + Web 双入口硬绑定"结构（AgentReplMain 三职责混杂：装配 + 呈现 + 启动器）。参照系：本仓库插件化总纲（AGENTS.md：能力以插件组装）与 WebPlugin 先例（M8）。

## 背景

插件化理念确立以来，所有能力都以插件组装——唯一的例外是 CLI。`AgentReplMain`（duo-harness-example）把三个职责焊在一起：① Boot 装配入口（读 yml、拉起插件树）；② CLI 呈现位（REPL 循环、ConsoleAnswerer、会话续接）；③ 进程保活。后果：

1. **CLI 不可配置、不可关闭**——不想要终端入口的部署也得带着它，与"不挂载零残留"的插件原则相悖。
2. **example 模块承担运行时职责**——演示模块里长出了正式能力，模块定位漂移。
3. **纯 Web 部署无先例**——JVM 存活依赖 CLI 的阻塞读，Web 独活形态从未成立。

Web 面（M8 起）已验证"呈现位即插件"的可行性：Boot yml 一行启用、卸载零残留。M10 会话独占锁（ADR-0008 延伸）进一步保证"每呈现位一个会话、后到者被拒"的语义有锁兜底。

## 决策

1. **新模块 `duo-harness-cli`**（依赖 core/tools/session/agent/llm，与 duo-harness-web 对称）：`CliPlugin`（Boot 插件）+ `ConsoleAnswerer`（从 example 上移）。
2. **CliPlugin 生命周期**：`apply()` 装配完整执行链（LlmConfig → 重试 adapter → 会话续接/新建【独占锁，占用即 FAILED 点名】→ ChatAgent + 治理 → ConsoleAnswerer + 审计桥），并以**虚拟线程**启动 REPL 循环（读 stdin、/new、/exit）；`stop()` 置停止标记并中断循环、关闭会话释放锁、摘除回答者。输入/输出流构造注入（测试 seam，沿 `AgentReplMain.run(in, out)` 先例）。
3. **`/exit` = CLI idle**：REPL 循环退出、会话锁释放、回答者摘除，**插件保持挂载、整树与 Web 不受影响**。彻底停止交给进程信号 + shutdown hook 级联 dispose（启动器职责）。
4. **通用启动器 `DuoMain`**：薄壳——`Boot.from(yml)` + 非守护等待（CountDownLatch）+ shutdown hook 调 `root.dispose()`。纯 Web 部署下 JVM 存活由等待 latch 保证，Ctrl-C 走 hook 释放全部会话锁。`AgentReplMain` 瘦身为兼容壳（main 委托 DuoMain，启动命令与文档不变）。
5. **回答者路由维持注册序**：CLI 与 Web 双开时，yml 行序决定审批/提问落在哪个呈现位（首个非空胜出，ADR-0008 语义）；"广播等待先答"列为演进方向，本期不做。
6. `ChatReplMain`（M4 演示）保留不动。

## 拒绝的选项

- **CLI 留在 example**：演示模块承担正式运行时职责，定位漂移；且 example 无法被其他部署以插件方式引用。
- **AgentReplMain 直接改造为唯一启动器**：名字与"通用启动器"职责不符，example 模块继续承担运行时入口。
- **废弃 AgentReplMain 只留 DuoMain**：启动命令与文档破坏性变更，兼容壳零成本。
- **`/exit` 停整树（现状延续）**：双开场景下终端退出会误杀 Web 面——与"可独立开关"的立项目标直接矛盾。
- **`/exit` 触发 CliPlugin 行级自卸载**：需要新的自卸载机制（插件请求树卸载自身），且"彻底关闭"已有进程信号覆盖，收益不抵机制复杂度。
- **本期实现回答者广播路由**：交互 seam 演进为"全部回答者并行询问、先答者胜"，涉及 seam 契约变更与双端竞态处理，留演进。

## Consequences

- 新模块骨架与 `duo-harness-cli` 构件；`duo-harness-example` 瘦身（AgentReplMain 委托 DuoMain，ChatReplMain 等演示不动）。
- **WebPlugin 与 CliPlugin 的重复装配逻辑**（adapter → 会话 → agent → 治理）提取为共享装配器（agent 模块）——双份代码在两个插件中不可接受。
- 双开语义文档化：yml 行序即回答者路由；CLI 与 Web 各自独占会话，互不共享（延续 M10-03）。
- Boot 的 `disabled: true` 行字段成为呈现位开关的正式机制（保留行、不加载）。
- 启动器接管保活与 shutdown hook 后，Ctrl-C 语义从"靠 OS 杀进程"升级为"级联 dispose 释放全部会话锁"。
- 理解关卡：M10 前欠账的多门补考须在 M11 实现开工前完成（duo-workflow 阶段闸门）。
