# 扩展机制：hooks 生态格式复用、插件可选依赖、awaitStartup 可配超时

Status: 批准（2026-09-18，M18 grill 七题裁定；范围预定义于 ADR-0016，本文立落地语义）

M17（0.12.0）并发调度收官后，扩展机制按 ADR-0016 排期落地为 M18（0.13.0）主题，三个子项：hooks（复用 Claude Code/Codex 的 hooks 配置格式——PreToolUse→tools/pre-execute 等映射、exit 2 阻断且 stderr 回给模型、opt-in——而非自定协议）、插件可选依赖、awaitStartup 可配超时 + 点名缺失服务。"并发居先、hooks 居后"的排期逻辑已在 ADR-0018 兑现：钩子落在并发管线之上的既有瀑布挂点，调度零改动。本文记录 grill 七题的落地裁定。事实基础：Claude Code hooks 官方文档与 Codex hooks（`hooks.json` / config.toml，两家结构同族、Claude Code 为超集）核实，duo 配置体系与容器纪律考古（inject 全硬依赖、`hasService()` 仅存在性、`as()` 惰性视图、awaitStartup 无参无限阻塞零日志、BootLoader 审计点名文案）。

## 决策

1. **hooks 配置文件**：`~/.duo/hooks.json`，顶层 `{"hooks": {...}}` 与两家同形；未知键宽容忽略——Claude Code 的 settings.json 整文件粘贴即用（多余键跳过、hooks 段生效）。项目级双层（仓库内 `.duo/`）范围外进 backlog（duo 尚无"项目根"概念）。配置解析失败 → hooks 插件本身 FAILED、点名文件与位置（容器"异常只杀本实例不传染兄弟"承接，不连坐 boot 树）。
2. **定位与失败语义（fail-open）**：hooks 是生态兼容扩展层，运行期失败（超时、进程崩溃、起不来）一律放行 + WARN 日志，跟随两家官方行为；duo 自身的硬闸门需求由 guard（单调否决）与审批承担——外部脚本不承担执法边界。opt-in = boot yml 插件行：不装行零感知零开销；装行而配置缺失/为空 = 插件 ACTIVE 空转，合法。
3. **一期保真基线七项**：事件只做 PreToolUse + PostToolUse（映射 tools/pre-execute 与 tools/post-execute 既有瀑布挂点），其余事件跳过 + WARN 点名；处理器只做 `"type": "command"`；阻断双通道——exit 2（stderr 回给模型）与 exit 0 时 stdout JSON `permissionDecision` deny/allow（reason 优先呈现；allow 不带改写等价放行）；其余非零退出 = 非阻断 + WARN；matcher 两档（纯字母数字 `_ - | ,` = 精确名/多选，含其他字符 = 正则，`*`/省略 = 全匹配）；条目级 `timeout`（秒）缺省 600s 跟 Claude Code，超时 = 取消进程、丢弃输出、放行；`args` 数组在场 = exec 直启、缺省 `sh -c` shell 形态；stdin 载荷最小七字段（session_id、transcript_path、cwd、hook_event_name、tool_name、tool_input、tool_use_id）+ `DUO_HOME` 环境变量。
4. **PostToolUse 的"阻断" = 结果改写为错误**：工具已执行，stderr/reason 以 error 形态回给模型——不假装撤销副作用（Codex 同款 audit-only 立场）。
5. **顺序与能力边界（先到先决、只收不放）**：PreToolUse 钩子作为 pre-execute 监听器与审批策略解析者同段共存，按注册序先到先决——钩子 deny 占先即省掉审批交互（管线既有约定：deny 与审批互斥、deny 占先）；钩子没有"跳过审批放行"的能力，与 guard 单调否决同哲学：只收紧，不放松。
6. **并发零改动**：钩子在每次调用的管线内部执行（工作线程内），不参与 M17 分组判定与屏障语义；慢钩子只拖慢自己所在组，成对有序提交不受影响。
7. **可选依赖声明与读取**：`Plugin` 新 default 方法 `optionalInject()` 返回 `Set<String>`（空集缺省，与 inject 对称）——"就绪则用、缺失不拦"；`as()` 读取许可放宽为 `inject() ∪ optionalInject()`，实例仍只经声明名字取。不新增读取 API：`hasService()` 判存 + `as()` 惰性视图（快照式 Optional 与惰性代理架构相悖——取代理时无从知在场性，会说谎）。
8. **可选依赖 epoch 语义（唯一规则改动）**：与硬依赖唯一差别 = "缺失不阻塞 PENDING"；依赖指纹缺失项跳过（不置 null），在场项照常参与；服务出现/消失 → 既有 recheck 自动重载——升级↔降级双向对称，重载时 `apply` 以当时的在场性重新接线。
9. **可选依赖验收用例**：boot yml 去掉 fs 插件行 → CLI 照常启动聊天，`/permission` 降级提示"未挂载"（backlog 原始用例落地为端到端证据）。
10. **awaitStartup 重载**：新增 `awaitStartup(Duration timeout)`，超时抛点名异常（"缺失服务： a, b"，复用 BootLoader 审计文案逻辑）；无参版语义不变（等待服务动态就绪是容器合法模式，无限等不是罪——罪在静默），但进入等待打一条 INFO 日志点名在等谁。超时来源 = 调用方传参，不加全局配置；超时后插件保持 PENDING，后台就绪照常激活；异常沿调用方路径走（apply 内抛 = 只杀本实例）。
11. **搭车一：PipelineTimeout 双挂债销账**：cli + web 双开共享 ToolsService 时管线超时监听器叠挂（嵌套超时），挂载查重先到先得（与 registerTodoWriteTool 同模式）+ 测试。
12. **搭车二：测试进程收割限时评估**（backlog 挂账原文"随 awaitStartup 超时语义一并评估"）：结论要么方案很小顺手修、要么写清方案与规模继续挂账，不无限展开。

## 拒绝的选项

- **hooks 自定 yml 钩子协议**（ADR-0016 已拒，重申）：发明新格式割裂生态，兼容即上手成本归零。
- **fail-closed（钩子失败即阻断）**：安全闸门立场更硬，但与两家官方行为相反——同样的配置在两家放行、在 duo 阻断，兼容承诺打折；且死循环钩子脚本可把 agent 完全卡死。duo 的硬闸门由进程内 guard 承担，不依赖外部脚本存活。
- **逐条 blockOnFailure 开关**：官方格式不存在的字段，"复用格式"出现第一处偏离，配置面与测试面变大。
- **updatedInput 入参改写一期做**：`ToolExecution.args` 为 final，支持要动管线载荷 API，还连带"改写后参数怎么进日志"（M17 日志同构承诺不可轻动）；核心用例是拦不是改，backlog 记档。
- **UserPromptSubmit / Stop 等事件一期做**：需 agent 循环新增挂点，且 Stop 的 exit 2 = "禁止 agent 停止"语义重；一期聚焦工具事件，backlog 记档。
- **项目级 hooks.json 双层合并**：团队共享场景有价值，但 duo 尚无"项目根"概念（DUO_HOME 全局），先立概念再议。
- **DSH 式 `ctx.get(name)` 使用点探测**：绕开视图读取纪律的口子，且与惰性代理架构相悖。
- **可选依赖不进指纹（启动时快照）**：破坏容器"环境变化即重载"统一哲学——提供方插件重启时硬依赖者重载、可选依赖者不重载，行为分裂，降级桩拿过期判断继续跑。
- **`as()` 对缺失可选服务返回 null / 新增 `optional(name): Optional<T>`**：重定义既有契约，或新增会说谎的快照 API；`hasService()` + 惰性视图已覆盖读取需求。
- **awaitStartup 无参版加全局缺省超时**：全局超时语境错位（测试要秒级、引导要分钟级），且改变既有合法语义；诊断缺口由进入等待的点名日志补。
- **subagent（ADR-0017）搭车 M18**：独立域且体量不小，M18 三子项验收面已不窄，维持挂账独立挑期。

## Consequences

- 术语表同 diff 入册：钩子（hook）、可选依赖（optionalInject）。
- backlog 同 diff 对账：销账"插件可选依赖"、"awaitStartup 超时语义"、"PipelineTimeout 双挂"三条；新增"项目级 hooks 配置""UserPromptSubmit/Stop 事件""updatedInput 改写"三条；测试进程收割按评估结论处置。
- 新 Maven 模块 `duo-harness-hooks`：pom 与 README 模块表同 diff 增补。
- fail-open 的文档义务：面向用户文档须明示"钩子不是执法边界"（两家官方同款警告），防安全误用。
- stdin 载荷字段与 Claude Code 同名的映射代价：`transcript_path` 等字段 duo 有自己的对应物（会话 JSONL 路径等），映射关系在配置参考文档写清。
- MCP 首连已有 20s requestTimeout + `failOnStartupError` 缺省 false 兜底，不是 awaitStartup 卡死源——本 ADR 不动 MCP 域。
