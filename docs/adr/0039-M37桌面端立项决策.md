# M37 立项决策：桌面端——Electron 壳承载的 Web 呈现位桌面化

Status: 批准（2026-10-04，/grill-with-docs 十二问逐题裁定：Q1–Q7 当场作答；Q8–Q12 用户离席先按推荐落盘待核、同日用户逐题补答全部确认与推荐一致——十二问全落定；1.0 后轻量里程碑制第五期 M37）

## 背景

M36 已收口（1.2.0 实发，2026-10-03 版本对齐）。M37 诉求：桌面端——把「CLI + 浏览器手开 Web UI」升级为原生桌面体验。参考资产就绪：两家桌面端研究文档已于 2026-10-04 增量补扫至当前锚点（[DSH/呈现与UI/桌面端.md](../research/DSH/呈现与UI/桌面端.md) @ DSH 5badb15009、[ZCode/呈现与UI/桌面端.md](../research/ZCode/呈现与UI/桌面端.md) @ ZCode 29628c9），「对 duo 的启示」两节为直接输入。

版图对账：CHANGELOG 实发 1.2.0（tag 在）；全 ADR 库无 M37 定版记录（最新立项 ADR-0038），本 ADR 定版 **M37 = 1.3.0**（1.x 承诺「新功能进次版本」，M35=1.1.0、M36=1.2.0 惯例续延），无错位。分支 `1.3.0` 待 /to-spec 拆工单后自 main 切出（ADR-0037 先例），开发提交不落 main（红线 7）。

实现面实测底座（探索代理 smoke 级核查，HEAD e76305ef）：

- Web UI 为纯 HTTP+SSE（无 WebSocket/自定义协议），`HttpServer` 绑 `127.0.0.1`，静态资源 classpath 本进程服务（`WebFace.java:189-190`）——任何壳指 URL 即可加载，后端零改造即壳就绪。
- 端口来自 web 行 `config.port`（缺省 8080 写死，`WebPlugin.java:56-57`）；`port: 0` 随机分配机制已在（`WebFace.java:102` 可取回实际端口）但无产品路径——DSH 教训（Windows Hyper-V/WinNAT 保留段致 bind 失败）落地为小改动而非新工程。
- 鉴权令牌随机生成、全端点 fail-closed（`X-Duo-Token`/`?token=`），**只经 stdout 打印一次**（`WebPlugin.java:314-319`）——令牌交付是桌面壳的唯一硬依赖缺口。
- Host 白名单钉死回环三形态 + POST Origin 同源校验（`WebEntryGate.java:32-35`）——壳直连 `http://127.0.0.1:<port>` 即无事，自定义协议代理方案会被 403。
- 行序契约：装配 yml 的 web 行必须先于 cli 行（`DuoMain.java:66-71`、`WebPlugin.java:122-126` 双重点名）——桌面装配沿用同一约束面。
- 无打包阻碍单点：shade fat-jar SPI 合并已验证（含 sqlite native）、全仓零 JavaFX/Swing 依赖、`DUO_HOME` 可重定向（`DuoHome.java:39-46`）。
- 会话落 `~/.duo/agent-sessions/<id>.jsonl`，FileChannel 进程级独占锁 + 同进程注册表（`Session.java:268-313`）——跨进程双开同会话已被锁挡，多呈现位共存安全。

## 决策（grill Q1–Q12）

### 一、体验目标与范围四至（Q1/Q3，用户裁定）

体验目标 = **原生桌面体验**：托盘常驻、系统通知、应用菜单、duo:// 深链（「双击即用」未选——打包分发从简，本机跑或轻打包，安装器/签名公证不进本期）。范围 in：窗口加载 Web UI、托盘、通知、菜单、深链、拉起并看护 Java 后端（崩溃走原生恢复对话框）、**退出前探活确认**（后端还有 agent 在跑时弹确认防误杀长任务，探活用既有 `/api/status`）。范围 out（显式挂账）：更新链、CLI 命令安装（DSH 所有权模型）、内置浏览器受控宿主（ZCode 重资产）——三项均桌面端后续期候选，backlog 记账。

### 二、技术路线（Q2，用户裁定；红线 4 同意面）

**Electron 壳**：壳只做五件事——开窗口加载 `http://127.0.0.1:<port>`、托盘/通知/菜单、注册 `duo://` 协议、拉起与看护 Java 后端（fat-jar 子进程）、退出编排。仓库新增 Node/JS 工具链（壳代码预计数百行 TS），**用户已明确同意**（红线 4）。两家参考的壳经验（最小 host 协议、动态端口、quit-inspection、恢复对话框、托盘/深链范式）可直接照抄。

### 三、平台面（Q4，用户裁定）

**macOS 优先**：托盘/通知/深链三件每平台行为不同，验证成本按平台翻倍——本期只真机验证 macOS；壳代码用 Electron 跨平台 API、不写 mac 专属形态，Windows/Linux 留待真有需求时再验（预期届时补验证而非重写）。

### 四、版图（Q5，用户裁定）

M37 = 1.3.0；分支 `1.3.0` 于 /to-spec 拆工单后自 main 切出；立项决策即本 ADR（0039），版图勘误注无需（无错位，定版随本 ADR 首次落）。

### 五、呈现位身份与术语（Q6，用户裁定）

桌面形态 = **Web 呈现位的桌面载体**，不新增呈现位类型：同一 WebPlugin、同一套 SSE/端点，审批路由（谁发起谁作答）、fail-closed 宽限期、命令标记（ANY/CLI/WEB）语义全部不变，后端零改动。术语表只新增「桌面壳」词条（本 diff 已落），_Avoid_「桌面客户端」（暗示独立呈现位类型）。

### 六、端口与令牌交付（Q7/Q8/Q12，用户裁定）

- 端口策略（Q7）：**壳选空闲端口注入**，后端缺省 8080 行为不变——壳与端口同生命周期，CLI/Web 直跑用户无感。
- 端口注入实现位（Q12）：`WebPlugin` 读端口时先看 `DUO_WEB_PORT` 环境变量覆盖 yml 值——后端一行级改动；`plugins.yml` 唯一装载源不动，三方配置统一。拒绝「壳生成临时 yml」（JS 重写用户 yml，脆）与「桌面专用装配」（配置分裂）。
- 令牌交付（Q8）：**stdout 解析 + 机器可读锚点行**——后端在现有 URL 打印处旁加 `duo:web-ready url=…` 形态锚点行，壳认锚点不认人读文案。拒绝「裸解析现有文案」（文案漂移壳即碎）与「后端回调通道」（加参数/HTTP 客户端/重试，为替代读一行 stdout 不值）。

### 七、数据目录与原生能力面（Q9/Q10/Q11，用户裁定）

- 数据目录（Q9）：**共享 `~/.duo`**——桌面是第三呈现位（决策五），会话/装配/插件资产与 CLI 天然互通；会话锁已防同会话双开。拒绝独立数据目录（资产分裂，与决策五自相矛盾）。
- 通知触发面（Q10）：**三项全要**——turn 完成、审批/提问等待（agent 卡在等人，最需通知）、错误中断；点击通知/托盘聚焦主窗。实现路径（前端 Web Notification API 经 Electron 原生透传 vs 壳侧订阅）留 spec 期定——本期裁定的是触发事件集合。
- 深链路由面（Q11）：**仅 `duo://open`**（唤起/聚焦主窗），协议注册本期就做；多路由（oauth/支付回调类）依赖登录流/支付流，duo 无此需求，路由面留白按需加。

## 拒绝的选项

- **Tauri 壳**：包更小、内存更低，但引入 Rust 工具链（仓库无人维护过）、系统 WebView 渲染细节需适配，两家研究经验不可照抄——EC 栈一致性让位 Electron。
- **纯 Java 硬做（jpackage + AWT 托盘 + FFM 原生胶水）**：零新栈但达不到裁定目标——macOS 托盘/通知/深链全要手写原生胶水，质量与两家差距大。
- **后端缺省改动态端口**：改产品缺省行为（文档/用户习惯/URL 可预期性全变），且 CLI 直跑用户的 Windows 保留段问题动了却不彻底。
- **壳直选 `port:0` 后端随机**：端口选择权在后端则壳须解析才知道，与壳编排生命周期相悖；壳选端口注入让「谁拉起谁负责」边界清晰。
- **新增 DESKTOP 呈现位标记**：审批路由/命令适用面/术语表连带改动，本期无差异化处理需求，纯增复杂度。
- **更新链 / CLI 命令安装 / 内置浏览器入本期**：分别需要发布基础设施、服务分发场景、数万行浏览器编排——均无本期受益场景（「双击即用」未选），显式挂账。
- **独立桌面数据目录**：会话资产分裂，与「桌面只是新呈现位」冲突。

## Consequences

- 分支 `1.3.0` 于 /to-spec 拆工单后自 main 切出；开发提交不落 main（红线 7）。
- 后端改动面收敛为两处（均为行级）：stdout 锚点行、`DUO_WEB_PORT` 环境变量覆盖；其余全部改动落在新壳工程（仓库新增 Node/JS 工具链目录，结构 spec 期定）。
- 术语表同 diff 入册：桌面壳一词（本 diff 已落）；启动器（DuoMain 薄壳）词条语义不变。
- 挂账三项入 backlog：更新链（检查+提示起步）、CLI 命令安装（DSH 所有权模型照抄）、内置浏览器受控宿主（独立立项）。
- spec 阶段待定细节（非悬置——/to-spec 时定点处理）：壳工程目录结构与构建链（electron-builder 配置）、菜单栏内容清单、崩溃恢复对话框形态与文案、通知实现路径、壳打包形态（dev 模式 vs 轻打包）、深链 scheme 终名确认（`duo`）、退出编排细节（Cmd-Q vs 托盘退出 vs 关窗隐藏的 mac 惯例映射）。
- Q8–Q12 已于同日由用户逐题补答确认（全部与推荐一致），待核面转批准面；后续调整走 ADR 修订，不静默改。
