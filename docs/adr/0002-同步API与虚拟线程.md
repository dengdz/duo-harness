# 内核 API 采用同步阻塞模型，由虚拟线程承载

Status: 批准

插件 apply/dispose、事件监听器、waterfall 链全部以同步阻塞式签名书写（waterfall 监听器是 `(args, next) -> result` 而非 `Function<T, CompletableFuture<R>>`），内核用 JDK 21 虚拟线程承载插件启停与 IO 密集操作。DSH 的 async/await 手感在 Java 的对应物就是虚拟线程上的同步代码；异步签名会传染所有插件接口并使调试栈断裂。拒绝的选项：全 CompletableFuture 异步 API、Reactor/RxJava 响应式流（后者同时违背最小依赖红线）。

## Consequences

- 所有插件接口签名以同步语义为契约；插件代码内的阻塞调用视为正常（虚拟线程消化）。
- synchronized 等 pin 虚拟线程的惯用法在插件代码中需谨慎（内核文档应给出替代建议）。
