# 输入面与会话工具：附件内容寻址库、提及模式与后端无关会话检索

Status: 批准（2026-09-20，M21 grill 裁定；事实基础 = [DSH 输入面与会话工具研究三件套](../research/DSH/输入面与会话工具/架构设计.md)，锚点 ddefc45f = release 0.1.6-alpha.2）

[ADR-0016](0016-M16至1.0里程碑规划.md) 排期的 M21（0.16.0）：duo 的输入面目前只有键盘文本——图片进不来、文件靠模型自己猜路径；会话历史只有侧栏列表——没有检索与导出。本决策给出四条能力线：附件（内容寻址库）、read_image 多模态、@file 路径提及、会话查询/导出。grilling 六问裁定，关键事实修正：**DSH 的 @file 是"纯路径提及"而非内容注入**（索引 only、内容留在模型侧 read 工具后），**/export 是 ZIP 流式下载**而非 Markdown/JSON 文件——ADR-0016 的措辞按源码事实修正后进入本决策。

## 决策

1. **范围**：四件全做，计费口径统计不搭车（留 backlog）。
2. **附件库**：`~/.duo/attachments/v1`，SHA-256 内容寻址、tmp fsync → 硬链接发布（EEXIST 即去重）→ 0400 只读，**无 GC（永不自动删除）**；会话日志**只存引用块**（`{attachmentId, mediaType, bytes, name, width?, height?}`）不存字节；模型侧唯一写入口是 `read_image`（先持久化再返回引用——wire 调用者永远无法引用未上传的附件）；Web 渲染图片走授权读取端点（先验证会话日志确实引用了该 id 再回字节）。
3. **多模态完整对齐 DSH 三层**（用户裁定，轻量方案被否）：
   - **存储规范化**：入库前解码 → 格式/像素/边长校验 → 长边受限重编码（8-bit sRGB、字节预算内），以规范化字节寻址；
   - **请求变体**：发给模型前按目标尺寸确定性缩放 + 字节预算压缩，variantId = sha256(附件+目标+编码版本)，变体缓存落盘；
   - **Files API**：`imageDelivery: files` 时上传换 file_id（省 token），完整机制——本地索引去重、配额满回收最旧自有文件、file_id 失效重传一次、上传失败自动回退 inline base64。
4. **图像依赖**：TwelveMonkeys ImageIO（imageio-jpeg/imageio-webp——WebP 解码刚需 + 强 JPEG）+ Thumbnailator（缩放，单 jar）；全部纯 Java 零 native（grill A1 裁定）。
5. **配置形态**：`llm.vision`（缺省 **false**）——false 时 Web 收图即拒、read_image 执行前即拒（非视觉部署零感知）；`llm.imageDelivery: inline | files`（缺省 **inline**）——inline 为 base64 data URI（任何 OpenAI 兼容端点可用），files 为 DeepSeek 形态 Files API 全机制。
6. **llm 模块多部件改造**：消息 content 从纯文本扩展为多部件（text + image base64 data URI，OpenAI 兼容形态）；非视觉配置下多部件不可达（闸门在更上游）。
7. **@file 提及模式**（源码事实修正 ADR-0016"注入"措辞）：`@path` 纯文本提及 + system 指南（"@ 是工作区路径；要内容调 read；**未 read 不得声称已看过**"；仅 read 工具在册的部署注入）+ Web 输入框 `@` 补全（工作区路径索引、目录下钻、引号路径、越界/symlink/不可读子树防护、排除目录清单对齐 DSH）；CLI 一期文本直打不做补全 UI。零内容注入管道，文件内容永远经 read 工具（接读前写闸门）。
8. **会话检索**：一期**纯 Java 内存倒排索引**（懒构建首次搜索才扫 + 文件 mtime 增量；分词 AND + snippet；索引内容对齐 DSH 清单——消息文本/tool 调用与结果/todo/turn 错误，reasoning 不入）；`session_search` 单工具（模型侧）+ Web 侧栏搜索框（用户侧）；子代理会话不索引；opt-in = yml 装 session-query 插件行即启用（索引懒构建），不装零感知。**检索服务接口后端无关，后期转 SQLite**（用户演进承诺——接口语义对齐 FTS5 形态防切换漂移，limitations 记量级边界）。
9. **会话导出**：`/export [markdown|json]` 双格式（缺省 markdown 人读版：角色/时间戳头部 + 工具摘要行 + 尾部附件引用清单；json 为会话 JSONL 原样副本）；**附件字节不打包**（库内永不删除，Markdown 给引用清单、JSONL 本有引用 id；ZIP 全打包留后续）；注册进命令注册表双面（busySafe，`command/run`+`command/done` 审计白得）；读前 flush 持久化屏障 + fail-loud；只导当前会话；CLI 写盘 cwd（`duo-session-<id>.md/.jsonl`）/ Web 下载流。
10. **横切**：入口面 = Web 拖拽/粘贴上传端点 + read_image（CLI 走路径由模型自读；子代理会话拒收附件）；`read_image` 归本地读类（三档放行），附件库写入属 harness 自身数据目录不受三档管辖；子代理上下文**过滤附件引用块**（照交互工具先例）；图片**一期不计入**治理 token 估算（真实 usage 侧自然覆盖）。

## 拒绝的选项

- **轻量多模态**（存原始字节不规范化、无变体、无 Files API）：用户裁定完整对齐——规范化与变体的 token/传输优化是长期价值；DSH 三层设计已完整存档研究三件套，实现有据可依。
- **纯 JDK ImageIO（拒 WebP）**：WebP 是网页图片主流格式，附件场景拒收 WebP 体验残缺；CMYK JPEG 亦解不了。
- **SQLite JDBC FTS5 一期落地**：native 库打包（~10MB）绑死上游版本，与最小依赖理念冲突；用户裁定"短期内存倒排、后期转 SQLite"——接口后端无关设计保证切换不漂移。
- **Lucene**：能力过剩、依赖树巨大。
- **@file 内容注入模式**：注入管道（大小上限/截断/二进制识别/不可信声明）与 read 工具、读前写闸门语义重叠——"注入过的文件算不算读过"是新语义泥潭；DSH 源码自证路径提及模式（"选中的候选从不读取或附带文件内容"）。
- **/export DSH 式 ZIP**：附件库永不删除前提下打包字节价值打折；Markdown（人读）+ JSON（归档）双格式覆盖两域；ZIP 流式压缩留后续增强。
- **计费口径搭车**：四线作战不加码（backlog 维持）。
- **子代理附件传递**：M21 不做（框架过滤附件引用块）。

## Consequences

- 新依赖：TwelveMonkeys ImageIO（imageio-jpeg/imageio-webp）+ Thumbnailator（grill A1 已获批，纯 Java 零 native）。
- llm 模块消息 content 多部件改造；会话词汇新增附件引用块（向前兼容）。
- 附件库落 `~/.duo/attachments/`（DuoHome 体系，天然不入仓库）。
- limitations 新增：内存倒排索引量级边界（SQLite 演进方向）、治理 token 估算不含图片、Files API 仅 DeepSeek 形态端点（inline 为通用兜底）。
- 术语表新增：附件库 / 附件引用块 / 提及模式 / 会话检索。
- 文档同 diff：工具目录（read_image/session_search）、插件配置参考（web-tools 外新增附件与会话查询段）、运行 Demo、demo yml。
- 子代理模板工具清单可点名 read_image / session_search；附件引用块经框架过滤不进子代理上下文。
