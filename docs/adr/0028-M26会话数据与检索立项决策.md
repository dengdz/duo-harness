# M26 会话数据与检索立项决策

Status: 批准（2026-09-26，M26 立项 grill 十三问逐项裁定；【2026-09-30 注：其中「交付声明 present 工具」已随 M29 工单 12 用户裁定退役——Web 呈现位停注册，交付物呈现改前端产物预览卡自动推导；deliverable 事件的检索/导出消费方不变】细化 [ADR-0024](0024-M23至1.0里程碑版图重排.md) M26 节的执行决策，四件主菜的范围与排序仍以 ADR-0024 为准，本决策不取代它）

## 背景

M25（0.20.0）收口后开启 M26（0.21.0）「会话数据与检索——历史找得到、带得走」立项 grill。ADR-0024 已定四件主菜（FTS5 迁移、/export 增强、会话文件格式版本头、watermark 防护），本轮 grill 把其中难逆转的执行决策磨定。事实基础：`docs/research/DSH/网络与数据/会话检索与导出.md` 与 `docs/research/ZCode/Agent循环与会话/投影、恢复与分页.md` 两份探测文档，及 duo 现状核对（全仓无 SQLite 依赖、会话存储全 JSONL、无 cwd 字段、无交付声明事件、检索游标为裸整数）。

## 决策

### 一、引入 sqlite-jdbc，FTS5 索引为派生只读层

引入 `org.xerial:sqlite-jdbc` 作为全仓首个 SQLite 依赖（红线 4 依赖审批：2026-09-26 用户裁定同意）。索引库文件落 `~/.duo/`，定位为**派生只读加速层**：会话 JSONL 仍是唯一权威数据源，索引 schema 版本不符就地重建，库文件可随时删除重建，不承载任何独有数据。

检索接口面维持现状（`SessionQueryService.search(String, int)` 单 query 语义不变，兑现 M21「转 FTS5 上层零改动」承诺），工具参数与 Web 搜索 UI 不扩过滤器。本期可见改善：中文分词对齐 FTS5 形态（unicode61 + 外部分词，保住汉字逐字 AND 语义）、**活跃会话可搜**（live 供数通道，消除 M21#1「当前会话不可检索」缺口）、无常驻内存倒排索引。

### 二、会话文件版本头——读时识别，磁盘永不重写

新会话文件首行落 `{type:"session", version:1}`。**M26 前的旧文件一个字节不动**：读端遇无头文件即按最老格式（v0）处理，v0 语义就是现有格式、无需转换。迁移链机制随本期建好：读端认出版本后按 vN→vN+1 相邻接力在内存中转换，磁盘文件永不重写。

依据：会话文件 append-only + `force(false)` 的崩溃安全承诺、microcompact「JSONL 原文完整保留」的审计承诺，均与任何形式的历史重写相抵触。同车落盘新字段：会话 cwd（决策三的过滤前提，仅新增会话写入）。

### 三、cwd 严格授权过滤，老会话不进跨会话检索

跨会话检索（`session_search` 工具与 Web 搜索）结果逐条校验会话 cwd 与当前工作目录**相等才收**（对齐 DSH `recordAuthorized` 语义）。动机：防上下文跨项目污染——模型在项目 A 工作时若能搜到项目 B 的会话内容，私有代码可能经提示词流入他项目产物。

代价明示：M26 前的老会话无 cwd 记录、无法判定归属，**从跨会话检索结果中消失**（文件本体仍在、可打开，只是不进搜索）。升级路径均为后续按需立项：目录归属回填（侧车文件补记，不动老文件本体）、显式跨目录开关。

## 拒绝的选项

- **SQLite 作权威存储**：JSONL append-only 是崩溃与审计承诺的根基，不为索引能力倒置权威方向。
- **旧文件迁移（原地重写 / DSH 式新代文件）**：重写违反只追加红线；新代文件（`session.vN.jsonl` 后继发布）为不存在的转换需求付出文件命名与发现逻辑大改的代价。duo 格式演进传统是「可选字段缺省不破坏旧文件」，v0 本就可被新代码直读。
- **显式 generation 代际编号**（watermark 载体）：duo 事件日志只追加、序号稳定，会话 id 即天然代际边界；ZCode 需要独立 epoch 是因其日志支持删行重写，duo 无此形态。防串台采用「会话 id + 序号」复合游标、前后端双侧核对——协议细节进 spec。
- **/export 升级 ZIP 打包**：服务迁移/归档场景，与本期「检索与导出内容增强」主线不同，backlog 已有 1.0 后菜单条目。
- **自动抽取子代理纳入 M26**（backlog「M26 规划时复议」项的复议结论）：触发时机/噪声治理/与显式写合并策略三题未解，且属记忆域而非会话检索域；M25 显式写刚上线，先看使用反馈。留 backlog 继续发酵。

## Consequences

- `sqlite-jdbc` 依赖进 pom（模块归属与版本 spec 定）；依赖审批留痕以本 ADR 为凭。
- 用户可感知行为变化须 CHANGELOG 记账（红线 6）：老会话不再出现在跨会话搜索结果；新会话文件首行多出版本头行。
- backlog 对账（同 diff）：自动抽取子代理条目「→ M26 规划时复议」结论落为「不纳入，留 backlog」；ZIP 导出维持 1.0 后菜单。
- 范围裁定记档（不足立 ADR 的流程项）：M25 comprehension 补课不设节点、由用户主动发起，拆工单前凭证未发 duo-workflow 须停下询问；M26 立项后从 main 切 `0.21.0` 分支。
- spec 输入直接引用两份探测文档（ADR-0024 依据行），锚点 `ddefc45f` / `872ad96` 过期才增量补扫。
