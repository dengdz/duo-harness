# 路线图：插件化三支柱先行，agent 循环最后

Status: 批准

里程碑顺序：M1 内核 + 示例插件 → M2 工具域强化 + MCP 接入 → M3 页面插件 / Web 双面 → M4 agent 循环 + LLM 适配。插件化三支柱（工具 / MCP / 页面）先全部立稳，把"能对话"放在最后。理由：与项目目标（插件化框架）对齐，每步都可用示例验证；agent 循环只是框架的第一个大消费者，放最后能倒逼内核接口不被单一业务带偏；依赖顺序自然（MCP 消费工具域，Web 消费会话事件）。拒绝的选项：agent 优先（先有能对话的产品，但 agent 循环会反向对内核提出大量需求，容易把内核带向单体）、三线并行（焦点分散）。
