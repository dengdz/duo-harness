# 技能写作规范：移植 writing-for-agents 五支柱与调用权分流兜底方案

Status: 批准（2026-09-24，C1 决策段工单 03，grill Q4 裁定时点——分析完成后、改写开工前；分析依据 = [docs/research/mattpocock-skills/](../research/mattpocock-skills/机制清单.md) 三件套（机制清单 C1-01 / 对比报告 C1-02 / 讲义），Matt 侧锚点 = 插件 mattpocock-skills 1.2.3 插件缓存，ZCode 侧探测锚点 = 本地源码 `872ad96`；下游 = 工单 04《技能写作规范》本体与改写组 05–11）

## 背景

C1 problem statement 的实证（duo-code-review 自诊断"描述性条款跨会话必然衰减"、workflow experience 的"凭记忆声称完成"、brief 即兴手写漂移）把根因指向机制层而非措辞。分析段（工单 01/02）给出 15 机制对照系与覆盖矩阵：duo 侧 3 项 ✓、9 项 ◐、3 项 ✗（调用权分流/显式工具调用/词汇治理全缺），且 duo 无写作理论元文档——25 个 Matt 技能从同一部理论"编译"而来，一致性是机械的。本 ADR 只钉跨工单、难逆转的语义级裁定：移植什么、怎么分流、改写纪律；规范条文本体归工单 04，逐技能改写归工单 05–11。

## 决策

### 一、移植 writing-for-agents 五支柱为中文《技能写作规范》（工单 04 交付）

- **五支柱**：上下文指针（含调用权框架）/ 完成判据 / 领先词 / 否定治理 / 剪枝纪律。以中文规范化，每条附 duo 正反例——正例池与反例池取自对比报告 §2/§5（acceptance 判据、trim-cot-leakage 保留规则、doc-standards 对账命令为正例；code-review:15 弱指针、code-review:33 三重否定、workflow 箭头链、bug-ledger 反模式节、skill-evolution 328 行为反例）。
- **与 duo-prose-standard 的分工**：不改既有定位——prose-standard 管 prose 质量（命题完整性、契约保留），新规范管技能机制层（指针措辞、判据写法、调用权表达、剪枝纪律作为写作规则）。新规范引用 prose-standard 的文风条款、不复制（单一事实源）；prose-standard 增一行指针指向新规范（改写段同 diff）。
- **词汇治理**：docs/agents/domain.md 升级为 CONTEXT.md 式「首选 + _Avoid_」格式（工单 04 定词条、工单 11 收口）；SKILL.md 不引入表外同义词；首批词条见对比报告 §5.4。
- **description 预算**：user 档（AGENTS.md 显式命令表内技能）≤60 字、model 档 ≤80 字；领先词前置、身份句删除（正文 H1 已有）、触发按概念收敛不罗列口语变体、领先词中英并列锚点。预算细则本体归工单 04。

### 二、调用权分流：探测不支持硬隔离，按语义兜底落地并记档

**探测结论（2026-09-24 实测，ZCode 本地源码锚点 `872ad96`）**：ZCode skills frontmatter 解析为白名单制，`SAFE_FRONTMATTER_KEYS` 仅 `name/description/when_to_use/license/metadata` 五键（`apps/zcode-cli/packages/adapters/src/skills/index.ts:21-27`），metadata 的描述面仅产出 description 与 whenToUse（:223-224）；`disable-model-invocation` 不在键表、被解析器静默忽略。技能清单经 `buildSkillsSection` 全量注入模型上下文、无任何按字段过滤（`core/src/context/sections/skills.ts:17-37`）。写入该字段的唯一副作用是 `safeToAutoLoad: false`（index.ts:231——键不在 SAFE 集即 false），而 safeToAutoLoad 的唯一消费方是 `/skills` 命令的展示输出（`cli/src/skills-command.ts:160,228`），无运行时行为；此外 `policy.allowImplicitInvocation` 硬编码 true（index.ts:234）且全仓无消费方——调用权杠杆在 ZCode 侧整体缺位。ZCode 仓库自家的 dep-refs:4 与 dogfood:5 写入了 `disable-model-invocation: true`，实测无隔离效果（模型仍可见可调）。

**裁定**：M1 硬隔离不具备 harness 条件，调用权分流按语义兜底落地——

1. **AGENTS.md 显式命令表是唯一用户门禁面**：表内六命令（/grill-me、/grill-with-docs、/to-spec、/to-tickets、/implement、/handoff）保留"模型不可自动触发，须提示用户显式调用"强制条款，改写为正向判据形态（"流程到达该段时：出示命令名并停止，等用户键入"）。
2. **全部 duo-* 技能 frontmatter 不写 `disable-model-invocation`**：写了无隔离效果、反而击穿 safeToAutoLoad 展示语义——此结论记档，防后续会话照搬 Matt frontmatter 误加。
3. **流程门禁的强制力由判据承担**：各流程类技能的关键门（定级、验收、收口、复盘）写成"出示证据"判据（对比报告 M3 行），跳步在收口核对与红线 8 复盘处可检出——Matt 的"结构不可能"在 duo 降级为"判据可检出"，衰减风险见 Consequences。spec 决策 4 的"正文点名文件+章节"形态由决策三第 2 条承接执行。

**备选讨论（拒绝）**：迁移 `.zcode/commands/` 自定义命令体系可获天然模型不可达（命令不进 skills_listing，仅用户敲 `/name` 时展开 prompt），但该体系无技能正文加载语义（无 SkillMetadata、无 Skill tool 引用），duo 技能需被模型在流程中经 Skill tool 引用（决策三的显式调用），迁移得不偿失。

### 三、改写纪律（改写组 05–11 共同约束）

- description 重写与 AGENTS.md 路由表**同一 diff** 双向同步（duo-workflow:62 既有红线延续）；description 改写单独立 commit，保证触发行为整体回滚（C1 spec 风险记档）。
- 跨技能 operative 引用一律显式调用形态（"Call the Skill tool with \"X\""）；引用规范/配置本体写"读 `<路径>` 的 `<节>` 并按其执行"，禁用"用法以该技能为准"。
- 保留资产不得损失（对比报告 §4 采纳条 4，源出 spec Implementation Decisions 9）：experience.md 回流、豁免治理、brief 填空模板、表格化分支、L0/L1/L2 渐进加载、判例节。
- 变更历史迁出 SKILL.md（duo-code-review 6 段 → experience.md），SKILL.md 零历史节；反模式节改正向判据。
- C1 不发版：全部产物直接落 main 文档提交；改写不触任何 Java/yml/pom，误触即事故记档。

## 拒绝的选项

1. **照搬英文 writing-for-agents 原文为 duo 规范**——duo 技能与团队工作语言是中文，英文规范在写作时加一层翻译负荷；且 Matt 理论的实例全部是英文技能，不附 duo 正反例则规范无法直接指导中文技能改写。
2. **不移植理论、靠直觉逐技能改**——C1 problem statement 的三项实证恰是直觉写作的衰减产物；无成文规范则改写结果不可复审、工单 04 之后的 M25+ 新技能无约束可依，违反 C1 作为 M25 前置约束的定位。
3. **等待 harness 支持硬隔离后再改写**——探测已确认不支持且 harness 开发在 C1 范围外（spec Out of Scope）；阻塞改写违反"C1 收口先于 M25 启动"的时点。兜底方案的漂移风险有检出手段（判据 + 红线 8 复盘 + bug-ledger），且本节探测记档使未来 harness 支持时可升级为硬隔离。
4. **迁移 `.zcode/commands/` 体系换取天然隔离**——见决策二备选讨论：无技能加载语义，与显式调用路线冲突。

## Consequences

- **正**：duo 获得中文成文写作规范，M25+ 新技能写作有约束、有正反例可对照；改写组有唯一依据，改写结果可机械复审（对比报告矩阵即核对表）；description 常驻成本有量化预算（4–5 倍溢价收敛至约 1.5–2 倍：user 档 ≤60 字 ≈1.5 倍、model 档 ≤80 字 ≈2 倍，Matt model 档均值 31 词 ≈ 40 token 为基准）；探测记档使分流路径的"为什么"可追溯。
- **负 / 风险**：①调用权为语义兜底——模型擅自启动流程段的风险从"结构不可能"降为"判据可检出"，跨会话仍有漂移可能，依赖红线 8 复盘与 bug-ledger 记档闭环，异常频发则重开本 ADR；②safeToAutoLoad 展示语义未被利用，`/skills` 列表不区分用户/模型档；③中文规范与 Matt 原文存在翻译差，机制语义争议以 docs/research/mattpocock-skills/ 三件套的原文锚点为终审依据；④description 全量重写等于触发行为整体变更，预留一个真实使用周期观察命中，异常按 bug-ledger 记档再修。
- **升级路径**：ZCode 未来版本若支持分流类字段（进 SAFE 键表并参与 skills_listing 过滤），按本 ADR 记档直接升级为硬隔离（届时另立 ADR 修订决策二）。
