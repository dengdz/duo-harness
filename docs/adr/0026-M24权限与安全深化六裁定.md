# M24 权限与安全深化六裁定：规则引擎、只读免审批、计划硬禁、MCP 命名、Web 令牌与模型切换

Status: 批准（2026-09-22，M24 启动 grill 二十问逐题裁定；同日 spec 期增补决策七——Anthropic 适配器与 provider 声明，spec 对账发现 effort 映射落地面矛盾后用户裁定；范围与依据锚 = [ADR-0024](0024-M23至1.0里程碑版图重排.md) M24 节，事实基础 = docs/research/ 两家探测文档（工单 08 只读命令识别、07 审批交互、20 存储配置与凭据、14 MCP、18 桌面端、01 模型选择保存意图、09 LLM 调用层），锚点 ZCode `872ad96`）

## 背景

M23 放开了后台执行（ADR-0025），控制面必须跟上——这是 ADR-0024 把 M24 定为「权限与安全深化——放得开也收得住」的依据。现状缺口：审批决策枚举只有 allow/deny，无任何规则记忆（bash 与未知工具恒 ASK）；plan 态只挂指导片段不硬禁工具（M7#1 挂账）；MCP 工具名清洗坍缩即抛错、重连耗尽静默注销；Web 面零鉴权、服务端单全局会话多标签互踩（M8#4 挂账）；无运行时切模型与思考档位。本 ADR 只钉跨工单、难逆转的语义级裁定；命令清单本体、schema 字段级、携带细节归 spec（`.scratch/m24-permission-security/`），spec 直接引用上述探测文档。

## 决策

### 一、权限规则引擎：两级作用域、词边界前缀、高危双拦

- **存储两级**：项目级持久于项目根 `.duo/settings.json` 的 `permissions` 段（duo 首个项目级设置文件写入器，后续同类设置同文件扩展）；会话级随会话事件流持久、resume 恢复——ADR-0024「会话（内存）」措辞澄清为「非项目级、随会话生命周期」，与 permissionMode 事件投影恢复同机制。
- **记法与匹配**：bash 规则 `Bash(prefix:*)` 按词边界前缀匹配——命令名后必须紧跟串尾或空白，`Bash(ls:*)` 不匹配 `lsof`；多词前缀（docker logs 等）为 spec 阶段清单扩展。
- **裁决序**：deny 恒优先（与 guard 单调否决同构）；allow 规则只查非只读命令（ADR-0024 原文），deny 规则查全部命令。
- **来源分离**：allow 规则只产自审批卡「总是允许」；deny 规则仅手写 `.duo/settings.json`（审批卡不产 deny，误触风险）。
- **高危根命令双拦**：sudo / su / doas / rm / dd / mkfs / chmod / chown / shutdown / reboot 十个根命令，审批卡不出现「总是允许」键（不生成），运行时手写 allow 也不生效（命中走 ask/档位并日志说明）——「永不生成」强化为「永不放行」。git 破坏子命令级排除（push --force / reset --hard / clean）spec 评估、做不进即 backlog。
- **管理面与键位**：审批决策枚举扩四值，CLI 键位 y=允许 / a=总是允许（项目）/ s=仅本会话 / n 或空回车=拒绝，Web 卡片对应按钮且回填改按卡片 ID 关联（销 M23 工单 03 记档的按位置回填坑）；`/permission` 扩 `rules list`（项目+会话两级）与 `rules rm <n>`，Web 端本期不做规则管理页。

### 二、只读 bash 免审批：三态 fail-closed

- **三态策略表**：每命令产出 true/false/undefined，undefined（含解析失败、不支持语法、动态词）一律按非只读→ask；首期约 30 个 allowAnyArg 只读命令 + git 四件套 status/log/diff/show，清单本体 spec 敲定。
- **git 信任分类**：四件套必叠 cwd `.git` 存在性检查（防 `git -C` 指向任意仓库的逃逸）。
- **复合结构不算只读**：管道、`&&`、命令替换、重定向、别名一律 undefined。
- **接入 seam**：经「运行时 capability 覆盖静态 metadata」接入审批链（ADR-0024 原文），判定 true 即免审批放行。

### 三、计划模式硬禁：不注入 + deny 兜底

- **机制**：plan 态下非白名单工具定义不注入模型（不可见），仍被调用时 pre-execute deny 兜底——术语表「计划模式：引导式、不硬禁工具」口径废止（M7#1 销账）。
- **白名单**：只读 bash 策略表判定通过者 + 既有只读工具（read/glob/grep 等）；web_fetch/web_search 维持现行只读档 ask 语义。
- **保留不动**：ExitPlanModeTool 批准闭环、plan/mode 事件与续接恢复原样。

### 四、MCP 命名一律哈希后缀

- **防坍缩**：远端工具名有损规范化（非法字符替换）后一律追加短哈希后缀（`mcp__{server}__{tool}__{hash8}` 形态）——工具名被审批卡、规则、会话历史引用，稳定优先于美观；废弃「清洗后重名即抛错」旧语义。
- **重连耗尽终态**：现状 GAVE_UP + 注销之上补会话事件通知（模型与用户可见）+ Web 状态面标注，消灭静默消失。

### 五、Web 鉴权令牌 + 标签级会话绑定

- **令牌**：启动生成随机 token，控制台打印带 token 的 URL；浏览器首载后存 localStorage，后续 HTTP/SSE 请求携带；校验失败一律 403（fail-closed）；yml 保留 `web.auth` 显式关闭开关，关闭时启动横幅警示「鉴权已关闭」。
- **标签绑定最小版**：每标签 localStorage 持自己的 sessionId，服务端从单全局会话字段改 Map 多会话并存；新标签打开默认新建会话（不弹选择页，互踩隔离优先），无记录旧标签视为新标签；resume 仍走面板现有手动入口。完整多会话协调仍属 1.0 后（ADR-0024 原文）。

### 六、/model 同源切换 + /effort 思考等级

- **/model 首期限同 provider**（baseUrl 不变换模型名）：可切名以 yml `llm.models` 白名单为准，无参列出清单+当前、带参只准切清单内——模型名直接决定成本面，白名单即「收得住」；跨 provider 路由（yml 预声明、适配器重建）销账 1.0 后菜单。
- **保存意图与执行绑定分离**（探测工单 01 结论落地）：模型切换落会话事件记「保存意图」；resume 时意图 ≠ 当前配置模型仅横幅提示「上次用 X（当前 Y），/model X 切回」，不自动切——防成本意外（休假期换便宜模型后被静默换回）。
- **/effort 四档归一**：off/low/medium/high，缺省 medium；provider 映射——Anthropic thinking+budget、OpenAI 兼容 reasoning_effort、DeepSeek 靠切模型、GLM thinking 开关，不支持即显式降级标注（不静默）；辅助性请求（标题生成等）强制降档；切档落会话事件、下一 turn 生效。

### 七、Anthropic-messages 适配器与 provider 显式声明

- **背景**：决策六的四行映射里 Anthropic 行（thinking+budget）无处落地——现状仅 OpenAI 兼容一个适配器，Anthropic-messages 协议适配原钉 1.0 后菜单。spec 期对账发现此矛盾，用户裁定本期补齐适配器、四行映射全量真落地。
- **Anthropic-messages 协议适配器**（新增，与 OpenAiCompat 并列的仅有的两个协议实现）：SSE 流式、tool_use/tool_result 块映射、system/messages 结构映射、`x-api-key` + `anthropic-version` 鉴权头；/effort 映射 thinking + budget。不引官方 SDK（红线 4 精神，零新依赖）。
- **provider 显式声明**：yml 增 `llm.provider` 四值——openai-compat（缺省，兼容现状零改）/ anthropic / deepseek / glm；决定适配器选型、鉴权头形态与 effort 映射策略。deepseek/glm 仍走 OpenAI 兼容面（仅映射策略与降级标注不同）；provider 不再由 baseUrl 隐式表达；新 provider 接入 = 加一个枚举值 + 对应映射行。

## 拒绝的选项

- **`.duo/permissions.json` 单一职责文件**：每加一类项目级设置多一个文件，settings 型留唯一入口。
- **会话级规则纯内存、resume 即失**：同一会话续接再弹一遍卡，体验割裂；事件流持久化已有 permissionMode 先例。
- **审批卡加「总是拒绝」产 deny**：误触风险高，一条手写 deny 可达同样效果。
- **多规则命中按文件顺序/最长前缀优先**：破坏与 guard 单调否决的同构性，裁决序出现第二套语义。
- **纯字符串前缀匹配**：`Bash(ls:*)` 误匹配 `lsof`（写/挂载类），短前缀吞掉长命令名。
- **git 破坏子命令级排除首期就做**：解析粒度从根命令深入子命令参数，工作量失衡，spec 评估后再定。
- **plan 态注入但调用即 deny**：模型反复撞墙浪费轮次，与「硬禁」字面不符。
- **MCP 仅坍缩时加哈希**：名字随服务器加载顺序漂移，重启可能改名，引用断裂。
- **Web 令牌强制开不可关**：本机单人场景无退路；fail-closed 指校验语义非不可关闭，关闭必横幅警示兜底。
- **新标签先弹「新建 or 恢复」选择页**：首屏多一层，隔离目标后置一步；resume 已有面板入口。
- **/model 本期做跨 provider**：密钥面 + 适配器重建，与「同源换名」的收益不成比例，1.0 后菜单。
- **任意同 provider 模型名可切**：拼错名要到请求时才暴露，可切面不可预期。
- **resume 自动切回意图模型**：静默换模型有成本意外风险，提示制让人拍板。
- **/effort 缺省 off**：思考型模型能力被压，与功能初衷相悖。

## Consequences

- ADR-0024 M24 节两处措辞由本 ADR 修订：「会话（内存）」澄清为「非项目级、随会话生命周期」；「高危根命令排除（永不生成前缀规则）」强化为生成+运行时双拦。
- 术语表与本 ADR 同 diff 增改：计划模式（改写硬禁）、权限规则（新）、只读命令（新）、鉴权令牌（新）、标签会话绑定（新）、思考等级（新）、模型切换（新）、工具名规范化（新）、provider 声明（新，决策七）、审批小队列（扩四值枚举与键位）。
- limitations 对账随实现销账：M7#1（计划模式硬禁）、M8#4（标签级会话绑定最小版）；backlog「/model 运行时切换」「Web 鉴权令牌 + bind」两条销账于 M24 收口；Anthropic-messages 协议适配从 1.0 后菜单提进本期（决策七），随实现销账。
- backlog 新增：跨 provider /model 路由（1.0 后菜单既有条目兑现挂账）、git 破坏子命令级高危排除（spec 评估不进则入）。
- spec 归属：约 30 个只读命令清单本体、`.duo/settings.json` permissions 段 schema 字段级、多词前缀扩展清单、token 在静态资源/SSE 的携带细节、`llm.models` schema、tabId 信任模型、/model 与 /effort 会话事件命名、辅助请求降档实现面。
- 行为迁移显式化：bash 从「恒 ASK」变为「只读免审批 + 规则可放行」——验收必须覆盖正反两面（只读放行不弹卡、高危十命令手写 allow 仍拦）；多标签从「互踩单会话」变为「各持会话」，验收必须含双标签并行操作。
