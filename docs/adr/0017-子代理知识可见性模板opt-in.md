# 子代理知识可见性：模板 opt-in 携带技能名录与 AGENTS.md

Status: 批准（2026-09-17，M16 grill 裁定——只立裁定，实现归后续里程碑）

M15 交付后 limitations 挂账："子代理不可见技能清单与 AGENTS.md"——子代理 system = 框架基线 + 模板专属提示，不含呈现位的 prompts 片段（ADR-0015 决策 5 的模板制边界使然）。三方对照（[subagent 派发与提示词对照](../research/subagent-派发与提示词对照.md)）：DSH 子代理继承父全部 prompt 段；ZCode 向子代理注入 skills 名录；duo 现状不含。实际代价：子代理接到"按仓库规范审查"类任务时拿不到项目约定，父 agent 只能把规范内容拷进任务描述——浪费父上下文，且同一知识随任务反复传递。

## 决策

模板 opt-in：知识面裁量权与工具配置权同构，都归部署者。

1. 子代理模板增加两个可选布尔字段 `withSkills` / `withAgentsMd`，缺省 `false`——未声明零变化，M15 既有模板不受影响。
2. `withSkills: true` 时，子代理 system 追加**技能名录片段**：按技能域既有发现根与优先级生成"name + description"清单，不含 SKILL.md 全文。名录用于子代理自知能力边界，不用于自加载——需要全文时由父 agent 在任务描述中点名，保持子代理"短命一次性执行者"定位。
3. `withAgentsMd: true` 时，追加 AGENTS.md 注入内容，沿用既有 64KB 预算与截断规则（M7 注入链同源）。
4. 拼装顺序固定可审计：框架基线 → 模板专属提示 → 知识片段。
5. 框架不替部署者裁量：不设全局开关、不按任务内容动态决定可见面。

## 拒绝的选项

- **恒不含（现状维持）**：模板作者永远无法给子代理知识，父拷贝知识的上下文浪费固化。
- **恒继承父全部 prompt 片段（DSH 形态）**：部署者失去逐模板裁量，子代理可见面不可控；fork 大前缀叠加全量片段推高每轮 token；与模板制边界（ADR-0015 决策 5）直接冲突。
- **子代理运行时动态加载技能（挂 skill 工具）**：越出短命执行者定位——技能加载与会话延续是父 agent 的职责面。
- **AGENTS.md 全链注入（含嵌套子目录发现）**：父呈现位本链都只有用户全局 + 项目根两文件（M7 已知限制），子代理不得先行超越父能力形态。

## Consequences

- 模板解析白名单、record 字段、基线拼装各一处扩展；模板 config JavaDoc 示例同步。
- 名录片段与 AGENTS.md 内容进子代理 system 有 token 面——名录通常小，AGENTS.md 受 64KB 预算约束，部署者可预期。
- 实现归后续里程碑（启动新里程碑时按 backlog 挑）；落地时同一 diff 更新 limitations 对应条目去向。
