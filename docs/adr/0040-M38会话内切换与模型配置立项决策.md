# M38 立项决策：会话内切换——四态档位选择器、模型/思考实时切换与模型配置

Status: 批准（2026-10-05，/grill-with-docs 五问逐题裁定，共识纪要经用户确认后落盘；1.0 后轻量里程碑制第六期 M38）

## 背景

1.3.0 已发（桌面端 + 亮色缺省当日发布）。M38 诉求：参考 ZCode 的会话内四件 UI 能力——安全等级切换、模型实时切换、思考等级切换、模型配置管理。实现面预研（探索代理，HEAD 2b828b6c）四能力现状：审批档位**后端全通**（`/permission` 双面 busySafe 命令 + `permission/mode` 事件 + latest-wins 恢复）；模型/思考切换**机制在但仅 CLI 面**（`SwappableLlmAdapter` 换链 + `/model`、`/effort` 为 CommandScope.CLI，Web 面装配裸 adapter 未接换链）；模型配置运行时增改**完全缺失**（config.yml 启动只读、无写回通道）。

版图对账：CHANGELOG 实发 1.3.0（tag 在，当日发版）；本立项定 **M38 = 1.4.0**（新功能进次版本），无错位。分支 `1.4.0` 自 main（2b828b6c）切出，开发提交不落 main（红线 7）。

## 决策（grill Q1–Q5，用户逐题裁定）

### 一、四态统一档位选择器（Q1）

选择器四态 = **计划模式 / 变更前确认 / 自动编辑 / 完全访问**（ZCode 同款文案，用户心智），后端映射既有机制零新增：计划模式 → `/plan` 计划态；变更前确认 → 档位 READ_ONLY；自动编辑 → 档位 WORKSPACE_WRITE；完全访问 → 档位 DANGER_FULL_ACCESS。计划态与档位的正交性由选择器内部消化（选计划 = 入 plan；选其余三态 = 若在 plan 先退出再切档）。

### 二、入口与布局（Q2/Q5）

**composer 左下角双选择器**：四态档位选择器 + 模型/思考选择器（点开列 `llm.models` 预设与四档思考）——对话中高频操作在手边（ZCode 同位同交互）。**状态面板新增「模型配置」管理区**：查看/编辑/新增预设（provider/baseUrl/apiKey/model/思考档）——低频管理面，与主题选择器先例同区对称。

### 三、模型/思考切换：本呈现位独立（Q3）

Web 面自己的执行链接入换链通道（SwappableLlmAdapter 包装 + `/model`、`/effort` 命令升 CommandScope.ANY + 预设解析上提）：Web 切模型只影响 Web 的对话，与 CLI 各自独立、互不同步——对称「双呈现位各自装配执行链、各自持会话」的既有架构。跨面全局同步不做（新契约大改）。

### 四、模型配置：编辑写回 + 重启生效（Q4）

状态面板「模型配置」区：查看/编辑/新增预设（provider/baseUrl/apiKey/model/思考档）→ **写回 `~/.duo/config.yml`**（密钥本就在该文件，不入仓库红线不变）→ 提示「重启生效」。**执行链热重建不做**（装配点重建/失败回滚/在飞 turn 处理的复杂度不成比例）；重启语义与「模型/思考重启回落 config.yml 预设缺省」的既有机制自然衔接——写回后重启即用新配置。

### 五、随案既有语义（不改，spec 锚）

档位切换 busySafe **即时生效**（busy 中可切）；模型/思考切换**下一轮生效**（换链语义）；档位重启恢复 latest-wins（会话级）；模型/思考重启回落 config.yml 预设缺省（配合决策四写回即自然持久）；完全访问档无额外确认（与 CLI 一致，fail-closed 闸门不随档位放松）；Web UI 改动浏览器/桌面壳同源自动双达。

> 范围增补（2026-10-05，用户裁定）：新增第七能力「创建会话时选择工作区」——启动壳时选默认工作区（记住上次）+ 每次新建会话可改（后端建会话接线扩展：Session.createDeferred 本收 cwd 参数；档位治理随所选目录，与 CLI cd 等价安全口径）。工单 07 承载；收尾票 06 依赖边随之扩含 07。
>
> 拒绝的选项

- **跨面全局同步**（执行链上提共享服务）：装配层重构 + 跨面状态同步新契约，改动量大且触碰 llm 装配层——本期不做。
- **配置写回 + 热重建**：执行链热重建新契约（在飞 turn/失败回滚），风险与工作量不成比例——写回 + 重启生效。
- **只切换不配置**：presets 白名单本身需手改 config.yml，「模型配置」落空，违背立项诉求。
- **三档位与计划模式分开两处**：概念上正交但操作上高频同域，统一四态选择器贴合用户心智（ZCode 同款）。
- **状态面板单处/双处主镜**：切档是对话中高频操作，面板单处体验差；双处主镜多状态同步成本。

## Consequences

- 分支 `1.4.0` 已自 main 切出（本 ADR 同 diff）；开发提交不落 main（红线 7）。
- 后端改动面：⓪建会话 workspace 参数接线（工单 07，Session.createDeferred cwd 参数既有）；①`/model`、`/effort` 命令升 CommandScope.ANY；②预设解析从 CLI 闭包上提（LlmConfig.models 共享读取）；③WebPlugin 执行链接 SwappableLlmAdapter；④config.yml 写回契约（LlmConfig 序列化写回 + 原子写，密钥留在 ~/.duo）；⑤composer 四态选择器 + 模型/思考选择器 + 状态面板配置区（前端）。
- 既有语义锚：档位 busySafe 即时；模型/思考下轮生效；`model/intent`、`model/effort` 事件照发；档位 `permission/mode` 事件 + latest-wins 恢复照旧。
- spec 阶段待定细节（非悬置）：选择器与配置区的具体样式（M36 主题 token 体系内）、`llm.models` 预设条目的字段形态对齐 LlmConfig 既有字段、busy 中切模型/思考的 UI 提示文案。
- 明确不做（本期）：跨面全局同步、执行链热重建、配置热重载、签名/打包路线（已取消）、通知/深链（已移除，重启需重新立项）。
