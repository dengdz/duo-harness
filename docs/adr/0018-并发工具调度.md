# 并发工具调度：并发执行、model 序成对提交

Status: 批准（2026-09-18，M17 grill 七题裁定；范围预定义于 ADR-0016，本文立落地语义）

M16（0.11.0）发布后，agent 循环仍是单轮 tool_calls 逐个串行执行：调研类轮次（read × N / glob / grep）总时延为各工具之和，并行收益全部流失。ADR-0016 已把并发工具调度定为 M17（0.12.0）主题并预定词汇（DSH 同款：isConcurrencySafe、独占屏障、model 序提交、并发度缺省 10），同时明示本期主战场是**事件乱序对 M10 游标增量回放、M13 尾窗单趟定窗、投影合法性的假设冲击**。本文记录 grill 七题的落地裁定。事实基础：DSH 研究档案（`docs/research/DSH/` 总览、核心功能全景、插件化架构细节备忘——isConcurrencySafe 按参判定与 fail-closed 语义的出处）、duo 现有架构考古（串行点、事件序号机制、投影/回放/尾窗假设、超时现状、管线预留挂点）。

## 决策

1. **并发安全声明**：`ToolDefinition` 接口新增 `default boolean isConcurrencySafe(JsonNode args)`（带参版，DSH 同款签名——未来按参数放开某类调用时接口不用动）。fail-closed：未覆写、判定抛错、返回非严格 true，一律按独占处理——宁可慢，不可错。
2. **首批标注面**：`read` / `glob` / `grep` 并发安全（纯只读）；`write` / `edit`（读前写闸门的已读集合是会话级共享状态，并行即竞态）、`bash`、`ask_user`、`exit_plan_mode`、`skill`（技术上只读，保守起步）、subagent 五件套（跨 agent 状态）全部独占；MCP 远端工具恒独占（第三方副作用不可由 duo 代码代判）。
3. **调度语义**：按 model 序扫描单轮 tool_calls，连续并发安全调用成组进虚拟线程滚动池（`maxParallelToolCalls` 缺省 10、yml 可配；配置为 1 即完全串行，兼排障开关，不设独立总开关）；撞独占调用即屏障——排空当前池、独占调用单独执行、再继续。`requiresApproval() == true` 的调用无论安全声明如何一律不进并行池（审批即独占）。
4. **成对有序提交（主战场裁定）**：无论完成先后，tool/call 与 tool/result 严格按 model 序成对写入事件日志——日志形态与串行时代逐字节同构；M10 游标回放、M13 尾窗定窗、投影修复（repairToolMessageAdjacency）、M16 崩溃闭合（sealDanglingToolCalls）全部零改动；日志写入收敛单点，会话单写者约定原样保持。接受的安全组内可见性延迟（慢工具延迟快工具的结果呈现）：组内均为毫秒级只读工具，实际无感；真正的慢工具 bash 是独占的，结构上不在池内。
5. **工具超时推广为管线缺省**：三段管线 execute 段挂 around 终端监听器（管线既有预留挂点）。缺省 120 秒（与 bash 对齐）、yml 可配；`ask_user` 声明式豁免（等人类回答不限时）；超时 interrupt 虚拟线程 + 超时错误作为 error 工具结果回填（沿用异常收敛语义），不可中断操作后台跑完丢弃；bash 保留 terminateTree；优先级为工具自身声明 > 管线缺省（bash 模型可传 timeoutMs 的协作式原样保留）。
6. **todo_write 分解抓手（DSH 同款）**：全量整表替换 schema（content + status 三态，无 id/priority，校验非空不重复）；`todo/write` 事件落日志（log-only、latest-wins 投影、重开恢复）；模型只收计数回显、完整清单只走事件流给 UI；多 in_progress 不校验不配置（并行时代常态，纪律靠工具 description 引导）；呈现为 Web 双表面（工具行摘要 + 输入框上方常驻折叠圆圈清单）+ CLI 一行计数摘要；投影清空映射（新 user/message 清空、终版回复后保留）；todo_write 本身是独占工具；goal 域不做。
7. **搭车**：Web 迭代上限错误卡（completed=false 时直推 run/error 帧，BUG-20260917-03 验收发现的缺口）；limitations 遗留 #2/#3 加并发后复审注记（注：grill 时曾把 #3 表述为"顺路销账"，经核对原文为容器六态 recheck 的跨线程竞态、与工具执行并发不同层，修正为注记——多线程测试义务落在工具域真并发）。

## 拒绝的选项

- **结果按完成序提交**（ADR-0016 已拒，重申）：投影与重放需自行消化乱序，直接冲击 M10/M13 既有算法假设。
- **call 批量先发 + result 按序提交**：立即可见性更好，但日志形态变为 call 与 result 不相邻——投影需改缓冲配对、M13 边界重审、M16 崩溃闭合与投影修复按"相邻"语义全部重审。为几秒可见性动摇三套已验收算法，不值。
- **isConcurrencySafe 无参布尔**：更 Java 惯用，但将来按参数放开（如 bash 只读命令）是破坏性接口变更；带参成本几乎为零。
- **MCP 工具 yml 白名单本期就做**：部署者裁量有价值，但本期主战场是调度管线本身，验收面收窄优先（backlog 记档）。
- **write/edit/skill 并行放开**：write/edit 有闸门状态竞态；skill 虽只读但保守起步——skill 列为后续放开第一候选。
- **统一"并发总开关"配置**：`maxParallelToolCalls: 1` 即完全串行，语义已覆盖，不重复发明。
- **DSH 的 `maxParallelSubCalls`**：管 PTC run_code 的嵌套子调用并发，duo 无该路径（run_code 在 1.0 后菜单）。
- **todo 增量更新 / 带 id / priority / activeForm**：DSH 源码注释明证"整表替换无需稳定 id"——模型全量重写清单即真相，机制刻意最小。
- **todo 多 in_progress 做成配置**（DSH 的 `allowParallelInProgress`）：并行时代多任务是常态，缺省放开 + 纪律引导即可，省一块配置面与验收面。
- **goal 跨轮目标域**：DSH 独立域（CAS 修订、人类权限门、自动续跑），与轮内清单正交，不混入本期。
- **ADR-0017 搭车 M17**：subagent 域与并发正交，主线三大块（调度+超时+todo）验收面已不窄，留 M18 或独立挑期。

## Consequences

- 术语表同 diff 入册八词条：并发安全（isConcurrencySafe）、独占工具（exclusive）、管线缺省超时、工具并行池、顺序屏障、model 序提交、并发度、todo 清单。
- backlog 同 diff 对账：销账"Web 迭代上限可见化"；新增 MCP 并发白名单、skill 并发放开候选（工具并发域小节）、goal 域（1.0 后菜单）。
- limitations 同 diff：遗留 #2/#3 加复审注记；M15#6 待 todo_write 落地销账。
- 事件日志形态不变是本设计的核心承诺——M10/M13/M14/投影/崩溃闭合零改动的验证义务在测试（并发轮日志与串行轮对照同构断言），spec Testing Decisions 已列。
- 审批即独占今天无实际影响（唯一审批工具 bash 本就独占），是给未来工具立的 fail-closed 规矩。
- hooks（M18）在本并发管线之上设计（ADR-0016 排期逻辑：并发居先、hooks 居后才不用返工）。
