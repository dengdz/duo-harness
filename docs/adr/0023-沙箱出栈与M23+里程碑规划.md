# 沙箱出栈与 M23+ 里程碑规划：ZCode 升主参考后的版图修订

Status: 批准（2026-09-21，M22 探测里程碑收尾裁定；探测证据 = docs/research/DSH+ZCode 两家 22 张探测工单产出 44 份五段模板文档 + 沙箱与权限专册 ×2，锚点 DSH `ddefc45f` / ZCode `872ad96`）

本决策修订 [ADR-0016](0016-M16至1.0里程碑规划.md) 的 M22 及其后版图：① 沙箱出栈；② M22 改道为「参考项目深度探测与后续阶段规划」里程碑（已完成，见 `.scratch/m22-reference-probe/`）；③ 重排 M23 至 1.0。

## 背景

两件事改变了 ADR-0016 的前提。其一，2026-09-21 注册 ZCode 为第二参考项目并经用户裁定**以 ZCode 为主、DSH 为辅**（duo-research 惯例已修订）；对沙箱域的两家对照探查（docs/research/DSH/沙箱与权限.md、docs/research/ZCode/沙箱与权限.md）显示：DSH 拥有生产级四平台沙箱但其 Landlock 路依赖外部 C 启动器二进制分发（连 TS 生态都绕开了进程内 FFI），ZCode 曾实现 protected-resource sandbox 后**整体撤除**（源码注释留证，撤因不可考）。其二，duo 的硬约束「零新 native 依赖」（红线 4）与个人工具形态（审批兜底、单用户）使 OS 级沙箱的成本收益明显失衡——ADR-0016 为此预留的**出栈阀**（「研究结论成本收益不匹配则明示出栈、1.0 不等」）被触发。

探测阶段（22 张工单，44 份文档）为后续每期提供了机制级事实基础；本决策的版图表逐期引用其「对 duo 的启示」段作为依据。

## 决策

### 一、沙箱出栈

duo **不引入 OS 级沙箱**（Seatbelt/Landlock/bwrap/e2b 任一路径均不落地）。bash 的安全边界维持「可信代码内策略检查 + 审批」：非 danger 档一律 ask（ADR-0012 语义不变）。证据与理由：

1. **参考权重**：主参考 ZCode 曾实现沙箱并整体撤除（撤除先例入档：docs/research/ZCode/沙箱与权限.md）；次参考 DSH 的实现虽完整，但其 Landlock 路需分发 native 启动器（docs/research/DSH/沙箱与权限.md），直接触碰红线 4。
2. **成本**：duo（Java 21）侧 FFM 为 preview 需 `--enable-preview`；分发预编译启动器需新增 native 构建链与四平台验证面。
3. **收益不足**：个人单用户工具，非 danger 档审批已兜底破坏性风险；M20 后的出网面已有 SSRF 三道防线（ADR-0021）。
4. **1.0 兼容**：ADR-0016 的 1.0 安全基线措辞为「沙箱**进退决议**已做出」——本决议即闭合该判据。

若未来重启沙箱，DSH 的设计仍为首选参照：Seatbelt `sandbox-exec` 包裹（与 duo ProcessBuilder 同构、零新依赖）、fail-closed 无 unconfined 回落、升级审批词汇（`WIDER_MODES` 阶梯 + `sandbox_permissions`/`justification` 一次性重试）、`writableRoots` 单一推导家。

## 拒绝的选项

- **继续 M22 沙箱实现**：出栈阀已触发（证据见决策一）；为 parity 而 parity 违背 ADR-0016 的差异定位原则。
- **不插 M23 直接 1.0**：ZCode 升主参考后权限/执行的三个 gap（规则引擎、只读识别、run_in_background）真实存在，1.0 前后权限体验与主力参考代差明显；一期换一个对齐的主版本（用户裁定）。
- **照抄 DSH SandboxProvider 全套**（四方言链+升级审批）：首期无沙箱故不适用；仅作「若重启沙箱」的参照存档（见决策一）。
- **e2b 云沙箱**：实为云远程执行后端而非沙箱方言（docs/research/DSH/沙箱与权限.md）；密钥/成本/数据出域对个人本地工具不匹配，出栈。
- **M24 并入 1.0**：前端脆弱性债（魔法串耦合）会随功能增长复利，赶出来的 1.0 不是干净的 1.0（用户裁定）。

## Consequences

- limitations：M12#1 转长期边界不再指向里程碑；M20#1 措辞更新；**不新增**「沙箱未实现」条目（本 ADR 即决议记录）。
- 术语表/ADR-0016/backlog 同 diff 对账（见决策四）；本 ADR 与 ADR-0016 双向注记可达。
- 后续每期启动消费规则：**先读 `docs/research/<别名>/<域>/` 探测文档再 grill**，锚点过期才增量补扫，不重扫源项目；M23 启动仍走 grill → to-spec → to-tickets → 逐工单实现。
- 探测期间的全部文档改动（docs/research 22 张 × 2 + 手册/总览/专册 + spec/issues + 本 ADR 对账）随本 ADR 同一确认后提交。
