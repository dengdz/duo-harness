# 模块划分

> 状态：M1-M5 全量落地——内核（M1）、工具域治理与 MCP 接入（M2）、LLM 适配（M3）、
> 会话上下文（M4）、agent 工具循环（M5）；端到端 Demo 与两个可交互 REPL 演示全部机制。

## 模块与依赖方向

| 模块 | 角色 | 依赖 |
|---|---|---|
| `duo-harness-core` | 容器内核：插件加载、config 绑定、可逆副作用、服务注入、事件分派、依赖驱动生命周期、配置驱动 boot、DuoHome 目录约定 | Jackson（databind + dataformat-yaml）、SLF4J api |
| `duo-harness-tools` | 工具域：ToolDefinition 注册 + 三段执行管线（pre-execute 准入 → execute around 本体 → post-execute 结果治理），审批 ask 三态 / guard 单调否决 / 输出契约挂链生效，以 "tools" 服务发布 | core |
| `duo-harness-mcp` | MCP 接入：官方 Java SDK（internal 隔离）连接 MCP 服务器（stdio），远端工具同步进工具域 | core + tools + MCP SDK |
| `duo-harness-llm` | LLM 适配：provider 中立调用契约（流式 chunk）+ OpenAI 兼容适配器 + DuoHome 配置加载 | core + Jackson |
| `duo-harness-session` | 会话域：事件溯源（append 单写 + JSONL 同步落盘）+ 投影（多轮记忆）——中立数据基座，不依赖任何功能模块 | core + Jackson |
| `duo-harness-agent` | agent 循环：LLM + 会话 + 工具的编排层（ChatAgent 契约 + AgentListener 过程回调）——依赖图顶层汇合 | core + llm + session + tools |
| `duo-harness-example` | 示例插件集（greeting 服务对 / tools 工具与治理 / mcpfs 迷你 filesystem server 等功能子包）与三个演示入口（DemoMain / ChatRepl / AgentRepl） | core + tools + mcp + llm + session + agent |

依赖方向单向、无环：core 是底座；tools / llm / session 只依赖 core，mcp 另依赖 tools；agent 汇合 llm + session + tools；example 聚合全部。版本由根 pom 的 dependencyManagement 统一管理，子模块不写版本号。

**契约位置约定**（duo-project-structure 的二选一记录）：core 因体量大采用 `api` 子包形态（核心 / events / boot 三个契约子包 + internal 实现）；tools、example 小域采用**域根包平铺**形态（契约在根包、实现在 `<域>.internal`）。新模块默认平铺，超过拆包阈值或出现多契约子域时再拆 `api` 子包——避免读者学两套词汇的关键是：同一形态内保持一致，跨形态的差异有本记录背书。

## core 的包边界

- `dev.duo.harness.core.api`——容器内核的核心契约：`Plugin`（apply 入口 + config 类型声明）、`Context`（plugin 挂载 / effect 注册 / 服务发布寻址 / 事件监听派发 / dispose）、`PluginHandle`（实例句柄与六态查询）、`Disposable`、`Service` 基类、异常类型。接口静态工厂 `Context.root()` 创建根作用域。
- `dev.duo.harness.core.api.events`——事件契约：`EventListener`（emit/parallel/serial/bail 监听形状）与 `WaterfallListener` / `WaterfallNext`（瀑布管线）。
- `dev.duo.harness.core.api.boot`——引导契约：`Boot.from(yml)` 与 `BootException`。
- `dev.duo.harness.core.internal`——实现（`ContextImpl` / `EventsImpl` / `PluginInstance` / `PluginRegistry` / `ServiceRegistry` 等），不对外暴露；包名即"勿用"契约。

## mcp 的包边界

- `dev.duo.harness.mcp`——MCP 接入契约：`McpClientPlugin`（一行配置一个 stdio 服务器连接）。
- `dev.duo.harness.mcp.internal`——连接生命周期、重连策略、工具同步与本模块自绑定配置。
  MCP SDK 类型不外泄到契约包（ADR-0006 的 SDK 隔离约定）。

## llm 的包边界

- `dev.duo.harness.llm`——LLM 契约：`LlmAdapter`（stream 直答 / streamTurn 聚合两种调用形态）、`LlmConfig`（`~/.duo/config.yml` llm 段加载，`DUO_LLM_*` env 覆盖）、`ChatRequest` / `ChatMessage` / `ChatChunk` / `LlmTurn` / `ToolSpec` / `ToolCallRequest`。
- `dev.duo.harness.llm.internal`——OpenAI 兼容适配器（SSE 解析与 tool_calls 分片聚合），协议细节不外泄。

## session 的包边界

- `dev.duo.harness.session`——会话域全部类型平铺于根包：`Session`（append 单写 + JSONL 落盘 + 投影）、`SessionEvent` / `Message` / `ToolCall`（中立数据记录，不依赖功能模块）。

## agent 的包边界

- `dev.duo.harness.agent`——agent 契约：`ChatAgent`（send 入口）、`AgentReply` / `ToolInvocation` / `AgentListener`（过程回调）。
- `dev.duo.harness.agent.internal`——`ToolCallingAgent` 循环实现与会话投影转换（Messages）。

## 关键语义

行为语义的权威是源码 JavaDoc 与 ADR——本表每条只留一句话语义与权威指针，逐条展开在权威处维护（避免改代码同步两处）。Demo 的可运行演示见 [01-入门/运行Demo](../01-入门/运行Demo.md)。

| 机制 | 一句话语义 | 权威 |
|---|---|---|
| 同步加载 | `Context.plugin()` 阻塞至 apply 返回，失败不留残留副作用 | `Context` JavaDoc、ADR-0002 |
| 逆序回滚 | 作用域销毁按注册逆序执行全部副作用，子插件级联 | `Context` / `Disposable` JavaDoc |
| config 绑定 | Jackson 严格绑定 config record（缺字段即失败），错误点名插件与字段路径 | ADR-0003、`PluginConfigException` |
| 事件五模式 | emit 异常隔离 / parallel 并发聚合 / serial·bail 顺序投票 / waterfall 洋葱否决 | `core.api.events` 各类型 JavaDoc |
| 服务注入 | provide 发布、`as(视图)` 惰性寻址、inject 声明许可，同名冲突点名 | `Context` / `Service` JavaDoc |
| 六态 + epoch | 依赖指纹变化驱动实例迁移：消失回 PENDING、回归/换实现自动重启 | `PluginState` / `PluginStatus` JavaDoc |
| 配置 boot | `Boot.from(yml)` 行序无关、审计点名（FAILED 带因 / PENDING 列缺失服务）、失败整树回滚 | `core.api.boot` JavaDoc |
| 工具三段管线 | pre-execute 准入否决 / execute around 本体 / post-execute 结果治理；工具异常收敛为 error 结果 | `ToolsService` JavaDoc |
| 审批策略 | pre-execute 决策三态（allow / deny / ask）：治理插件或工具声明 ask，策略服务解析裁决；未配置即拒 | `ApprovalPolicyService` / `ToolExecution` JavaDoc |
| 输出契约 | `ToolDefinition.output()` 声明结果 JSON Schema；声明即校验，违约转 error 结果点名原因；未声明宽松透传（双轨制） | `ToolDefinition.output()` JavaDoc |
| guard 单调否决 | `guard(registrant, check)`：审批之后、本体之前的动态检查；理由即拒、null 放行、无"允许"结果——拒绝无法翻回；随注册作用域销毁摘除 | `ToolsService.guard` JavaDoc |
| MCP 连接生命周期 | 首连同步、断连指数退避重连、稳定窗口清零、预算耗尽放弃（工具随之注销）；插件停止即断连 | `ConnectionSupervisor` JavaDoc、ADR-0006 |
| 远端工具同步 | `mcp__<server>__<tool>` 命名注册进工具域；两阶段换新（拉取校验失败保留旧代）；`list_changed` 自动重同步 | `McpToolSync` JavaDoc |
| LLM 适配 | provider 中立流式契约（stream 直答 / streamTurn 聚合）+ OpenAI 兼容 SSE 适配器；配置 `~/.duo/config.yml` llm 段，`DUO_LLM_*` env 逐项覆盖 | `LlmAdapter` / `LlmConfig` JavaDoc |
| 会话事件溯源 | `append` 唯一写入原语同步落 JSONL，`deriveMessages` 投影多轮上下文；事件不可变、旧格式向后兼容 | `Session` JavaDoc |
| agent 工具循环 | Function Calling 闭环：tool_calls 经三段管线与治理链执行，结果回填循环至最终回答；迭代上限防失控 | `ToolCallingAgent` JavaDoc |
