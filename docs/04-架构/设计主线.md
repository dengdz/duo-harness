# 设计主线

> 状态：随 M8 收官定稿。本文是**叙事导览**——回答"这个框架为什么长这样、机制之间如何组合"；模块清单、包边界与逐条语义表见[模块划分](模块划分.md)，可运行演示见[运行Demo](../01-入门/运行Demo.md)。

## 一句话

**duo-harness 是一个插件化的 AI agent harness**：自研轻量插件容器作内核——工具域、MCP、交互审批、prompt、技能、Web 界面以 yml 插件行组装（不想用的能力不挂载，零残留），LLM 适配、会话与 agent 循环由装配层以十余行 Java 接线。

## 主线一：一切皆插件

整个系统建立在一个自研插件容器内核上。选择自研而非套用现有 IoC 容器，是因为 agent harness 需要的容器语义很特别：**能力是可逆的副作用**——挂载一个 MCP 连接、注册一批工具、发布一个服务，都要求"作用域销毁时按注册逆序回滚、失败不留残留"（ADR-0001）。围绕这条根约定长出四组机制：

- **同步加载 + 虚拟线程**：`Context.plugin()` 阻塞至装载完成，失败即抛——API 面同步、执行面用虚拟线程承接阻塞（ADR-0002）
- **config 严格绑定**：插件声明 config 类型，Jackson 缺字段即失败、错误点名到插件与字段路径（ADR-0003）
- **服务注入三件套**：provide 发布、`as(视图)` 惰性寻址、inject 声明许可——插件之间的协作全部走服务，没有直接引用
- **六态生命周期 + 配置 boot**：依赖指纹驱动实例迁移；`Boot.from(yml)` 把"挂哪些插件"变成文件里的一行行声明

这一层的成果是：**"组装一个 agent"降维成"编辑一份 yml"**。

## 主线二：工具不是函数指针，是受治理的能力

工具域把"给模型用的函数"变成一条三段执行管线：**pre-execute 准入 → execute 本体 → post-execute 结果治理**。准入段做两件大事——审批 ask 三态（治理插件声明"这个写操作要问人"）与 guard 单调否决（理由即拒、拒绝无法翻回）；本体段执行并把异常收敛为 error 结果；治理段做输出契约校验（声明即校验）与提醒附加。设计立场：**agent 能动的东西都要过闸门，闸门之外没有旁路**。

MCP 接入是管线的第一个真实客户：一条配置一个 stdio 服务器连接，远端工具以 `mcp__<server>__<tool>` 命名同步进工具域，断连自动重连、工具自动增删（ADR-0006）。对模型来说，本地工具与远端工具毫无区别。

## 主线三：会话是事件日志，不是消息数组

会话采用事件溯源：`append` 是唯一写入原语，事件同步落 JSONL，多轮上下文由 `deriveMessages` 从日志**投影**出来。工具调用、审批决定、流式过程全部入日志——所以崩溃后可回放、跨进程可续接、Web 页面刷新就是重放一遍日志。这条"中立数据基座"不依赖任何功能模块，是 CLI 与 Web 两个呈现位能共享同一份历史的物理基础。语义细节见[会话事件类型表](../05-参考/会话事件类型表.md)。

## 主线四：agent 循环与人机协同

`ToolCallingAgent` 把上面三条主线拧成 Function Calling 闭环：模型发起工具调用 → 三段管线执行 → 结果回填 → 循环至最终回答，迭代上限防失控。真正的分水岭是 M6 的**交互 seam**（ADR-0008）：审批与提问被抽象为"seam + 可注册的回答者"——

- 机制侧不知道答案从哪来，只定义"问什么、等什么、无人应答时 fail-closed"
- 呈现侧注册回答者：终端是 y/n 问答，浏览器是按钮卡片
- **换呈现位不动机制**——M8 的 Web 双面就是对这条承诺的验收考场

围绕 seam 还长出 prompt 注册表（片段动态组装）、技能系统（SKILL.md 双形态发现 + 按名加载）、计划模式（引导式：呈交计划经 seam 复核）。

## 主线五：呈现是壳，机制是核

终端 REPL 与 Web 双面操作**同一份会话、同一个交互 seam、同一套治理管线**。Web 面是标准插件（yml 一行，不挂载零残留），只绑 127.0.0.1；页面断连时悬空的审批立即按拒绝处理——人不在环等于不批准。当前已知的呈现位边界（多标签、鉴权等）见[已知限制](../limitations.md)。
