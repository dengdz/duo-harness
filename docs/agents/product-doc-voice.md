# 产品文档口吻规范（product doc voice）

站内公开文档（`docs/01-入门` 至 `docs/05-参考` 与 index）的统一写作标准。受众：写与审文档的 agent 与维护者。立项依据：[ADR-0033](../../docs/adr/0033-M31文档官方化立项决策.md)（M31 文档官方化）。与 [duo-prose-standard](../../.agents/skills/duo-prose-standard/SKILL.md)（通用行文质量）、[duo-doc-standards](../../.agents/skills/duo-doc-standards/SKILL.md)（位置与层次）配合使用：它们管行文与位置，本规范管「产品文档与开发笔记的分界」。

## 三主干

### 1. 用户任务视角

每篇回答「我想做 X 怎么操作」或「这是什么、怎么用」，以**读者的任务**组织小节，不以开发史或模块结构组织。开篇一段说清这篇解决什么问题；操作路径优先，机制一句话点到、链接到高级/架构章深读。

- 写「把文件导出带走：敲 `/export`」——不写「M26 工单 07 为导出端点增加了显式 sessionId 参数」。
- 自查：小节标题删掉后读者能否只靠标题找到他要的操作？不能即视角偏了。

### 2. 里程碑叙事禁入正文

正文不出现：M 期号（M23、工单 05）、验收流水、状态注记（「状态：M1+M2 可用」）、立项背景、版图沿革。历史只有两个家：CHANGELOG（版本变更）与 docs/adr/（决策缘由）。

- 允许的唯一历史形态：**兼容性说明**「自 0.26.0 起……」——服务读者判断「我的版本有没有这个行为」，别的一律不写。
- 旧叙事材料删除不存档：git 历史即存档，文档站不承担考古职责。

### 3. 术语对齐术语表

概念命名用 [术语表](../05-参考/术语表.md) 词条（如「会话检索」不写「搜索引擎」、「记忆本」不写「知识库」），不造同义词；文中出现术语表没有的新概念，先入册再使用（duo-tracker 惰性规则）。

## 配套规则

- **活体引用**：命令逐条可复跑（从文档复制命令以代码块为单位整块复制）、配置样例与配置绑定代码一致、界面描述与实际页面一致——文档与代码不符时，文档按代码现状写，行为争议开 bug 台账（M31 spec 裁定）。
- **完整命令块**：给命令给整块（含续行与全部旗标），不给「首行 + 跳过测试」的拼装形态。
- **中文行文**：代码、命令、字段名、路径保持原文；中文与代码间空格。
- **失败路径要点到**：高频踩坑（如「Web 行必须在 CLI 行前」「令牌缺省随机见横幅」）在操作步骤旁一句话给足，不展开成排障章（排障归对应参考篇）。

## 违例判例

| 违例 | 改法 |
|---|---|
| 「M24 落地了标签级会话绑定，解决了多标签互踩」 | 「多标签各自绑定自己的会话；后台任务运行中会话在别的标签显示灰点」 |
| 「状态：M1+M2 一条命令演示全链路可用；M3 聊天 REPL 可交互运行」 | 「跑起来：`java -jar duo-harness-<version>.jar`」 |
| 「工单 12 用户裁定 present 工具退役，改为自动推导」 | 「回复定稿后，产物文件自动成卡（无需模型动作）」 |
| 「本功能源自 DSH 探测工单 21 的发现」 | 删——设计缘由在 ADR，读者不需要 |
