# Domain Docs（领域文档）

工程技能探索本仓库代码时，如何消费领域文档。

## 探索前先读

- 仓库根的 **`CONTEXT.md`**（术语表）；若存在 **`CONTEXT-MAP.md`**（多上下文仓库），按它指向读取与主题相关的各 `CONTEXT.md`
- **`docs/adr/`** —— 阅读与工作区域相关的 ADR；多上下文仓库还需检查 `src/<context>/docs/adr/` 下的上下文级决策

这些文件不存在时**静默继续**：不标记缺失、不主动建议创建。`/domain-modeling`（经 `/grill-with-docs` 触达）会在术语或决策真正落定时惰性创建它们。

## 文件结构

单上下文仓库（默认）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-<slug>.md
│   └── 0002-<slug>.md
└── src/
```

多上下文仓库（根存在 `CONTEXT-MAP.md` 时）：各 `src/<context>/CONTEXT.md` + `docs/adr/`（系统级）与 `src/<context>/docs/adr/`（上下文级）。

## ADR 约定

- 命名：`NNNN-<slug>.md`，四位编号从 `0001` 递增
- 文件头部 `Status:` 行标记**立卷时点**的状态（`提议` / `批准`）；ADR 落卷后不可修改——不升档、不补内容、不改状态，事后补写等于伪造决策历史
- 决策被取代时新开一份 ADR 并在正文注明取代哪份旧 ADR，旧文件保持原样
- 记录门槛：难逆转 + 无上下文会困惑 + 存在真实权衡，三条齐备才立 ADR

## 使用术语表的词汇

输出中命名领域概念（工单标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 定义的术语，不漂移到术语表明确回避的同义词。SKILL.md 与 AGENTS.md 的用词同受此约束——不引入表内词条 _Avoid_ 清单中的同义词（技能写作词条见「技能写作域」，规范见 docs/05-参考/技能写作规范.md）。

需要的概念不在术语表里是个信号——要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 技能用词（SKILL.md 写作约束）

技能正文与 description 的跨技能协作词汇，首选词 + _Avoid_（完整词条含定义见术语表「技能写作域」，docs/05-参考/术语表.md）：

| 首选 | 含义与分工 | _Avoid_ |
|---|---|---|
| 工单 | 本地 tracker 的一张可执行工作卡 | ticket（仅引外部系统原文）、任务卡 |
| 收口 | 流程末段完成核对关口（审查语境 = 四轴齐全 + 最窄测试全绿） | 完成（歧义两义） |
| 验收 | 用户亲手运行确认（done 的定义） | 验证（agent 自跑测试）、确认（口语） |
| 完成判据 | 步骤末可判定的 done 条件，强形态出示证据 | 硬判据 |
| 上下文指针 | 常驻上下文中命名外部材料的触达描述 | 链接、引用 |
| 领先词 | 预训练已有概念词锚定行为与触发 | 关键词 |
| 证据先行 | 判据要求出示路径/命令/输出 | 留痕 |
| 渐进式披露 | 部分分支内容推到指针后按需加载 | 渐进式加载、按需加载 |
