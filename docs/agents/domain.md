# Domain Docs（领域文档）

工程技能探索本仓库代码时，如何消费领域文档。

## 探索前先读

- 仓库根的 **`CONTEXT.md`**（术语表）；若存在 **`CONTEXT-MAP.md`**（多上下文仓库），按它指向读取与主题相关的各 `CONTEXT.md`
- **`docs/adr/`** —— 阅读与工作区域相关的 ADR；多上下文仓库还需检查 `src/<context>/docs/adr/` 下的上下文级决策

这些文件不存在时**静默继续**：不标记缺失、不主动建议创建。`/domain-modeling`（经 `/grill-with-docs` 触达）会在术语或决策真正落定时惰性创建它们。

## 文件结构

单上下文仓库（默认）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-<slug>.md
│   └── 0002-<slug>.md
└── src/
```

多上下文仓库（根存在 `CONTEXT-MAP.md` 时）：各 `src/<context>/CONTEXT.md` + `docs/adr/`（系统级）与 `src/<context>/docs/adr/`（上下文级）。

## ADR 约定

- 命名：`NNNN-<slug>.md`，四位编号从 `0001` 递增
- 文件头部 `Status:` 行标记**立卷时点**的状态（`提议` / `批准`）；ADR 落卷后不可修改——不升档、不补内容、不改状态，事后补写等于伪造决策历史
- 决策被取代时新开一份 ADR 并在正文注明取代哪份旧 ADR，旧文件保持原样
- 记录门槛：难逆转 + 无上下文会困惑 + 存在真实权衡，三条齐备才立 ADR

## 使用术语表的词汇

输出中命名领域概念（工单标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 定义的术语，不漂移到术语表明确回避的同义词。

需要的概念不在术语表里是个信号——要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

输出与既有 ADR 矛盾时显式提出，不静默覆盖：

> 与 ADR-0007（事件溯源订单）冲突——但值得重开，因为……
