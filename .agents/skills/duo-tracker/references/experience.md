## 复盘维度

任务收尾调用 duo-skill-evolution 复盘时（AGENTS.md 红线 8），本技能按以下口径收集输入：

- 任务摘要：操作类型（建 spec/工单/ADR/术语表）、生成的文档数量、关键内容
- 执行过程关键点：spec/工单模板是否正确应用、术语表/ADR 是否准确更新、状态流转是否合规、是否有遗漏字段
- 用户反馈：用户对 spec/工单质量、术语表准确性、ADR 完整性的反馈
- 自我感知：流程中是否有遗漏环节、模板应用是否准确、可优化点

## [2026-09-21] 批量落盘 spec/工单后跑一遍乱码自检

**问题描述**：
M23 一次 Write 发布 11 张工单后，自检发现工单 01 正文夹带一处生成乱码（"不做事chod事件溯源"）。

**原因分析**：
长内容单次生成易夹带个别乱码 token，Write 落盘不报错、不读回就不会被发现。

**解决方案**：
批量 Write spec/工单/ADR 后追加一步自检（grep 可疑片段或抽查关键句），发现即修；本例靠 grep "chod" 捕获并已修复。

**影响范围**：
所有多文件文档批量落盘场景（to-spec / to-tickets / ADR 与术语表批量产出）。

## [2026-09-26] 引擎/机制类 ADR 落卷时，同 diff 检查术语表 _Avoid_ 反噬

**问题描述**：
M26 立项落 ADR-0028（FTS5 引擎迁移）时发现：「会话检索」词条的 _Avoid_ 清单写着"FTS5（DSH 实现细节）"——那是 M21 内存索引时代把 FTS5 排斥为参考项目用词的口径。M26 起 FTS5 成为 duo 自家引擎名，若不同步翻转，按红线 9（SKILL.md/AGENTS.md/工单标题用词受术语表约束）全库将"禁用"FTS5 一词，与 ADR 直接冲突。

**原因分析**：
_Avoid_ 清单记录的是立词条时点的取舍；后续 ADR 让 duo 采纳该词时，没人检查旧词条的回避清单。

**解决方案**：
落"引擎/机制采纳"类 ADR 时，同 diff 检索术语表中把该机制名列入 _Avoid_ 的既有词条，将词从回避清单移除并把词条定义更新到新形态（本次：会话检索词条改为 FTS5 引擎 + cwd 授权边界口径）。

**影响范围**：
所有引入外部机制名为自家概念的 ADR 场景（引擎迁移、协议采纳、工具引入）。

## [2026-10-02] ADR 落卷时同 diff 核对索引页补登行

**问题描述**：
M32 落 ADR-0034 时未往 docs/adr/index.md 补登行（索引 M31 建成后首个新 ADR 就漏了）；M33 落 ADR-0035 前主动抽查才发现——「全部架构决策原文」的索引缺了最新一卷，读者按索引巡览会漏掉 1.0 收口决策。

**原因分析**：
索引是 M31 文档大改的新增面，ADR 落卷的既有流程（写正文 → Status → 关联注）没有索引这一步；「落卷即冻结」的纪律只覆盖正文，不覆盖登记面。

**解决方案**：
ADR 落卷的收口核对固定加一步：`grep <新ADR编号> docs/adr/index.md` 必须命中，未命中即同 diff 补登；顺手回查上一卷是否也在（本次补登 0034 + 0035 两行）。

**影响范围**：
所有 ADR 落卷场景（立项决策类 ADR 每期一张，重犯面 = 每期一次）。
