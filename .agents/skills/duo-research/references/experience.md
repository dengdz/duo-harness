## [2026-09-21] 注册第二参考项目 ZCode：新目录惯例与历史文档路径的冲突

**问题描述**：
SKILL.md 新增"对照文档落 `docs/research/<别名A>+<别名B>/`"目录惯例时，既有对照文档（`docs/research/subagent-派发与提示词对照.md`）平铺在根目录，二者形态不一致，曾考虑把旧文档迁入新目录。

**原因分析**：
旧文档已被 ADR-0016 / ADR-0017 与 .scratch 历史记录按当时路径引用，迁移会破坏 ADR 链接稳定性（ADR 是决策记录，引用应保持当时形态）。

**解决方案**：
不迁移旧文档；SKILL.md 明确"新对照文档走新目录，既有平铺先例因被 ADR 引用路径稳定不迁移"。以后凡要迁移已被 ADR / 工单历史引用的研究文档，默认豁免，新惯例只约束新文档。

**影响范围**：
所有涉及 docs/research/ 文档移动的场景；索引条目的文档路径列同步以实际落盘为准。

## [2026-09-21] 离线 pull 的锚点一致性惯例 + 注册表元数据亲核

**问题描述**：
（1）两家仓库 `git pull --ff-only` 因 github.com 离线双双失败，SKILL 只规定"失败时报告原因"，未规定能否继续分析；（2）Explore 负结论暴露注册表元数据错误——DSH 注册标"Java"，实为 TypeScript monorepo（全仓 0 个 .java），此前历次研究未核证过该标注。

**原因分析**：
（1）pull 的目的是"锚点新鲜"，离线时若本地锚点恰与索引登记一致，分析有效性不受损——缺的是这条判定惯例；（2）注册表的语言/形态描述是写下时的快照，无人复核过。

**解决方案**：
（1）离线 pull 失败时：报告原因 → 对比本地 `rev-parse HEAD` 与索引登记锚点 → 一致则继续并在文档头注明"离线，锚点与登记一致"；不一致则停止并挂账待补扫。（2）凡引用注册表元数据做结论（语言、形态、版本）前，以一条廉价亲核命令验证（如 `find -name "*.java" | wc -l`）；错误随发现随手修正并在文档中留痕。

**影响范围**：
所有网络受限环境的调研；注册表元数据被下游 ADR/文档引用前。

## [2026-09-21] 大规模「全面探查」请求的分批模式

**问题描述**：
用户要求对参考项目做覆盖功能/结构/设计/UI/路由的全源码探查——一次全库扫会失焦，逐功能深析又不成体系。

**原因分析**：
「全面探查」的合理粒度是**维度**而非功能：按维度（代码结构与模块划分 → 核心功能与业务逻辑 → 整体设计与架构风格 → UI 界面与组件 → 页面路由与交互流程）划批次，每批双项目并行派 Explore（报告中密锚点、限字数、禁贴大段代码），批间汇报、末批汇总成各项目「总览」单文档。

**解决方案**：
固化五批次模板与总览文档结构（一句话定位 + 五节 + 总体评价三标签/最可借鉴/最重负担）；已有同项目旧总览且锚点过期时，全景探查顺带完成增量补扫（重写总览、更新索引锚点，不另立平行文档）；每域已有专册的（如沙箱与权限）在总览中只标位置不重复展开。

**影响范围**：
"全面探查/整体看一看 X 项目"类请求；总览文档的维护策略。
