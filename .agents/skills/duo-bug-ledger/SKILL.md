# duo-bug-ledger：bug 全流程跟踪

bug 修完不等于结束——**没留存的 bug 一定会以另一种形态复发**。本技能把每个 bug 变成一个全生命周期留痕的档案：从用户报问题那一刻建档，排查、定位、修复、测试每一步落盘，事后可完整回放"当时什么问题、怎么排查、怎么修的、怎么防的"。

**范围**：bug 不限于代码崩溃与逻辑错误——文档与代码不一致（过时叙述、导航漏条目、自相矛盾、术语漂移、结构与约定冲突）同样是仓库可修的缺陷，同样走本流程入账（首例 BUG-20260913-01，用户裁定）。判别标准与代码 bug 相同：仓库内可修、可验证、有明确"与现实应有的样子"的差距。

与 `diagnosing-bugs`（mattpocock）的分工：它提供诊断**方法论**，本技能提供**生命周期档案**与防复发复用。

## 第一步：报问题即建档（自动触发，不等用户要求）

用户报告问题（"发现一个问题"、"有报错"、"不符合预期"、"验收失败"）时，**立即**创建档案文件：

- 位置：`.scratch/bugs/BUG-<日期yyyymmdd>-<当日序号两位>.md`
- Status 置 `reported`，症状节**原样引用**用户提供的报错/日志/输出（逐字保留关键行）
- 台账索引（`.scratch/bug-log.md`）同步加一行（ID / 标题 / 状态）

完成判据：档案文件存在、Status=reported、台账索引行已加、症状节与用户原文逐字一致（转述即未完成）。

档案模板：

```markdown
# BUG-<日期>-<序号> · <一句话标题>

**Status**: reported → investigating → fix-planned → fixing → verifying → done

## 症状（建档时记录）
- 发现于：<里程碑/工单/谁发现>
- 原样引用：<报错/日志/输出片段>
- 复现方式：<用户做了什么>

## 排查记录（定位过程，逐步追加）
- 假设 1：<...> → 验证：<...> → 结论：<成立/排除>
- 假设 2：<...> → ...

## 根因（定位后填写）
<机制层解释：为什么这条代码路径会产生该症状>

## 修复方案（计划，改前填写）
<改哪些文件、影响面、备选方案取舍>

## 修复与验证
- 改动：<...>
- 回归测试：<测试名与结果>
- 防复发：<回归测试锁定 / 文档更新 / 技能规则更新 / 无（说明理由）>

**关联**：<commit>；台账索引见 .scratch/bug-log.md
```

## 第二步：排查（过程落盘）

排查方法：Call the Skill tool with "diagnosing-bugs"，取其反馈环 / 假设排序 / 最小化方法执行——档案的"排查记录"节即其 Phase 3-4 的留痕位置。

完成判据：排查记录每行 = 假设 + 验证 + 结论（含被排除项与排除理由——排除理由是下次排查的路标）；根因节写到机制层（"X 被 Y 覆盖"这类结构解释，"我改错了"是操作层，未完成）。

## 第三步：修复计划 → 修改 → 测试

- 修复方案先写入档案（改哪些文件、影响面），**再动代码**
- 修改与回归测试结果记入"修复与验证"节
- 防复发三问逐条回答：① 回归测试锁住了吗 ② 是不是 mock 验证不到的差距（是 → 验收对照表补真实场景）③ 是不是技能规则缺口（是 → 更新对应 SKILL.md）——答案落到具体动作：回归测试名 / 验收对照表条目 / SKILL.md 规则位置；"以后注意"不是答案，写不出动作者视为归档未完成
- 遇 NPE / 异常：记录现象后继续流程（"错误呈现后可继续"是本技能的能力承诺）

完成判据：修复与验证节含改动清单与回归测试结果；防复发三问各有具体动作或"无 + 理由"。

## 第四步：完成归档

- Status → done，台账索引行更新（状态 + 防复发摘要）
- 提交 bug 修复的 diff 内包含：档案文件 + 台账索引 + 修复代码 + 回归测试
- **查同族**：grep 台账，同根因第二次出现 → 升级为结构化防线（不是再修一次）

完成判据：Status=done、台账行含防复发摘要、同根因查询已执行且结论已记。

## 阶段收官回顾

里程碑收官时（comprehension 通过后或 release 验收后），扫一遍 `.scratch/bugs/`：

- Status 未到 done 的 → 收敛或明确移期
- "防复发"是测试的 → 确认测试还在套件里跑
- 高频根因（同类 ≥2 次）→ 提升为 spec 级决策或结构化防线（如"mock 与真实 provider 协议差距"出现 2 次 → 真实 provider 冒烟纳入常规验收）

## 建档边界

用户配置错误、环境问题：档案可建，标注写明"环境问题"；台账只收仓库可修的缺陷。
