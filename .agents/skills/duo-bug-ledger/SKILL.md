# duo-bug-ledger：bug 全流程跟踪

bug 修完不等于结束——**没留存的 bug 一定会以另一种形态复发**。本技能把每个 bug 变成一个全生命周期留痕的档案：从用户报问题那一刻建档，排查、定位、修复、测试每一步落盘，事后可完整回放"当时什么问题、怎么排查、怎么修的、怎么防的"。

**范围**：bug 不限于代码崩溃与逻辑错误——文档与代码不一致（过时叙述、导航漏条目、自相矛盾、术语漂移、结构与约定冲突）同样是仓库可修的缺陷，同样走本流程入账（首例 BUG-20260913-01，用户裁定）。判别标准与代码 bug 相同：仓库内可修、可验证、有明确"与现实应有的样子"的差距。

与 `diagnosing-bugs`（mattpocock）分工：它提供诊断**方法论**（反馈回路/假设/最小化）；本技能提供**生命周期档案**与防复发复用。遇到难缠 bug 时两者配合：档案里的"排查记录"节就是它的 Phase 3-4 留痕。

## 第一步：报问题即建档（自动触发，不等用户要求）

用户报告问题（"发现一个问题"、"有报错"、"不符合预期"、"验收失败"）时，**立即**创建档案文件：

- 位置：`.scratch/bugs/BUG-<日期yyyymmdd>-<当日序号两位>.md`
- Status 置 `reported`，症状节**原样引用**用户提供的报错/日志/输出（不转述、不省略关键行）
- 台账索引（`.scratch/bug-log.md`）同步加一行（ID / 标题 / 状态）

档案模板：

```markdown
# BUG-<日期>-<序号> · <一句话标题>

**Status**: reported → investigating → fix-planned → fixing → verifying → done

## 症状（建档时记录）
- 发现于：<里程碑/工单/谁发现>
- 原样引用：<报错/日志/输出片段>
- 复现方式：<用户做了什么>

## 排查记录（定位过程，逐步追加）
- 假设 1：<...> → 验证：<...> → 结论：<成立/排除>
- 假设 2：<...> → ...

## 根因（定位后填写）
<机制层解释：为什么这条代码路径会产生这个症状>

## 修复方案（计划，改前填写）
<改哪些文件、影响面、备选方案取舍>

## 修复与验证
- 改动：<...>
- 回归测试：<测试名与结果>
- 防复发：<回归测试锁定 / 文档更新 / 技能规则更新 / 无（说明理由）>

**关联**：<commit>；台账索引见 .scratch/bug-log.md
```

## 第二步：排查（过程落盘）

按 diagnosing-bugs 的方法诊断，但**每个假设与其验证结果追加到档案"排查记录"节**——包括被排除的假设（排除理由是下次排查的路标）。定位到机制层根因后填"根因"节。

排查纪律：

- 症状必须原样引用，不转述——下回排查靠它模式匹配
- 根因写到机制层（"X 被 Y 覆盖"），不写到操作层（"我改错了"）
- 每个假设都要有验证结论，不写"猜是 X"就跳走

## 第三步：修复计划 → 修改 → 测试

- 修复方案先写入档案（改哪些文件、影响面），**再动代码**
- 修改与回归测试结果记入"修复与验证"节
- 防复发三问逐条回答：回归测试锁住了吗 / 是不是 mock 验证不到的差距（是 → 验收对照表补真实场景）/ 是不是技能规则缺口（是 → 更新对应 SKILL.md）

## 第四步：完成归档

- Status → done，台账索引行更新（状态 + 防复发摘要）
- 提交 bug 修复的 diff 内包含：档案文件 + 台账索引 + 修复代码 + 回归测试
- **查同族**：grep 台账，同根因第二次出现 → 升级为结构化防线（不是再修一次）

## 阶段收官回顾

里程碑收官时（comprehension 通过后或 release 验收后），扫一遍 `.scratch/bugs/`：

- Status 未到 done 的 → 收敛或明确移期
- "防复发"是测试的 → 确认测试还在套件里跑
- 高频根因（同类 ≥2 次）→ 提升为 spec 级决策或结构化防线（如"mock 与真实 provider 协议差距"出现 2 次 → 真实 provider 冒烟纳入常规验收）

## 反模式（不要做）

- 只修不记、或修完才补记——档案价值在过程的每一步落盘，事后补写必失真
- 症状转述、根因写操作层、防复发写"以后注意"——三条登记纪律不可破
- NPE/异常直接崩掉 REPL 或跳过验收——档案里"错误呈现后可继续"的承诺必须兑现
- 把用户配置错误、环境问题记成代码 bug——档案可建，但标注"环境问题"，台账只收仓库可修的缺陷
