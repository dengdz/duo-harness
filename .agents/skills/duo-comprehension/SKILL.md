# duo-comprehension：阶段理解关卡

AI 实现的功能，用户没理解，项目就在变成自己看不懂的屎山。**理解关卡**在阶段与阶段之间设卡：不过 90 分，不开下一阶段。

## 第一步：圈定课程范围

1. 圈定阶段 diff（`git diff <上一版本锚点>..HEAD --stat`）
2. 按机制主题切课，**3~6 课为宜**（超过则分轮次）——切课依据：diff 的功能簇 + 该阶段新增 ADR + CONTEXT.md 术语。每课登记：主题、涉及文件清单（file:line 级）、对应术语与 ADR
3. 课程清单先给用户过目确认（可增删），再开讲

## 第二步：逐课源码走读（学习阶段，不考试）

**先学后考，两段式**——本阶段只走读不提问。逐课进行：

1. 每课打开对应源码文件（让用户在 IDE 里跟着看），按**执行路径走读**：入口方法 → 数据怎么流 → 出口效果，逐段讲
2. 走读纪律：每段先让用户看代码本身（贴出段落或指路 file:行号），再讲"这段在干嘛、为什么这么写"；抽象概念必须有刚看过的代码作锚
3. 每课走读完，讲义立即落盘 comprehension.md（该课节：问题→概念→走读要点（file:line）→ ADR 取舍）
4. 全部课走读完成后才进入第三步考试

## 第三步：统一考核（选择题，全部课学完后）

每课出 3~5 道单选题（按课分批，一次一题），等用户回答后再继续。题目可引用走读中看过的代码段：

- **题必有唯一正确答案**；干扰项来自真实误区（常见混淆、似是而非的表述），不出"以上都对/都不对"
- **考理解不考记忆**：题型指向"为什么 / 什么场景 / 边界在哪 / 两个概念的区别"，不出"哪个类第几行"式细节
- **答错即时讲解**：讲清正确答案的道理与干扰项错在哪；讲解须引用走读阶段看过的代码段（"还记得 EventsImpl 里那个逆序循环吗"），该题记入错题本（所属课标记）
- 用户答"不知道"也按错处理并讲解——诚实比猜对有价值

## 第四步：评分与补考

- 总分 = 全部题目等权折算百分制；**≥ 90 过关**
- 未达 90：**只重讲 + 重考错题本涉及的课**（弱课出全新题目），已过关课的成绩保留，重考后合并重算——不整轮重来

## 第五步：产物与闸门

边学边落盘 `<feature>/comprehension.md`（**每课讲完考核后立即追加该课节**，中断可续）——三部分构成完整产物：

```markdown
# <阶段> 理解关卡
## 讲义（每课一节，边学边追加）
### 第 N 课：<主题>
- 解决什么问题 / 核心概念（术语表锚定）/ 实现要点（file:line）/ ADR 取舍
- 本课易错点（来自考核中的错题，一句话正解）
## 错题本（题 → 当时错选 → 正解一句话）
## 凭证
- 日期 / 最终得分 / 通过（≥90）——未通过时此节标"补考中"并记弱课
```

- 讲义是产物主体：用户以后翻项目先翻它（"我自己项目的说明书"），不必重讲
- 凭证是闸门口径：未获得"通过"，duo-workflow 不拆下一阶段工单（与 duo-acceptance 的 done 定义同级）
- 用户可随时说"看看我的错题本"复习弱项后再补考；补考通过后更新凭证节

## 好题长什么样（字面示例）

考理解的单选题（M1 真实素材）：

> 拔掉一个服务的提供方插件后，依赖它的活跃插件会经历什么迁移？
> A. 直接 DISPOSED，需要重新 boot 才能恢复
> B. UNLOADING 后回到 PENDING，服务回归时自动重启
> C. FAILED，因为依赖缺失属于启动错误
> D. 保持 ACTIVE，只是读取服务时会抛错

正确答案 B（考 epoch 语义：停止是可逆的等待）；C 是高价值干扰项（把"依赖缺失"误归为错误而非等待）。
