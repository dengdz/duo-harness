# duo-skill-evolution — Skill 自我进化元技能

本技能是「元技能」，服务于其他 Skill 的持续改进：其他 Skill 任务收尾时（AGENTS.md 红线 8）被调用，对刚才的执行过程复盘评估——有问题或改进空间就进化，执行顺畅则明确说"无需进化"并结束。目标：每个 Skill 越用越好。

进化以「下次少犯一个已记录的错误」为唯一收益标准。

## 接入约定（给其他 Skill 的作者）

- **触发与强制**：AGENTS.md 红线 8 承担（收尾先复盘再总结）；workspace Stop hook 注入收尾自查提醒兜底——机制细节以根 AGENTS.md 为准，本技能不复述。
- **经验参考前置**：红线 8 同时要求执行任何 duo- 技能前先读其 `references/experience.md`。
- **新技能接入只需一步**：在该技能 `references/experience.md` 头部（首个 `---` 后）写"复盘维度"段（本技能复盘时按什么口径收集任务摘要、执行关键点、用户反馈、自我感知）。SKILL.md 不需要任何复盘章节。

## 调用时机与输入

- **必须**：任务完整结束后（中途不调用）
- **可选**：用户点名"这次执行有问题"或"记录一下这次经验"时
- **跳过**：用户明确拒绝复盘、或任务被中断/取消时

调用时提供：Skill 名称、任务摘要（2-3 句）、执行关键点（主要步骤 / 障碍 / 变通）、用户反馈（若有）、自我感知。

## 复盘流程

### 1. 快速判断：是否需要进化

触发进化的信号：出现错误或遗漏；流程不顺畅（重复劳动、冗余步骤、工具选择不当）；用户提出改进建议；发现新边界情况或最佳实践；与既有指令冲突。

**无需进化**——输出一句"本次执行无明显问题，无需进化"，复盘结束。

### 2. 提炼改进点（1-3 条）

按六个维度审视执行过程：执行结果质量（准确/完整/符合预期？）、流程顺畅度（冗余/重复/工具不当？）、错误处理（异常优雅与否）、用户体验（反馈与痛点）、可复用经验（普遍性？）、与既有指令的一致性（冲突/模糊/遗漏？）。

每条改进点含：问题描述 / 原因分析 / 改进建议。

### 3. 选择进化方式（优先级：方式 A 默认）

**方式 A：追加经验文档（默认——轻量、可逆、易积累）**。适用：边界情况、最佳实践、踩坑经验、不需改主流程的细节。操作：目标技能 `references/experience.md` 追加条目；文件不存在时建档——标题 `# <Skill 名称> 经验文档` + 一句引言 + `---`，条目格式 `## [日期] <简述>` + 问题描述 / 原因分析 / 解决方案 / 影响范围。

**方式 B：修订 SKILL.md（谨慎）**。仅在：既有指令明确错误或遗漏、改进属必须执行的红线、流程结构性调整时使用。操作：修订相关章节，并在该技能 `references/experience.md` 的变更历史节（无则创建）追加记录——触发原因 / 改动内容 / 预期效果。修订超 3 处先征得用户同意。

两种方式可组合（B 改红线 + A 记案例）。追加前查重：类似条目已存在则不重复记录。

## 输出格式（进化触发时）

改进点逐条列出（问题/原因/建议）→ 进化方式与落盘位置 → 预期效果。输出模板不含人格前缀——按全局 AGENTS.md 的响应规则套用（分层解耦：全局规则改动时本技能零修改）。

## 边界

- 进化是优化细节，不重构技能的核心定位
- 涉及技能根本逻辑或用户偏好的改动，先询问确认
- 用户可以主动禁用某次复盘（"这次不用复盘"）
- 本技能自身可进化：直接修订本 SKILL.md，或在自身 references/experience.md 记录改进点
