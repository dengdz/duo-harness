# duo-skill-evolution 经验文档

本文档持续记录该元技能在实际使用中积累的经验教训、边界情况和最佳实践。

## 复盘维度

被复盘技能的口径以该技能 experience.md 头部的"复盘维度"段为准；本元技能自身复盘按以下口径收集输入：

- 任务摘要：元技能调用场景、执行的复盘次数、进化方式分布（A/B/无需）
- 执行过程关键点：改进点提炼是否准确、经验条目是否查重、SKILL.md 修订是否克制
- 用户反馈：用户对复盘产出质量、进化克制度的反馈
- 自我感知：流程是否有冗余、输出格式是否清晰、本技能自身是否需进化

## [2026-10-01] 复盘追加/查重前必须读目标经验档全量

**问题描述**：
M30 grill 复盘向 duo-workflow 经验档追加「逐题提问节奏」条目，与既有 [2026-09-21] 同主题条目重复——追加前只 sed 了目标文件前 60 行做查重，逐题条目在第 117 行视野外。下一轮整理提交内容读全量时才发现，自纠删除并按先例回填「重现与强化」注记到原条目。

**原因分析**：
「追加前查重」要求知道既有条目全貌，而经验档是多条目长文件（duo-workflow 档近 400 行）；用头部片段代表全文件做查重，中后段条目必然漏检——与经验档自身教训同构：截断读法 = 没读。

**解决方案**：
向任何经验档追加条目前整文件 Read（不用 head/sed 截断）；查重命中已有条目时不另立新条，改「重现与强化」注记回填原条目（duo-workflow 档 [2026-09-22] 新服务发布条目先例），保持同主题经验单点收敛。

**影响范围**：
所有 duo-skill-evolution 复盘的方式 A 查重步骤；长经验档的读取纪律。

**背景**：
创建元技能，用于其他 Skill 的自我进化。

**设计原则**：
1. 轻量原则：无问题不强制进化
2. 双轨进化：经验文档（优先）+ 修订 SKILL.md（谨慎）
3. 复盘维度：质量、流程、错误、体验、复用、一致性
4. 接入约定：其他 Skill 在任务结尾主动调用

**注意事项**：
- 本技能自身也可以进化，发现问题可直接修订或记录到本文档
- 避免过度进化：大部分调用应该是"无需进化"
- 保持经验文档简洁：只记录真正有价值的教训
