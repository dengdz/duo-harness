## 复盘维度

任务收尾调用 duo-skill-evolution 复盘时（AGENTS.md 红线 8），本技能按以下口径收集输入：

- 任务摘要：任务级别（L1/L2/L3）、实现内容、涉及模块、关键步骤
- 执行过程关键点：分级是否准确、流程是否完整、测试是否充分、验收是否通过、提交前核对是否遗漏
- 用户反馈：用户对流程执行、代码质量、验收结果的反馈
- 自我感知：流程中是否有遗漏环节、质量卡点是否有效、可优化点

## [2026-09-20] CHANGELOG 未发布段多条目拆分两笔提交的技法

**问题描述**：
里程碑进行中两类无关变更（如技能整理与研究落盘）需分两笔提交，但两条 CHANGELOG 记账同处一个"未发布"版本段，`git add` 按文件暂存无法拆分同一文件内的不同行——直接整文件暂存会让第一笔提交夹带第二笔的记账。

**原因分析**：
"用户可见变更同 diff 记账"要求每笔提交携带自己的 CHANGELOG 行，而未发布段是多条目共存的单一文件。

**解决方案**：
先临时摘除后一条记账行 → 暂存并提交前一笔（携带自己的记账行）→ 补回被摘除的行 → 暂存并提交后一笔。顺序执行，两笔提交各自满足红线；发布时未发布段整体落日期。

**影响范围**：
后续所有里程碑的多提交记账场景（0.15.0 分支 M20 启动日实测有效）。

## [2026-09-20] 包私有 API 的手动验收——用同包临时类，别用 jshell

**问题描述**：
给用户写 jshell 脚本验证库行为，脚本第一步即"找不到符号"全线失败——被验类型是包私有（库的内部细节，设计正确），jshell 代码落在无名包够不到包私有成员；且 jshell 逐段求值放大级联错误、受检异常未包的语句也易写漏。

**解决方案**：
手动验收脚本改为 /tmp 下临时 Java 类，文件头声明与库同包（`package dev.duo.harness.attachment;`）——同包即合法访问包私有，一次 javac+java 出全部证据，跑完即删。给用户的可复跑命令须自带清场。

**影响范围**：
所有"让用户亲眼验证库行为"的场景（工单级手动验收）；jshell 仅适合纯公开 API 的随手验证。
