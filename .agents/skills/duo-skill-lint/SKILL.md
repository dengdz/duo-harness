# duo-skill-lint：技能规范整改

把 SKILL.md 整改到符合《技能写作规范》（docs/05-参考/技能写作规范.md）。对象：duo 技能（`.agents/skills/*/SKILL.md`）与根 AGENTS.md 路由行。三类场景——新写技能入路由表前的自查、存量技能的规范化整改、规范演进后的复查。编辑判断（保留什么删什么）：Call the Skill tool with "duo-trim-cot-leakage"；prose 质量层：Call the Skill tool with "duo-prose-standard"——本技能只管机制符合度。

## 第 0 步：定对象与依据（fail-fast）

1. 明确对象技能路径；缺失即停下报告（fail-fast：范围推断属越权）。
2. 读《技能写作规范》全文（执行标准）+ 该技能 `references/experience.md`（红线 8）。
3. 列出 ADR 中涉及该技能的决策条目——它们是本票验收清单的一部分（C1-09 教训：ADR 决策漏执行 = 阻断级发现）。

完成判据：对象路径、规范位置、ADR 条目清单三者已在对话出示。

## 第一阶段：机械核对（先全量跑，再逐条修）

每项出示一类证据；每条都对应规范条款与 C1 实证教训：

1. **frontmatter**：仅 `name` + `description` 两键、YAML 可解析、无 `disable-model-invocation`（ADR-0027 探测：写了无效还毁 safeToAutoLoad 展示语义）。
2. **description**：`wc -m` 字数（模型触发 ≤80、AGENTS.md 显式命令表内 ≤60）；三规则——领先词前置（中英并列仅当英文侧有预训先验，自造词硬配英文反而错）、身份句删除（正文 H1 已携带）、触发按概念收敛（不罗列口语变体）。
3. **路由对账**：触发概念有增删 → AGENTS.md 路由行同一 diff 双向改；仅词面收敛不必同步（同概念不同词面在工单标注即可）。
4. **否定性保证清单**：全篇扫描（不是只扫被改节——C1-08 教训）。每个"不 X"句给正向等价或标唯一硬护栏（全篇至多 1 条）；定义句与例外句单列核对（剪除误判高发区）。
5. **完成判据**：流程型技能的步骤带"完成判据："标签、可判定 done 与 not-done、强形态出示证据（路径/命令/输出）；审查/参考型技能的判据可为一句话总判据（如"唯一判据"）——两者都是达标形态，判据密度按技能类型分档（C1-09 对 teach 的同款观察）。
6. **显式调用**：operative 技能引用一律 `Call the Skill tool with "X"`；目标存在性核对（基准 = 项目内 `.agents/skills/` ∪ 环境技能清单——基准写窄会误报 MISSING）；配置/规范本体引用用"读 `<路径>` 的 `<节>` 并按其执行"。
7. **引用断链**：grep 正文"见 / 如 / 上述"，其目标句或节仍存在（被引用概念的定义丢失 = 断链，C1-08）。
8. **数量词重数**：正文每个"N 处 / 共 N 条"回数实际枚举，表格与结论句互核（C1-01/02 四连教训）。
9. **词汇 Avoid**：红线 9——按 domain.md「技能用词」表逐词 grep，专名白名单（技能名如 /to-tickets）先过再计数。
10. **检查点**：交用户决策是独立阻塞步骤（出示 + 等答复）；非阻塞检查点显式声明不阻塞。
11. **末尾换行**：`tail -c 1 | od -c` 检查（Write 工具的静默回归点，C1-09）。

完成判据：11 项核对证据全部出示，缺陷清单成型（阻断 / 建议 / 边界记档三级）。

## 第二阶段：修复处置

- 阻断（规范硬条款违反）直接修；judgement call（措辞与形态取舍）列选项给用户裁定。
- 路由行 / 术语表 / domain.md 的联动改动与 SKILL.md 同一 diff（红线 3）；新概念词条随 diff 落术语表。
- 修复引入的新句对新句重跑相关核对项（计数 / 否定 / 断链——修复自己也会引入新缺陷，C1-08）。
- 删除操作前过否定性保证清单（改写删句 ≠ 语义等价，被删句承载的保证要有正向承载）。

完成判据：发现逐条处置（修复 / 记档），无未处置项遗留。

## 收口（证据先行）

- 出示整改后终值：description 字数、完成判据数、禁令句数、显式调用数、Avoid grep 清零——数字以终态 wc/grep 为准（禁自估，C1-06 起三连教训）。
- 动了 docs/ 时重跑 `cd docs && npm run docs:build`。
- 整改总结追加 `.scratch/review-log.md`（模式化问题沉淀，供下次 lint 的 brief 前置）。

**新技能场景补充**：新写的 SKILL.md 全项通过后才入 AGENTS.md 路由表——路由表是入口，先整改后接入。
