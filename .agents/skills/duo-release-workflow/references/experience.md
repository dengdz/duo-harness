## 复盘维度

任务收尾调用 duo-skill-evolution 复盘时（AGENTS.md 红线 8），本技能按以下口径收集输入：

- 任务摘要：版本号、发布类型（大需求/功能/bug修复）、涉及的改动范围
- 执行过程关键点：分支创建是否正确、开发流程是否完整、审查是否充分、验收是否通过、推送前检查是否遗漏、合并推送是否顺利
- 用户反馈：用户对发布流程、文档同步、验收结果的反馈
- 自我感知：流程中是否有遗漏环节、检查是否全面、可优化点

## [2026-09-29] 0.24.0 发版：0.23.0 漏打 tag 无人发现——tag 是发版序列的固定步骤

**问题描述**：
0.24.0 发版准备时发现 tag 序列停在 v0.22.0——上一版 0.23.0 盖章提交（d5036f8）从未打 tag，且隔了一个版本周期无人察觉（CHANGELOG、CI、docs-site 均不依赖 tag，缺口静默存活）。

**原因分析**：
发版流程第七步只写了「合并与推送」，打 tag 不在流程文字里，靠操作者记忆；0.23.0 那轮恰好没做，之后没有任何机械校验点会报警。

**解决方案**：
发版操作序列固定四件：合并 → **打 tag（`v{版本号}` 指向 main 的盖章提交）** → 推 main/分支 → 推 tag；第六步推送前检查追加一项「tag 连续性核对」（`git tag` 尾项应指向上一版本，断档即回填）。

**影响范围**：
所有后续发版（0.25.0 起）；tag 断档的存量回填姿势 = `git tag v{版本号} {盖章提交SHA}` 后随下次推送带出（本次 v0.23.0 即此法补齐）。

## [2026-09-24] M24 发版：推送前检查抓到两处存量发版缺陷

**问题描述**：
0.19.0 发版推送前检查发现：① 13 个 pom 版本仍是 0.18.0（分支创建时未升级，M24 收尾工单 checklist 也未列该项）；② 文档站 sidebar 缺 ADR-0025（M23 期就漏的存量）与 0026 两条——「新 ADR 必须有 sidebar 条目」在 M23、M24 连续两期漏网。

**原因分析**：
版本号升级与 docs 导航对账都不在任何工单的 checklist 里，只活在发版流程第六步——里程碑收尾工单（每期 11 号）与发版检查之间没有显式交接，靠人记得。

**解决方案**：
每期「里程碑收尾」工单的 checklist 固定补两项：①全模块 pom 版本 = 分支名（版本号规范锚点）；②config.mts nav/sidebar 与 docs/ 新增文件双向对账（新 ADR/新篇章）。这两项前移到收尾工单后，发版第六步成为复核而非首查。

**影响范围**：
M25 起每期收尾工单模板与发版流程。

## [2026-09-26] 0.20.0 盖章：盖章提交落错分支——发布操作前必须确认当前分支

**问题描述**：
0.20.0 盖章提交落在了 0.20.0 分支（上轮里程碑收官后工作区停在 0.20.0 分支），`git push origin main` 显示 "Everything up-to-date" 掩盖了问题，tag 指向了 main 历史之外的提交。

**原因分析**：
盖章/打 tag/推 main 是"以 main 为对象"的操作序列，但没先确认 HEAD 在 main——收尾期常在版本分支与 main 间切换，工作区停在哪是上轮操作的残留状态。

**解决方案**：
发布操作序列第一步固定为 `git branch --show-current` 确认输出为 main（不是则先 checkout main）；推 main 后核对推送输出含 SHA 前缀更新行（"Everything up-to-date" 在此场景 = 异常信号，须回查）。出错修正姿势：cherry-pick 到 main → 删 tag 重打 → force 推 tag（刚推出无消费者才可 force）→ 版本分支快进复位。

**影响范围**：
所有盖章发布操作（工单 01 形态的里程碑启动手续）。
