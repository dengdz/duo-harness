## 复盘维度

任务收尾调用 duo-skill-evolution 复盘时（AGENTS.md 红线 8），本技能按以下口径收集输入：

- 任务摘要：验收范围（工单级/里程碑级）、准备的验收件、用户运行结果
- 执行过程关键点：三件套是否齐备、演示是否一次跑通、日志是否清晰、对照表是否完整
- 用户反馈：用户对验收流程、日志详细度、预期对照表的反馈
- 自我感知：流程中是否有遗漏环节、日志是否足够详细、可优化点

## [2026-09-29] 交互功能验收的标准装备：隔离实例 + 内置浏览器驱动 + 诊断日志先行

**问题描述**：
C2 工单 07 验收发现 BUG-20260929-01（Web 提问卡挂起期永不渲染）——既有测试全绿（直调 completeById 绕过了前端真实 payload 与渲染链），用户报"弹卡无回复"后先后排除了两个错误假设（缓存旧脚本、作答链路断裂），最终靠"隔离实例 + 内置浏览器驱动页面真实点击 + WebAnswerer 挂起/收回路径诊断日志"三件套一锤定音：服务端挂起正常、作答链路正常，缺的是渲染事件源。

**解决方案**：
凡「阻塞等人的交互工具」（ask_user / 审批 / 计划卡）的验收，三件套作为标准装备：
1. **隔离实例**（独立端口 + 独立 DUO_HOME 复制真实 LLM 配置——密钥只进 /tmp 不入库），避免与用户日常实例互踩（端口/会话锁/配置三处，连败三次的老坑）；
2. **内置浏览器驱动真实点击**（页面内 evaluate 触发按钮，绕过自动化定位层的不稳定）——直调式测试抓不住渲染与协议缝隙；
3. **服务端诊断日志先行**：在挂起/完成/各收回路径布 INFO 留痕再复现，失败路径一锤定音不靠推测。

验收清单新增检查项：**交互卡的"挂起期可见性"**——卡片必须在等待期实时渲染（事件源在 ask 前落盘），而非工具完成后才出现。

**影响范围**：
一切阻塞等待用户输入的功能验收（Web 卡片、HITL 交互）；"测试形态与生产形态有缝"模式的第三实例（前两例见 review-log M28 条目与 C2 条目）。

## [2026-09-22] 验收命令必须自己完整跑过一遍再交用户

**问题描述**：
工单 01 验收演示命令漏了 `-am package`（只给 `-pl example`），用户复制粘贴即 BUILD FAILURE（兄弟模块 jar 不在本地仓库、nexus 无私有构件），验收第一轮直接卡死在启动。

**原因分析**：
命令从记忆拼装而非从文档原样引用（README 与 运行Demo.md 的官方命令本带 `-am package`）；三件套判据明写「命令在干净检出上复制粘贴即可执行成功」，但交付前没有自跑验证。

**解决方案**：
演示命令交付前自己完整跑一遍到「可交互/出预期首行」为止；从记忆写命令后与 README/运行Demo 的先例逐 token 对照。本仓库多模块未 install，凡 `-pl` 必带 `-am`。

**影响范围**：
所有验收件准备（尤其 example 演示命令）。

**再犯与加重（2026-09-22 晚）**：
同日第二次踩 `-pl` 忘 `-am`（依赖解析失败）与 `-Dexec.args` 相对路径错误——教训落档仍再犯，说明根因是「从记忆拼装命令」而非「不知道」。纪律升级：涉及 mvn 命令的一律从 `docs/01-入门/运行Demo.md` 或既有 README 原样复制后仅改动 mainClass；改任何参数前先查 DuoMain 的参数解析语义（args[0] 相对路径按 cwd 解析，classpath 资源应省略让缺省加载）。

## [2026-09-22] 起 Web 验证实例的隔离三件套（连败三次的教训）

**问题描述**：
工单 02 停止按钮视觉验证，起 example 真实装配连败三次：① `-Dexec.args=agent-demo.yml` 相对路径读不到（cwd 是模块目录）；② 固定端口 18080 被用户终端里活着的验收 REPL 占用；③ 最新会话锁被同一实例持有（Web 插件启动失败）。另有一次 `-pl` 忘带 `-am` 直接依赖解析失败（同一晚第二次踩）。

**原因分析**：
验证实例与用户日常实例（活 REPL、真实 ~/.duo）共居：端口、会话锁、配置路径三处都会撞；yml 相对路径的解析目录与直觉不符。

**解决方案**：
起验证实例一律用隔离三件套：`DUO_HOME=/tmp/xxx`（拷贝 config.yml 保 LLM 配置，会话锁天然隔离）+ 复制 agent-demo.yml 改端口（绝对路径传 `-Dexec.args`）+ `-pl example -am package`（永不裸 -pl）。验证完 kill 进程、删临时目录。

**影响范围**：
所有需要真实装配的 Web 视觉验证与手动演示环境。

## [2026-09-23] 「会话已被占用」排查：先比时间戳 + Java 同语义探锁 + classpath 前置 classes

**问题描述**：
工单 09 resume 横幅验收连卡多轮「会话已被占用 → 新建会话」。先后误判为「上一进程未死透」「锁残留」，考古终端时序耗大量轮次；隔离实验里改完代码验证竟毫无变化，几乎误判修复无效。

**原因分析**：
① 真根因是同 JVM 装配争抢——web 行先于 cli 行，Web 面 `latest()` 抢走目录最新会话，CLI 撞同进程持锁注册表被顶开新建，每轮的「被占会话」正是上一轮 CLI 刚建的；现象与「进程残留」一模一样，先入为主走了弯路。② python `fcntl.flock` 与 JVM `FileChannel`（fcntl 锁族）是独立锁族，flock 探测 fcntl 锁恒假阴性，一度把误判"验证"成结论。③ `dependency:build-classpath` 生成的是 ~/.m2 旧版本 jar，改完 session/web 源码跑验证时 classpath 根本没带上新 classes。

**解决方案**：
① 时间戳判别法：被占会话与本次实例启动**同一秒** = 同 JVM 内争抢（查装配顺序/服务单例），跨时段 = 跨进程残留（查进程生死）——先比时间戳再选排查方向。② 锁探测一律写 5 行 Java `FileChannel.tryLock`（与被测代码同语义），不用 shell/python 的 flock。③ 改码后的运行验证，classpath 必须把各模块 `target/classes` 前置在 build-classpath 产物之前（本仓库未 install，.m2 里只有旧版本）。④ 隔离终验标准姿势升级：`DUO_HOME=/tmp/xxx` + **单次 shell 调用内完成全流程**（起 → 操作 → `kill -9` + `wait` → 再起——跨调用 kill/ps 在沙箱下不可靠）。

**影响范围**：
所有涉及会话锁、双呈现位（CLI+Web）、多进程交互的验收与排障；一切"改了代码但行为没变"的验证场景。

## [2026-09-23] 验收预期必须对照平台既有不变量设计

**问题描述**：
工单 07（标签级会话绑定）验收步骤第 4 步预期「B 标签可切换到 A 正在绑定的会话」，用户实测必得「会话已被占用」409——预期与 M10 起的会话独占锁不变量（一进程一锁，后到者明确报错）直接冲突，验收步骤本身写错，非实现缺陷。

**原因分析**：
写验收步骤时只对着本工单的新能力（按标签换绑）设计场景，没有核对目标操作撞上的既有平台不变量（独占锁、fail-closed、幂等约定）；「空闲」被误当成「未绑定」。

**解决方案**：
设计每条验收预期前先问一句「这一步撞不撞既有不变量」——涉及会话/锁/审批/fail-closed 的操作，先确认目标状态的精确语义（是空闲还是未绑定、是可答还是可见）；被不变量拦下的路径本身就是一条正向验收用例（占用 409 正是「后到者明确报错」的验证），按「预期该拒」写进步骤而不是当反例。

**影响范围**：
所有涉及资源独占、交互门禁、fail-closed 语义的工单验收步骤设计。

## [2026-09-26] 验收件交付单一焦点：一次只给「命令 + 预期对照」

**问题描述**：
M26-01 验收件交付时把验收命令、验收中暴露 bug 的定性、key 轮换安全提醒、后续 frontier 提示混在同一条消息，用户回"没懂什么意思"，被迫拆成大白话重讲一遍才完成验收。

**原因分析**：
验收件本身要"用户逐行对照"，认知负载已经不低；再叠加多线程事项，用户抓不住"我现在要做什么"。第三步"交用户运行"是阻塞步骤，消息的有效性直接决定验收轮次。

**解决方案**：
交付验收件的消息只含三件：要跑的命令、预期对照表、跑完之后的两个出口（过 → 转 done / 不过 → 修复回路）。bug 定性、安全提醒、后续安排等一律另起消息，且排在验收件之后。

**影响范围**：
所有工单级/里程碑级验收件交付。

## [2026-09-26] agent 预验真实实例的副作用必须在交付前清场（锁/进程/数据）

**问题描述**：
M26-06 浏览器验收：agent 用 curl 预验时把 default tab 换绑到手造会话（服务端持锁），交付用户后侧栏显示该会话"使用中"无法打开，用户验收多一轮往返才定位是 agent 预验副作用。

**原因分析**：
预验的 curl 操作改变服务端状态（会话绑定/占用锁）；清理只想到"临时目录与后台进程"，漏了"预验动作本身留下的服务端状态"。另外 agent 后台起的实例用户终端 Ctrl+C 够不着——用户无法自行清场。

**解决方案**：
预验产生的服务端状态（换绑/占用/生成数据）在交付前归位：要么重启实例（状态全释放），要么预验用独立的 tab/资源不与用户操作路径相交；凡 agent 后台起的验收实例，交付说明里必须给出用户可控的停止方式或由 agent 先停再交。

**影响范围**：
一切带真实服务实例（Web/CLI）的验收准备。

## [2026-09-28] 交互式入口的自跑口径——「跑到启动横幅」即可闭环，漏 mainClass 再犯的根因升级

**问题描述**：
M28 验收首版命令漏 `-Dexec.mainClass`——exec 跑的是 pom 缺省 mainClass + 缺省 demo.yml（M1 叙述），CLI/Web 根本没起；用户第一轮就抓到。这是「从记忆拼装命令」教训的三犯，但根因有新面：REPL/Web 入口需要交互 + 真实 LLM 调用，「交付前自己完整跑一遍」对交互式入口似乎不可执行，于是退回了拼装。

**原因分析**：
「完整跑一遍」的口径没有为交互式入口分级——其实自跑不需要交互：后台起进程 + stdin 接 /dev/null + 抓启动横幅（如「Web 面已启动」与 `你>` 提示符）即完成「到可交互/出预期首行为止」的验证，随后 kill。本轮第二次正是这样跑成功的（横幅与提示符均出），证明口径可行。

**解决方案**：
交互式入口的自跑口径 = **后台起 + stdin 空流 + 抓启动横幅/首行提示后 kill**（不进交互、不调 LLM）；命令拼装一律从运行文档原样复制，mainClass/args 逐 token 对照；macOS 无 timeout 命令，用后台 + sleep + kill 组合。影响范围：所有 REPL/Web/headless 类验收命令的交付前自检。

## [2026-09-28] 预期对照表生成前先校验用户环境——项目规则可穿透档位语义

**问题描述**：
M28 验收单写「read-only 档写操作转 [待审批]」，用户实测 write 直接 ALLOW（策略=permission-rules）——排查确认非缺陷：用户项目 `.duo/settings.json` 存在无路径限定的 `write allow` 规则，M24 编排序（deny 规则 → 只读 bash → **allow 规则 → 档位**）下规则命中即短路，档位不被查询。验收单预期与用户环境事实不符，制造了一次假阳性排查。

**原因分析**：
预期对照表从「设计语义」推导（档位 → 审批），没有先查用户环境的覆盖性配置（项目/用户级权限规则、settings 覆盖、yml 定制段）——设计语义与用户环境叠加后的实际行为才 是对照基准。

**解决方案**：
里程碑级验收单生成前，先机械核对用户环境的覆盖性配置（`<项目>/.duo/settings.json`、`~/.duo/config.yml` 的非缺省段、yml 副本与官方的差异），凡环境配置会改变预期行为的验收点，预期按「设计语义 + 环境覆盖」的合成结果书写，并注记成因。影响范围：验收件预期对照表的生成流程。

## [2026-10-02] 浏览器判可见性用 computed style，offsetParent 对 fixed 定位元素恒为 null

**问题描述**：
M33 浏览器实测批 3 验证「子任务全程」抽屉：点击开关后用 `offsetParent !== null` 判可见性两轮均报「仍隐藏」——实际抽屉（position:fixed）早已打开且内容完整，是判据自身失效；同类探针在批 4 再犯一次（toast 容器）。

**原因分析**：
`offsetParent` 的语义是「最近的非静态定位祖先」，元素自身或祖先为 fixed 时该属性恒为 null——「null = 不可见」的直觉判据对浮层类 UI（抽屉/toast/对话框，多为 fixed）系统性失效。

**解决方案**：
浏览器验证浮层可见性一律用 `getComputedStyle(el)` 的 display/visibility/opacity（或 getBoundingClientRect 非空）判定，不用 offsetParent；M33 报告 O6/O16/O18 另有三条同族实测纪律（原生点击、busy 会话不发送、探针「点击即返+外层轮询」拆步）可一并复用。

**影响范围**：
一切内置浏览器驱动 UI 验收的浮层可见性断言（抽屉/toast/模态/下拉）。
