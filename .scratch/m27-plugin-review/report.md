## 一、命题与总结论

命题（ADR-0029 M27）：**「后续功能挂得上」**。

**结论：成立，且边界清晰。**

- **能挂**：22 个扩展点全部有真实先例插件（最简 23 行、最全 65 行）；demo 插件零内核改动接入成功并经用户手动验收（统计员串起事件监听/命令/工具/服务消费四插口）。

- **写死接线**：16 条台账定性完毕——病 3（H-05 已修、H-12 触发不足归 M28、H-08 修复出栈 1.0 后）+ 丑 13（归宿 M28 / backlog / 1.0 后，逐条在册）。
- **审查驱动小步改有实证产出**：H-05 行序契约 fail-fast 上线（非纯审查空转），且修复中发现 mcp-cli 半条契约已被 ADR-0019 自愈——缩小修复面、纠正一条过期契约。

## 五、修复记录（工单 05，用户裁定修）

**H-05 装配顺序隐式契约 → 已修**：

- web-cli 半条：`InteractionService.hasAnswerer()` 只读探测（新接口方法，未来新呈现位自动被约束）+ WebPlugin apply 期 fail-fast（web 后于既有回答者 → 启动点名「行序契约」+ 调整指引，Boot 整树回滚）。契约知识归当事插件，**core 零改动**（优于工单原文的 BootLoader 校验设想——核心不获产品知识）。
- mcp-cli 半条：复核确认已被 ADR-0019 epoch 自愈（connectorStatus 在 CliPlugin optionalInject 内，行序后置 → 自动重载补订阅），契约降级为建议，注释已更正。
- 回归：WebPluginRowOrderContractTest（违例点名）+ 97 web 测试 + 全仓 14 模块绿。
- **修复 v2（用户验收实测补强）**：用户手动对调行序实测，发现更深机制——cli 行的 apply 即 REPL 主循环（同步阻塞至会话退出），交互场景下 web 行后置的病灶是「Web 呈现位**静默缺席**」而非路由翻转（fail-fast 不响属正确——翻转未发生）。补强：DuoMain boot 前预检（cli+web 同在册且 web 后置 → exit 2 点名）；yml 注释、扫描册、CHANGELOG 同步。此为「用户亲手验收 > agent 自跑测试」的实证：探针三连（注册表实例身份/注册调用/检查读取）定位出测试环境覆盖不到的启动时序机制。

**不做与理由**：H-12 fileRefs 旁路（病但本期无预演/demo 卡点，不满足判据）→ M28；H-08 装载（新功能非手术）→ 1.0 后；其余丑条目 → M28/backlog 逐条在册。
