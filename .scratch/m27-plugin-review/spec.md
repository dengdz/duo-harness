# M27（0.22.0）插件化审查——「后续功能挂得上」

Status: ready-for-agent

## Problem Statement

- **口号与事实有差距**：术语表宣称"所有能力（工具 / MCP / 页面 / agent 循环）以插件形式组装"，但真的以第三方插件身份接一个新能力试试，会撞上一圈绕过插件机制的写死接线——呈现位写死两个、agent 执行链十几个构造参数焊死、三处呈现位装配同构重复（headless 首版曾因此漏挂管线超时与审计回答者）、会话事件不上插件事件总线、装载全靠手写 yml 全限定名行。"后续功能挂得上"目前只是一句口号，没有证据。
- **卡点无人盘点**：1.0 后菜单里的功能（goal / schedule / agents[] 等）今天若做成插件会在哪里卡住，没有系统答案；没有这份盘点，M28 规范化重构就没有靶子。
- **立项口径两处失真**（2026-09-27 启动 grill 实测勘误，已注回 [ADR-0029](../../docs/adr/0029-M27至1.0版图重排第二弹.md)）：装配参数实测 chatAgent 全参重载 14 参、全仓最大装配点为命令注册接线 17 参（立项原文「15 参」）；接线同构重复实为三处（CLI/Web/headless，立项原文「双呈现位」）。

## Solution

审查驱动的里程碑（范围与排序以 ADR-0029 为准），五步一条线：**盘点 → 预演 → 小步修 → demo → 交付**。

1. **盘点**：内核边界矩阵（插件能挂什么、内核独占什么）+ 全仓硬连点扫描册（绕过插件机制的写死接线逐处登记、按病/丑定性）。
2. **预演**：goal、schedule、agents[] 三个未来功能推演"今天做成插件会卡在哪"，卡点即真缺陷入册。
3. **小步修**：按"只修病"判据当场修 ≤3 处接口缺陷，每处指认卡点；"丑"一律记 M28。
4. **demo**：工具使用统计员插件——独立模块 + 依赖行/配置行两行接入，不动既有代码一行。
5. **交付**：审查报告（验收材料，留工作区）+ 插件扩展点清单（升格文档站参考章）。

## User Stories

### demo 插件（验收核心）

1. 作为部署者，我想把新插件做成独立 Maven 模块、只在依赖清单和启动配置各加一行就接入运行，以确信"后续功能挂得上"不是口号。
2. 作为部署者，我想让"接入"的口径明确为不动既有代码一行（配置与依赖的新增行不算改动），以便验收有可判定的边界。
3. 作为用户，我想敲 /toolstats 命令看到本次运行的工具使用统计（哪个工具用了几次、成败各多少），以便直观感受新插件带来的新能力。
4. 作为模型，我想调用 demo 插件注册的统计查询工具回答"最近哪些工具用得多"，以验证插件注册的工具对模型可见可用。
5. 作为验收者，我想亲手跑一遍 demo 全程（两行接入 → 启动 → 模型调工具 → /toolstats 出报表），以亲眼确认零内核改动接入成立。
6. 作为第三方插件开发者，我想让 demo 展示"事件监听 + 命令注册 + 工具注册 + 服务消费"四个现成插口的完整用法，以便把它当第三方插件的参考实现。

### 盘点与扫描

7. 作为第三方插件开发者，我想有一份「插件扩展点清单」（哪里能挂、怎么挂、挂了能干什么），以便不读内核源码就能规划新插件。
8. 作为维护者，我想要一份硬连点扫描册（类型下探、常量钉死、字符串分发、装配顺序隐式契约、服务名撞名等逐处登记），以便 M28 重构有的放矢。
9. 作为维护者，我想让扫描册每处硬连点都有病/丑定性（阻塞挂载 vs 能跑难看），以便划清 M27 与 M28 的修复边界。

### 预演

10. 作为维护者，我想预演 goal 做成插件的接入过程，以实证循环域卡点（turn 边界无插件挂点、跨轮目标存储无服务、再触发路径不通）。
11. 作为维护者，我想预演 schedule 定时提醒的接入过程，以实证时间域卡点（无调度服务、提醒无进对话的通道）。
12. 作为维护者，我想预演 agents[] 声明式自启的接入过程，以实证装载域卡点（手写全限定名行、无批量装载）。
13. 作为维护者，我想让预演卡点直接回填扫描册并与"病"判据对照，以便该修的当场修、该记的明确记。

### 小步修与交付

14. 作为维护者，我想让审查撞出的"病"（上限 3 处）当场修掉并有测试作证，以便后续功能真的挂得上而不只是记在册子上。
15. 作为维护者，我想让"丑"（参数堆、重复接线、大文件、改名类破坏性变更）全部记档移交 M28，以避免本期大拆伤稳。
16. 作为验收者，我想拿到一份审查报告（边界矩阵 + 扫描册 + 预演记录 + 修复记录 + demo 记录），以作为 M27 验收与后续写作的底料。
17. 作为后续会话（M29），我想让扩展点清单升格进文档站参考章，以便「多插件协同」等三章有稳定事实底座。

## Implementation Decisions

六项 grill 裁定（2026-09-27 启动 grill 逐项裁定；里程碑范围与排序以 [ADR-0029](../../docs/adr/0029-M27至1.0版图重排第二弹.md) 为准，本期执行细则以本节为准）：

**demo 接入口径**
- demo 做成独立 Maven 模块；接入动作 = example 模块依赖清单加一行 + 启动 yml 加一行插件行，除此之外不改任何既有文件的一行；验收口径 = **不动既有代码一行**。
- 不为 demo 增设目录扫描/jar 级装载——那是预演 agents[] 的素材，本期只推演不实现。

**demo 功能（工具使用统计员）**
- 监听工具域 post-execute 瀑布事件，按工具名累计调用次数与成败；注册 /toolstats 命令（inject commands 服务）现场输出统计；另注册一个模型可调的统计查询工具（inject tools 服务）。
- 服务消费走声明纪律：必需服务进 inject、可选服务进 optionalInject（ADR-0019）；服务名对照既有 SERVICE_NAME 先例（camelCase、视图接口方法名逐字一致）。
- 力度判据：一个插件串起**事件监听、命令注册、工具注册、服务消费**四个既有插口；全程零内核改动，不走"扫会话日志文件"之类的绕机制实现（那是扫描册要登记的反面形态）。

**预演三件（卡点推演，不实现）**
- goal（循环域）：turn 边界无插件挂点、跨轮目标存储无服务、goal→agent 再触发路径（收件箱未服务化）不通。
- schedule（时间域）：内核无时间/调度服务、Boot 一次性引导无进程级钩子、提醒无进对话通道。
- agents[]（装载域）：插件装载 = 手写 yml 全限定名行 + classpath 依赖，无批量自启、无 jar/目录装载。
- **关键边界事实**（2026-09-27 核实）：会话事件不上 Context 事件总线、会话实例不以服务形式暴露——插件可听面 = 插件状态事件、工具三段瀑布、插件间自定义事件。demo 与预演均以此为界；预演若判"会话事件桥"为病，因超出接口手术精度记 M28/1.0 后，不在本期修。

**小步修判据**
- 只修"阻塞或实质拖累未来功能挂得上"的接口缺陷，每处必须指认预演或 demo 的具体卡点（能说出"不修它挂不上"）；上限 3 处，一处没撞上就空过。
- 预判记 M28：类型下探改他者内部状态、呈现位常量钉死、服务名撞名改名（破坏性接口变更）、接线三连抄（除非预演/demo 证明它阻塞新呈现位接入则升本期）。
- 服务名撞名（子代理宿主服务名与呈现位撞词）入扫描册，作 M28 立项对账条目。

**产物归宿**
- 过程与验收材料：`.scratch/m27-plugin-review/`（边界矩阵、扫描册、预演记录、审查报告）。
- 扩展点清单升格 `docs/05-参考/插件扩展点清单.md`（参考体裁，与术语表互链）；审查报告属过程体裁留工作区，不把缺陷快照永久化。

**模块归属**
- demo 插件：新独立 Maven 模块（依赖面收窄到声明所用的服务域接口）；example 引依赖 + 加 yml 行。
- 扩展点清单：docs/05-参考/；其余产物均在 .scratch/m27-plugin-review/。

## Testing Decisions

接缝方案：**无新接缝，全部沿用既有**（demo 是本期唯一成规模代码，修复至多 3 处）。

- **好测试的标准**：只测外部行为（命令已注册可执行、事件计数正确、工具已注册且结果契约正确），不断言插件内部实现；断言沿用 JUnit 原生 Assertions（全仓无 AssertJ/Mockito）。
- **demo 插件——插件装配接缝**（最高可复用 seam）：插件上下文装配后断言三个可观察面（命令注册表含 /toolstats、工具清单含统计查询工具、模拟工具调用后统计输出正确）；编程挂载用 awaitStartup 超时语义（ADR-0019）；yml 装载路径至少一条装配测试（BUG-20260915-02 教训：Boot 装载路径不能零测试）。
- **修复（若有）——最窄 seam 单测**：按所改面的既有测试形态走（先例：管线超时监听查重的单测，M18-05）；提交前沿用两 grep 机械自检（duo-workflow 经验）。
- **验收 = 用户亲手跑**（duo-acceptance 三件套）：验收件 = demo 接入演示（两行接入 + 启动 + 模型调工具 + /toolstats 出报表）+ 过程日志 + 预期对照；审查报告与扫描册随验收一并出示。

## Out of Scope

- **装载机制新功能**（目录扫描 / jar 级 / 批量自启）——预演素材，1.0 后按需立项。
- **goal / schedule / agents[] 本体实现**——1.0 后菜单（ADR-0016/0024）。
- **接线三连抄消除、装配参数对象化、WebFace 拆分、user.dir 提取、Data Clumps**——M28 挂账（ADR-0029）。
- **服务名改名**（含撞名修复）——破坏性接口变更归 M28 裁。
- **会话事件桥接到插件总线**——预演若判病也超出接口手术精度，记 M28/1.0 后再议。
- **前端按工具名渲染的协议化**——backlog（M23 旧口径）。
- **度量工具进构建**（PMD/CPD 等）——ADR-0029 已拒绝。
- **理解关卡补考**——不排期、用户主动发起（ADR-0029 横切口径）。
