# M34（1.0.1）修复批——M33 浏览器实测缺陷七档全修

Status: ready-for-agent（工单已拆 6 张见 [issues/](issues/)——01 BUG-01 先行，06 回归验证 + 发版收口）

## Problem Statement

- **M33 百例实测坐实 7 档 P2 缺陷**（全部有档案、根因假设与修复候选口径，见 `.scratch/bugs/BUG-20261002-01 ~ 07`）：/api/status 空响应（状态面五区块全盲，波及面最大）、坏行会话三症状（加载抛异常 + 锁泄漏 + 导出静默零事件）、翻页进度被新事件重置、审批放行后按钮态提前回落、提问卡回放态不完整、todo 面板首帧冻结、占位符承诺 /技能名 直调未兑现。
- **1.x 向后兼容承诺需要兑现节奏**：缺陷修复进修订号（1.0.1），七档不修则 1.0 的质量背书悬空；M33 的 13 例阻塞中有 8 例被 BUG-01 连带，修复后这些测试资产可直接复验翻转。

## Solution

五步排期修复七档 + 两个顺手项（O15 chip 残留、O17 auth:none 页面横幅，挂在对应工单不单开），第六单回归验证 + 发版 1.0.1。范围与排期以 [ADR-0036](../../docs/adr/0036-M34修复批立项决策.md) 为准；每档的修复候选口径以各档案「修复方案（计划）」节为执行输入。

## User Stories

1. 作为使用者，我想要状态面五区块（上下文/后台任务/连接器/插件/工具）有真实数据，以便打开页面即见系统实况而非全盲「—」。
2. 作为使用者，我想要含坏行的会话仍可打开回放（坏行跳过并计数标注），以便数据损坏不演变成会话不可入。
3. 作为使用者，我想要坏行会话导出时坏行被明示计数而非静默零事件，以便交付物可信。
4. 作为使用者，我想要滚动翻页加载的更早内容在新事件到达后仍在页面上，以便回看长会话不被反复打断。
5. 作为使用者，我想要提问卡在刷新后仍显示问题与我的作答状态，以便回放与实时形态一致。
6. 作为使用者，我想要审批放行后发送按钮保持「停止」直至轮真正收口，以便运行态指示可信、不误发消息。
7. 作为使用者，我想要侧栏 todo 面板跟随清单推进，以便与聊天内清单卡一致。
8. 作为使用者，我想要输入框承诺的「/技能名 直调」真实可用（或占位符不再承诺），以便文案与行为一致。
9. 作为使用者，我想要发送后的附件 chip 自动清理，以便 composer 不残留已发出的附件。
10. 作为使用者，我想要 auth:none 时页面顶部有「鉴权已关闭」警示，以便打开页面的任何人即刻看到不安全状态。
11. 作为维护者，我想要每档缺陷带回归锁（各档案「回归测试」候选已预写），以便修复不以复发收场。
12. 作为验收者，我想要 M33 报告 13 例阻塞中的 8 例 BUG-01 连带例复验翻转并回填附注，以便测试资产变成修复验收件。
13. 作为使用者，我想从 GitHub Release 拿到 v1.0.1（jar + sha256），以便缺陷修复有明确下载锚点。

## Implementation Decisions

四问确认裁定（2026-10-02，草案三项默认 + 直排工单，全记录见 [ADR-0036](../../docs/adr/0036-M34修复批立项决策.md)）：

- **版本与分支**：1.0.1（缺陷修复进修订号——1.x 策略在案），分支 `1.0.1` 随立项自 main 切出；开发提交不落 main（红线 7 恢复适用）。
- **范围**：BUG-01 ~ 07 全修 + O15/O17 并入对应工单（不单开）；M33 报告 13 例阻塞中非 BUG-01 连带的 5 例（设计不可达 4 + IAB 1）不在修复范围——它们不是缺陷。
- **排期**：五步按波及面 × 依赖——① BUG-01 → ② BUG-07 → ③ BUG-02+04（回放语义并修）→ ④ BUG-03+O15（态机）→ ⑤ BUG-05+06+O17（小面收尾）→ ⑥ 回归验证 + 发版。
- **流程降级**：按 ADR-0035 预留口子「范围简单可降级直排工单」——跳过修复批 grill，七档档案的「修复方案（计划）」节即工单执行输入；工单内仍需小裁定的（BUG-06 补注册 or 改文案）在单内定并回写档案。

## Testing Decisions

- **回归锁前置**：每档档案「回归测试」候选即本批测试设计输入（如：坏行会话可打开可回放、审批放行后按钮保持停止至收口帧、滚顶态新事件首条仍在 DOM）——先写锁再修。
- **接缝复用**：服务端行为走既有 web 模块真 HTTP 集成测试形态（10 个先例）；前端行为走 M33 同款内置浏览器实测口径（原生点击、隔离实例、行为类判据）——修复批验收 = M33 用例复验翻转。
- **只测外部行为**：断言页面可见行为与 API 契约，不锁实现细节。
- **回归红线**：既有 151 个 Java 测试全绿 + M33 报告相关例复验翻转记录回填附注。

## Out of Scope

- M33 缺陷池之外的任何新功能、重构、依赖变更（1.0.1 纯修复语义）。
- 设计性「阻塞」5 例（双标签同会话独占锁 ×3、busy-409 ×1、IAB localStorage ×1）——不是缺陷，不改。
- M33 观察项 O1-O14、O16、O18（行为澄清与测试脚本自省，无修复对象）；O17 已并入工单 05。
- 1.0 后菜单任何条目（含 browser-use 产品化 ㉒）。
- limitations 页大规模重写——仅随修复回写「已修复」状态与总报告「新发现」4 条的核实结果。
