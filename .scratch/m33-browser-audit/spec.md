# M33 浏览器实测质量期——「百例基线」

Status: ready-for-agent（工单已拆 7 张见 [issues/](issues/)——01 设计与 smoke 即刻可开工，02-06 逐批执行，07 收口）

## Problem Statement

- **浏览器行为零基线**：1.0 已发布，但 Web UI 的浏览器端从未有过系统化实测——历史口径是「浏览器端以人工验收为准」（m8-web spec 在案），历期验收都是单点、随工单的目测/半自动验证。151 个 Java 测试类不测页面 JS，浏览器端真实行为（渲染、交互、容错、实时流）没有任何一份完整档案。
- **1.x 承诺需要行为背书**：1.0 起 1.x 内向后兼容（README 声明在案），承诺的前提是「现状行为有底」——哪里是实的、哪里是虚的，说不出。已知限制页（docs/limitations.md）按里程碑记账，但没有一次针对浏览器面的系统排查。
- **缺陷无台账入口**：浏览器面若存在缺陷（对照 BUG-20260929-01 提问卡挂起期不渲染这类先例），目前只能靠用户偶然撞见——没有主动发现机制。

## Solution

纯测试期（范围与裁定以 [ADR-0035](../../docs/adr/0035-M33浏览器实测立项决策.md) 为准；产品代码零改动）：用内置浏览器（ZCode browser-use）对隔离实例跑 **100 个复杂场景用例**（硬指标），十域全功能面 × 风险加权覆盖（跨域组合链占三成），真实模型驱动对话类用例。产出三件：**测试报告**（100 例逐例终态 + 证据）、**缺陷台账**（duo-bug-ledger 建档 + P0/P1/P2 分级）、**下一步输入**（修复批工单池 + limitations 回写候选清单）。

## User Stories

### 基线与覆盖

1. 作为验收者，我想要 100 例逐例的终态结论（通过 / 发现缺陷 / 阻塞三值），以便 1.0 的浏览器行为有一份完整、无悬置的基线。
2. 作为维护者，我想要十域风险加权的覆盖矩阵（高危域 10-20 例、展示类 3-8 例、跨域组合链 30 例），以便容易出事故的面被加密覆盖而纯展示面不被漏测。
3. 作为长会话关注者，我想要跨域组合链用例（如长会话中途切走 + 切回 + 导出），以便真实使用形态（而非孤立功能点）被测到。
4. 作为安全基线关注者，我想要鉴权栅栏负路径用例（token 无效/缺失、Origin/Host 错位、403 fail-closed），以便 1.0 安全承诺有实测背书。
5. 作为实时流关注者，我想要断线重连 / 心跳 / 回放 / 分页用例，以便网络抖动与长会话下的行为有底。
6. 作为 vision 链路关注者，我想要「传图 → 模型看图回答」全链路用例，以便多模态呈现与 vision 闸门有基线。

### 真实性与环境

7. 作为 1.x 使用者，我想要对话类用例由真实模型驱动（我日常的 `~/.duo/config.yml`），以便测得的是真实使用成色而非编排出来的假象。
8. 作为行为判据读者，我想要判据全部写成行为类（该出现的出现、不该出现的没出现），以便模型随机性不产生假失败。
9. 作为关注成本的维护者，我想要纯 UI 用例复用已产出的真实会话数据，以便 100 例不重复烧模型。
10. 作为环境隔离关注者，我想要隔离 DUO_HOME + 随机端口起实例，以便测试不碰日常会话与活会话锁。
11. 作为连接器域覆盖者，我想要微型 MCP fixture（echo 型本地 server）提供真实桥接数据，以便连接器正向链路可测而非只剩配错负路径。
12. 作为文件类功能覆盖者，我想要真实 git 仓库工作区夹具，以便 edit/read/glob 卡片、.gitignore 判定、@ 补全都吃真实文件。

### 证据与台账

13. 作为验收者，我想要每例证据四件套（步骤 / 预期 / 实测 / 结论），以便逐例可复核、不听代理自证。
14. 作为关注缺陷的人，我想要缺陷例必附截图与最小复现，以便修复批拿到就能开工。
15. 作为验收者，我想要通过例按两成抽样附截图存证，以便批次抽查有据、报告不臃肿。
16. 作为修复批排期者，我想要报告内 P0/P1/P2 分级，以便按严重度挑修复顺序与估量。
17. 作为台账读者，我想要每个缺陷按 duo-bug-ledger 建档（`.scratch/bugs/` 全生命周期档案），以便与既有缺陷纪律同一套留痕。
18. 作为进度关注者，我想要 5 批 × 20 逐批小节报告，以便中途纠偏而非收口才发现方向跑偏。
19. 作为维护者，我想要阻塞例如实记因（环境限制 / 模型能力边界），以便阻塞不伪装成通过或失败，阻塞面可审议。

### 档案与收口

20. 作为维护者，我想要测试报告与用例清单落 `.scratch/m33-browser-audit/`，以便回看测试期有完整档案（用例设计、执行证据、结论同库）。
21. 作为决策回看者，我想要立项裁定有 ADR-0035 档案（八问逐题 + 拒绝的选项），以便将来再测知道当初怎么定的、为什么。
22. 作为 limitations 读者，我想要报告出「已知限制确认 / 新发现」一节，以便文档站已知限制页的回写有据可依。
23. 作为发现缺陷的流程执行者，我想要缺陷即建档（报问题即建档纪律），以便没有缺陷只活在报告表格里。
24. 作为验收者，我想要收口完成判据 = 逐批抽查 + 终验通过 + 100/100 终态齐备，以便 done 由我判定。

## Implementation Decisions

八问 grill 裁定（2026-10-02，七问启动 grill + 一问 to-spec 缝裁定，全记录见 [ADR-0035](../../docs/adr/0035-M33浏览器实测立项决策.md)；本节为执行细则）：

- **期定位**：纯测试 + 台账——只测、记档、出报告；**不在当期修任何缺陷**，修复另立项（入口 = 报告分级）。资产纯文档直落 main，不发版、不打 tag、CHANGELOG 不记账（无用户可见变更）。
- **覆盖矩阵**（100 例硬指标；「链」= 跨域组合链）：

  | 域 | 例数 | 其中链 |
  |---|---|---|
  | ① 会话生命周期（新建/切换/搜索/分页/导出） | 12 | 3 |
  | ② 对话主循环（发消息/打断/追加指令/busy 竞态） | 12 | 4 |
  | ③ 卡片分型渲染（15 种分型逐类过） | 15 | 2 |
  | ④ 人机协作卡（审批/提问/计划） | 10 | 3 |
  | ⑤ 图片附件与 vision 全链路 | 6 | 1 |
  | ⑥ 状态面（插件六态/工具表/连接器/后台任务/上下文占用） | 8 | 2 |
  | ⑦ 实时流（回放/心跳/断线重连/分页） | 12 | 5 |
  | ⑧ 鉴权与安全栅栏 | 8 | 2 |
  | ⑨ 输入辅助（@ 补全/斜杠命令/附件按钮） | 7 | 2 |
  | ⑩ 刷新与容错（中断恢复/异常卡/错误呈现） | 10 | 6 |
  | **合计** | **100** | **30** |

- **测试缝**：主缝唯一——真实浏览器对真实实例，断言主面 = 页面可见行为（卡片出现与否、文本内容、交互结果）。HTTP 例外清单：仅协议负路径类（token 无效/缺失、伪造 Origin/Host、403 fail-closed，约 8 例）明示走 HTTP 通道断言（浏览器安全模型不允许页面伪造 Origin/Host 头）；每例标注走哪条缝。
- **终态三值**：通过 / 发现缺陷 / 阻塞（附原因）。跑不通（环境限制、模型能力边界）如实标阻塞，也算交付；素材不足的域宁可在高危域加密，不注水凑数。
- **环境件**：隔离实例（独立 DUO_HOME + 随机端口）+ 三件套（微型 MCP echo fixture、vision 图片全链路、真实 git 仓库工作区）。三件均为测试夹具（环境脚本与数据），非产品代码。
- **模型侧**：真实模型（现有 `~/.duo/config.yml`），判据写行为类；纯 UI 用例（回放/分页/导出等）复用已产出的真实会话数据，不重复烧模型。
- **批次与证据**：5 批 × 20 逐批交付小节报告；批次切分原则 = 环境形态相近同批、每批恰 20 例（具体切分随用例清单定稿）。每例证据四件套；缺陷例必附截图 + 最小复现；通过例抽两成附图。
- **用例编号与报告结构**：`TC-<域码>-<序号>`（域码如 SESS/CYCLE/CARDS/HITL/ATTACH/STATUS/SSE/AUTH/INPUT/TOLER）；报告按域分组，报告头放覆盖矩阵实跑对照、报告尾放「已知限制确认 / 新发现」与 P0/P1/P2 分级汇总。
- **缺陷衔接**：测出缺陷即按 duo-bug-ledger 建档（报问题即建档），报告表格只做索引；分级（P0 崩溃/数据错乱/安全栅栏失效、P1 功能缺陷有绕行、P2 体验/视觉瑕疵）落在报告，供修复批排期，不改台账既有格式。
- **零代码红线**：产品 Java 源码与构建配置零 diff（对齐 M31/M32 纯手续纪律）；本期动面仅 `.scratch/m33-browser-audit/`、`.scratch/bugs/`、`.scratch/bug-log.md`、ADR-0035、duo-workflow experience.md 补注。

## Testing Decisions

- **只测外部行为**：断言主面 = 浏览器页面可见行为，不扒内部状态、不断言实现细节；HTTP 例外清单仅服务协议负路径（详见 Implementation Decisions 缝设计）。判据形态 = 行为类（该出现的出现、不该出现的没出现），不做逐字比对。
- **先例复用**：m8-web 七场景验收对照表（浏览器操作步骤模板）；BUG-20260929-01 的「隔离实例 + 内置浏览器 + WebAnswerer 诊断日志」实证法；「evaluate 原生点击」先例（Playwright 真实鼠标点击有竞态不可靠，m8-web/issues/03 在案）；web 模块 10 个真 HTTP 集成测试作协议面素材参考。
- **不新建产品测试设施**：无 Playwright/Puppeteer 入库、无 e2e 目录、无产品代码改动——浏览器驱动用 ZCode browser-use 能力即席执行，证据落 markdown，不沉淀为代码资产（browser-use 作为产品能力是 1.0 后菜单第 ㉒ 条，另行立项）。

## Out of Scope

- 任何缺陷的当期修复（修复另立项，入口 = 报告 P0/P1/P2 分级）。
- browser-use 浏览器操作作为产品能力的实现（1.0 后菜单第 ㉒ 条，本期只把它当测试工具用）。
- 设置页相关用例（schema 驱动设置页 = 菜单第 ⑩ 条，未实现，不假设存在）。
- CLI / headless 出口测试（浏览器缝之外，CLI 面已有单点验收惯例）。
- e2e 测试基建入库（脚本化框架、可复跑套件）——本期产物是报告与台账，不是测试代码。
- 发版与 CHANGELOG 记账（无用户可见变更）；limitations 页回写（收口后凭报告另行裁定）。
- 新功能、重构、依赖变更（纯测试期，零代码）。

## Further Notes

- **轻量里程碑制首次实操**：M32/ADR-0034 钉定的「1.0 后从菜单/backlog 按需挑活」形态，M33 是第一个实操期——活源是质量承诺本身（1.x 行为基线），不占菜单条目。
- **smoke 前置风险**：实现面 smoke 未做（M30 经验：定版范围关键路径先实测）。工单 01 第一动作 = 隔离实例起得来 + 浏览器连得上 + token 闭环 + 三件套 fixture 可用；失败即回头改方案，不带病铺 100 例。
- **工单构成预告**（/to-tickets 定稿）：01 用例设计与 smoke 前置（100 例清单 + 环境件就绪）→ 02-06 五批执行（每批 20 例 + 小节报告）→ 07 总报告 + 台账核对收口。
- **模型随机性处置**：个别用例因模型行为不可控反复不满足前提时，按「阻塞 + 原因」如实记，不硬跑、不注水；同族阻塞 ≥3 例时报告单列一节议模型依赖度。
- **经验档补注**：duo-workflow experience.md 的逐题提问四犯存证条目已补「机械强制生效实证」注（本次 grill 零纠正），随本期首笔提交同 diff 入库。
