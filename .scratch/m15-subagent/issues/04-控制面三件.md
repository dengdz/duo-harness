# 04: 控制面三件——send_message / interrupt / list

## What to build

父 agent 获得子代理治理权（ADR-0015 决策 2）：`send_message` 给运行中的子 agent 补充指示（纠偏）或给空闲子 agent 开新轮；`interrupt_agent` 中止跑偏子任务（中止语义明确、子会话留下可审计的终止痕迹）；`list_agents` 列出各子代理状态（id/模板/状态：运行中/空闲/完成/中断）。三件仅对装配了 subagent 的实例注册，不进子模板可用集。

## 实现记录

**三件工具（agent.subagent 新增）**：
- `SendMessageTool`：运行中 → 纠偏（往子会话 append `[父补充指示]` user 消息——子 agent 下一轮 `deriveMessages()` 投影自然带上，事件溯源架构零新 seam，指示留痕可审计）；空闲/失败 → 开新轮（`Session.load` 重新持锁同一子会话 + 同模板再跑，任务即指示）；已中断（终态）→ 点名拒绝。
- `InterruptAgentTool`：置中断标志 + 打断后台线程（协作式中止，阻塞 IO 处最有效）。**终局单点收尾**（Manager.finish）：子会话落 `subagent/interrupted` 终止痕迹、父会话回流"已被中止"——控制面只置标志，无双写竞态。
- `ListAgentsTool`：渲染 id/模板/状态清单，空注册表明确呈现。

**Manager 改造**：State 四态 `RUNNING / IDLE / FAILED / INTERRUPTED`（工单"完成"态由 **IDLE** 承担——DSH idle 语义：正常完成待命、可续轮；FAILED 同样可 send_message 重试；INTERRUPTED 终态不可续）；Entry 持 childSession/jsonl/worker/parentSession；后端绑定改 `bindBackend`（呈现位装配一次绑定，spawn/fork/续轮共用——bind 前派生点名失败）；父会话关闭后的回流失败降级为仅子会话留痕（不炸后台线程）。

**接线**：`SubagentPlugin` 的 `CONTROL_TOOLS` 清单挂入三件——模板非空即随插件注册（02 的条件注册机制首次实战）；`PresenterAssembly.registerSubagentTools` 负责 bindBackend + spawn/fork。三件均不进子模板可用集（02 强制过滤已锁定）。

**会话域**：新增 `subagent/interrupted` 事件（子会话终止痕迹，投影跳过；SessionTest 补往返用例）。

**测试**：ManagerTest 6 → 11 用例（新增：steer 时序——backend 在子会话投影中等到指示、续轮 RUNNING 窗口 latch 锁定、interrupt 中止痕迹与终态拒绝、list 状态渲染、未知/不可达点名）；agent 全量 88 绿，session 37 绿，全仓 compile 零破坏；Demo 输出含"控制面三件随插件自动注册"。

**已知限制（进 06 收口候选）**：interrupt 是协作式中止——若子代理正处非阻塞 CPU 段，打断在其下次阻塞时生效；steer 竞态窗口（指示 append 时子代理恰好刚结束）下指示留痕子会话但无新轮消费，需再 send_message 一次。
