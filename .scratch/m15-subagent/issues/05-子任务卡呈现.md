## 实现记录

**方向修正（用户裁定，2026-09-16）**：子代理呈现须与主 agent 一致——回放形态由最初的
"居中弹层 + 事件行列表"改为**右侧抽屉 + 复用主对话渲染器**（用户原话："可以做成一个
右侧的抽屉，点击打开后是一个子 agent 的消息渲染区域"）。事件行列表是自成一套的降级
呈现，与主对话割裂，已废弃。

**render 多渲染目标重构**：`makeTarget(container, isMain)` 封装一套 DOM 容器 + 渲染
状态（toolCards / subagentCards / 打开卡 / 流式气泡），主对话与抽屉各持一份，共用全部
渲染函数（消息气泡、工具卡、子任务卡形态完全一致）；`onTarget(target, fn)` 同步切换，
`replayInto(container, events, taskDesc)` 供抽屉整批回放。渲染函数零重复实现。

**抽屉**（index.html `#subagentDrawer` + theme.css）：右侧滑入、宽 min(560px,48vw)、
贴右边缘；Esc 与按钮可关；开场显示任务描述；**种子边界渲染为居中标注**（"↑ 以上为
继承的父对话背景 ｜ 前 N 条来自父会话 X ｜ 以下为子代理自身行为 ↓"）——ADR-0015
决策 4 的审计可区分要求在呈现层落地。滑入用强制重排而非 rAF（后台标签下 rAF 被节流，
类不添加——实测踩中后修正）。

**后端**：WebFace 新增 `/api/subagent/events`（静态只读、不持子会话锁、id 白名单防
穿越、坏行跳过、不存在返回 found=false）；CLI 加 `attachSubagentTrace` 会话监听打印
[子任务] 派生/完成两行（完成行携最终回答），/new 换绑后重挂。

**装配依赖反转（关键修正）**：初版让呈现位经服务探测拿 manager 再注册 spawn/fork，
触发内核纪律"插件作用域内读服务须先在 inject 声明"——而声明即硬依赖，未配置模板的
部署会挂起（违反用户故事 20）。改为**呈现位发布 `presenter` 服务**（LLM/治理阈值/
当前会话供给，先到先得），SubagentPlugin 经 inject 读取并**自行装配五件工具**：呈现位
不再需要知道 subagent 是否存在，依赖方向单向。

**踩坑记录（内核契约，供后续复用）**：① 视图方法名即服务名，**服务名不能含连字符**
（初版 `"subagent-host"` 无法被视图寻址，改 `"presenter"`）；② `ctx.plugin()` 同步
阻塞至 apply 返回，**依赖未就绪的插件会永久阻塞挂载方**——测试里观察 PENDING 状态会
死锁；③ `provide` 与 `plugin` 跨线程并发调用互等（用例设计须避免）。

**测试**：SubagentPluginTest 3（未配置零注册 / 供给清单 / 宿主驱动五件装配）、CLI
子任务过程行 1（真实插件树 + mock 分流 LLM，断言派生行与完成行）、WebFaceTest 子任务
回放端点 1（坏行跳过、白名单拒绝、found=false）；agent 31、CLI 8、web 全模块、session 37 全绿。

## 验收对照（实测快照 2026-09-16）

**Web 路径**（agent 已实测，您可复跑）：

```
mvn -pl duo-harness-example -am compile exec:java \
  -Dexec.mainClass=dev.duo.harness.example.subagent.SubagentWebDemoMain
# 打开 http://127.0.0.1:18080 → 点完成态子任务卡的"查看子任务全程"
```

实测结果：抽屉贴右边缘滑入（宽 560px，`rightGap=0`），内容复用主对话渲染器——
4 条消息气泡（父背景 2 条 + 子任务提问 + 结论）、2 张工具卡（多轮循环的两次 echo，
带 ✓ 成功徽标与可折叠结果）、1 个种子边界标注、1 条任务描述开场；Esc/按钮可关。

**CLI 路径**（您可直接实测——真 LLM）：

```
mvn -pl duo-harness-example -am compile exec:java \
  -Dexec.mainClass=dev.duo.harness.example.DuoMain \
  -Dexec.args="duo-harness-example/target/classes/subagent-demo.yml"
```

装配实测通过（插件树启动、五件工具注册）。试探话术：
"用 spawn 派一个 researcher 模板的子代理去调研 X"、"用 list_agents 看看状态"、
"给那个子代理发条消息让它改用方案 B"。应看到 `[子任务] 已派生子代理 …（模板 researcher），后台运行中`
与 `[子任务] 子代理 … 已完成` + 最终回答两行。

**Demo 路径（loop 能力实证）**：

```
mvn -pl duo-harness-example -am compile exec:java \
  -Dexec.mainClass=dev.duo.harness.example.subagent.SubagentDemoMain
```

应出现子代理三轮循环证据：

```
  [子代理] 第 1 轮：调工具探路
  [子代理] 第 2 轮：看到结果，继续调工具深挖（循环未结束——与主 agent 同一套迭代机制）
  [子代理] 第 3 轮：信息足够，给出最终回答收尾循环
[子会话] 事件链（子代理自身的多轮循环全程落档）：
  [1] tool/call：{"text":"第一步探索"}
  [2] tool/result：echo:第一步探索
  [3] tool/call：{"text":"第二步深挖"}
  [4] tool/result：echo:第二步深挖
  [5] assistant/message：调研结论：X 可行，建议按方案 A 推进。
```

**测试路径**（`mvn test`）：SubagentPluginTest 3 用例、CliPluginTest 8 用例（含子任务过程行）、WebFaceTest 38 用例（含回放端点）、SubagentManagerTest 11、SessionTest 37。

## 验收记录（2026-09-17，用户 CLI 三层递进实测）

1. **小任务**（读两份 pom 总结依赖）：子代理几轮内交付带行号证据的完整报告，范围严格自守（主动标注"其余 7 个模块未在本次范围"）；`[上下文治理]` 刷屏消失（P4）。
2. **大任务**（调研全部模块）：父 agent 先 ask_user 确认产出方式、bash 统计模块规模，然后**自行按"边界清晰的小块"拆成 4 个 researcher 并行派发**（措辞与 SpawnTool 描述引导一致——描述层引导生效的铁证）；4 个子代理真并行（并发注册表实测）。
3. **未完成回流**：4 个子代理达 40 轮上限，父会话收到"已达迭代上限 + 已完成的中间成果（工具调用清单摘要 + 末次结果摘录）+ 完整摘要见子会话文件"的新形态回流（修复③ + P3 生效），成果不再丢失。

两个非缺陷观察：模块级调研对单个子代理仍偏大（使用粒度可再细，机制已全部按设计工作）；小报告开头混入一句模型独白（模型行为，基线已有"结论即交付物"约束）。
