# M36（1.2.0）呈现层——主题 token 体系、暗色精品主题与卡片声明式模板

Status: ready-for-agent

裁定与版图见 [ADR-0038](../../docs/adr/0038-M36呈现层立项决策.md)（立项细化 [ADR-0037](../../docs/adr/0037-M35M36插件生态化立项决策.md) 决策四）；术语（主题令牌 / 主题包 / 呈现贡献口 / 展示卡 / 交互卡 / 内核独占面）以[术语表](../../docs/05-参考/术语表.md)为准。

## Problem Statement

- **不好看**：Web 页面"功能及格、视觉不及格"（M35-06 验收用户原话"挺丑"）——三档债务在案：鉴权关闭横幅红块叠压会话侧栏、宽视口三列布局塌陷（会话/状态面板堆叠左下、主区大空白）、插件中心抽屉表单堆形态（裸表格/原生对话框）；高亮配色是亮色 GitHub 主题、与暗色基调混杂。
- **换不了肤**：颜色/间距/字号没有完整变量化——`theme.css` 虽有 19 个 token 的 `:root` 块（头注释立约"只增不改名"），但 `:root` 之外还有约 20 处硬编码色值加 JS 内联样式；想换一套视觉等于全文件翻改。「呈现层可被插件改写」的换肤半边没有兑现。
- **卡片长相写死**：工具卡片分型是前端 if/else 工具名链，工具名散布约 20 处、跨 5 类用途；新工具在 Web 无呈现路径（扩展点清单在案登记），第三方想替换某工具的卡片长相没有任何通道。
- **语义靠猜**：前端判工具成败与审批结果靠嗅探后端中文文案——三处魔法串（`deny` 前缀、`执行被拒绝|执行失败` 正则、`已获批准` 包含判定）横跨 agent/tools/web 三模块；后端改文案，前端静默错判。

## Solution

三块一体（ADR-0038 范围裁定）：**定语言 → 开换肤 → 模板化 → 收语义**。

1. **定语言**：token 名零变更，`:root` 缺省值切为暗色精品（开发者工具精致风：低饱和深底 + 单一强调色 + 细边框 + 适度留白）；`:root` 外硬编码全部收编为新 token；三档视觉债务与插件中心精修随 token 化一次修；高亮配色换暗色配套。
2. **开换肤**：主题包 = 插件包形态之一，内含一份 token 值集声明；经装前点名装载、装上即入主题列表、切换即时生效、停/卸回落内置暗色。改值不改构——第三方改得了所有变量值，注入不了任意样式规则。
3. **模板化**：前端 if/else 分型链改为声明式注册表（内核为全部内置工具注册全量表）；第三方插件经呈现贡献口贡献/替换展示卡声明——先到先得、冲突点名拒绝、卸了再装即替换。交互卡（审批/提问/计划）留内核独占。
4. **收语义**：事件载荷补结构化枚举字段（纯新增、1.x 兼容内），前端改读字段、退役三处文案嗅探——「工具名协议化渲染」销账完整闭合。

## User Stories

1. As a duo 使用者, I want 打开页面默认即是打磨到位的暗色主题, so that 视觉与开发者工具审美一致、不再是"功能及格视觉不及格".
2. As a duo 使用者, I want 在状态面板的主题选择器里切换主题且即时生效, so that 试主题不用重启进程或刷新丢状态.
3. As a duo 使用者, I want 我选的主题被记住（刷新、重开浏览器仍保持）, so that 不必每次重选.
4. As a duo 使用者, I want 停用或卸载正在使用的主题插件后页面自动回落内置暗色, so that 页面永不裸奔.
5. As a duo 使用者, I want 鉴权关闭横幅不再叠压侧栏且形态与整体视觉一致, so that 警示可见但不糊脸.
6. As a duo 使用者, I want 宽视口下三列布局不塌陷、主对话区不空置, so that 大屏不浪费、窄屏不堆叠.
7. As a duo 使用者, I want 插件中心的安装/改配置是卡内表单交互而非原生弹窗, so that 流程流畅可信、与整体视觉一致.
8. As a duo 使用者, I want 代码块高亮配色与页面主题一体, so that 阅读代码不再被亮色块突兀打断.
9. As a duo 使用者, I want 换主题或装主题插件后审批/提问/计划卡的可信观感与交互语义不变, so that 安全交互面不被第三方视觉干扰.
10. As a 主题作者, I want 交付一个主题 = 做一个常规插件包（fat-jar）内含 token 值集声明, so that 零新概念——会做插件就会做主题.
11. As a 主题作者, I want 装前点名校出示我的主题名与来源包信息（路径/大小/sha256）, so that 安装者知情后才装.
12. As a 主题作者, I want 我的声明只能改变量值、触不到布局结构与交互语义, so that 责任边界清晰、出问题不背锅.
13. As a 主题作者, I want 内置暗色主题作为参照系（token 分组结构与配套高亮映射在案）, so that 照抄结构就能调出自己的主题.
14. As a 插件作者, I want 为我的工具注册展示卡声明（图标/名称/参数摘要/卡片形态）, so that 我的工具呈现贴合数据形态而不是挤进通用卡.
15. As a 插件作者, I want 替换某工具的默认展示卡（先到先得、卸了再装）, so that "哪个插件不如意就换上自己的"在呈现面兑现.
16. As a 插件作者, I want 我的声明与已注册工具名冲突时被点名拒绝, so that 替换结果可预期、不搞后装覆盖的玄学.
17. As a 插件作者, I want 我的卡片声明触不到审批/提问/计划交互卡, so that 没人能误解我在改安全语义.
18. As a duo 使用者, I want 前端判定工具成败与审批结果基于结构化事件字段, so that 后端文案演进不会让页面静默错判.
19. As a duo 使用者, I want 主题与卡片声明数据一律经内核鉴权栅栏与序列化白名单下发, so that 插件没有任意样式/脚本注入面.
20. As a duo 使用者, I want token 值经格式校验（颜色/尺寸字面量）, so that 恶意值（如 url 型函数值）进不了样式面.
21. As a 排障者, I want 「页面为什么长这样」只看两个来源（`:root` 内置值 + 所选主题值集）, so that 样式排障不翻全文件.
22. As a 排障者, I want 主题/卡片声明注册失败被点名（名称/冲突方/原因）, so that 坏声明在装配期暴露而非运行期半死.
23. As a 验收者, I want 端到端走通"拿到主题包 → 放目录 → 页面点名 → 装 → 主题列表出现 → 切换生效 → 卸载回落", so that 全程不重启、可演示.
24. As a 验收者, I want token 值应用后有关键页面截图对照裁定, so that "精品"有共同裁定物而非各说各话.

## Implementation Decisions

**裁定来源**：以下全部锚定 ADR-0038（grill Q1-Q8 用户裁定），本 spec 只做工程化落钉；缝勾稿与三项落钉已出示（见 Further Notes）。

- **呈现贡献口**：WebPlugin 发布 camelCase 服务 `presentationRegistry`（SERVICE_NAME 与视图接口方法名逐字一致，先例 `pluginCenter`/`webRoutes`），两类注册——主题（主题名 → token 值集）与展示卡（工具名 → 卡片声明）。申请制 + 同名冲突点名拒绝（对齐 `webRoutes` claim 哲学）；注册器挂提供方作用域，拔除即注销（对齐 claim 移除器先例）。无 Web 部署下消费方 `optionalInject` 优雅缺席——**声明必须显式**（M34 三盲教训：hasService 真 ≠ 可读）。
- **内核聚合端点**（`/api` 内核面，非贡献端点通道）：下发主题清单与所选主题值集、卡片声明聚合表。插件数据一律经内核序列化下发——插件没有直达前端的注入通道，这是「改值不改构」安全模型的落地面。鉴权栅栏全覆盖 + 异常 500 兜底铁律照旧（无 token 403、`auth: none` 行为一致）。
- **token 值格式校验**：值集声明经颜色/长度/字号字面量白名单校验，函数值（url 等）拒收——CSS 自定义属性值带不进选择器但带得进 `url()`，白名单堵这个面。
- **token 体系**：现有 19 token 名零变更（「只增不改名」契约延续，锚点是名不是值）；`:root` 缺省值切暗色精品（原亮色值集留作后续亮色主题素材）；`:root` 外硬编码与 JS 内联样式收编为新 token（扫光动画、子代理八色、diff 红绿、状态色、抽屉阴影、横幅 danger）；token 按 底色阶/文本阶/品牌阶/语义色/几何/字体 分组注释组织；`theme.css` 头注释契约同步改写（名不变 + 缺省值随内置主题走）。
- **前端主题机制**：启动拉聚合端点 → 按 localStorage 所选主题（键名对齐既有前缀形态；跨标签一致——鉴权令牌先例，非 tabId 的 sessionStorage 隔离语义）把值集套到根元素；切换即时生效并持久化；主题插件停/卸 → 服务随作用域消失 → 前端回落内置暗色。切换入口放状态面板（插件中心入口同区先例）。
- **卡片声明式注册表**：render IIFE 边界开注册口（M29 边界纪律：上提或经返回面暴露，机械核对引用作用域）；内核为全部内置工具注册全量声明（图标/中文名/参数摘要/卡片形态），分型 if/else 链改表驱动；ask_user / exit_plan_mode / todo_write 等交互卡与特殊渲染路径留内核硬编码——独占面裁定不改前端结构。
- **魔法串收敛**：事件载荷纯新增——tool/result 补 status 枚举（ok / denied / failed：拒绝语义由审批管线注入、计划批准语义由工具结果注入）、approval/decided 补 decision + source 枚举字段；SSE 事件与 headless NDJSON 帧同源对齐；旧文案字段保留（1.x 向后兼容承诺内），CLI 侧 `deny` 前缀耦合断言不动。[会话事件类型表](../../docs/05-参考/会话事件类型表.md) 与 NDJSON 契约文档同 diff 更新。
- **视觉债务三档与插件中心精修**随对应工单落：鉴权横幅改 CSS 类 + token 化（退役 JS 内联样式）、三列布局响应式修法（固定像素列宽改弹性口径）、抽屉向导改卡内表单（原生 prompt/confirm 退役）。
- **高亮配色**：高亮主题随内置暗色主题配套更换（整文件替换或 token 映射属工单细节）；第三方主题不自带高亮文件，选内置配套或映射语义色。
- **文档义务**：主题包与卡片声明的交货文档（M35 插件包交货文档续章）；已知限制页补「主题只能改 token 值不能改布局」「交互卡独占」条目；扩展点清单「前端渲染」行兑现更新 + 呈现贡献口增补；术语表五词条已入册（立项 diff 已落）。
- **时序风险落钉**：主题/卡片插件行依赖 `presentationRegistry` 而 WebPlugin 行在其后时，Boot 启动审计的口径对齐 pluginRows 先例（M35 工单 05：发布时机前置或可选依赖不判败），实现期验证并留回归。

## Testing Decisions

- **只测外部行为**：注册后在聚合端点可见、切换后值集生效、冲突被点名、事件字段在载荷中——不测注册表内部结构与私有协作。
- **四缝复用，唯一新缝是 `presentationRegistry` 服务面（归装配缝覆盖）**：
  - **S1 插件装配缝**：主题/卡片插件以插件形态入树测，含声明闸门断言（`optionalInject` 声明在案才可读）与 SERVICE_NAME/视图方法名逐字一致核对。先例：`WebPluginAssemblyTest` 形态（M34 三盲教训——root 上下文测不出声明闸门）。
  - **S2 Web HTTP 缝**：聚合端点装配后实测（主题清单/值集/卡片声明表），鉴权负路径（无 token 403 fail-closed、`auth: none` 一致）、同名冲突 400 点名、处理器异常 500 兜底。先例：`WebRouteContributionTest`、`WebFaceAuthTest`。
  - **S3 事件缝**：tool/result status 与 approval/decided decision/source 字段发射断言（含计划批准 → denied 语义、审批 allow/deny 映射）；旧文案不断言删除（兼容承诺）。先例：既有事件发射测试；`CliPluginTest` 的 deny 前缀断言保持不动即兼容锁。
  - **S4 浏览器视觉缝**：默认暗色、切主题即时生效与持久化、卸载回落、卡片分型按声明渲染、横幅/三列/抽屉三档债务修复——红线 5，M33 百例实测形态执行，不进 CI 常态。
- **回归锁纪律**：服务消费方声明闸门用例必备（M34 经验）；断言插件异常沿 cause 链收集（M27 经验）；前端验证以真实页面首载为准、`node --check` 语法绿不算数（M29 经验）；验收件成文后作者先自跑全流程并留证据（M35-09 判据）。

## Out of Scope

- **插件自带页面/静态资源服务、整页替换**——呈现层开放的后续台阶，ADR-0037 拒绝项维持，后续期另立项。
- **亮色/多套内置主题**——单暗色精品裁定；亮色值集留第三方主题或后期内置（token 集与值分离，零结构成本）。
- **CSS 文件注入式主题、白名单附加 CSS 段**——ADR-0038 拒绝项（任意样式注入面 vs fail-closed）。
- **查阅组卡嵌套（事件流分组投影）**——backlog 另案，视观感再立项。
- **交互卡（审批/提问/计划）模板化**——内核独占面裁定（改得了长相，改不了交互语义）。
- **明暗自动切换（`prefers-color-scheme` 联动）**——单主题期无切换对象，留主题选择器演进。
- **主题市场/策展/签名验签/兼容校验**——信任模型后补机制；sha256 仅作点名展示不作信任锚。
- **后装覆盖式替换语义**——先到先得 + 卸了再装已裁。

## Further Notes

- **缝勾稿与三项落钉已出示待核**：presentationRegistry 单服务方案、主题切换入口（状态面板 + localStorage）、token 名零变更缺省值切暗、高亮配套更换——本轮用户未及逐项回复，按推荐落盘；spec 评审与各工单验收均可调整，调整不触 ADR 裁定面。
- **token 值格式校验是安全补钉而非新裁定**：ADR-0038「改值不改构」的攻击面落实——CSS 自定义属性带不进选择器但带得进 `url()`，白名单堵的就是这个缝。
- **Boot 审计时序是实现期头号风险**：依赖 `presentationRegistry` 的行与 WebPlugin 行的装载序、启动审计 PENDING 判定口径，pluginRows 先例（M35 工单 05）在案，工单实现首日先验证。
- **版本分支**：`1.2.0` 于工单开拆、实施启动时自 main 切出（红线 7；ADR-0038 Consequences 在案）。
- **验收口径预告**：done = 用户手动运行验收件确认（duo-acceptance 流程）；端到端叙事 = "拿到主题包 → 放目录 → 页面点名 → 装 → 主题列表出现 → 切换生效 → 卸载回落"全程不重启 + 卡片声明替换演示 + 魔法串退役抽查（后端改文案，页面不再误判）。
