# 07: WebFace 拆分与结构化协议

## What to build

WebFace 从 777 行巨类收敛：注册方法退化为路由表、每个端点独立 handler 方法、响应写入统一 helper。`/api/answer` 切结构化协议——审批回答 `{decision: "approve"|"reject"}` 与自由文本答案分离，前端三件与后端同 diff 直接切换、不留兼容层；用户在提问卡自由输入"拒绝"二字按普通回答传递，不再被误判为审批拒绝（隐式字符串协议根治）。

### 用户验收对照表（2026-09-17 备；agent 已实测，用户可复跑）

**准备**（一条命令起双入口；浏览器开 http://127.0.0.1:18080）

```
./mvnw -q -pl duo-harness-example -am package -DskipTests exec:java -Dexec.mainClass=dev.duo.harness.example.agentrepl.AgentReplMain
```

**验收 1：计划呈交卡**（CLI 发起、Web 卡片作答——行序路由；轻任务避免探索超预算）

- 在跑演示的**终端**输入：`/plan 设计一个两步的早餐清单（不需要探索仓库），直接调用 exit_plan_mode 呈交`
- 应出现：浏览器渲染「[计划呈交]」卡片（计划全文 + 反馈输入框 + 批准/打回按钮）
- 反馈框写"把第二步拆细"→ 点**打回**：卡片冻结为 `✗ 计划未获批准`；终端可见模型按反馈继续修改
- 再次呈交 → 点**批准**：卡片冻结为 `✓ 计划已获批准`；模型开始执行
- 注：真实仓库级设计任务（需连读多份文档）请先在 yml 给 web/cli 配 `maxIterations: 30`（BUG-20260917-03）

**验收 2：Enter 发送无回归**

- 输入框打字 → 回车：消息气泡出现（SSE 渲染）、**输入框清空**、发送按钮转"思考中…"

**验收 3（可选复跑）：审批卡两态**

- 输入"请用 bash 执行 echo hello" → 审批卡 → **批准**：工具卡显示输出与退出码
- 再触发一次 → **拒绝**：模型回答含"工具调用被人工拒绝"
