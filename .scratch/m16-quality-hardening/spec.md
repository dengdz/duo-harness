# M16 质量与安全加固 spec

Status: ready-for-agent（2026-09-17 grill 十题落定 + 侦查事实支撑；路线图见 ADR-0016，技能可见性裁定见 ADR-0017）

## Problem Statement

M15（0.10.0）发布后，457 个用例只在本机执行——push/PR 无回归防线，换机器或协作者时质量基线不可复制。同时双轴质量审查与 M15 验收暴露一批具体伤口：浏览器里任意网页可向本机 Web 面发跨站 POST 驱动 agent（无 Host/Origin 校验，DNS rebinding 可绕）；子代理调用需审批工具（如 bash）会真的挂起等应答；provider 半开连接会永久挂死 agent 循环（CLI 卡死、Web 单飞标志永久 busy）；进程崩溃恰好停在工具调用与结果之间时，该会话永久无法续聊；诊断信息以无级别 stdout 散落三个模块，无法关断；WebFace 777 行巨类、8 个端点内联一个方法，审批按钮靠自然语言"拒绝"作前后端协议；README 停在 8 个版本前；子代理的审批、环境、知识边界各有一笔挂账。

## Solution

一个不添新功能的加固期（ADR-0016）：把质量审查 Top 10 与子代理安全小改清账。建成 Java CI 门禁（push/PR 即回归）；Web 面入口两级栅栏封死跨站与 DNS rebinding；子代理审批钉死为确定性拒绝 + 理由回传；LLM 流式加空闲超时；会话崩溃后自动补齐断口；日志统一 SLF4J；WebFace 拆分并切结构化回答协议；README 补账；子代理技能可见性裁定立卷（ADR-0017）。每件事都可独立验收，CI 绿从此是每期收官的固定验收件。

## User Stories

1. 作为协作者，我 push 代码或开 PR 时 CI 自动跑全量构建与测试，所以回归在我看到之前就被拦下。
2. 作为在新机器上接手的开发者，我克隆仓库后用 `./mvnw` 即可构建，所以不再依赖本机是否装了正确版本的 Maven。
3. 作为浏览器用户，我正常访问 127.0.0.1 的 Web 面发消息、点审批卡一切照旧，所以栅栏对我不可感知。
4. 作为浏览器用户，我误开的恶意网页无法驱动本机 agent 执行工具或伪造审批作答，所以我的 agent 不会被跨站请求劫持。
5. 作为用 curl 调试本地 API 的开发者，我不带 Origin 头的请求照常工作，所以脚本化使用不受栅栏影响。
6. 作为部署者，我给子代理模板配置了含 bash 的工具清单也不怕——子代理调用时收到明确的确定性拒绝与理由，所以子任务不会静默挂起。
7. 作为父 agent，我的子代理被拒绝需审批操作时会在最终回答里说明该限制，所以我能接管这一步而不是等一个永不返回的调用。
8. 作为 CLI 用户，provider 半开连接断流时最多等 90 秒就拿到可重试错误，所以终端不再永久挂死。
9. 作为 Web 用户，断流发生后页面单飞标志会恢复，所以我可以重新发消息而不是刷新页面。
10. 作为思考模型用户，模型长思考间隔（超 60 秒）不会被误判为断流，所以默认超时对我安全。
11. 作为用户，我的进程在工具执行中途崩溃后重新打开该会话，日志自动补上一条"结果未知"的合成闭合，所以会话可以继续聊而不是每次发消息都协议报错。
12. 作为用户，打开经历中断的会话时我能从日志里看到"这里发生过中断"，所以历史是可信的。
13. 作为排障的开发者，我把日志级别调到 debug 就能看到连接与生命周期诊断，所以不用翻 stdout 洗刷屏。
14. 作为 REPL 用户，终端里的对话流、提示符与审批卡保持原样，所以日志化改造不改变我的交互体验。
15. 作为二次开发的开发者，WebFace 的每个端点是独立 handler 方法、响应写入走统一 helper，所以我加端点不用在 333 行方法里找位置。
16. 作为前端开发者，我发出的审批回答是结构化 decision 字段，所以后端判定不再取决于用户是否恰好输入了"拒绝"二字。
17. 作为提问卡用户，我在自由文本里输入"拒绝"两个字会被当作我的回答原样传给模型，而不是被误判为审批拒绝。
18. 作为评估者，我打开 README 看到的模块表、版本与能力清单与 CHANGELOG 一致，所以第一印象不失真。
19. 作为部署者，我在子代理模板里声明 withSkills / withAgentsMd 就能让子代理看见技能名录或项目约定（裁定已立卷，实现归后续期），所以知识下发的裁量权在我手里。
20. 作为维护者，subagent 包按功能边界拆成子包，所以 15 类的包不再超出结构标准阈值。
21. 作为维护者，测试进程被强杀后不再累积僵尸子进程，所以长期开发的机器不劣化。

## Implementation Decisions

**范围与切分**：十一件按域细切为工单 01-11（颗粒度裁定：方案甲），实施序 01 CI → 06 日志 → 07 WebFace → 02 栅栏 → 03 钉死 → 04 环境块 → 05 idle 超时 → 08 崩溃恢复 → 09 小杂件 → 10 文档裁定 → 11 收官。`0.11.0` 版本分支从 main 切出为里程碑第一步。

**CI 门禁（01）**：新 workflow——触发 push（main + `0.*` 版本分支）与全部 PR；单 JDK 21；步骤为 `mvn -B verify`；Maven wrapper（mvnw）入库。不做 JaCoCo 覆盖率报告（门槛另议）。

**入口栅栏（02）**：两级校验——所有请求 Host 头必须在 `{127.0.0.1:<port>, localhost:<port>, [::1]:port}`（封死 DNS rebinding）；POST 类写端点额外校验 Origin 为空（本地工具）或同源，非空且不同源返回 403。GET/SSE 不校验 Origin（无副作用，Host 已兜底）。不做配置化白名单——未来 bind 配置化时白名单随 bind 派生。

**子代理审批钉死（03）**：目标语义为"需审批调用确定性拒绝 + 理由回传"（DSH 恒 never 形态）。落点：子代理装配处注入恒否策略对象，子代理工具视图在委托前对声明了 requiresApproval 的工具按该策略产出标准格式拒绝文本（附"该步骤交回父代理处理"指引）；拒绝作为工具结果回填子代理上下文。不改动工具域公共 API（拒绝裁决下沉管线的方案因侵入度否决）；交互工具本已被模板过滤，不在范围。

**子代理环境块（04）**：子代理 system 追加环境段（工作目录、操作系统平台、当前时间），任务描述不改；父 agent 呈现位顺路补时间上下文片段（同源事实，DSH time-context 对照）。

**LLM 流式空闲超时（05）**：连续 N 秒无新字节判流死——缺省 90 秒，`llm.streamIdleTimeoutSeconds` 可配且不配置也生效。与重试二分：尚未交付任何 chunk 的超时按可重试错误走既有重试链；已交付增量后的超时终止本轮并保留已输出文本（对齐"已交付不重试"的既有流式安全语义）。落点为响应体流的包装委托（单点覆盖直答与工具轮两条读取路径），不改两处逐行循环。

**日志统一（06）**：五模块补 slf4j-api 依赖（根 pom 已统一版本，属版本对齐补齐而非新依赖，经用户裁定）。迁移边界："给人看的"留 stdout（REPL 对话流与提示符、终端审批提问卡、`[子任务]` 过程行、demo 叙事、Web 启动横幅）；"给排障的"转 slf4j（Web 异常与连接诊断、标题生成降级、agent 域诊断；治理日志已由既有开关管理，不动）。example 演示叙事不迁移。

**WebFace 拆分与结构化协议（07）**：端点各自拆为私有 handler 方法、响应写入提取统一 helper、注册方法退化为路由表；`/api/answer` 请求体改结构化字段——审批回答 `{decision: "approve"|"reject"}` 与自由文本答案分离，前端三件与后端同 diff 直接切换、不留兼容层（根治自由输入"拒绝"误判）。

**会话崩溃恢复（08）**：打开会话取得锁后，探测日志尾部未闭合的工具调用事件，追加一条合成 tool/result（文本注明"结果因进程中断未知，只可重试只读/幂等操作"）后再建快照。日志自包含、投影零特判；子代理会话走同一加载路径自然受益。

**小杂件清账（09）**：两处 javadoc 错位归位；热路径 ObjectMapper 提为共享常量；两处全量读文件改逐行流式（标题探测找到即停）；子代理包按功能边界拆子包；测试进程收割兜底（子进程 shutdown hook 与 REPL 线程退出路径，backlog 挂账项）。

**文档与裁定（10）**：README 版本口径、模块表补 cli 行、能力清单补治理/权限/分页/子代理；技能可见性裁定已立卷 ADR-0017（模板 opt-in：withSkills / withAgentsMd 缺省 false，技能名录不带全文、AGENTS.md 沿用 64KB 预算），本工单只做文档联动与 limitations 指针对账。

**收官（11）**：CHANGELOG 0.11.0 段同 diff 记账、limitations 全清单终审、全量对账与验收件。

## Testing Decisions

只测外部行为，不测实现细节；全部用既有 seam，不建新 seam。

- **会话域**：`Session` 公共 API seam（既有 SessionTest 先例）——构造"工具调用后无结果"的日志文件，load 后断言合成闭合存在且投影出合法消息序列；孤儿结果、正常会话不受扰动。
- **Web 面**：HTTP 交换层 seam（既有 WebFaceTest 先例）——伪造 Host/Origin 头断言 403/放行矩阵；`/api/answer` 新协议的判定与误判用例；栅栏对 GET/SSE 与静态资源不误伤。
- **LLM 域**：适配器 seam（本地桩服务先例）——桩服务发响应头后停发字节，断言 90s 超时抛可重试错误；已交付增量场景断言不重试且已输出保留；短思考间隔（模拟 60s 停顿）不断流。
- **子代理**：管理器与端到端 seam（既有 SubagentManagerTest / SubagentEndToEndTest 先例，门闩控速的桩后端）——需审批工具调用收到标准拒绝文本且循环继续；模板过滤交互工具的既有断言不回归。
- **CLI**：插件 seam（既有 CliPluginTest 先例）——日志迁移后交互输出仍走标准输出流。
- **CI**：workflow 本身无单测 seam，以 push 后工作流绿为验收（0.11.0 分支上即生效）。
