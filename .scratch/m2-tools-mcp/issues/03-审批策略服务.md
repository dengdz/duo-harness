# 03 — 审批策略服务（ask 三态）

## What to build

工具执行的审批语义：pre-execute 的决策从两态扩为三态（allow / deny / **ask**）——治理插件或工具可声明"此调用需要审批"；`ask` 委托**审批策略服务**裁决。M2 交付两个预设策略：`always-deny`（默认，未配置即拒，错误结果注明"被审批策略拒绝"）与 `auto-approve`（按配置白名单放行）。审批决策（决策结果 + 策略来源）有日志可查（安全审计）。MCP 工具与本 地工具走同一审批路径——审批策略一旦配置，远端工具的调用同样被治理。完成的判据：配置 always-deny 后工具调用返回带策略来源的错误结果；切 auto-approve + 白名单后放行；决策日志可查（接缝 B）。

## 实施记录

### 协作机制：事件总线，不是服务读取

策略解析者是 `tools/pre-execute` 监听器（审批插件注册），工具域只消费
`ToolExecution` 上的解析结果。工具域对审批零硬依赖——若改为读审批服务，要么
撞内核 inject 纪律（未声明即拒读），要么声明 inject 后工具域在无审批插件时
永久 PENDING（审批是可选治理件）。监听器表全树共享、无需 inject，是内核既定的
跨插件可选协作机制。

### 声明与裁决分离（三态的落点）

| 阶段 | 承担者 | 动作 |
|---|---|---|
| 声明 | 工具（`ToolDefinition.requiresApproval()`）或治理插件（pre-execute 监听器 `exec.requestApproval()`） | 只置位，不裁决 |
| 裁决 | 审批策略插件的解析监听器 | `next.invoke` 先行（内层否决与声明先落定）→ 仅当已声明 ask 才 `exec.resolveApproval(policy.decide(...))` |
| 消费 | `ToolsServiceImpl` 一段 b | 记决策日志；DENY → error 结果（含策略来源）；未解析 → "未配置即拒" |

解析监听器以 around 语义（先 `next` 再裁决），因此与自身注册次序无关——
既能看到外层声明者的 ask，也能看到内层的否决。**策略只裁决被声明的 ask**，
不主动治理未声明的调用（"可声明"的语义）。

### 9 个用例

| 用例 | 覆盖 |
|---|---|
| alwaysDenyRejectsAndNamesPolicySource | 声明 ask + 配置即拒，错误结果含"被审批策略拒绝"+"always-deny" |
| autoApproveWhitelistsAndDeniesOutsiders | 白名单内放行、外拒绝（含"不在审批白名单"+"auto-approve"） |
| undeclaredCallIsNotGoverned | 未声明 ask 的调用不被审批介入 |
| toolDeclaredAskIsResolvedByPolicy | 工具自身声明 ask → 策略放行 |
| listenerDeclaredAskWithoutPolicyDefaultsDeny | 治理插件声明 ask 但无策略 → 默认拒（"审批策略未配置"/"none"） |
| approvalAppliesToMcpToolName | `mcp__<server>__<tool>` 名走同一审批路径 |
| directDenyShortCircuitsApproval | 监听器直接 deny → 审批段不执行（消息不含策略来源） |
| decisionIsLoggedForAudit | 捕获 stderr 断言决策日志含结果 + 策略来源 + 工具名 |
| policyIsPublishedAndConfigurableByYml | Boot.from(yml) 端到端：策略经视图寻址 + 白名单放行 |

### 配置形态

内核严格绑定要求 `config` 块在场（`configType()` 非 null 时缺配置即装载失败），
块内字段可省：`policy` 省略即 `always-deny`，`allowedTools` 省略即空集。

### 验收件：审批策略三幕演示

**一条命令**（在仓库根目录复制粘贴即跑，无需先 install）：

```bash
mvn -pl duo-harness-example -am package -DskipTests exec:java \
  -Dexec.mainClass=dev.duo.harness.example.approval.ApprovalDemoMain
```

IDEA 等价路径：打开 `duo-harness-example/src/main/java/dev/duo/harness/example/approval/ApprovalDemoMain.java`
→ main 方法旁绿色箭头 → Run。

**预期输出对照表**（`[审批决策]` 行由 SLF4J 打到标准错误，与标准输出交织在同一终端；逐行核对下表）：

| # | 应出现 | 含义 |
|---|---|---|
| 1 | `[第一幕] yml 配置 auto-approve + 白名单 [read_file]` | 配置路径：读 `approval-demo.yml` |
| 2 | `审批决策：工具=read_file 结果=ALLOW 策略=auto-approve` | 白名单内 → 放行（审计日志） |
| 3 | `read_file -> [放行] read_file 已执行` | 工具本体真的执行了 |
| 4 | `审批决策：工具=delete_file 结果=DENY 策略=auto-approve` | 白名单外 → 拒绝 |
| 5 | `delete_file -> [被拒] 工具 "delete_file" 执行被拒绝: 不在审批白名单（策略: auto-approve）` | 错误结果含策略来源 |
| 6 | `echo -> [放行] echo 已执行`（第一幕） | 未声明需审批 → 审批不介入 |
| 7 | `[第二幕] 编程 API 换策略为 always-deny：同一批工具全拒` | 策略可换 |
| 8 | `read_file -> [被拒] …被审批策略拒绝（策略: always-deny）` | 恒拒策略 |
| 9 | `delete_file -> [被拒] …被审批策略拒绝（策略: always-deny）` | 恒拒策略 |
| 10 | `echo -> [放行] echo 已执行`（第二幕） | 恒拒也不碰未声明的工具 |
| 11 | `[第三幕] 无审批插件：声明需审批的调用按"未配置即拒"处理，未声明的照常` | 边界：无策略解析者 |
| 12 | `read_file -> [被拒] 工具 "read_file" 执行被拒绝: 审批策略未配置（策略: none）` | 未配置即拒，来源署名 none |
| 13 | `echo -> [放行] echo 已执行`（第三幕） | 未声明工具照常可用 |
| 14 | `=== 三幕结束（整树均已回滚）===` | 收尾 |

**输出流约定**：`[审批决策]` 行是 SLF4J 打的审计日志（标准错误，立即刷）；
叙述行走标准输出，在幕末显式刷盘。因此两种环境下顺序都稳定为一幕一组
"决策日志 + 结果叙述"（IDE 控制台不刷标准输出时才会把同一幕拆到输出两端）。
