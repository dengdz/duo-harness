# duo-harness 里程碑规划（2026-09-15 基线）

> 规划基线：0.6.0 已发布（M11 CLI 插件化完成）。本文是 M12+ 的路线图——每期开工仍走各自流程（grill-with-docs → ADR → spec → 工单 → 实现 → 验收 → 收口），本文提供方向与优先级依据，不替代单期 ADR。
> 事实来源：本会话全量侦查（模块/实现/流程/审查发现）+ docs/limitations.md + .scratch/backlog.md + docs/research/DSH/（全景 + 源码精查）。

## 一、系统现状盘点（0.6.0）

### 1.1 模块与规模（10 模块，主代码 ~10.1K 行 / 166 类，测试 ~10.7K 行 / 291 用例）

### 1.2 运行流程（一条命令的完整链路）

```
DuoMain.main → Boot.from(agent-demo.yml)
  → 插件树按行序激活：tools → prompts → agents-md → skills → answers
    → approval → write-protector → repeat-reminder → web（持最新会话锁，18080）
    → cli（撞锁 → 提示 + 新建会话）
  → onRootCreated 回调：MCP files 沙箱挂载 + 演示提示片段
  → CountDownLatch 保活（Ctrl-C → hook 级联 dispose → 全部锁释放）
用户输入两路：
  终端 REPL（CliPlugin 虚拟线程）——/new /plan /技能名 /exit
  浏览器（WebFace SSE + POST）——对话/审批卡/提问卡/会话切换
执行：ChatAgent 工具循环 → 三段管线 + 审批 + guard → 结果回填 → 治理（spill→修剪→计量→compaction）
持久：Session.append 单写 JSONL（独占锁内）；消费：deriveMessages 投影 + SSE 游标回放
```

### 1.3 能力清单（已达成）

事件溯源会话（独占锁 + 多轮投影）、工具循环（Function Calling + 审批 y/n + ask_user + 计划模式）、技能三路触发、AGENTS.md 注入、治理四件套（spill/修剪/计量/compaction，真实 usage 优先）、Web 双面（对话/状态/HITL 卡/MD 渲染/占用可视化/SSE 增量回放/刷新不误杀/安全加固）、CLI 插件化（idle 语义/DuoMain）、双开互拒。

## 二、不足与风险清单

### 2.4 DSH 对照小结（差距与衔接点）

**已追平**：agent 循环/流式/工具循环、审批 seam（ask/never+fail-closed）、ask_user、计划模式、技能三路、AGENTS.md 注入、llm-retry、治理四件套（spill/修剪/计量/compaction）、Web 双面、**独占会话锁**（DSH 用 flock，我们 M10-03 FileLock——同语义）、**呈现位插件化**（DSH bundle 思路的对称实现）。

**差距（按衔接难度）**：
- **直接可衔接**（我们的机制已有落点）：尾部窗口分页（journal-stream 范式，backlog 已记）、斜杠命令注册表（我们已有 commands 语义缺位）、权限预设（审批策略已备）、steering（answers seam 可延展）、设置体系（服务注入模式同构）
- **需新建域**：本机 fs 工具族（DSH 最大生产力来源，含 workspace 约束）、subagent（控制面 + 后端抽象）、hooks（配置映射层）、附件（内容寻址存储）、web_search（外部依赖）
- **DSH 也承认的限制**（不必自卑）：无终端 REPL（我们反而有——M11 后是差异化优势）、无永久放行、MCP 仅桥接 tools

## 三、里程碑规划（M12-M16 + 远期池）

> 排序原则：① 生产力跃升优先（工具族）② 用户体验债随用随清（会话体验）③ 结构债在能力膨胀前清偿（拆包/性能）④ 生态扩展在后。每期开工走完整流程（grill → ADR → spec → 工单 → 实现 → 双轴审查 → 验收 → 收口），且开工前清理解关卡欠账。

### M12：本机工具族与权限预设（能力跃升，★★★）

- **目标**：agent 从"MCP 沙箱演示"升级为"可真实操作用户项目"——workspace 约束的 fs 工具族 + 命令执行 + 三档权限预设打包
- **任务**（草案，grill 细化）：
  1. workspace 概念 ADR（cwd 绑定 + 路径约束边界；与 M10-03 会话锁的关系）
  2. fs 工具族：read / write / edit（精确替换）/ glob / grep（workspace 内）
  3. bash 工具（沙箱模式挂钩：workspace-write 档约束可写范围）
  4. 权限预设插件：read-only / workspace-write（默认）/ danger-full-access 三档 + 审批联动（ask 策略沿用）
  5. 呈现适配：Web/CLI 的工具卡与审批卡对新工具零特化（元数据驱动起步，收 S5 前置）
- **预期产出**：新工具入工具目录对账测试、ADR（workspace+预设）、三档切换演示、全量绿
- **验收标准**：agent 能在 workspace 内完成"读→改→检索→执行"真实任务闭环；越界写被拒；三档切换行为正确；审批按档联动；全量测试绿
- **风险**：bash 沙箱边界（workspace-write 档）需 grill 细化；Windows 兼容暂不承诺

### M13：会话体验（大会话范式，★★）

- **目标**：DSH journal-stream 范式落地——大会话（80K+ token）刷新/切换秒级、历史可翻、占用可见
- **任务**：新 ADR（尾部窗口快照 + 向上分页，取代 ADR-0010 的首连全量）→ 服务端分页参数（`maxMessages` + `hasMore`）→ 前端尾窗渲染 + 向上加载 UI → 会话切换无刷新（消 location.reload）→ 侧栏被占会话标注 → 治理阈值 yml 化 + /compact（backlog 清账）
- **预期产出**：新 ADR、分页协议、前端分页 UI、占用标注、阈值配置化
- **验收标准**：80K token 会话刷新 < 2s；向上分页连续性校验（缺口修复语义）；切换无刷新；阈值热可读
- **风险**：分页与治理折叠（compaction 改写日志下标）的游标对齐——ADR 重点

### M14：结构治理与性能（技术债清偿，★★）

- **目标**：agent 拆包 + 事件快照性能 + 测试密闭化 + 流程欠账清零——为 subagent/生态期打地基
- **任务**：agent 按域拆包（governance / skills / plan / presenter / loop）+ `events()` 快照策略优化（差量或版本化）+ 装配测试密闭化（LlmConfig 注入 TempDir）+ limitations 收编定稿（M7-M11 段 + M9-M11 补录）+ 理解关卡清零（M3-M11）
- **预期产出**：拆包后模块图、性能基准（大会话投影/回放耗时）、密闭测试、limitations 定稿
- **验收标准**：duo-project-structure 审查通过、80K 会话投影耗时可测且达标、全量绿、零"未发布"陈旧段
- **风险**：拆包波及 import 面——纯机械重构 + 全量回归兜底

### M15：subagent（能力扩展，★）

- **目标**：任务分解——spawn（全新）/ fork（父历史播种）+ 控制面（send_message / interrupt / list）
- **任务**：subagent 域 ADR（后端抽象：先只做同进程内嵌 agent）→ spawn/fork 语义与 KV-cache 取舍 → 控制面工具三件 → 呈现（子 agent 过程卡）→ 测试
- **预期产出**：subagent 模块或 agent 域扩展、控制面工具、呈现适配
- **验收标准**：父 agent 能分解任务给子 agent 并聚合结果；中断/列表可用；全程事件可审计
- **风险**：会话与锁语义（子 agent 会话归属）、嵌套深度控制——grill 重点

### M16：扩展生态（★）

- **目标**：hooks 兼容（Claude Code 配置映射到 tools/pre-execute 等内部扩展点）+ 斜杠命令注册表（F6）+ 设置体系（F7）
- **验收标准**：外部 hooks 配置可映射生效（exit 2 阻断语义）；/compact 等迁入注册表；设置分层解析

### 远期池（不排期，按需求拉动）

附件（F8）、web_search/fetch（F3）、run_code PTC、声明式 agent、goal/todo/schedule/jobs（F12）、会话查询/导出（F9）、steering（F10）、并行工具调用（F11）、鉴权+局域网（F14）、多 provider 原生适配（R5）、侧栏分页范式前端深化（S5）

## 四、优先级依据与里程碑关系总览

```
生产力： M12 工具族+预设 ──→ M15 subagent ──→ M16 hooks/命令注册表
体验：   M13 会话分页+无刷新（依赖 ADR-0010 不可改 → 新 ADR）
健康：   M14 拆包+性能+密闭（建议插在 M13 前后，避免债务跨期累积）
远期池： 附件/联网/PTC/导出/鉴权……按需求拉动
```

- **M12 先于 M13**：工具族是用户价值主线（agent 能干活），会话体验是锦上添花；且 M13 的分页在"历史更有料"之后收益更真实
- **M14 可拆散插入**：拆包与密闭测试不必整期——可随各期 prefactor 逐步消化，M14 只收尾对账
- **理解关卡（R6）**：M12 开工前必须清零（duo-comprehension）——连续两期例外放行已到上限
