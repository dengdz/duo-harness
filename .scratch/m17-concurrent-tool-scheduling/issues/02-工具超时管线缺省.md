# 02: 工具超时管线缺省

## What to build

任何卡死的工具最多 120 秒返回超时错误、agent 循环继续（术语：管线缺省超时，ADR-0018 决策 5）：用户不再遭遇一个挂死的 read 永久停住会话，且并发化后不会积压一整批已完成结果的提交。落点：工具域三段管线 execute 段挂 around 终端监听器（管线既有预留挂点），超时 interrupt 执行中的虚拟线程、超时错误作为 error 工具结果回填（沿用异常收敛语义、不炸循环）。

## Status

ready-for-agent

## Blocked by

01（执行线程模型先定：超时监听器中断的是并行池执行线程，避免先自建线程后整合的返工）

## Checklist

- [ ] execute 段超时监听器：缺省 120 秒、yml 可配（与 maxParallelToolCalls / maxIterations 同族装配 config）
- [ ] 超时错误作为 error 工具结果回填模型可见（哪一步失败、为什么）；不可中断操作后台跑完、结果丢弃
- [ ] `ask_user` 声明式豁免（等人类回答不限时）
- [ ] 优先级：工具自身声明 > 管线缺省（bash 模型可传 timeoutMs 的协作式原样保留；bash 超时杀进程树行为不变）
- [ ] 测试（ToolsService execute 段 + 短超时注入 100ms 级，不等真实 120s）：超时错误回流、ask_user 豁免生效、工具声明优先于缺省
