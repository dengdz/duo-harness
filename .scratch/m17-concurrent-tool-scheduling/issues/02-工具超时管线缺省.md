# 02: 工具超时管线缺省

## What to build

任何卡死的工具最多 120 秒返回超时错误、agent 循环继续（术语：管线缺省超时，ADR-0018 决策 5）：用户不再遭遇一个挂死的 read 永久停住会话，且并发化后不会积压一整批已完成结果的提交。落点：工具域三段管线 execute 段挂 around 终端监听器（管线既有预留挂点），超时 interrupt 执行中的虚拟线程、超时错误作为 error 工具结果回填（沿用异常收敛语义、不炸循环）。

## Status

ready-for-agent

## Blocked by

01（执行线程模型先定：超时监听器中断的是并行池执行线程，避免先自建线程后整合的返工）

## Checklist

- [x] execute 段超时监听器：缺省 120 秒、yml 可配（与 maxParallelToolCalls / maxIterations 同族装配 config）
- [x] 超时错误作为 error 工具结果回填模型可见（哪一步失败、为什么）；不可中断操作后台跑完、结果丢弃
- [x] `ask_user` 声明式豁免（等人类回答不限时）
- [x] 优先级：工具自身声明 > 管线缺省（bash 模型可传 timeoutMs 的协作式原样保留；bash 超时杀进程树行为不变）
- [x] 测试（ToolsService execute 段 + 短超时注入 100ms 级，不等真实 120s）：超时错误回流、ask_user 豁免生效、工具声明优先于缺省

## Comments

- 2026-09-18 实现完成：`PipelineTimeout.mount`（tools/execute 段 around 终端监听器，虚拟线程限时执行 `next.invoke` + 超时 `cancel(true)` interrupt + `markError` 回流）；声明面为 `ToolDefinition` 两个新 default——`exemptFromPipelineTimeout`（ask_user 覆写）与 `pipelineTimeoutMs`（bash 覆写 = 协作式 timeoutFor + 5s 缓冲，杀树归协作式、管线只兜挂死）。配置面 `parsePipelineTimeoutMs`（严格绑定）+ `mountPipelineTimeout` helper，Web/Cli 装配各接线一行（config 注释同步）。
- 实现注记：首版 `resolveTimeout` 忽略了挂载方传入的缺省值、回落到常量 120s——测试以 100ms 注入立即暴露（工具跑满 10s 返回正常结果）。修复为显式传参。教训：**兜底常量与可配参数同名时，参数链路要有测试盯住**。
- 测试证据：`PipelineTimeoutTest` 5 用例（超时中断回流 + interrupt 感知 latch、豁免不限、覆盖双向优先、工具异常收敛路径不被监听器破坏、bash 协作式放宽）+ `PresenterAssemblyTest` 解析用例；全量 `mvn verify` BUILD SUCCESS。
- 2026-09-18 用户真机验收实测暴露竞态缺陷并已修复：超时 `cancel(true)` 中断工具后，被中断工具的**迟到返回值**经 `setResult` 覆盖了超时错误（`setResult` 会清 error 态）——flaky 竞态（本地两绿是时序运气），违反 ADR-0018"迟到的真实结果不再采用"。修复：`ToolExecution` 新增超时终局 `markTimeout`（写错误并冻结，`setResult` 见冻结即丢弃；同步方法消除跨线程窗口；普通 `markError` 不冻结，post 段修复语义不受影响），PipelineTimeout 超时路径改走 `markTimeout`。测试补显式断言"迟到值不得覆盖超时错误"，连跑三遍 + 全量 verify 复验通过。教训：**"执行线程之外的另一线程写结果"一旦出现，结果写入路径必须整体审视可见性与终局性**。
