# M17 并发工具调度 spec

Status: ready-for-agent（2026-09-18 grill 七题落定 + 测试接缝确认；路线图见 ADR-0016，落地语义见 ADR-0018 同 diff 立卷）

## Problem Statement

调研与执行类任务里，模型一轮常同时发起多个工具调用（"读这三个文件"、"glob 之后再 grep 两处"），而 agent 循环逐个串行执行——总时延是各工具之和，并行收益全部流失。同时整个工具面只有 bash 有超时：一个卡死的 read 会永久挂住循环，且并发化后一个卡死会积压一整批已完成结果的提交。长任务缺结构化分解抓手：spawn/fork 只能靠工具描述引导"大任务拆分"，用户看不见 agent 的计划与进度（M15#6）。另有验收实证伤口：agent 达迭代上限返回未完成时，Web 页面无提示地停住（BUG-20260917-03 验收 B 实测，会话 213120-b3c8）。容器真并发路径（limitations 遗留 #3）自 M1 起无多线程测试覆盖，工具域引入真并发后该风险面需重新评估。

## Solution

单轮多 tool_calls 按并发安全性分流执行（ADR-0016/0018 词汇，DSH 同款）：并发安全工具进虚拟线程滚动池并行执行、独占工具作顺序屏障单独执行、需审批调用永不进池；无论完成先后，结果与事件严格按 model 序成对提交——事件日志形态与串行时代逐字节同构，增量回放、尾部窗口、投影修复、崩溃闭合全部零改动。工具超时推广为管线缺省（120 秒可配、ask_user 豁免、工具声明优先）。todo_write 分解抓手照搬 DSH 形态：全量清单替换、事件落盘、计数回显、Web 双表面 + CLI 摘要。搭车清两笔小账：Web 迭代上限错误卡、limitations 遗留 #2/#3 的并发后复审注记。

## User Stories

并发调度：

1. 作为用户，我让 agent 同时看 5 个文件时 5 个 read 并行执行，所以总耗时接近最慢的那个而不是五者之和。
2. 作为用户，无论工具以什么顺序完成，我在页面与终端看到的工具呈现顺序都与模型意图顺序一致，所以不会误解执行过程。
3. 作为用户，bash 等有副作用的调用绝不与其他工具同时执行，所以不会出现两条命令交错写坏文件。
4. 作为用户，write/edit 并发化后仍保持读前写闸门语义，所以防盲改防线不因并发失效。
5. 作为部署者，我可以把并发度配置为 1 退回完全串行，所以怀疑并发引发问题时能一键排障。
6. 作为部署者，并发度缺省 10 且无需配置即合理工作，所以默认体验就有并行收益。
7. 作为部署者，接入的 MCP 远端工具一律独占执行，所以第三方工具的任意副作用不会被并发放大。
8. 作为工具开发者，我给新工具覆写 isConcurrencySafe 即可进并行池，漏声明时默认独占，所以漏声明不会引发事故。
9. 作为用户，模型一轮混发 read 与 bash 时，read 们先并行跑完、bash 再单独执行、之后继续，所以混发轮的顺序语义清晰可预期。
10. 作为用户，并发执行过的会话在断线重连、刷新、崩溃恢复时行为与串行会话完全一致，所以并发对我不可感知（M10/M13/M16 机制零回归）。

工具超时：

11. 作为用户，任何卡死的工具最多 120 秒就返回超时错误且循环继续，所以会话不会永久挂死。
12. 作为用户，ask_user 等我回答不限时，所以慢思考不会被超时误杀。
13. 作为用户，bash 的超时仍杀整个进程树（模型可传 timeoutMs 的协作式语义不变），所以长命令的既有体验不受影响。
14. 作为工具开发者，我的工具自己声明的超时（或豁免）优先于管线缺省，所以特殊工具不被一刀切。
15. 作为用户，超时错误以工具错误结果的形式回到对话，所以我能看到哪一步失败了、为什么。

todo 分解抓手：

16. 作为用户，agent 接手多步任务时先拆成清单，所以我看得见它的计划而不是黑盒等待。
17. 作为用户，任务清单常驻输入框上方、圆圈状态实时更新（完成带勾、进行中圆环、待办虚线），所以我随时知道进度到哪了。
18. 作为用户，我发下一条消息时上一轮清单清空、终版回答后清单保留，所以阅读节奏自然。
19. 作为 CLI 用户，todo 更新时终端打一行计数摘要，所以终端会话也有进度感。
20. 作为用户，关闭再打开会话后 todo 清单恢复，所以进度不因重开丢失。
21. 作为模型，我 todo_write 后只收到一句计数回显而不是整张清单，所以我的上下文不被重复内容撑大。
22. 作为模型，我被引导"多步任务先拆清单、平凡单步不拆、完成即刻标记不攒批"，所以分解质量有纪律约束。

搭车项：

23. 作为 Web 用户，agent 达迭代上限时页面出现错误卡提示，所以不会遭遇无提示的停住。
24. 作为维护者，工具域真并发路径有多线程测试覆盖，所以并发正确性有回归防线（含 limitations 遗留 #3 风险面的重新评估）。

## Implementation Decisions

**声明与标注（grill Q1/Q2）**：`ToolDefinition` 接口新增 `default boolean isConcurrencySafe(JsonNode args)`（带参版，DSH 同款签名）。fail-closed：未覆写、判定抛错、返回非严格 true，一律按独占处理。首批标注——并发安全：`read` / `glob` / `grep`（纯只读）；独占：`write` / `edit`（读前写闸门的已读集合是会话级共享状态）、`bash`、`ask_user`、`exit_plan_mode`、`skill`（技术上只读、保守起步，是后续放开的第一候选）、subagent 五件套（跨 agent 状态）；MCP 远端工具恒独占（白名单放开记 backlog）。todo_write 本身为独占工具。

**调度与提交（grill Q3/Q4，本期主战场）**：按 model 序扫描单轮 tool_calls——连续并发安全调用成组进虚拟线程滚动池；撞独占调用 → 排空当前池、独占调用单独执行、再继续（顺序屏障，DSH 同款）。`requiresApproval() == true` 的调用无论安全声明如何一律不进并行池（审批即独占，给未来工具立的规矩）。并发度 `maxParallelToolCalls` 缺省 10、yml 可配，配置为 1 即完全串行（兼排障开关，不设独立总开关）。**成对有序提交**：无论完成先后，tool/call 与 tool/result 严格按 model 序成对写入事件日志——日志形态与串行时代同构；M10 游标增量回放、M13 尾窗单趟定窗、投影修复、M16 崩溃闭合全部零改动。日志写入收敛单点（提交线程），会话单写者约定原样保持。已知且接受的代价：并发安全组内慢工具会延迟快工具的结果可见性（组内均为毫秒级只读工具，实际无感；真正的慢工具 bash 是独占的、结构上不在池内）。

**工具超时推广为管线缺省（grill Q5）**：在工具域三段管线的 execute 段挂 around 终端监听器（管线既有预留挂点）。缺省 120 秒、yml 可配；`ask_user` 声明式豁免（等人类回答不限时）。超时触发：interrupt 执行中的虚拟线程 + 超时错误作为 error 工具结果回填（沿用异常收敛语义、不炸循环）；不可中断的操作后台跑完、结果丢弃（模型已收到超时错误，迟到结果不再采用）；bash 保留 terminateTree 杀进程树。优先级：工具自身声明 > 管线缺省（bash 模型可传 timeoutMs 的协作式原样保留）。配置面与 `maxIterations` 同族（呈现位装配 config）。

**todo_write 分解抓手（grill Q6，DSH 同款词汇）**：参数 schema 为全量整表替换——单一必填 `todos` 数组，每项 `content`（非空祈使句）+ `status`（pending / in_progress / completed），无 id、无 priority；校验内容非空且不重复。数据三通道：`todo/write` 会话事件落日志（log-only、重放 latest-wins、重开会话恢复）；模型只收计数回显（"已更新：X 待办 / Y 进行中 / Z 已完成"），完整清单不作为第二条模型消息；完整状态只走事件流给 UI。多任务同时进行中不校验数量、不做配置（并行时代常态，纪律靠工具 description 引导：多步先拆、平凡不拆、全量发送、完成即刻标记不攒批）。呈现：Web 双表面（会话流工具行摘要"done/total 已完成 · 活动任务" + 输入框上方常驻折叠面板，展开为圆圈状态清单，空清单不渲染）；CLI 一行计数摘要（跟随既有工具行风格）。投影生命周期映射 duo 事件：新 user/message 清空、终版 assistant/message 后保留。goal 域（跨轮目标+自动续跑）不做，记 backlog 备查。

**搭车项（grill Q7）**：Web 迭代上限可见化——agent 返回未完成（迭代上限）时 Web 面直推一帧 run/error 错误卡（帧机制与前端渲染已存在，语义补全）。limitations 记账——遗留 #2（bail 与 serial 等价）与遗留 #3（recheck 真并发未测）各加"工具并发落地后复审"注记；M15#6 待 todo_write 落地时销账。ADR-0017（子代理知识可见性）不搭，留 M18 或独立挑期。

**切分建议（供 /to-tickets 参考）**：01 声明与调度核心（isConcurrencySafe + 屏障调度 + 成对有序提交 + 并发度配置）→ 02 管线缺省超时 → 03 todo_write 工具与事件 → 04 呈现面（Web todo 双表面 + CLI 摘要 + 迭代上限错误卡）→ 05 文档与收官（CHANGELOG / limitations 终审 / 双轴审查预备）。`0.12.0` 版本分支已从 main 切出（f964d84）。

## Testing Decisions

只测外部行为，不测实现细节；全部用既有 seam，不建新 seam（接缝已经用户确认）。

- **agent 循环（主 seam）**：`ChatAgent.send` + fake LLM 桩（既有 ToolCallingAgentTest 先例）+ 受控 fake 工具（可控延迟、可控安全声明）。断言三面——事件日志序：tool/call+tool/result 严格按 model 序成对、屏障分组正确、并发轮日志与同等串行轮对照同构；墙钟：并行组总耗时显著小于各工具延迟之和（如三个 200ms 工具 < 400ms），工具域真并发由此获得多线程覆盖；屏障互斥：fake 工具记录进出时间戳，断言独占工具执行期间无其他工具在飞。
- **工具域**：`ToolsService` 的 execute 段监听器（既有测试挂过该段的先例）——注入短超时配置（100ms 级，不等真实 120s），断言超时错误作为 error 结果回流、ask_user 豁免生效、工具自身声明优先于管线缺省。
- **会话域**：`Session` 公共 API（既有 SessionTest 先例）——todo/write 事件落盘、投影 latest-wins、新 user/message 清空、终版回复后保留。
- **Web 面**：HTTP 交换层（既有 WebFaceTest 先例，raw socket 备用）——todo/write 事件到前端的数据通道、迭代上限时 run/error 帧下发。
- **手动验收（duo-acceptance）**：Web todo 双表面与 CLI 摘要的视觉验证（红线 5）；真机并发演示（多 read 并行可感的墙钟对比）。

## Out of Scope

- MCP 工具并发白名单（yml 按服务器/工具名放开——backlog 记档）
- `skill` 工具的并发放开（后续第一候选，backlog 记档）
- goal 跨轮目标域（DSH 参照的独立域——backlog 1.0 后菜单记档）
- 结果按完成序提交、call 批量先发 + result 按序提交（均已在 grill 否决，理由见 ADR-0018）
- DSH 的 `maxParallelSubCalls`（嵌套子调用并发——duo 无 PTC run_code 嵌套调用路径，无对应场景）
- ADR-0017 子代理知识可见性的实现（留 M18 或独立挑期）
- 容器 recheck 深度竞态的专项多线程测试（limitations 遗留 #3 本体不在本期范围，本期只加复审注记）
- 理解关卡补考（用户裁定延后至 1.0 前集中两场）
