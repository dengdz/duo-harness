# M26（0.21.0）会话数据与检索——「历史找得到、带得走」

Status: ready-for-agent

## Problem Statement

- **历史搜不全也搜不稳**：检索靠内存倒排索引——占常驻内存、中文能力有限，且**正在进行的会话整体搜不到**（本进程持锁的活跃会话被排除，M21#1 挂账）。搜索也没有授权边界：在任何项目里搜，所有项目的会话内容都会被翻出来，跨项目上下文污染无防护。
- **交付不可追溯**：导出报告只有对话过程，没有"这次交付了什么、实际改了哪些文件"——成果要靠人翻聊天记录归纳；交付物本身也不入检索索引，按成果反查会话查不到。
- **会话文件没有版本标识**：格式演进至今靠"可选字段缺省不破坏旧文件"的软约定，将来格式一旦结构性变化，程序无法认出文件的新旧年代。
- **翻页与重连游标会串台**：分页 `before` 与 SSE `Last-Event-ID` 都是裸整数、不绑定会话身份——切换会话或服务重启后，旧游标若落在新会话事件范围内，会静默从错误位置续播、把新会话事件当旧页装进页面（M10/M13 遗留防护缺口）。

## Solution

四件主菜（范围与排序以 ADR-0024 为准，执行决策以 [ADR-0028](../../docs/adr/0028-M26会话数据与检索立项决策.md) 为准）：

1. **FTS5 检索迁移**：引入 sqlite-jdbc，检索引擎换 SQLite FTS5；索引为派生只读层（JSONL 仍是唯一权威源，库可随时重建）；活跃会话经 live 供数入检索；结果按 cwd 授权逐条过滤。检索用法与界面不变，能力变强。
2. **/export 增强**：导出报告新增「交付清单」（模型经交付声明工具上报、经存在性校验的成果文件）与「变更摘要」（系统客观视角的文件改动对账）两章节；写出改流式。
3. **会话文件版本头**：新会话首行落 `{type:"session", version:1}`；旧文件读时识别（无头即 v0 直读）、磁盘永不重写；迁移链机制建好备用（读端内存逐级转换）。
4. **代际戳**：翻页与重连游标升级为「会话 id + 序号」复合游标，前后端双侧核对，防跨会话串台。

## User Stories

### 检索（FTS5 迁移）

1. 作为用户，我想当前进行中的会话也能被搜索到，以便刚聊过的内容立刻找得回（消除 M21#1 活跃会话盲区）。
2. 作为用户，我想中文关键词检索保持逐字 AND 语义与排序口径不变，以便换引擎后搜索体验不退化。
3. 作为用户，我想跨会话检索只返回与我当前工作目录相同的会话，以便项目 A 的上下文不被项目 B 的内容污染。
4. 作为用户，我想检索索引不占常驻内存，以便长时间运行不因索引膨胀而变慢。
5. 作为用户，我想索引库文件损坏或被删后能自动就地重建，以便不需要手工维护。
6. 作为用户，我想模型的 session_search 工具与 Web 搜索框得到一致的结果与授权边界，以便两个入口行为一致。
7. 作为用户，我想交付声明能被检索命中，以便按"那次交付了某报告"反查会话。
8. 作为用户，我想模型的检索 query 被当作字面数据匹配而非查询语法执行，以便模型输出特殊字符不引发注入或报错。

### 导出（交付清单 + 变更摘要）

9. 作为用户，我想导出报告里有交付清单章节（模型声明的成果文件、经存在性校验），以便交付物一目了然。
10. 作为用户，我想导出报告里有变更摘要章节（实际动过哪些文件、加减行数），以便评审者快速了解改动规模。
11. 作为用户，我想模型在任务收尾用交付声明工具上报成果（1-N 个文件、工具先校验存在再落事件），以便声明可信、可回放。
12. 作为用户，我想非 git 目录下的会话导出也有变更文件清单（无行数统计），以便任何目录都有基础可用。
13. 作为用户，我想 Web 端下载导出件时服务端流式写出，以便大会话导出不撑爆内存。

### 版本头

14. 作为用户，我想新会话文件首行携带版本头，以便将来格式升级有据可依。
15. 作为用户，我想旧会话文件永远一个字节不被改写，以便崩溃安全与审计承诺不破。
16. 作为用户，我想读端认出旧版本文件后在内存中走迁移链逐级转换再读，以便隔代格式演进也能兼容。

### 代际戳

17. 作为用户，我想切换会话后在途的旧翻页请求被识别并丢弃（而不是把新会话事件装进旧页面），以便页面内容不串台。
18. 作为用户，我想断线重连携带的游标经代际核对、不符则重新对齐，以便恢复的事件流不接错位置。
19. 作为用户，我想分页与 SSE 共用同一套复合游标语义，以便两条恢复路径行为一致。

### 横切

20. 作为后续开发者，我想有契约测试基类钉住 SessionQueryService 的接口语义，以便再换实现时"上层零改动"承诺由机器验证。

## Implementation Decisions

grill 十三问已裁定的决策（详情与拒绝选项见 ADR-0028）：

**检索引擎**
- 引入 `org.xerial:sqlite-jdbc`（全仓首个 SQLite 依赖，红线 4 审批留痕 ADR-0028）；索引库文件落 `~/.duo/` 下。
- 索引定位为**派生只读层**：会话 JSONL 是唯一权威数据；索引 schema 版本不符就地整库重建；库文件可随时删除重建，不承载独有数据。
- 接口面**不扩**：`SessionQueryService.search(String, int)` 单 query 语义不变（多词 AND、每会话至多一条最强命中、score 降序并列 mtime 降序、snippet 就近窗口、线程安全）；工具参数与 Web 搜索 UI 维持现状。
- **live + persisted 双形态供数**：本进程持锁的活跃会话经 live 通道入检索（消除 M21#1 盲区），落盘会话入持久索引；懒构建语义维持，增量刷新能力不劣于现状（mtime+size 戳形态演进为索引库增量）。
- **中文分词**：FTS5 侧 unicode61 + 外部分词（汉字逐字形态），保住现有汉字逐字 AND 与短语加分语义。
- **模型 query 字面化防注入**：模型侧 query 包成单个字面短语，FTS5 查询语法永不执行；SQL 全参数化绑定（对齐 DSH 形态）。
- **cwd 授权过滤**：结果逐条校验会话 cwd 与当前工作目录相等才收；无 cwd 记录的 M26 前旧会话不进结果。前提改造：新会话落盘 cwd 字段（与版本头同批）。
- 内存倒排实现**退役**（替换为 FTS5 实现；契约测试不以它为生产对照）。

**交付声明与变更摘要**
- 新增模型侧**交付声明工具**（工具名实现时定，语义对齐 DSH present）：任务收尾时调用、单次申报 1-N 个文件、工具校验文件真实存在与路径合法后落会话事件（事件类型实现时定，语义对齐 DSH `deliverables/presented`）；事件入检索索引白名单；审批面沿用"harness 内部数据不受三档管辖"先例（ADR-0022 决策 10 同款，不设审批卡）。
- **变更摘要**：会话级对账——会话开始拍一次 git 快照，导出时再拍一次，比对出文件清单与加减行数；非 git 目录退化为文件工具操作记录聚合（有清单无行数）。不做轮次级（per-turn）对账，不造轮次边界事件。
- 导出物理形态**维持 md/json 双格式**，新增两章节；Web 下载与 CLI 写盘改**流式**（不整包驻内存）；ZIP 打包不做。

**版本头与格式**
- 新会话文件首行落 `{type:"session", version:1}`；旧文件**读时识别**（无头即 v0，v0 语义即现有格式、无需转换）；磁盘文件永不重写。
- **迁移链机制**：读端认出版本后按 vN→vN+1 相邻接力在内存转换（隔代逐级），本期无实际迁移要执行，机制建好备用。
- 同批落盘新字段：会话 **cwd**（授权过滤前提，仅新增会话写入）。
- 全部"每行必是事件"的既有逐行读者（标题静态读、权限档静态读、检索索引扫描、子会话事件端点、导出行遍历）需统一过"首行可能是版本头"分流。

**代际戳**
- 游标从裸整数升级为**「会话 id + 序号」复合游标**（SSE Last-Event-ID 与分页 before 参数同语义）；不引入独立 generation 编号（duo 日志只追加，会话 id 即天然代际边界）。
- **前后端双侧核对**：请求携会话 id（服务端可校验绑定关系）、响应回带会话 id（前端校验不符即整页丢弃重新对齐）；旧形态裸数字游标不再接受为有效续播凭据（前后端同包发布，协议一步切到位）。
- 换绑/重启场景下旧游标**明确失效**：返回"游标不属于当前会话"类语义，前端触发重新对齐（尾部窗口快照恢复），不静默从错误位置续播。

**模块归属**
- FTS5 实现与契约测试：duo-harness-session-query（新实现类，接口同包）。
- 版本头 / cwd 字段 / 迁移链 / 导出渲染：duo-harness-session。
- 交付声明事件落盘：duo-harness-session（事件类型）；交付声明工具注册：agent 侧插件装配。
- 复合游标端点改造与流式导出：duo-harness-web（CLI 侧导出命令同步流式化）。

## Testing Decisions

接缝方案（2026-09-26 用户确认）：**唯一新接缝为检索契约测试基类，其余四处沿用既有接缝**。

- **好测试的标准**：只测外部行为（接口语义、HTTP 端点行为、渲染输出、落盘-重放往返），不断言实现细节；契约用例不引用任何实现类。断言沿用 JUnit Jupiter 原生 Assertions（全仓无 AssertJ/Mockito，stub 匿名内部类手写）。
- **接缝 1（新）——检索契约测试基类**：把 SessionQueryService 语义（AND、每会话一条最强命中、排序、snippet、坏行跳过、线程安全）抽为抽象契约用例集，FTS5 实现继承执行；另设实现专属测试类钉 FTS5 特有面（live 供数、就地重建、cwd 过滤、query 字面化）。
- **接缝 2——Session 持久化单元**（SessionTest 形态，@TempDir + 代码生成事件 + 手写旧格式 JSONL）：版本头落盘与识别、无头 v0 直读、cwd 字段往返、交付声明事件往返、迁移链用测试用迁移器验证 v1→v2→v3 接力。
- **接缝 3——导出渲染纯函数**（SessionExportTest 形态）：交付清单与变更摘要章节断言；变更摘要的 git 对账用 @TempDir + `git init` 迷你仓库夹具（全仓首例 git 夹具）、非 git 退化路径用普通临时目录。
- **接缝 4——Web HTTP 集成**（WebFaceTest / WebSessionExportEndpointTest 形态：真实内置 HttpServer + HttpClient）：换会话后旧游标被拒/整页丢弃、SSE 重连带复合游标、导出附件流式下载。
- **接缝 5——工具装配**（SessionSearchToolTest 形态）：交付声明工具的注册、渲染面与存在性校验失败路径。
- 先例参照：M25 的"纯函数单元 → 持久化单元 → 装配/集成"三层分层组织（memory/microcompact/cacheControl 测试）。

## Out of Scope

- **ZIP 打包导出**（子会话/附件字节随包）——backlog 1.0 后菜单。
- **自动抽取子代理（A 形态）**——M26 立项 grill 已复议不纳入（ADR-0028 拒绝的选项），留 backlog。
- **检索过滤器扩展**（按时间/会话/类型筛选项）与 DSH 五工具检索面（event_search/trace/event_read）。
- **显式跨目录搜索开关**与**老会话目录归属回填**（升级路径，后续按需立项）。
- **旧会话文件迁移/重写**——永不（ADR-0028 决策二）。
- **轮次级（per-turn）变更对账**与轮次边界事件——会话级够用，升级路径顺。
- **撕裂恢复 / 行校验和**（DSH 点名的 duo 崩溃半行无处理）——同域但未入 M26 范围，记 limitations 待议。
- **OTel model-attempt 级评估**——随 M27 收口再议。
- M25 comprehension 补课——用户主动发起，不排期（拆工单闸门口径见 Further Notes）。
