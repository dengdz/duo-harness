# M29（0.25.0）文档与视觉——「1.0 的脸面与说明书」

Status: ready-for-agent（11 张工单已拆，见 issues/；大纲确认是 02-04 的硬关卡）

## Problem Statement

- **文档断层**：01-入门 / 02-指南 / 04-架构 / 05-参考四章齐备，但 03-高级整章缺席（站点导航标注「建设中」）——一个想给 duo 写技能、接 MCP、组装自己插件的进阶用户，只能翻源码与 ADR。素材不是没有，是散落：MCP 机制散落 7+ 处文档各一句话级覆盖，无一篇专文；唯一范例插件 duo-harness-stats 零 README，四扩展点串一插件的叙事只存在于 javadoc。
- **界面「可用非惊艳」**：M8 原型评审用户原话，挂账至今（backlog 视觉打磨词条）。具体缺口三类：消息流代码块纯等宽灰底无高亮；present 交付声明事件已随 SSE 到达前端却被 dispatch 链静默丢弃（成果无处可见，只有 /export 后才见交付清单章节）；思考模型的思考过程根本不进事件流（仅 tool/call 携带 reasoning 供回传 provider），前端无处呈现。
- **视觉参照系缺位**：用户高频使用 ZCode，点名其思考折叠、分工具卡形态、子代理页、确认交互卡四块形态值得参照——但现有 ZCode 研究文档（呈现与UI 三篇共 122 行）讲的是机制层（wire 帧/投影 store/分发协议），视觉与交互形态细节零覆盖。

## Solution

两条线一条收口（范围与排序以 [ADR-0029](../../docs/adr/0029-M27至1.0版图重排第二弹.md) 为准、裁定细则以 [ADR-0031](../../docs/adr/0031-M29文档与视觉立项决策.md) 为准；版图顺移 M29=0.25.0）：

**文档线**：三章大纲齐出 → 用户确认 → 逐章交付（每章一工单，成章即审查即验收）。技能编写章 = SKILL.md 技能教程（写作规范教程化 + 发现/热加载机制侧）；MCP 深入章 = 散落素材聚合升格；多插件协同章 = duo-harness-stats 主线「从零写一个插件」+ 组装协同。示例一律活体引用。

**视觉线**：ZCode 形态研究先行（源码级，产出落地清单）→ 三件卡片/渲染落地（思考折叠完成态卡、成果卡片、语法高亮）→ 整页走查打磨收尾（把新卡片与既有界面一起走查，基线 = M8 冻结原型 + DSH 亮色 token + ZCode 形态参照，打磨不重设计）。

两线无相互依赖，并行推进；收口 = 四轴审查 + 用户手动验收 + 发版 0.25.0。

## User Stories

### 文档线·三章

1. 作为想给 duo 写技能的插件开发者，我想要一篇从零到一的技能编写教程（SKILL.md 结构、description 三规则、完成判据、发现与热加载机制），以便不翻源码就写出合规技能。
2. 作为想接 MCP 服务器的部署者，我想要一篇 MCP 深入文档（连接生命周期、指数退避重连、工具同步、带哈希命名规则、config 面全表、connectorStatus 消费），以便连接问题可自查。
3. 作为想组装自己 agent 的进阶用户，我想要一篇「从零写一个插件」端到端教程（duo-harness-stats 四扩展点：事件监听/命令注册/工具注册/服务消费），以便照着做就能挂上第一个零内核改动的插件。
4. 作为多插件组装者，我想要服务 provide/inject/optionalInject、事件协同与装配序的协同讲解（含双启动校验等既有契约），以便多插件并存不踩依赖与行序坑。
5. 作为文档读者，我想让三章示例全部活体引用（锚定 duo-harness-stats、demo 装配 yml、既有 mcp 配置面，可复制可编译），以便照抄不踩「文档与代码脱节」的坑。
6. 作为文档站读者，我想让三章进导航与 sidebar（03-高级不再是「建设中」），以便从站点结构直接抵达。
7. 作为用户，我想在三章动笔前先审三章大纲（机制点/示例/引用逐节列明），以便方向跑偏在动笔前拦住。

### 视觉线·卡片与渲染

8. 作为 Web 用户，我想让消息流代码块有语法高亮（vendor 直挂零构建链），以便快速读模型输出与工具结果里的代码。
9. 作为 Web 用户，我想让 present 成果在消息流渲染为成果卡片（📦 件数 + 逐行路径、点击复制），以便任务收尾一眼看到交付物。
10. 作为 Web 用户，我想让思考模型的思考过程以折叠卡呈现（默认收起、点开全文），以便关注结论时收起、需要审计时展开；非思考模型会话零变化。
11. 作为 Web 用户，我想让不同类型工具调用有各自的展示形态而非一律通用卡，以便快速扫读执行过程。
12. 作为 Web 用户，我想让审批/提问/计划卡与子代理抽屉的视觉细节（间距/层级/过渡）对齐打磨，以便界面「可用且舒服」。
13. 作为多标签/回放用户，我想让成果卡与思考卡在刷新回放后原样呈现（回放与实时同源），以便历史会话与新事件同构。

### 视觉线·走查与验收

14. 作为验收者，我想逐区域拿到截图前后对照并目测裁定，以便视觉打磨由我判定而非代理自证。
15. 作为后续工单实现者，我想要一份 ZCode UI 形态研究（四块：思考折叠/分工具卡/子代理页/确认交互卡的形态与交互细节 + 对 duo 落地清单），以便卡片实现有源码级参照而非凭感觉。

## Implementation Decisions

八问 grill 裁定（2026-09-29，全记录见 [ADR-0031](../../docs/adr/0031-M29文档与视觉立项决策.md)；本节为执行细则）：

**文档线**

- **大纲先行确认制**：三章大纲齐出（逐节列机制点/示例/引用），载体 `.scratch/m29-docs-visual/outline.md` → 用户确认后才进逐章交付；每章一工单、成章即审查即验收；篇幅 300-600 行/章。
- **章域划分**：技能编写章不含插件工具编写（归多插件协同章）；MCP 深入章为聚合升格而非新机制叙述（素材锚点：模块划分 §mcp 包边界与关键语义表、插件配置参考 §编程形态、工具目录 §MCP 远端、02-指南 §第四步、mcpfs 示例）。
- **示例活体引用**：锚定真实模块与真实装配文件（项目惯例——既有文档示例均锚定 agent-demo.yml 等，不用虚构代码）；不为文档新写 demo 模块、不做机械一致性校验。

**视觉线**

- **ZCode 形态研究先行**：源码级（本机 `/Users/zhangyl/IdeaProjects/ZCode/`，锚点 872ad960，v3.14.0 快照），四块形态提炼 + 对 duo 落地清单；产出落 `docs/research/ZCode/呈现与UI/` 下新篇，喂给走查与三张卡片工单。
- **语法高亮**：highlight.js 全量 vendor 直挂（约 100KB min 包体，同 marked v18/DOMPurify 3.4 先例，零构建链）；`/web/` 静态服务白名单放行任意单段 .js、token 注入正则自动覆盖新 script 标签——均已实测，零 Java 改动；renderMarkdown 照 vendor 缺失降级纯文本先例接入高亮初始化。
- **成果卡片**：挂 present 工具卡的 toolName 二次分发（同 ask_user→提问卡、todo_write→todoCard 先例）；卡面 = 成果件数 + 逐行路径（文件名突出）、点击行复制路径；deliverable/presented 事件保持不渲染（同动作只一张卡，回放天然一致，零去重负担；事件消费方检索索引与导出交付清单不变）；「与导出交付清单联动」= 同源展示，不加导出按钮。
- **思考折叠卡（完成态）**：后端把 assistant 思考内容补进会话事件面（一次补齐；具体形态——assistant/message 事件扩字段或独立事件——实现工单定，硬约束：非思考模型会话零变化、回放/实时同源、不重演「tool/call 才带 reasoning」的回传专用歧义）；前端折叠卡默认收起、点开全文；流式实时思考展示不入本期（backlog）。
- **整页走查打磨收尾**：在新卡片落地后执行（一次走查覆盖全量面）；基线 = M8 冻结原型 + 现有 DSH 亮色 token + ZCode 形态参照；打磨不重设计——不加暗色主题、不换色板、不重排布局；重点区 = 分工具类型展示样式、子代理抽屉、审批/提问/计划卡；流程 = 隔离实例 + 内置浏览器驱动逐区域截图、前后对照、用户目测逐区域裁定。
- **执行顺序**：大纲确认后两线并行；视觉线内部研究 → 思考折叠 → 成果卡片 → 语法高亮 → 走查收尾（走查最后，覆盖新卡片）。

**记账口径**：视觉四件均为用户可见变更，每张工单提交同 diff 记 CHANGELOG 0.25.0 未发布段（红线 6）；三章文档与 ADR/研究文档同 diff 同步（红线 3）。

## Testing Decisions

- **接缝全复用既有，零新接缝**（最高接缝原则）：
  - **Java 事件面**（思考折叠后端）：会话事件构造与投影的既有测试形态（提问卡 `question/requested` 事件先例）；断言「非思考模型不产生新事件形态、思考模型事件可回放」。
  - **Web 静态服务**（语法高亮）：WebEndpoints 静态资源白名单既有测试域，补新 vendor 文件可获取断言。
  - **端到端浏览器**（成果卡/思考卡/走查）：隔离实例 + 内置浏览器驱动（C2 验收三件套先例：隔离实例/内置浏览器驱动/诊断日志先行）——卡片以页面 DOM 断言与截图为准；走查截图同通道产出。
  - **文档**：`ignoreDeadLinks: true`（ADR-0005，.scratch 链接有意容忍）故 vitepress build 无死链闸门——三章内链与活体引用在章节工单 Checklist 做链接自查与源码对账（工具目录 ToolCatalogTest 对账先例仅覆盖既有工具条目，不为本期新建对账测试设施）。
- **只测外部行为**：卡片测试断言页面呈现与交互结果（复制到剪贴板、折叠展开），不测 app.js 内部函数（前端零构建无 JS 单测设施，维持）。
- **回归红线**：全仓既有测试全绿跨工单保持；Web 端点与 SSE 行为不因 vendor 与 dispatch 新分支改变既有事件类型的渲染。
