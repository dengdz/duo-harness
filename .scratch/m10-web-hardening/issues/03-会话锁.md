# 03: 会话锁

## What to build

同一会话文件不允许两个进程同时写入：第二个进程打开已被占用的会话时得到明确报错，而不是静默分脑（JSONL 交错追加、两侧上下文分叉，BUG-20260914-01 的结构性根源）。只拒绝、不协作——跨进程写协调等真需求出现再升级。

## Blocked by

无（可立即开工）

## Status
done

## Checklist
- [x] 会话打开时取得进程级文件锁并持有至会话关闭（session 域增量，不改事件溯源语义）
- [x] 锁被占时的三处呈现：Web 启动失败并指明被占会话、CLI 打开时明确提示、会话切换返回占用错误
- [x] 测试：两个 Session 实例争用同一会话文件，后者报错、前者不受影响
- [x] 单进程正常路径回归绿（既有会话测试不破）

## Comments

- 实现（2026-09-14）：
  - **session 域**：`create`/`load` 经统一 `lock()` 取得 JSONL 文件的独占 `FileLock`（持有至 `close()`）——同进程第二实例由 `OverlappingFileLockException` 拒绝、跨进程由 `tryLock()` 返回 null 拒绝；新增 `SessionLockedException`（带 `sessionId()` 与不含路径的 `brief()`）；`close()` 幂等（原子标志）释放锁 + 文件通道 + 摘除监听器；`append` 加关闭守卫（关闭后写入抛 `IllegalStateException`——锁已释放，继续写会与可能接手的新属主无锁并发）。
  - **呈现层**：WebPlugin 启动遇占用抛「Web 面无法启动：<占用详情>」（点名会话与路径），启动失败路径释放锁；AgentReplMain / ChatReplMain 遇占用打印明确提示后**改开新会话继续**；WebFace 的 `/switch` 返回 409 + `brief()`（不回显内部路径），换绑与 `stop()` 释放旧会话锁；前端切换失败显示服务端文案。
  - **文档同步**：limitations 第 2 条、运行Demo、组装指南、agent-demo.yml 注释均改为会话独占语义。
- 验证：SessionTest 20/20（3 个锁用例 + 关闭守卫 + 既有用例的 close 插入）、WebFaceTest 25/25（占用冲突 409 + 切当前会话幂等）；全量 `mvn -o test` **281 用例绿**；**跨进程手工冒烟**——进程 A（Web+CLI 同进程）内部即复现争用：Web 持锁、CLI 打印「会话已被占用：<id>」并新建会话继续；进程 B 启动被拒（「Web 面无法启动：会话已被占用：<id>（路径）」）。日志留档 `/tmp/duo-lockA.log`、`/tmp/duo-lockB2.log`。
- **审查（委托 OCR + 双轴）修复项**：
  1. **真 bug**：`/api/session/switch` 切到"当前已是同一会话"的 id 会误报 409（重新 load 自己必撞独占锁）——改为幂等返回 200，补回归用例。
  2. **真并发缺陷（重要，既存隐患被本工单暴露）**：`events()` 的 `List.copyOf(ArrayList)` 与并发 `append` 竞争会读到扩容空洞 → NPE（M8 起的隐患，javadoc 声称的"读取与追加并发安全"实际不成立）。修复：读写经同一把锁（`events()` 同步拷贝、`append` 在同步块内追加并固定序号，抽出 `persist()`）；连续 3 轮 SessionTest 稳定绿。
  3. JavaDoc 契约补齐：WebFace 的会话所有权声明（换绑/stop 会关闭传入会话）、`Session.close()` 摘除监听器、`lock()` 的 `PluginException`、close 的线程语义。
  4. 风格与去重：`Session` 的 FQN 改 import；`SessionLockedException` 消息单点化（`describe` + `brief`）；WebPlugin 启动失败释放锁。
- **留档**：① 跨进程路径无自动化测试（`tryLock()==null` 分支）——由手工冒烟覆盖，全仓无 `ProcessBuilder` 先例，不为此引入；② 三处占用处理文案重复但降级行为不同（CLI 新建 / Web 抛错），提取收益低于跨模块耦合，接受重复。
- **待用户裁定**：CLI 遇占用后的行为——spec 原文写「明确报错**退出**」，实现为「明确提示 + 改开新会话继续」（后者保住了 demo 主路径可用性：agent-demo.yml 同时装载 Web 与 CLI，严格退出会让 CLI 一启动即终止）。风险：用户需读提示才知道在写新会话。
- 待手动验证：用户亲跑确认后置 done。

- **验收中用户报告"切换会话一直提示被占用" → 排查揪出两个 POSIX 陷阱级缺陷（已修，2026-09-14）**：
  1. **append 走独立 fd 触发 POSIX 锁释放陷阱**：进程关闭同一文件的任意 fd 会释放其在ese文件上的全部锁——append 每次新开 BufferedWriter 写完即关，第一条事件写完独占锁就蒸发（跨进程防护失效；同 JVM 因 FileLockTable 仍记录故拒绝照常，形成"拒绝还在、防护没了"的假象）。修复：load 读取与 append 写入**全部经持锁通道**（position 管理 + `lockChannel.force` 落盘），不再另开 fd。实测：追加写入后探针确认锁保持 ✓。
  2. **同 JVM 重复打开失败路径连带释放他人内核锁**：第二实例 open→tryLock 失败→close 探测 fd，会释放同进程**已成功持有者**在ese文件上的内核锁（JVM FileLockTable 仍记录，形成"同 JVM 拒绝照常、内核锁已丢"的假象）。修复：新增 JVM 内持锁注册表（`HELD_LOCKS`，绝对路径键）——同进程重复打开在**开 fd 之前**即拒绝，失败路径不再触碰他人锁。实测：重启后 Web 与 CLI 各自的会话锁均保持 ✓。
  - **归因方法（用户问)）**：服务端日志 `[web] 会话切换被拒（占用冲突）: 会话已被占用：<id>` 点名被拒会话——对照属主即可归因：被拒 id = 本进程 CLI 当前会话 → 防护正确（本次 8 次被拒全是它，侧栏按修改时间排序它居首）；被拒 id = 浏览器当前会话或死会话 → 机制缺陷（本次排查正是由此发现上述两缺陷）。锁状态可用 fcntl 探测脚本实证。
  - 侧栏 UX 优化（被占会话置灰/标注）不拒绝语义的一部分，留 backlog 视需求。

- **缺陷 3（换绑竞态泄漏，用户验收实测）**：并发切换（快速连点侧栏/新话题）时 `bindSession` 各关各的快照"上一个"，中间会话被跳过——其独占锁**永久泄漏**（实证：76ae 非 current 却内核锁被占，切它永远 409）。修复：`bindSession` 经 `bindLock` 串行化——换绑链线性化后每会话恰被关闭一次。回归用例：6 线程并发切换风暴，不变量断言"除当前会话外全部可加锁"。重启后 76ae 恢复可切（泄漏锁随进程死亡消失）。全量 282 用例绿。
