# 02 — 事件总线五种分派模式

## What to build

插件间通信的事件总线：支持 emit（广播不等待）、parallel（并发全跑）、serial（顺序可提前终止）、bail（同步投票取首个非空）、waterfall（洋葱管线：监听器收 (args, next)，可改写参数、包装返回值、不调 next 即否决含默认行为的链）。监听器注册为插件实例的 effect——插件停止时自动摘除，不留僵尸监听。完成的判据：五种模式各自语义有用例锁定（尤其 waterfall 的否决与改写），插件停止后其监听器不再被派发（spec 用户故事 17/18/20 的机制基础）。

## Comments

- 设计说明：同步阻塞模型下 bail 与 serial 语义等价（DSH 的差异源于异步监听器），bail 委托 serial 实现并保留 DSH 词汇；投票终值判定为"非 null 即终值"（FALSE 是合法投票值，与 DSH 排除 false 不同，JavaDoc 已记录）。
- 监听器异常策略按模式分化：emit 隔离记 warn、parallel 聚合（主异常 + suppressed）、serial/bail/waterfall 包装上抛（治理管线中异常是信号）——工单"不传染兄弟与派发方"按广播类模式理解，已在测试锁定。
- SLF4J 接入获用户同意（slf4j-api + simple test），E-04 尾巴（disposeQuietly 吞错）改为 warn 日志。
- ocr 审查修复：派发入口补 event null 防御（与 on 一致）；虚拟线程名加序号；泛型 T/R 一致性约定与全部 @throws 补入 JavaDoc。
- 测试竞态修复：parallel 聚合断言从依赖并发完成顺序改为集合断言（曾间歇失败）。
- 30 用例（12 插件闭环 + 18 事件）三连跑全绿。
