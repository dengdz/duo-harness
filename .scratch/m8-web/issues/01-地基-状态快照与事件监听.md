# 01: 地基——内核状态快照 + Session 事件监听器

**What to build:** M8 的两个地基 API：① core 的 `Context.snapshots()` 只读快照——返回全部已挂载插件的标识与六态状态（内核注册表在挂载/卸载/状态迁移时维护，PluginSnapshot record：标识 + PluginState）；② session 的 `Session.addListener`——订阅新事件（Consumer<SessionEvent>，返回注销器），append 时同步回调。纯新增向后兼容，其余消费者（compaction、遥测）同样受益。

**Blocked by:** None (can start immediately)

**Status:** implemented（2026-09-13，待用户验收）

## Checklist

- [x] core：`PluginSnapshot` record（插件标识 + PluginState）+ `Context.snapshots()`；Boot 装载的插件带 yml id，编程挂载为类全名（内核既有约定 getClass().getName()）
- [x] 快照实时性：挂载出现、dispose 消失、依赖缺失 PENDING / 服务就绪转 ACTIVE 均反映
- [x] session：`addListener(Consumer<SessionEvent>)` 返回注销器；append 落盘成功后同步回调（reasoning 字段完整传递）
- [x] 测试：PluginSnapshotTest 3 例（挂载 ACTIVE / 卸载消失 / PENDING→ACTIVE）+ SessionTest 监听器 1 例
- [x] 文档同步：CHANGELOG 未发布段记两个地基 API；JavaDoc 完整

## 实现记录（2026-09-13）

- core：PluginSnapshot record + Context.snapshots()（接口新增方法，ContextImpl 唯一实现者无兼容问题）+ PluginRegistry.snapshots()（复用 pluginName()/state() 既有访问器）
- session：CopyOnWriteArrayList 监听器表（回调中注销安全），落盘成功后才通知（监听器看到的事件必然已持久化）
- 过程修正：awaitStartup() 返回 void 不能赋值；编程挂载快照名为类全名而非简名（内核既有约定，测试按 endsWith 断言）
