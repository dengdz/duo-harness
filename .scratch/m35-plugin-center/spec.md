# M35（1.1.0）插件生态化一期——链路闭环：插件包装载、插件中心与端点贡献口

Status: ready-for-agent

裁定与版图见 [ADR-0037](../../docs/adr/0037-M35M36插件生态化立项决策.md)；术语（插件包 / 插件中心 / 装前点名 / 内核独占面 / 扩展点）以[术语表](../../docs/05-参考/术语表.md)为准。

## Problem Statement

- **装不了**：第三方插件今天是"编译期联营"——类必须在 classpath 上、改动要重打包宿主（`tool-stats` 示例宣称"接入仅两行"，第一行是加 Maven 依赖）。别人给一个 jar，没有合法通道让它跑起来（已知限制 #4）。
- **管不了**：运行期没有任何管理面——装/停/卸/换实现都要改配置重启进程（已知限制 #1）；六态容器明明具备"提供方消失→依赖方回落 PENDING、服务回归→自动重载"的插拔语义（ADR-0019 依赖指纹），但没有任何入口能在运行期触发它。
- **换不了**：审批策略三选一是装配期决定，"不如意就换上自己的"在页面上做不到；llm/session 在内核独占面（这是裁定要维持的，不是本期问题），但**可换槽位**（approval、answers 等）也没有一个统一的"看得到、换得动"的界面。
- **信不过**：即便上述都通了，装第三方代码前没有"它会要什么"的告知机制——信任模型（自用 + 熟人圈）需要一条最低限度的知情闸门。

## Solution

插件生态链路闭环（M35 = ADR-0037 五组裁定的落地期）：**装进来 → 看清楚 → 管得住 → 换得动**。

1. **装进来**：插件包（fat-jar 单文件）放 `~/.duo/plugins/`，目录扫描进入安装视野；yml 行新增 `jar:` 来源字段，装载模型从"仅 classpath"扩为"classpath + 插件包目录"（启用 ADR-0001 预留扩展点）。
2. **看清楚**：装前点名——从类声明零副作用读依赖与 config 契约，出示"它会消费哪些服务、config 长什么样、来源包校验和"，确认才装载。
3. **管得住**：插件中心（独立插件模块）+ 内核两个受控口（运行期行级控制、Web 端点命名空间贡献口）；一切操作写回 plugins.yml 单一事实源；治理三闸门（guard 单调否决、规则 deny 恒优先、审批 fail-closed）不随任何插件替换放松。
4. **换得动**：页面上启停/卸载/换审批策略运行期热生效；配置编辑走"停→改→启"向导；拔不得的插件标注重启生效。

## User Stories

1. As a 部署者, I want Web 页面有一个「插件中心」tab, so that 不碰命令行就能看到装了哪些插件、各自处于六态中的哪一态.
2. As a 部署者, I want 把别人给的插件包放进约定目录后页面扫描即列出待装项, so that 安装不需要重启进程或重新打包宿主.
3. As a 部署者, I want 点安装时先看到装前点名校（消费的服务、config 形态、jar 路径/大小/sha256）, so that 我确认过它要什么才放它进进程.
4. As a 部署者, I want 启用/停用插件运行期即时生效, so that 试插件不用反复重启.
5. As a 部署者, I want 卸载后该插件的服务、工具、监听全部摘除且依赖它的插件自动回落等待, so that 拔除是干净、可预期、可逆的.
6. As a 部署者, I want 用自己的 approval 实现替换内置三选一, so that 审批语义按我的工作流定制.
7. As a 部署者, I want 破坏性操作（卸载、换审批策略）二次确认, so that 误触不会拔掉正在用的能力.
8. As a 部署者, I want 插件中心每个操作落回 plugins.yml, so that 重启后装配与页面所见一致、永远只有一本账.
9. As a 部署者, I want 拔不得的插件（cli 呈现位——apply 即 REPL 主循环）被明确标"重启生效", so that 不会出现"页面一点把终端主循环拔了"的事故.
10. As a 部署者, I want 无状态插件改配置走"停→改→启"向导, so that 改配置不必整进程重启.
11. As a 部署者, I want 插件包行装载失败时被点名（行 id + 原因 + 包路径）且整树回滚, so that 坏包在启动期 fail-fast 暴露而不是运行期半死.
12. As a 插件作者, I want 交付物就是一个 fat-jar 加一行 yml 说明（`jar:` 路径 + `name` 入口 FQCN）, so that 交货格式最简单、零新概念.
13. As a 插件作者, I want 我的插件拿到的公开 API（Plugin/Context/服务/事件）与内置插件完全对等, so that 能力面没有二等公民.
14. As a 插件作者, I want 我的插件包与其他插件类互不可见, so that 我的依赖冲突既不影响别人也不被别人影响.
15. As a 插件作者, I want 有一个官方插件包形态的活样板（tool-stats 包化）, so that 照着打包就能交货.
16. As a 插件作者, I want 装后状态页能看到我插件的完整注册面（服务/工具/命令/监听）, so that 行为可核验、与点名校的预期对得上.
17. As a duo 使用者, I want guard 单调否决、规则 deny 恒优先、审批 fail-closed 三道闸门不随插件替换放松, so that 装插件不会悄悄拆掉安全底线.
18. As a duo 使用者, I want 贡献口端点一律过既有 Web 鉴权栅栏, so that 插件加的 HTTP 面不能绕过 token 变成旁门.
19. As a CLI 使用者, I want 插件中心的热插拔同步反映到终端会话可用的工具与命令, so that 双呈现位能力一致、无隐藏分叉.
20. As a 排障者, I want "这插件为什么在跑/为什么没跑"只看 plugins.yml 一个文件, so that 排障不跑两个事实源.
21. As a 排障者, I want 类加载器泄漏被检测并提示"需重启生效", so that 卸载不干净时有明确兜底而不是静默劣化.
22. As a 部署者, I want 插件包升级有明确路径（停用→覆盖 jar→重装）, so that 升级不靠玄学.

## Implementation Decisions

**裁定来源**：以下全部锚定 ADR-0037（grill Q1-Q11 用户裁定），本 spec 只做工程化落钉；四项 ADR 留待细节在落钉处注明。

- **新模块 `duo-harness-plugin-center`**（独立插件形态，生态基建自举）；内核两口分别落 core 与 web 既有模块，不新增内核模块。
- **内核口一·运行期行级控制（core）**：按 yml 行 id 装载/拔除的受控 API。六态状态机与依赖指纹语义原样复用，**不加新状态**；Boot 装载产物按 id 登记可寻（现状句柄被 BootLoader 私有持有）；重复 id 装载点名报错（对齐服务同名互斥先例）。
- **内核口二·端点命名空间贡献口（web）**：插件按申请制获得 `/plugins/<贡献者前缀>/**` 形态的端点注册位。三条铁律：①贡献端点一律纳入既有鉴权栅栏（token fail-closed，`web.auth: none` 行为与既有端点一致）；②路由层异常兜底 500 + 日志（BUG-20261002-01 教训：路由层无兜底 = 连接裸关静默盲）；③插件中心自己是第一个消费者（吃自己狗粮），其 API 全部走贡献口。
- **插件包装载器**：每包一个独立 `URLClassLoader`（parent = 应用 classpath），fat-jar 约定（依赖全打入、无 lib/ 目录、无插件间互见）；yml 行 `jar:` 字段指向包路径、`name` 字段继续承载入口 FQCN（**不加 manifest 约定**——行结构正向兼容，作者零新概念，ADR 待定细节一落钉）；卸载 = 容器拔除 + loader close + 丢弃，泄漏检测（loader 存活可判）提示"需重启生效"。
- **装前点名**：实例化插件类（公共无参构造）后调 `inject()` / `optionalInject()` / `configType()`——三者契约上纯声明（副作用唯一入口是 `apply`），零副作用成立；点名校出示：消费服务清单、config 类型、jar 路径/大小/sha256。**诚实修正**：服务"提供意图"要 `apply` 才发生、静态读不到（ADR-0037 决策一原文含"服务提供意图"）——点名校如实只出示消费面并标注"完整注册面以装后状态页为准"（ADR 待定细节二落钉）。
- **账本与可写事实源**：一切操作写回 yml（装 = 新行带 `jar:` 来源、停 = `disabled: true`、卸 = 删行），Jackson-YAML 既有基建。**fat-jar 资源物化**：缺省启动来源是 classpath 资源（物理不可写），首次运行物化到 DUO_HOME 作此后唯一装载来源（资源仅作首次种子），保住"单一事实源"裁定不被"文件不可写"架空；升级漂移（内置种子新增行）以日志提示对账，合并工具不做（ADR 待定细节外的落钉，Further Notes 记代价）。
- **热重载档位**：结构操作（装/停/卸/启用/换槽位实现）热生效；配置编辑走"停→改→启"向导（六态自动善后依赖方）；`disabled` 行为与"拔不得"标注（cli 呈现位等 apply 阻塞型）由插件中心维护一份不可拔清单（呈现位与管理插件自身）。
- **换审批策略**：页面操作 = 停用现提供方行 + 启用目标行（结构操作组合），破坏性二次确认；治理三闸门在内核管线，替换不触及。
- **插件中心服务面**：发布 camelCase 服务（如 `pluginCenter`——先例 `sessionQuery`/`permissionRules`，SERVICE_NAME 与视图接口方法名逐字一致），供后续 CLI 消费；提供方 ≠ 声明方，无 epoch 指纹自环（fileRefs 教训在案）。
- **页面形态**：侧栏新增「插件中心」tab，四区——已装清单（六态 + 服务消费/提供面）、待装（扫描 + 点名卡）、操作（启停/卸载/换策略，破坏性二次确认）、状态行（`plugin/status` 叙述）。仍是无构建静态单页延伸，不引入构建链（M8 限制 #3 口径不破）。
- **Boot 审计语义不变**：坏包行装载失败点名（行 id + 原因 + 包路径）+ 整树回滚 fail-fast——与既有 Boot 契约一致，不为第三方包引入软失败。
- **示例与文档**：`tool-stats` 双形态交付（classpath 行保留 + shade profile 插件包化 + 交货文档）；文档义务两条随工单落——信任模型边界（自用 + 熟人圈，装插件 = 装任意代码）、approval 槽位可换风险自担声明；已知限制 #4 销账、#1 收窄改写随对应工单同 diff。

## Testing Decisions

- **只测外部行为**：装载后服务在册/工具可调、HTTP 响应、yml 回读结果、状态迁移终态——不测类加载器内部结构或私有协作。
- **四缝复用，零新增测试专用缝**（落盘前已出示核对，Further Notes 记录）：
  - **S1 Boot 最高缝**：插件包行全链路（装载→在册→行级拔除→依赖方回落→服务回归自动重载；yml 回写后 `Boot.from` 回读断言）。先例：`BootYmlTest`、`boot-resource-*.yml`；测试需一个最小 fat-jar fixture（打包方式属工单细节）。
  - **S2 插件装配缝**：插件中心自身逻辑（扫描、点名提取、启停）以插件形态入树测——**声明闸门只在插件上下文生效**（M34 三盲教训：root 上下文测试绿而生产断链），先例 `WebPluginAssemblyTest` 形态。
  - **S3 Web HTTP 缝**：贡献口端点 + 插件中心 API 走装配后 Web 树实测，含鉴权负路径（无 token 401、fail-closed）。先例：`WebSessionExportEndpointTest`、`WebFaceAuthTest`。
  - **S4 浏览器视觉缝**：页面四区视觉与交互（红线 5），M33 百例实测形态执行，不进 CI 常态。
- **回归锁纪律**：插件异常断言沿 cause 链收集（M27 经验）；涉及服务读取的新消费方必须有"声明闸门"用例（M34 经验）；新服务发布核对 SERVICE_NAME 与视图方法名逐字一致（M24 经验）。
- **并发口径**：行级控制与依赖指纹 recheck 的交互以单线程语义测试为主；跨线程深度竞态沿用已知限制 #2 口径如实记档，不假装修复。

## Out of Scope

- **M36 全部**（换肤主题 token、工具卡片声明式模板/协议化渲染）——相邻期，版图 ADR-0037 已定盘。
- **会话事件桥**（插件可听对话内容）——显式续挂，隐私声明分级单独一期。
- **llm/session 服务化**——ADR-0037 显式维持内核独占。
- **页面上传安装、签名验签、策展仓库/兼容校验**——信任模型后补机制；sha256 仅作点名展示，不作信任锚。
- **插件间类互见、lib/ 目录依赖解析**——fat-jar 约定已裁。
- **CLI `/plugin` 命令**——后续消费 `pluginCenter` 服务即可，本期不做。
- **插件自带页面/静态资源服务、整页替换**——呈现层开放的第二、三台阶，后续期另立项。
- **全量 HMR**（配置一改自动拔-改-装）——已知限制 #1 收窄口径即本期边界。
- **yml 注释保留**——结构化重写会丢注释，排障文档明示（见 Further Notes）。
- **插件包自动升级检测**（同路径覆盖 jar 的带外感知）——升级走"停→换→装"手动路径。

## Further Notes

- **缝勾稿与四项预裁定已出示待核**：S1-S4 测试缝、`jar:` 字段方案、零副作用点名口径、页面四区、双形态示例在落盘前已完整出示；本轮用户未及逐项回复，按推荐落盘——spec 评审与各工单验收时均可调整，调整不触 ADR 裁定面。
- **资源物化是 Q5 的工程化补钉而非翻案**：ADR-0037"写回 plugins.yml 单一事实源"在"启动来源是 classpath 资源"时不成立（不可写），物化后单一事实源保真；代价 = 升级漂移靠提示对账，后续可评估合并工具。
- **yml 重写丢注释**：操作型写回按结构化重写实现（Jackson-YAML 不保注释），不是缺陷是口径；排障文档与插件中心页面提示兜底。
- **版本分支**：`1.1.0` 于工单开拆、实施启动时自 main 切出（红线 7；ADR-0037 Consequences 在案）。
- **验收口径预告**：done = 用户手动运行验收件确认（duo-acceptance 流程）；端到端叙事 = "拿到一个第三方 fat-jar → 放目录 → 页面点名 → 装 → 热生效 → 换 approval → 卸载干净"全程不重启。
