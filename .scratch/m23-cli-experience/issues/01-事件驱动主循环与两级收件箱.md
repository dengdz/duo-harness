# 01: 事件驱动主循环与两级收件箱

## What to build

CLI 主循环从阻塞 readLine 改为事件驱动：虚拟线程常驻读 stdin，每行注入 agent 域收件箱；收件箱由 M19 单级升级为两级——`next-step`（step 边界注入当前 turn，CLI 执行期键入的默认去处）与 `next-turn`（turn 收口后生效，承载内部事件与显式排队消息）。端到端行为：CLI 用户在 agent 执行期间键入一行，提示行回显「已插队」，模型在下一步边界即看到该输入（会话日志落普通 user/message）——执行期输入不再被静默当新输入消费。想开全新任务的用户走 02 的暂停。Web 端 busy 注入 202 路径行为不变（既有 seam 演进，向后兼容）。

决策依据：ADR-0025 决策一（事件驱动主循环与两级收件箱）；spec「架构底座」节；探测文档 docs/research/DSH/ZCode 的 Agent循环与状态机.md（收件箱两级与 step 边界消费语义）。收件箱为内存态，不做事件溯源持久化。不引 NIO/jline。

| 步 | 你做什么 | 应出现 |
|---|---|---|
| 1 | 启动后等 `你> ` 提示符 | `会话 xxx（工具循环上下文）。/exit 退出，/new 开新话题。` |
| 2 | 输入：`用 glob 列出 docs/adr 下的 md 文件，然后逐个读前 3 个，最后每份用一句话总结` | 模型开始跑：`[调工具] glob …` 等叙述行陆续出现 |
| 3 | **趁模型还在跑工具时**，输入：`纠偏：第三个不用读了，只总结前两个` | **`[已插队] 纠偏：第三个不用读了，只总结前两个（下一步边界生效）`** ← 本工单核心验收行 |
| 4 | 等模型跑完 | 模型读完前两个后**不再读第三个**，总结只覆盖两份（纠偏生效） |
| 5 | 再发起一个会跑 bash 的任务（如 `用 bash 执行 echo hello`）；趁执行中输入 `/permission` | 立即显示 `当前预设: …`（busySafe 命令执行期即行） |
| 6 | 趁执行中输入 `/exit` | `agent 执行中，需等待空闲后再执行该命令。`（非 busySafe 被拒，不再静默吞输入） |
| 7 | bash 审批弹出时按 `y` | `[待审批] 工具 bash …` → y 放行、n/回车拒绝（应答闸门没抢输入） |
| 8 | 空闲后 `/exit` | `=== 对话结束 ===` 正常收尾 |

**核心判据**：步骤 3 的 `[已插队]` 回显 + 步骤 4 的行为改变——修复前这两步的输入会被静默吞掉当下一轮新输入。任一行不符即验收不过，回修复回路。

### 阻断（第一轮双轴发现，均已修复）

- **`CliPlugin` EOF 后审批挂死**——读者线程 EOF 仅对「当时已在飞」的应答补终止行；若 turn 随后才发起审批，`take()` 永久阻塞（旧实现 readLine 返 null 必然 fail-closed）。修复：AnswerGate 增 closed 标志，EOF/stop 置位后取行立即 fail-closed（含 200ms 轮询出口）。
- **`CliPlugin.startTurn` turn 线程登记窗口**——`turnThread` 在 `start()` 后赋值，stop 有漏打断刚启动 turn 的窗口。修复：unstarted 先登记后启动（NEW 态 interrupt 为无害空操作），停止后不启动并就地复位 busy。
- **`CliPlugin.runOneTurn` 只捕 PluginException**——RuntimeException 令 turn 线程静默死亡。修复：补 catch 收敛为错误行。

### 建议（不修，记档）

- **`CliPlugin.handleLine` 参数堆（Data Clumps 判断题）**：commands/skills/holder/agentHolder/agentBusy 六参随方法传递——沿仓库既有长参装配风格（registerCommands 同款），不收拢。
- **应答闸门残留行边界**：pending 清除与读者查询间的微窗内同窗口连投两行时，第二行留队列被下次审批误取——真实输入秒级 vs 窗口微秒级，正式的应答排队语义归工单 03（审批小队列）。
