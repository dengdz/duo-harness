# M25 · 上下文与记忆：长会话记得住

Status: drafted（2026-09-25，grill 五问收敛后落 spec；主题与范围依据 ADR-0024 M25 节，探测依据 docs/research/ZCode/LLM与上下文/ 工单 10（系统提示与上下文工程）、11（压缩治理）；裁定来源见 Implementation Decisions 逐条标注）

## Problem Statement

长会话与跨会话的两个记忆缺口：

1. **聊得越久忘得越早**：上下文窗口有限，长对话逼近上限时当前只有「整段总结压缩」一条路——要额外花一次模型调用（慢、贵），且压缩粒度粗、早期细节丢失后不可恢复。用户在长开发会话中后期的体验是：AI 对开头交代过的约束开始「失忆」，或压缩一次后关键细节没了。
2. **换个会话从零开始**：会话之间没有任何记忆载体——项目背景、用户偏好、上次的决策，每次新会话都要重新交代。用户的多日项目开发体验是「每天都要自我介绍一遍」。

## Solution

按 ADR-0024 M25 规划交付三件事（用户 grill 裁定三件全做）：

1. **memory 域最小形态（记忆本）**：项目级 `.duo/MEMORY.md`（不入 git）作为跨会话记忆本；会话中模型显式写入（更新 MEMORY.md 索引内容），每次请求将其注入模型上下文（meta_user 通道、system 规范段 + 索引）。解决「换会话失忆」。
2. **microcompact 免模型本地裁剪**：对话历史逼近窗口时，不劳烦模型总结，程序直接裁掉早期轮次、保留最近 N 组完整对话；媒体与错误内容豁免；配压缩熔断计数与 summary 预算隔离。解决「聊久了又慢又贵」。
3. **cacheControl 三级断点 + AGENTS.md 链升级**：对可缓存的稳定前缀（身份段/稳定身份段）打缓存断点省 token 提速；AGENTS.md 注入迁移到 meta_user 通道并支持嵌套子目录链（顺带销 M7#3 限制挂账）。

## User Stories

1. 作为重度长会话用户，我在会话中说过的关键约束在对话后段仍被遵守，以便不用反复重申
2. 作为长会话用户，对话超长时系统自动裁剪早期内容且保留最近几轮完整可用，以便不中断工作节奏
3. 作为长会话用户，裁剪动作不额外花费模型调用，以便省钱且不等待
4. 作为长会话用户，错误信息与媒体引用在被裁剪内容中被豁免保留，以便不丢失排障依据
5. 作为用户，我可以在会话中让 AI「记住这件事」，并在下次新会话中看到它生效，以便跨会话延续上下文
6. 作为用户，我的记忆本存在本项目目录下且不会被提交到 git，以便个人偏好不入库
7. 作为用户，我可以直接编辑 MEMORY.md 增删记忆条目，以便完全掌控 AI 记了什么
8. 作为多项目用户，不同项目各有独立记忆本，以便项目间互不串味
9. 作为用户，新会话开始时记忆本内容自动生效，无需任何手动操作，以便零负担
10. 作为用户，记忆注入占据的上下文有预算上限，以便记忆本膨胀不挤占工作空间
11. 作为用户，我重复发送的每轮对话中固定内容（身份/配置段）享受 provider 缓存，以便省钱提速
12. 作为多目录仓库的开发者，我在子目录放置的 AGENTS.md 会被对应目录下的操作加载，以便目录级约定生效
13. 作为用户，我确认缓存断点在切换模型/会话后行为可预期（断点失效自然回源），以便无隐性成本惊喜
14. 作为依赖压缩功能的用户，microcompact 与既有 summary 压缩并存且互不干扰，以便平滑过渡
15. 作为用户，压缩连续失败时有熔断计数兜底，以便不会陷入压缩循环卡死会话
16. 作为关心 token 成本的用户，我能在用量统计中看到缓存命中带来的计费差异，以便验证省钱效果
17. 作为代码阅读者，memory 域的实现遵循既有架构（插件化/服务域/会话事件），以便维护成本可控
18. 作为用户，MEMORY.md 不存在时功能静默降级（无注入、无报错），以便未启用记忆的用户零感知
19. 作为升级用户，0.19.x 的既有会话在 M25 后可正常继续使用，以便无迁移负担
20. 作为团队协作者（未来），记忆本不入 git 的决定使仓库历史不受个人记忆噪声污染

## Implementation Decisions

以下每条来自 2026-09-25 grill 会话的用户裁定（编号对应对话顺序）：

1. **主题与范围**：M25 按 ADR-0024 既定主题「上下文与记忆」三件全做（记忆本 / microcompact / cacheControl + AGENTS.md 链），体量预期 8~11 张工单。
2. **发布手续前置**：开工先给 0.19.0 盖章发布（CHANGELOG 去「未发布」标注 + 打 `v0.19.0` tag + 推送），再切 `0.20.0` 版本分支——干净锚点开新里程碑。
3. **记忆写入语义：最小版只做 B（会话中模型显式写）**；自动抽取子代理（A）作为可选增强排 M25 后段，做不完挂账下期——自动抽取的触发时机与噪声治理是独立难题，不拖累主线。
4. **记忆本位置：项目级 `.duo/MEMORY.md` + 不入 git**（.gitignore）；全局层与团队共享留待以后按需。模型显式写 + 用户可直接编辑；不存在时静默降级。
5. **microcompact 形态**（承 ADR-0024）：保最近 N 组完整对话（N 与触发阈值 spec/工单期定）；媒体与错误豁免；压缩熔断计数（连续失败兜底）；summary 压缩预算隔离（与 microcompact 互不干扰，用户故事 14/15）。
6. **cacheControl 三级断点**（身份前缀 / 稳定身份 / 动态段）+ AGENTS.md 迁 meta_user 通道 + 嵌套子目录 AGENTS.md 链（M7#3 搭车销账，随加载链同改）——按 ADR-0024 原文，断点的 provider 适配差异在工单期按探测文档（工单 10）落地。
7. **术语表**：新增词条（memory 记忆本、microcompact、cacheControl 断点）随实现同 diff 落术语表；红线 9 用词约束全程适用。
8. **写法约束**：M25 期间新增/修改的技能与文档遵循《技能写作规范》与红线 9（C1 交付即为 M25 前置约束）。

## Testing Decisions

- **好测试口径**：行为经公共接口验证，不测实现细节；核心逻辑（裁剪算法、断点划分、注入预算）走 tdd 红绿循环，seam 先与用户确认。
- **测试模块**：session（裁剪与历史管理）、llm/adapter（cacheControl 参数与 provider 映射）、context/builder（注入通道与预算）、web/CLI（记忆生效端到端）。
- **先例**：M24 的装配级测试（Boot.from + @TempDir + 属性覆盖）、M10/M13 压缩相关测试（summary 压缩既有套件是 microcompact 的并存对照）。
- **验收 seam**：memory = 会话中显式写 → 新会话注入生效的端到端演示；microcompact = 超长对话裁剪行为 + 豁免保留的叙述输出；cacheControl = 请求断言（断点位置）+ 用量差异演示。

## Out of Scope

- 自动抽取子代理（A）的完整实现——可选增强挂账（触发时机与噪声治理独立难题）
- 全局记忆层（~/.duo/MEMORY.md 跨项目）与团队共享入库——留待以后按需
- MEMORY.md 的格式治理与冲突合并（多人编辑场景不存在——不入库）
- M26 的 FTS5 检索、/export 增强、会话文件版本头（随 M26 或搭车项另议）
- provider 缓存计费的实际计费策略（只做断点与用量透出，计费由 provider 决定）
