## 阻断（P1）

- **`ContextGovernance.java:339-340`**（Standards）— manual 压缩缺空摘要防护：`compactNow` 摘要生成后直接落压缩点，LLM 返回空白时投影 `messages.clear()` 后只剩空摘要——整个会话上下文被摧毁（auto 路径有 isBlank 防护，两触发路径 fail 语义分裂）。
- **`ContextGovernance.java:313-318` 对照 `Session.java:423-431`**（Standards，复核后升格）— 压缩"一处语义两处触发"未闭合：治理返回值保留近端 20% 原文，但压缩点事件落日志末尾，**下一轮投影重放遇压缩点 clear 全部**——keepRecentRatio 只对压缩当轮生效，模型视野相邻两轮无故缩水；且近端 20% 未被总结即被投影丢弃，构成信息丢失。与 ADR-0020 决策 6"投影 = 最后压缩点之前以总结替换、之后照常"直接矛盾：正确语义是**总结输入 = 压缩点之前全部历史**，无切分、无保留比例（keepRecentRatio 属请求期变换时代的残留概念）。

## 建议（P2）

- **`PresenterAssembly.java:303-305`** — `restorePermissionMode` 对非法档位串未防 `IllegalArgumentException`（占用继承路径同数据源已防），坏会话文件致呈现位 FAILED；服务解析异常又被静默吞且无日志。
- **`PresenterAssembly.java:344`（WebFace.handleCommand）** — /compact 只有调用时点 busy 检查、无执行期互斥：压缩摘要走 LLM 可达数十秒，期间用户可发消息启动 agent，压缩点 append 与 agent 轮次交错致投影结构错乱（Web 是并发入口，CLI 单线程无此窗口）。
- **`WebFace.java:499-522`** — Web /compact 同步执行于 HTTP 线程，LLM 摘要无超时兜底，前端可长挂数分钟；异步化（202 受理 + 结果经既有 command/done 事件流）属结构性改造，本期记 backlog。
- **`InteractionRegistry.java:44-55`** — 发起方放弃作答权后注册序全遍历未跳过发起方，同一 answerer 被调两次（当前实现幂等未酿 bug，但违反 Answerer"null = 让渡"语义）。
- **`ExitPlanModeTool.java:69-76`** — sessionFor 回退"任一在册供给"取 ConcurrentHashMap 迭代首元素，plan/mode 事件落点随机（"计划状态串位"的残余形态）。
- **`WorkspaceGatePolicy.java:45-57`** — 三参 decide 与二参 decide 方法体逐行复制（应反向委托消重）。
- **`CliPlugin.java:203,320,352` + `CommandsRegistry.java:104`** — 全限定名冗余（PresenterAssembly 已 import）与两语句挤一行。
