## 台账

### P-01 命令分发族｜裁定：不改（策略已在位）

- 现状：`CommandsRegistry.dispatch` 是完整的命令模式——注册表 + 名称查找 + scope 审查 + busy 审查 + run/done 审计事件 + handler 回调收敛；CLI（REPL）、Web（输入框）、技能直调三面共享同一入口（M19/M20 统一）。
- 检查点：CliPlugin 内 `/permission rules`、`/plan off`、`/model models|effort` 为 handler **内部**子分发（≤3 子命令级），属局部控制流非跨域模式缺失。
- 理由：抽「子命令子注册表」在当前规模是过度设计；膨胀触发点挂观察——单命令子分发 ≥4 个或子命令跨呈现位语义分化时再收敛为表驱动。

### P-02 provider 映射｜裁定：不改（最小工厂形态）

- 现状：`LlmAdapters.withRetry(config)` 单点三目——anthropic → Anthropic-messages，openai-compat/deepseek/glm → OpenAI 兼容面（4 provider 值 → 2 适配器）；重试装饰同构收尾。
- 理由：二分支三目即最小合宜形态，改注册表是仪式化；膨胀触发点挂观察——适配器 ≥3 个（如 google-native）或 provider 声明值 ≥5 时改声明式映射表。

### P-03 ObjectMapper 散布（补充扫描）｜裁定：不改，挂账 backlog

- 现状：`new ObjectMapper()` 全仓主源码 **23 处静态实例、23 个文件**（每文件一个私有常量）——「重量级对象每类自建」的模式噪音。
- 理由：收敛为共享 mapper 需先逐处核查配置差异（任一处 configure 过特性即不能共享，共享即行为变更）——23 文件的核查与机械替换体量超出收益（无行为缺陷，纯噪音）；按步子红线 2 记档不修。
- 归宿：backlog 新条目「共享 JsonMapper 收敛（含配置差异核查）」，1.0 后按需。

### P-04 装配层工厂形态｜裁定：不改（单点静态工厂已在位）

- 现状：装配面均为「单点静态工厂」——`PresenterAssembly`（呈现位共享装配器，ADR-0011）、`LlmAdapters`（llm 契约包工厂）、`Session.create` 等；接线三连抄病灶已由 M27 扫描册 H-09 收录，工单 04 处理中（本册不重复）。
- 检查点：Boot 装载域（行解析/problems 点名）形态问题属 H-08/H-16，已裁 1.0 后，跳过。
