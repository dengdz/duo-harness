# 02: awaitStartup 可配超时 + 静默等待点名

**What to build:** 编程挂载的开发者用 `awaitStartup(Duration)` 限时等待——超时拿到点名缺失服务的异常，快速失败且知道在等谁；无参版语义不变（服务晚到会被唤醒是合法模式），但进入等待时日志点名，"静默卡死"从根上消失。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

语义权威：ADR-0019 决策 10/12；backlog 搭车原文"测试进程收割随 awaitStartup 超时语义一并评估"。

- [ ] 新增重载 `awaitStartup(Duration timeout)`：超时抛点名异常，消息含缺失服务清单（"缺失服务： a, b"——与 BootLoader 审计文案同源，缺失清单逻辑与 01 的抽取共用，不重写）
- [ ] 超时后插件保持 PENDING：后台服务就绪照常激活，再次 await 可成功；异常沿调用方路径走（apply 内抛 = 只杀本实例，容器既有语义承接）
- [ ] 无参版语义不变（无限等待），进入等待时打一条 INFO 日志点名在等哪些服务
- [ ] 超时来源 = 调用方传参，不加全局配置键
- [ ] 测试进程收割限时评估（backlog 搭车项）：结论二选一——方案很小顺手修（带修复与测试），或方案与规模写清继续挂账；不无限展开
- [ ] 测试走接缝 B（编程 API）：超时异常点名、超时后激活仍可达、无参版等待日志可见
