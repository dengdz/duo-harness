# BUG-20260926-02 · ChatReplMain LLM 调用 HTTP 404（疑环境配置过期）

**Status**: reported

## 症状（建档时记录）
- 发现于：M26 工单 01 用户手动验收（2026-09-26 13:47，ChatReplMain 官方命令）
- 原样引用（用户终端输出）：

  ```
  你> mohao
  AI>   [错误] LLM 调用失败: HTTP 404 - 
  ```

- 复现方式：`mvn -pl duo-harness-example -am package exec:java -DskipTests -Dexec.mainClass=dev.duo.harness.example.chat.ChatReplMain` 启动 → `/new` 开新会话 → 随便输入一句话 → AI 行报 404；REPL 不崩、提示符仍在（错误收敛正常）。
- 伴随事实：同次验收中 v0 旧会话续接正常（继续会话 20260912-160555-502c，已有 6 条消息）、`/new` 新会话创建正常（20260926-134659-cafa）——会话层行为全部符合 M26-01 预期。

## 排查记录（定位过程，逐步追加）
- 假设 1：M26-01 版本头改动引入 → 验证：工单 01 diff 全清单（Session/SessionFormat/WebPlugin/CliPlugin/SubagentManager/example/测试/CHANGELOG）无 LLM 请求路径文件；请求组装基于 deriveMessages(events)、版本头经 load 分流不进 events → 结论：**排除**
- 假设 2：~/.duo/config.yml 的 LLM 端点或模型名过期（404 = 请求已到达服务端、资源不存在；与"连不上"的连接错误不同）→ 验证：config 非密钥字段 = `provider: anthropic` + `baseUrl: https://api.deepseek.com/anthropic` + `model: deepseek-flash`——端点路由存在（否则不是 404 形态），疑 `deepseek-flash` 模型名在该端点不可用（改名/下线）→ 结论：**高度倾向成立，待用户在 DeepSeek 侧核对当前可用模型名**
- 备注：2026-09-25 M25-02 验收时 LLM 正常应答（同环境）——模型名失效发生在其后的窗口内（服务商侧变更或配置改动）。
- 排查过程事故记档：查 config 时密钥过滤命令漏大小写（`apiKey` 大写 K 未被 `grep -v "key"` 排除），key 在会话输出中暴露过一次——未写入任何文件；已提示用户轮换。

## 根因（定位后填写）
（初判：环境问题——config 的 `model: deepseek-flash` 在 DeepSeek anthropic 兼容端点返回 404，模型名疑似过期。非仓库可修缺陷；若用户确认模型名无误再深挖。可顺带改进项（非本 bug 根因）：LLM 失败的错误提示未携带 model/endpoint，用户无法从 `HTTP 404 - ` 空尾判断哪个资源不存在——可另立改进项）
