# BUG-20260914-01 · 切换会话后消息"丢失"——switch 换绑不重建 agent（分脑）

**Status**: closed（2026-09-14 根治修复 + WebFaceTest 断言锁定；待用户复验）

## 症状（用户验收报告原样）

- "有的时候我输之后，看不到我已经发出的消息气泡，并且回复的内容也会卡住，光标闪烁……刷新后会丢失。切换会话后，又能看到最新的消息内容。"
- 复验补充："重启应用后，也丢掉了相关的内容。"
- 关键鉴别点：**消息在另一个会话里能找到** → 数据已落盘，落错了会话。

## 根因（分脑）

`POST /api/session/switch` 只换绑了 WebFace 的会话引用（SSE 推送源 + 回放源），**没有重建 agent**——`ToolCallingAgent` 持有 final 会话引用，仍往切换前的会话写。结果：

- 用户消息 / assistant 消息落在**旧会话**（agent 写）
- 页面显示 / 刷新回放的是**新会话**（WebFace 写）
- → "看不到自己发的消息"；刷新回放新会话自然没有它（"丢失"）；切到旧会话就看见了（"切换后又能看到"）

排查途中连带发现并修复的独立缺陷（非本条主因，但同域）：`Session.events()` 返回活列表视图，流式追加期间并发回放会抛 ConcurrentModificationException 打断 SSE 回放——已改快照语义（`List.copyOf`），SessionTest 补快照用例；客户端 EventSource `onopen` 复位回放门并清空渲染区（重连幂等重建）；/api/events 回放 catch 收宽到 Exception。

## 修复

1. WebFace：会话变更回调泛化为 `onSessionChanged(Consumer<Session>)`——/new 与 /switch 换绑后**都**回调，装配层（WebPlugin）以换绑会话重建 agent
2. WebPlugin 接线拆分：`onNewSession(supplier)` + `onSessionChanged(fresh -> setAgent(new ToolCallingAgent(adapter, tools, fresh, prompts)))`
3. WebFaceTest：`sessionNewCreatesFreshSession` 补回调断言；新增 `sessionSwitchRebindsAndNotifiesRebuild`（switch 后 currentSession 换绑 + 回调以换绑会话触发）

## 防复发

- "换绑会话"与"重建 agent"是同一个动作的两面——凡新增换会话端点必须走同一回调，靠 WebFaceTest 的回调断言锁定
- 多入口（多标签/多页面）共用一个"服务端当前会话"，单入口约定仍是前提（见运行Demo M8 段）
