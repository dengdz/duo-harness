# BUG-20260917-02 · 契约演示测试断言第三方校验器中文文案——CI 英文 locale 下必败

**Status**: fixing（CI 重跑绿后置 done）

## 症状（建档时记录）
- 发现于：M16 工单 01——CI run #7 首次跑通全部前序模块后，example 模块快速失败（2.4s）
- 原样引用（CI 诊断注释，ContractGuardDemoMainTest）：
  - `org.opentest4j.AssertionFailedError:`（叙事上下文含 `[被拒] 工具 "search" 输出违约: integer found, string expected`）
  - 断言为 `assertTrue(output.contains("输出违约: 已找到 integer，必须是 string"), output)`
- 复现方式：CI（ubuntu，JVM 缺省 locale en）必败；本机（zh_CN）恒绿

## 排查记录
- 假设 1：demo 本体在 Linux 上行为不同 → 验证：诊断注释显示 demo 叙事完整输出到第三幕前，违约确实被点名拦截——行为正确，只是**文案语言**不同 → 排除行为差异
- 假设 2：违约文案出自 duo 自产代码 → 验证：`integer found, string expected` 是 networknt json-schema-validator 的 ValidationMessage（i18n 资源包按 JVM 缺省 locale 选取；本机 zh_CN 命中中文包、CI en 命中英文包）→ 成立

## 根因
测试断言写死了**第三方库的 locale 相关文案**（networknt 校验消息文本），而非 duo 自产的稳定前缀。CI 与本机 JVM 缺省 locale 不同（en vs zh_CN）导致同一行为产出不同文案，断言必败。

## 修复方案
断言改为只锚定 duo 自产前缀 `工具 "search" 输出违约`（产品常量，跨 locale 稳定），不再绑定校验器具体措辞——冒烟语义（"违约被点名拦截"）不变。

## 修复与验证
- 改动：ContractGuardDemoMainTest 一处断言
- 回归测试：本机 example 模块全量绿；CI 重跑绿（待推送验证）
- 防复发：**测试断言禁止绑定第三方库的 locale 相关文案**（ duo 自产消息或 locale 无关锚点）；CI 门禁对 locale 敏感用例的持续防线
