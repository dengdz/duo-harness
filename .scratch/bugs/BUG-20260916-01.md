# BUG-20260916-01 · 切换会话后发消息必报错——会话变更回调单槽被标题接线覆盖（分脑回归）

**Status**: done（2026-09-16 内置浏览器重验通过——切换后发消息正常回复、无执行异常卡；全程无"状态刷新失败"toast；切换清空输入框生效。同族第二次（0914-01/本案）已升结构化防线：onSessionChanged 单槽调用点唯一性纳入审查维度）

## 症状（建档时记录）

- 发现于：M13 批次验收（工单 02-06 合并验收，用户手动验证）
- 原样引用：
  > 切换会话时，会提示状态刷新失败。输入框输入字符。不管切换到哪个会话，它都会在输入框里显示。输入对话，回车后报错。⚠ 执行异常 消息处理失败，详情见服务端日志 ⚠ 执行异常 消息处理失败，详情见服务端日志
- 复现方式：Web 面切换会话 → 发消息 → 每次报"执行异常：消息处理失败，详情见服务端日志"；切换时伴随"状态刷新失败"toast

## 排查记录（定位过程，逐步追加）

- 假设 A（现象 3）：工单 06 接线把 `onSessionChanged` 的**单回调槽覆盖**——WebPlugin.apply 先注册"换绑重建 agent"回调、后又注册"标题 attach"回调，后者覆盖前者 → 切换后 agent 不重建（ToolCallingAgent 持 final 旧会话引用），发消息写**已 close 的旧会话** → append 抛 IllegalStateException → "消息处理失败" → **验证：读 WebPlugin.apply 确认两次 onSessionChanged 调用（onSessionChanged 是 volatile 单槽覆盖式 setter），且 BUG-20260914-01 的机制（换绑不重建即分脑）精确吻合 → 成立**
- 假设 B（现象 1"状态刷新失败"）：/api/status 服务端 500 → **验证：隔离环境（DUO_HOME=/tmp + 假 LLM env + 端口 18081）构造 30 条消息会话，切换 + 30 并发 status 请求全部 200、服务端日志无异常 → 服务端 500 不成立**。次级假设：回放期逐帧 `refreshStatus()` 造成瞬时 fetch 风暴（50 帧 50 次并发 fetch），浏览器同源 6 连接下与 keep-alive 复用竞态偶发 reject——无法本地实锤（需浏览器 Network 面板），按健壮性修复处理（回放期节流），观测点留验收
- 假设 C（现象 2 输入框字符跨会话保留）：工单 03"输入框与页面状态保留"为设计行为（保留 = 页面不重载的副产品）——用户验收反馈明确该行为是干扰（未发送的字符属原会话语境），按裁定改为**切换/新建时清空输入框**

## 根因（定位后填写）

现象 3（机制层）：`WebFace.onSessionChanged` 是单回调槽（volatile Consumer 覆盖式 setter，非多播列表）。工单 06 在 WebPlugin.apply 追加第二处注册，覆盖了 BUG-20260914-01 建立的"换绑重建 agent"回调——切换后 agent 仍持旧会话，旧会话已 close，发消息 append 即抛，页面呈现"消息处理失败"。**同族警示：这是分脑根因（0914-01）的第二次出现，形态是"新增回调接线覆盖既有回调"——单槽 setter 的调用点必须全局唯一。**

## 修复方案（计划，改前填写）

- WebPlugin.apply：合并为单次 onSessionChanged 注册（回调体内 setAgent + SessionTitles.attach 两件事都做），代码结构上消除覆盖可能
- 现象 1：回放期逐帧 refreshStatus 合并到 replay/done 一次（sse.replaying 状态门控）——消除 fetch 风暴，兼降竞态概率
- 现象 2：切换与新建成功路径清空输入框
- 防复发：单槽回调教训写入 WebPlugin 注册点注释；验收对照表补"切换后发消息"

## 修复与验证

- 改动（2026-09-16）：WebPlugin.apply 回调合并（单次注册）；app.js 回放期状态刷新节流 + 切换/新建清空输入框
- 验证：隔离环境（隔离 DUO_HOME + 假 LLM + 18081）跑用户操作链——发消息 → 新建 → 切换回 → 再发消息：第二条 user/message **正确落到切换后的目标会话**（agent 重建生效，修复前会抛 IllegalStateException）；WebFaceTest 32 / CliPluginTest 7 / WebPluginAssemblyTest 1 全绿；node --check 过
- 防复发：单槽回调教训注释钉在注册点；"切换后发消息"纳入验收对照表常设项。同族两次（0914-01、本案）→ 结构化防线：**WebFace.onSessionChanged 的调用点审查纳入 duo-code-review 手工维度（换绑链新增行为必须进既有回调体，不得新增注册）**
