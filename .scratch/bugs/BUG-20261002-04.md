# BUG-20261002-04 · 提问卡回放作答状态丢失——答案藏折叠卡体行面不可见

**Status**: done（2026-10-02 M34 工单 03 修复：答案摘要行面可见化；浏览器面回归验证通过。标题口径随根因实钉修正——[提问] 行不回放为 M29 裁定形态非缺陷）

## 症状（建档时记录）

- 发现于：M33 批 3 执行（CARDS-15 回放一致性）
- 原样引用（刷新前后 DOM 计数，2026-10-02）：

```
刷前: {"answered":1,"approved":3,"len":1416,"questions":1,"rejected":1}
刷后: {"answered":0,"approved":3,"len":1377,"questions":0,"rejected":1}
```

  - 实时形态：`[提问] 你想喝茶还是咖啡？` + `✓ 已回答：茶`（含作答状态）
  - 回放形态：仅剩底层「询问用户」工具卡（问题文本在卡内），`[提问]` 行与 `✓ 已回答：茶` 作答状态消失
  - 审批卡对照：`✓ 已批准`/`✗ 已拒绝` 回放计数完全一致——提问卡是唯一回放不完整的交互卡型
- 复现方式：ask_user 提问 → 作答 → 刷新页面 → 观察提问区域
- 关联背景：BUG-20260929-01 修复记录「实时流的完成时 tool/call 以 replaying 标志门卫跳过（消重复卡，回放保留出卡）」——本缺陷为该修复的回放面不完整形态（出卡保留了底层工具卡，提问/作答状态行未保留）

## 排查记录（定位过程，逐步追加）

- 假设 1：replaying 门卫把 question/requested 事件与作答状态行一并跳过（防重复卡的门卫口径过宽）→ 验证：回放区原文实读（批 3 报告证据）——question/requested 行不在、ask_user tool/call 卡在 → 结论：方向成立，门卫分支与作答状态事件的回放路径待修复批实钉

## 根因（定位后填写）

实钉修正（2026-10-02 M34 工单 03，档案标题口径一并修正）：**[提问] 行不回放是 M29 工单 12 的用户裁定形态而非缺陷**——回放期 ask_user 由 tool/call 渲染 askFrozenLine 冻结行（「询问用户 + 问题」行面可见，按 call id 注册），question/requested 被门卫跳过属裁定内。**实质缺陷收窄为：作答状态丢失**——tool/result 的回答 `.ask-frozen-a` 被 append 进 askFrozenLine 的 `.tcard-body`（display:none 折叠体），行面（tcard-primary）只有问题无答案——用户刷新后看不到「茶」这个作答。DOM 实证：回放后 `.ask-frozen-a`（「茶」）在 DOM 中存在但不可见。

## 修复方案（计划，改前填写）

已执行（M34 工单 03，收窄后口径）：toolResult 的 frozen 分支按冻结形态分流——有 `.tcard-body`（askFrozenLine 行卡）：答案入折叠体留全文，**同时把答案摘要写进行卡 primary（「问题 ｜ 答：茶」）行面可见**；无 body（其他冻结形态）：行内补「✓ 已回答：…」。question/requested 的回放跳过维持 M29 裁定不动。

## 修复与验证

- 改动：app.js toolResult frozen 分支一处（答案行面可见化 + 无 body 形态兜底）
- 回归测试：浏览器面（M33 口径）——ask_user 实时作答「茶」→ 刷新 → 回放行卡 primary = 「你想喝茶还是咖啡？ ｜ 答：茶」（行面可见）；证据 `.scratch/m34-1.0.1-fixes/evidence/工单03-BUG04-回放行面答案.png`。注：[提问]/✓已回答 标记行差为 M29 裁定形态（冻结行卡），非缺陷面——M33 报告该例的对比标记口径随本档案修正
- 防复发：答案行面可见化入库；「回放态与实时态的信息等价性」列入前端改动 review 关注
