# BUG-20260925-02 · 记忆注入已生效但模型首轮仍先 read 文件再回答（guide 提示词缺指令性）

**Status**: reported → investigating → fixing → verifying（待用户复验采信层） → done

## 症状（建档时记录）
- 发现于：M25 工单 02 用户手动验收（0.20.0 分支，提交 3c41abc，AgentRepl CLI）
- 原样引用（用户验收实录逐字）：
  - 新会话首问 `我的记忆本里记了什么？`，模型先走工具：
    > `[调工具] read {"path": ".duo/MEMORY.md"}` → 读到两条后才作答
  - 同会话次问 `我最喜欢的数字是几？`（用户已另终端把记忆改为 `- 我最喜欢的数字是 42`），模型**未调工具**直接答：
    > `按本轮注入的 \`<memory>\` 段，记的是 **42**。`
    > 但有个不一致要提醒你：我刚读 `.duo/MEMORY.md`，文件里实际只有两条……**没有 42 这条**。所以注入段与文件内容对不上
- 复现方式：手写 MEMORY.md 两条 → AgentRepl 新会话（/new）→ 问"我的记忆本里记了什么？"

## 排查记录（定位过程）
- 假设 1：meta_user 注入未生效，模型只能靠 read 兜底 → 验证：次问模型零工具调用、明确引用"本轮注入的 `<memory>` 段"答出 42（该内容未重启即达模型，现读语义同时得证）→ 结论：**排除**（注入通道工作正常）。
- 假设 2：装配时序差异导致首问时注入缺席 → 验证：注入是每请求现读（MemoryBook.read 无缓存），同进程同装配路径，首问与次问无机制差异；假设 1 的证据同样适用于首问时刻 → 结论：**排除**。
- 假设 3：guide 规范段措辞为信息性而非指令性 → 验证：GUIDE_TEXT 只陈述"其当前内容每轮请求以 <memory> 段注入"，没有"直接引用注入段、无需读取文件"的行为指令；header 免责语"可能过时"在对话历史存在过期 read 结果时被模型反向归因（拿首轮的过期文件内容质疑本轮的新鲜注入段）→ 结论：**成立**。

## 根因（机制层）
`<memory>` 注入段与 memory-guide 规范段都是**描述性**提示（"内容会注入"），不构成模型的行为约束——模型面对"记忆本里记了什么"这类问题保留了验证性读取的自由度（read 一次也不违反任何提示）；同时 header 的"可能过时"免责语没有锚定参照点，对话历史里存在更早的文件读取结果时，模型把"过时"错误归因到本轮新鲜注入段上（实际过时的是历史 read 结果）。注入管道（送达）与模型行为（采信并直接使用）是两层契约，本单只交付并验证了前一层。

## 修复方案（改前落盘）
纯提示词文本修复，零逻辑改动：
1. `MemoryPlugin.GUIDE_TEXT`：增指令句——回答与记忆本内容相关的问题时直接引用本轮 `<memory>` 段，它是当前最新内容，无需再读取文件（除非用户明确要求看文件本身）。
2. `MemoryBook.metaUserSection` header：把"跨会话持久的记忆，可能过时"改为锚定参照点的形态——"本段为本轮最新内容"（保留"与用户当前指令冲突时以用户为准"的权威序）。
3. 影响面：两处常量/拼接文本；MemoryBookTest 断言 `contains("以用户为准")` 不受影响。

## 修复与验证
- 改动：MemoryPlugin.java GUIDE_TEXT（增指令句"直接引用本轮 <memory> 段作答……无需再读取该文件"）、MemoryBook.java metaUserSection header（"本轮最新内容"锚定参照点，删无锚定的"可能过时"）
- 回归测试：Memory 三套件 12 用例全绿（2026-09-25，含 metaUser 组装断言"以用户为准"不变）
- 防复发三问：
  ① 回归测试锁住了吗——注入**送达**已由 MemoryInjectionTest 锁定；"模型**采信**注入段不再读文件"是真实模型行为，单测（mock 适配器）原理上锁不住。
  ② mock 验证不到的差距——**是**：送达 ≠ 采信。处置：验收对照表补真实场景——用户复验一条命令（重启 CLI → /new → 问"我的记忆本里记了什么？"→ 判据 = 不出现 `[调工具] read`），记入工单 02 Comments。
  ③ 技能规则缺口——**是**：提示词契约要写成指令形态而非信息形态（"X 会发生"不约束行为，"做 X / 引用 X"才约束）；已落 duo-workflow experience.md（M25 工单 03 的写协议 guide 同样适用）。
