# BUG-20260917-05 · 审批阻塞窗口的并发回流插入——投影消息序列协议非法，会话每轮 400

**Status**: fixing（投影修复已实现待用户验证；写入侧预防随本 diff 记档）

## 症状（建档时记录）
- 发现于：M16 工单 03/04 用户验收——钉死与环境块行为全部正确，但整轮收尾时报
  `[错误] LLM 调用失败: HTTP 400 - An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'. (insufficient tool messages following tool_calls message)`
- 原样引用（会话 20260918-000343-c2ad 事件序，实测提取）：
  ```
  tool/call   bash  {"command": "sleep 20"}          ← 父代理调 bash 等子代理
  approval/requested bash                            ← 终端 y/n 阻塞等待人工
  subagent/completed 20260917-235400-febe ...        ← 子代理完成回流（并发线程 append）
  （bash 的 tool/result 直到 fail-closed 才落盘——已插在 completed 之后）
  ```
  此后该会话每条消息（含换新话题前的所有输入）都报同一 400。
- 复现方式：父代理发起需要审批的 bash（终端 y/n 等待人工）+ 同期子代理完成回流 append 父会话——竞态窗口命中即必现，会话从此不可续聊。

## 排查记录
- 假设 1：钉死拒绝破坏了消息配对 → 验证：子会话里拒绝以 tool/result 形态正常配对落盘 → 排除
- 假设 2：投影把 tool/call 漏配对 → 验证：会话事件序为 tool/call → **subagent/completed** → tool/result——并发 append 插进了两者之间；投影按日志序输出即 [assistant(tool_calls), user, tool]，provider 要求 tool 消息紧跟 tool_calls 消息 → **成立**

## 根因
审批阻塞（终端 y/n 等待人工）期间，工具调用的 tool/result 尚未落盘，此窗口内任何并发线程向同一会话 append 事件（子代理完成回流、异步标题等），都会插在 tool/call 与 tool/result 之间——投影出的 tool 消息与配对 assistant(tool_calls) 被 user 消息隔开，OpenAI 兼容协议拒绝该序列，会话从此每轮 400（append-only 日志使坏顺序固化）。触发条件在本仓库真实高频：父代理派子代理后用 bash sleep 等待，是最自然的模型行为。

## 修复方案（两层）
1. **投影侧修复（本次落地）**：`deriveMessages` 末尾增加工具结果紧邻修复——tool 消息前移到配对 assistant(tool_calls) 消息之后紧邻排放（同 callId 保持到达序）；无配对调用的孤儿结果不投影（无法合法安置，日志原样保留可审计）。日志不动、正常序列恒等变换，**已损坏会话就此自愈**（投影修复即续聊可用）。
2. **写入侧预防（记档不阻塞）**：并发 append 与审批窗口的交错无法从写入侧单方面消除（会话 append 线程安全、但语义顺序属投影关注点）——投影修复即完整闭环。

## 修复与验证
- 改动：`Session.deriveMessages` + `repairToolMessageAdjacency`（session 模块）
- 回归测试：`toolResultInterleavedByConcurrentAppendMovesAdjacentToItsCall`（交错序 → 修复后合法）、`orphanToolResultsWithoutCallAreDroppedFromProjection`（孤儿结果不投影）；全量 432 用例绿
- 防复发：投影级修复对所有历史损坏会话 retroactive 生效；用户验收会话（000343-c2ad）修复后即可续聊
