# BUG-20261002-07 · 会话坏行导致加载抛异常 + 锁泄漏不可再入 + 导出静默零事件

**Status**: done（2026-10-02 M34 工单 02 修复：坏行跳过计数 + 锁释放兜 RuntimeException + 导出明示；回归锁三用例绿，旧锁 loadRejectsCorruptLine 语义变更已改写并注明）

## 症状（建档时记录）

- 发现于：M33 批 5 执行（TOLER-05/06 坏行容错，夹具 = f100 副本追加 2 行坏行）
- 原样引用（实例日志栈 + 协议面，2026-10-02）：

```
Caused by: com.fasterxml.jackson.core.JsonParseException: Unrecognized token '这行不是JSON垃圾':
  at dev.duo.harness.session.Session.parse(Session.java:1187)
  （经 HTTP exchange 线程抛出——换绑请求失败）

后续再切：INFO 会话切换被拒（占用冲突）: 会话已被占用：20261002-190100-b9f0 —— HTTP 409
导出同会话：HTTP 200，正文「事件数: 0」（文件实有 222 行好事件在前、坏行在后）
```

  - 三个症状面：①UI 侧栏列表两源不一致——首刷目录态在列，索引刷新后剔除，条目从可用变不可见；②点击切换 → Session.parse 抛 JsonParseException → 换绑失败，且**锁泄漏**（此后 409 占用死锁，重启前不可再入）；③导出 HTTP 200 但**静默零事件**（222 行好事件全数漏报——交付物失真比崩溃更隐蔽）
- 复现方式：会话 JSONL 末尾追加一行非 JSON 文本 → 侧栏点击该会话（或 API 换绑）→ 观察切换失败 + 后续 409 占用 + 导出零事件

## 排查记录（定位过程，逐步追加）

- 假设 1：Session.parse 全文逐行 parse、坏行直接抛——加载路径无「跳过坏行」容错；锁在 parse 前获取、异常路径未释放 → 验证：栈实锚 Session.java:1187 + 二次切换 409 占用 + 实例日志单次 JsonParseException（异常后锁未随 finally 释放的形态吻合）→ 结论：成立度高；泄漏的具体释放缺口（load 的 try/finally 结构）待修复批实钉
- 导出侧假设 2：导出走同一 parse 语义，遇坏行整体放弃但外壳仍 200 → 验证：事件数 0 与「遇坏即弃」吻合 → 结论：成立度高，投影路径待实钉

## 根因（定位后填写）

三层实钉（2026-10-02 M34 工单 02，与档案假设的修正一并记）：①**症状①②根因**——parse(String) 内部 catch IOException 后包装为 **PluginException「会话事件解析失败」**（RuntimeException）抛出，而 load 的释放 catch **只捕 IOException**——RuntimeException 穿透逃逸，session.close() 未执行 → 锁泄漏（HELD_LOCKS 残留 → 后续 409 占用死锁）+ 整会话不可打开。假设②「锁释放缺口」精确成立，缺口形态 = catch 类型面不含 RuntimeException；②**症状③根因修正**——导出非「复用同一 parse 静默归零」，而是 `heldSession()` 命中了症状①②泄漏的**半初始化实例**（parse 抛出时 events 已部分填充但快照未建）——export 走 `session.events().size()` 渲染，0 事件的精确机制为泄漏实例状态，与「导出自身 parse 失败」不同源；③坏行的异常包装链：`JSON.readTree` 抛 JsonParseException（IOException 子类）→ parse 包装 PluginException → load 不捕 → 泄漏。

## 修复方案（计划，改前填写）

已执行（M34 工单 02）：① load 事件循环逐行 try/catch PluginException → 跳过 + `skippedCorruptLines` 计数（新增字段 + 访问器；结构损坏如重复头/头错位的显式检查在循环外保持 fail-loud 不经此处）；② load 补 `catch (RuntimeException e) { session.close(); throw e; }`（锁释放缺口补齐，异常原样上抛保持 fail-loud）；③ SessionExport.markdown 头部「坏行跳过: N 条（无法解析为事件的日志行，未计入事件数）」明示（N>0 时）+ Web 分页端点响应补 `skippedCorruptLines` 字段（协议面可见）。
