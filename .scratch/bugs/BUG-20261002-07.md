# BUG-20261002-07 · 会话坏行导致加载抛异常 + 锁泄漏不可再入 + 导出静默零事件

**Status**: reported（排查与修复归 M33 后续修复批——M33 纯测试期不修；发现于 M33 批 5 执行）

## 症状（建档时记录）

- 发现于：M33 批 5 执行（TOLER-05/06 坏行容错，夹具 = f100 副本追加 2 行坏行）
- 原样引用（实例日志栈 + 协议面，2026-10-02）：

```
Caused by: com.fasterxml.jackson.core.JsonParseException: Unrecognized token '这行不是JSON垃圾':
  at dev.duo.harness.session.Session.parse(Session.java:1187)
  （经 HTTP exchange 线程抛出——换绑请求失败）

后续再切：INFO 会话切换被拒（占用冲突）: 会话已被占用：20261002-190100-b9f0 —— HTTP 409
导出同会话：HTTP 200，正文「事件数: 0」（文件实有 222 行好事件在前、坏行在后）
```

  - 三个症状面：①UI 侧栏列表两源不一致——首刷目录态在列，索引刷新后剔除，条目从可用变不可见；②点击切换 → Session.parse 抛 JsonParseException → 换绑失败，且**锁泄漏**（此后 409 占用死锁，重启前不可再入）；③导出 HTTP 200 但**静默零事件**（222 行好事件全数漏报——交付物失真比崩溃更隐蔽）
- 复现方式：会话 JSONL 末尾追加一行非 JSON 文本 → 侧栏点击该会话（或 API 换绑）→ 观察切换失败 + 后续 409 占用 + 导出零事件

## 排查记录（定位过程，逐步追加）

- 假设 1：Session.parse 全文逐行 parse、坏行直接抛——加载路径无「跳过坏行」容错；锁在 parse 前获取、异常路径未释放 → 验证：栈实锚 Session.java:1187 + 二次切换 409 占用 + 实例日志单次 JsonParseException（异常后锁未随 finally 释放的形态吻合）→ 结论：成立度高；泄漏的具体释放缺口（load 的 try/finally 结构）待修复批实钉
- 导出侧假设 2：导出走同一 parse 语义，遇坏行整体放弃但外壳仍 200 → 验证：事件数 0 与「遇坏即弃」吻合 → 结论：成立度高，投影路径待实钉

## 根因（定位后填写）

（修复批填——机制层：parse 全文语义 + 锁释放缺口 + 导出投影复用同一 parse 的三处耦合）

## 修复方案（计划，改前填写）

（修复批填——候选口径：①parse 跳过坏行并计数标注（回放显「N 条坏行已跳过」）；②load 异常路径锁必释放；③导出对坏行计数明示而非静默归零）
