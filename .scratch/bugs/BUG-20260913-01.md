# BUG-20260913-01 · 文档与代码多面不一致（审计发现：README/导航/模块划分/术语/词汇表/包结构）

**Status**: done（2026-09-13 修复与验证完成，修复代码 + 档案 + 台账 + 技能规则同 diff 提交）

## 症状（建档时记录）

- 发现于：M5 收官推送后，用户要求"检查一遍文档的内容。是否与当前的代码一致？"——全库文档审计（duo-doc-standards 清单）查出
- 原样引用（审计报告关键发现）：

```
1. 文档站导航漏 ADR-0007：侧边栏"决策记录"只列到 0006，而 docs/adr/ 有 7 个文件
2. README.md 整体停在 M1 时代："当前为 M1——…（0.1.0-SNAPSHOT，未发布）"（实际 0.2.0 已发布、M3-M5 落地）；
   模块表只列 3 个（实际 7 个）；"输出 34 条状态/事件叙述"为 M1 时期死数字
3. 模块划分.md 内部自相矛盾：状态行"M1 三模块全量落地；M2 全量落地"，正文模块表却已列 7 个；
   example 依赖写"core + tools + mcp"（pom 实为 + llm + session + agent）；
   "功能模块（tools/mcp/llm/session）之间不互相依赖"已被 agent（依赖 llm/session/tools）打破
4. 术语漂移："三段管线"（ToolsService JavaDoc 权威）vs"六段治理管线"（模块划分 tools 行、ADR-0007、M5 注释 5 处）
5. CONTEXT.md 词汇表缺 LLM/会话/agent 循环三域术语
6. LlmConfig 违反自己记录的平铺约定：跨模块消费的配置 record 在 llm.internal，example 直接 import internal
```

- 复现方式：任意一次 M3-M5 期间对照 README/文档站与仓库实际状态即可复现（如数模块表行数 vs `ls -d duo-harness-*`）。

## 排查记录（定位过程，逐步追加）

- 假设 1：导航漏条目是偶发遗漏 → 验证：`config.mts` sidebar ADR 条目数（6）vs `docs/adr/` 文件数（7）；0.2.0 曾因完全相同的原因漏 ADR-0006，且 duo-doc-standards 已明文"push 前必查" → 结论：**成立且是执行缺口**——规则在，检查未被执行（M5 收官提交时未跑）
- 假设 2：README/模块划分过时是"忘了改" → 验证：git log 显示 M3-M5 共 24 个提交全部只带代码与 .scratch，README/模块划分/词汇表零触碰；CHANGELOG 也只在 M3 落地时记过账（M4/M5 缺，推送前检查时补） → 结论：**成立**——门面类文档（README/导航/词汇表/架构篇）没有"随代码演进"的同 diff 触发点，被默认推迟到"收官时"且收官时也没排期
- 假设 3："六段"是新术语、JavaDoc 该改 → 验证：CONTEXT.md 词汇表权威词条是"三段管线"（审批/guard/输出契约是挂链机制，非第四五六段）；ToolsService/ToolsServiceImpl JavaDoc 全部用"三段"；"六段"仅出现于会话叙事、工单与演示注释 → 结论：**成立**——术语在对话中新生成时未回查词汇表权威，随即扩散进正式文档
- 假设 4：LlmConfig 位置是约定允许的例外 → 验证：模块划分.md 二选一记录明文"契约在根包、实现在 `<域>.internal`"，LlmConfig 是跨模块消费的配置 record（example 两处 import `llm.internal.LlmConfig`） → 结论：**成立**——代码违反了仓库自己记录的约定，且无 ADR 背书

## 根因（机制层）

文档同步的触发机制缺位：红线 #3（文档与代码同一 diff 同步）只对"该 diff 触及的文档"生效，而 README / 站点导航 / 词汇表 / 架构篇属于**跨里程碑门面**——单个功能 diff 不触碰它们，于是没有任何一次提交负责更新；收敛动作被心理记账为"收官时统一做"，但收官清单（duo-workflow 提交前核对）没有对应检查项，导致欠账无限累积。术语层同因：新词在会话/工单中生成时，没有"先查词汇表权威"的强制动作，叙事用语直接渗入正式文档。
