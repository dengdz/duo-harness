# BUG-20260915-02 · 装配测试不隔离——与在跑的演示实例抢真实会话锁与端口

**Status**: closed

## 症状（用户报告原样）

用户 IDEA 演示实例（`DuoMain`，会话 20260915-151243-b9be）仍在运行时执行全量 `mvn test`：

```
duo-harness-web FAILURE
[web] 启动失败（state=FAILED）: Web 面无法启动：会话已被占用：20260915-151243-b9be
      （/Users/zhangyl/.duo/agent-sessions/20260915-151243-b9be.jsonl）——同一会话同一时刻只允许一个进程使用
  at WebPluginAssemblyTest.pureWebAssemblyRegistersInteractionTools(WebPluginAssemblyTest.java:37)
```

## 根因

装配测试 boot 的插件树（WebPlugin/CliPlugin）经 `DuoHome.resolve()` 解析会话目录，**读的是真实 `~/.duo`**（surefire 默认继承环境，无 DUO_HOME 覆盖）：

1. **抢会话锁**：测试续接真实最新会话，撞上用户演示实例持有的独占锁（M10-03 设计：被占即失败）——测试失败与代码无关，与"用户开着自己的实例"有关。
2. **数据污染**（即使不撞锁也发生）：CliPlugin 遇到锁冲突会"新建会话"，此前测试一直在往真实 `~/.duo/agent-sessions` 写测试会话。
3. **抢端口**（连带发现）：example 模块 `ToolCatalogTest` 与 `AgentReplMainTest.agentDemoYmlBootsCleanly` boot `agent-demo.yml`（web `port: 18080` 固定）——演示在跑时绑定失败（`WebPlugin` 端口异常是致命 `PluginException`）。

## 修复

1. **根 pom surefire 全局环境隔离**：`DUO_HOME → ${project.build.directory}/test-duo-home`（各模块测试互不干扰，不碰真实 home）；`DUO_LLM_BASE_URL/API_KEY/MODEL` 三项假值兜底——隔离后 `~/.duo/config.yml` 不可见，装配测试只需"LLM 配置可得"（只构造适配器，不真实发请求）。
2. **example 测试夹具 `support/DemoYml`**：`agent-demo.yml` 的 `port: 18080` 替换为 `port: 0`（随机）的临时副本；`ToolCatalogTest` 与 `AgentReplMainTest` 改用它——单一事实来源仍是原 yml，替换缺失即点名报错。

## 防复发

- 测试永不依赖真实 `~/.duo`：surefire 已全局设置 DUO_HOME，新模块无需自管；装配测试需要 LLM 配置时直接用 env 兜底值。
- 测试 boot 含固定端口的 yml 时，用 `DemoYml` 模式换随机端口，避免与用户实例抢绑。

## 验收验证（2026-09-15）

全量 `mvn test` 在演示实例运行中零失败（此前 WebPluginAssemblyTest 因会话锁必挂）；example 两个 boot 演示 yml 的测试改用随机端口后与在跑实例并存通过。closed。
