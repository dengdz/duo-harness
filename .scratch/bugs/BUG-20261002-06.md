# BUG-20261002-06 · Web 输入框占位符承诺「/技能名 直调」但 slash 通道只认三命令

**Status**: done（2026-10-02 M34 工单 05 修复：WebPlugin 补声明 SkillRegistry（路线①注册兑现）+ 浏览器面验证 /greet 直调命中）

## 症状（建档时记录）

- 发现于：M33 批 3 执行（CARDS-11 技能卡验证）
- 原样引用（toast 实测，2026-10-02）：

```
输入框 placeholder：「输入消息，回车发送…（/技能名 直调）」
发送 /greet（工作区 .duo/skills/greet 技能已发现且可用）→
toast：「未知命令: /greet（可用命令: compact, title, export）」
```

  - 同技能自然语言触发正常：「向队长问一声好」→ 「加载技能 greet」卡 + 按技能脚本精确回复——技能挂载无恙，slash 通道不通
  - 对照：CLI 面「CliPlugin 声明依赖 skills——软件包内有 .agents/skills 时可用 /技能名 直调」（subagent-demo.yml 注释在案）——Web 面未注册技能命令
- 复现方式：Web 面输入 /greet（任意已发现技能名）→ 未知命令 toast

## 排查记录（定位过程，逐步追加）

- 假设 1：技能直调命令由呈现位插件注册，CliPlugin 注册了、WebPlugin 未注册——占位符文案却按 CLI 能力书写 → 验证：命令注册表三命令（compact/title/export）均为 Web 自有命令，无技能名 → 结论：方向成立（注册缺口或占位符文案越界，二选一待修复批裁定）

## 根因（定位后填写）

实钉（2026-10-02 M34 工单 05，与档案两候选均不同）：**既非「缺注册」也非「不该承诺」——是声明闸门拒读被吞**。斜杠解释链第二级（CommandsRegistry.resolveSkillOrUnknown）本身支持技能直调（skills.find 命中即注入透传），Web 面的 skillsOrNull() 也接了 Skills 视图——但 WebPlugin.optionalInject() 未声明 `skills`，`face.ctx.as(Skills.class)` 被声明闸门拒读（PluginException「服务未在依赖声明中」）→ catch(Exception) 吞成 null → 直调级永远未命中且提示不带技能清单。「hasService 真 ≠ 可读」家族第四次重现（permission-rules / fileRefs / connectorStatus / skills）。

## 修复方案（计划，改前填写）

已执行（M34 工单 05，路线①变体）：**补 optionalInject 声明**（非命令注册——技能直调本就是解释链第二级，无需逐技能注册；CLI 同样不注册技能名，靠解释链）。声明后 skillsOrNull 拿到注册表 → /技能名 命中直调注入。回归锁：WebPluginAssemblyTest.skillRegistryDeclaredAsOptionalDependency（声明断言）。

## 修复与验证

- 改动：WebPlugin.java optionalInject() +1（SkillRegistry.SERVICE_NAME）
- 回归测试：声明断言锁入库；浏览器面——/greet 队长 → 技能直调命中 → 模型按技能脚本回复「你好，队长！（来自 greet 技能）」（证据 `.scratch/m34-1.0.1-fixes/evidence/工单05-BUG06-slash直调.png`）。注：直调后用户消息显示注入的技能内容（非 /greet 原文）为 M12-03 既定语义（斜杠文本不透传）
- 防复发：「hasService 真 ≠ 可读」家族第四犯——WebPluginAssemblyTest 已形成声明断言锁组（workspace/connectorStatus/skills 三连），新可选消费方照此加锁
