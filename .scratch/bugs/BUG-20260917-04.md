# BUG-20260917-04 · 双呈现位下计划呈交卡不可达——计划请求无审计事件，卡永不渲染且终端无提示

**Status**: done（2026-09-17，双开端到端实测通过：卡渲染→打回→改细→批准→模型执行）

## 症状（建档时记录）
- 发现于：M16 工单 07 验收解除尝试——轻任务 `/plan`（1 轮内即调 `exit_plan_mode`）后**浏览器无计划卡、终端无任何提示**，CLI 阻塞直到 WebAnswerer 10 分钟超时 fail-closed
- 原样引用（本轮实测证据）：
  - CLI 会话 `20260917-193550-ead6`：`tool/call exit_plan_mode {"plan": "# 计划：两步早餐清单...`（呈交成功，等待复核）
  - 浏览器绑定的 Web 会话 `20260917-191357-cf7b`：**零新增事件**（无任何计划相关事件）
  - 演示进程输出停在 `已进入计划模式...` 后无后续提示；10 分钟后 `[异常终止]`/fail-closed 回填
- 复现方式：双呈现位部署（demo agent-demo.yml：web 行 + cli 行）→ CLI 输 `/plan <任务>` → 模型调 `exit_plan_mode` → 浏览器无卡、终端无提示

## 排查记录
- 假设 1：工单 07 结构化协议回归 → 验证：协议路径未被触达（无卡可点）→ 排除
- 假设 2：计划模式状态机/工具异常 → 验证：`tool/call exit_plan_mode` 正常落 CLI 会话、工具等待复核语义正确 → 排除
- 假设 3：前端渲染条件缺失 → 验证：前端 `dispatch` 对 `event.toolName === 'exit_plan_mode'` 的 `tool/call` 与 `approval/requested` 两路均可渲染计划卡，且 `approvalDecided` 已内置 `exit_plan_mode` 分支（**前端早已为审计链路备好席位**）→ 排除
- 假设 4：**计划请求（kind=question）在审计桥无留痕** → 验证：`AuditingAnswerer.answer` 仅对 `KIND_APPROVAL` 写 `approval/requested`；`ExitPlanModeTool` 以 `KIND_QUESTION` 发起（subject=问题文本）→ **成立**。机制链：①双呈现位下 CLI 恒新建会话（Web 先启动占住 latest，同进程二次加锁触发 SessionLockedException）；②计划卡渲染依赖**浏览器所绑会话**里的事件；③计划请求无审计事件、tool/call 在 CLI 会话 → 浏览器无卡；④回答者链 web 先注册，WebAnswerer 阻塞 10 分钟，ConsoleAnswerer 轮不到 → 终端也无提示

## 根因
计划复核请求走交互 seam 的 `KIND_QUESTION`，**审计桥只为审批（KIND_APPROVAL）留痕**——双呈现位部署下（CLI 与 Web 必为不同会话，M10-03 锁语义），浏览器会话里收不到任何计划事件，卡永不渲染；请求又被优先路由给 Web answerer（行序路由，ADR-0011 既定），终端回答者轮不到，人机两侧同时静默。审批卡不受影响的原因：审批有审计留痕（`approval/requested` 写进作答呈现位会话），计划没有。前端 `approvalDecided` 的 `exit_plan_mode` 分支证明原设计意图是计划走审计链路，**后端侧从未补齐**。

## 修复方案
补全计划请求的审计链路（对齐前端既有席位）：
1. `InteractionRequest` 新增 `KIND_PLAN`（"plan"）与工厂 `plan(plan 文本, options)`——subject 取工具名 `exit_plan_mode`（审计与卡渲染的身份键），detail 取计划全文；
2. `ExitPlanModeTool` 改发 `KIND_PLAN`（回答形状不变：values[0] = 批准选项或反馈文本）；
3. `AuditingAnswerer` 对 `kind ∈ {approval, plan}` 写 `approval/requested` / `approval/decided`（计划复核 = 对计划产物的批准决策，事件词汇零新增；前端两路均已支持）；
4. `ConsoleAnswerer` 增 `KIND_PLAN` 分支（纯 CLI 部署的终端呈现：计划全文 + 选项）；
5. 文档同步：会话事件类型表注明 approval/* 亦承载计划复核；术语表"审批钉死"无关、不动。

备选（更大）：回答者按发起呈现位亲和路由（backlog 已挂，ADR-0016 归 M19）——本修不与其冲突，亲和路由落地后计划卡自然回终端。
