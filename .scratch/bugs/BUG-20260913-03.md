# BUG-20260913-03 · 多轮工具链（5+ 轮）再次出现 reasoning_content 400——单轮回传修复不覆盖长链

**Status**: fixed（2026-09-13 修复 A 已落地 + 长链测试锁定；待用户重跑场景四观察）

## 症状（建档时记录）

- 发现于：M6 工单 05 用户手动验收，场景四"把 notes.txt 读五遍"（单次 send 内连续 5 轮相同工具调用）
- 原样引用（第 5 轮提醒之后）：

```
  [调工具] mcp__files__read_file {"path": "notes.txt"}
  [工具结果] agent 演示的文件内容

[提醒] 重复调用已升级（第 5 次）——当前方法大概率无效，请立即换一种思路。
  [错误] LLM 调用失败: HTTP 400 - The `reasoning_content` in the thinking mode must be passed back to the API.
```

- 复现方式：思考模型 + 单次 send 内 5+ 轮工具调用链；第 6 次 LLM 调用（第 5 个工具结果回填后）400。

## 排查记录（初步）

- 已知事实：BUG-20260912-05 的修复（pendingReasoning 附加到最近一条 assistant(tool_calls) 消息）在 M5 验收（2-3 轮链）与本轮场景一/二（2 轮链）均通过；本轮 5 轮链的前 5 次调用也都成功，**恰好第 6 次失败**
- 假设 1：第 5 轮模型响应未携带 reasoning_content（思考模型可空转）→ 我们的 aggregateTurn 把空串归一为 null → pendingReasoning 被清空 → 第 6 轮请求的最后一条 assistant(tool_calls) 无该字段 → 400。验证方向：查 DeepSeek 文档"思考轮无 reasoning 输出时回传义务"；代码侧验证 pendingReasoning 被置 null 的路径存在（`pendingReasoning = turn.reasoningContent()` 无条件覆盖）→ **疑似成立，待验证**
- 假设 2：DeepSeek 校验链内**所有** assistant(tool_calls) 消息（而非仅最后一条）→ 反证：第 3-5 轮请求各含 2-4 条无 reasoning 的历史消息却成功 → **疑似排除**（除非校验仅针对"最后一轮"且第 5 轮响应 reasoning 为空）
- 假设 3：续接的昨日旧会话（20260912-211843-a764，含 M5 时代未带 reasoning 的 tool/call 投影）触发校验 → 反证：场景一/二/三在同一续接会话上全部成功 → **排除**（校验范围应是最近一次 user 消息之后的当前链）

## 根因

假设 1 成立（代码路径 + 官方文档双重确认）：思考模型某轮响应可省略 reasoning_content 输出；BUG-05 修复实现把"本轮无思考"无条件清空 pendingReasoning（`pendingReasoning = turn.reasoningContent()`），导致下一轮请求的最后一条 assistant(tool_calls) 消息缺字段，被 provider 以 400 拒绝。官方文档（api-docs.deepseek.com/guides/thinking_mode）明确：思考模式下执行工具调用的轮次，reasoning_content 必须完整传回后续请求（JetBrains YouTrack LLM-27762 引述："for turns that do perform tool calls, the reasoning_content must be fully passed back"）；DSH 的 llm-deepseek 适配器同样"reasoning 内容逐字回传后续请求"（docs/research/DSH/核心功能全景.md 第六节）。为何第 5 轮会省略输出：provider 侧行为（可能与服务端思考预算/触发条件有关），harness 侧无法控制，只能保证"有史以来出现过就不再缺"。

## 修复与验证

- **修复 A（已落地）**：ToolCallingAgent 链内 pendingReasoning 不被 null/空白覆盖——仅当本轮返回非空思考时才更新，否则保留链内最近一次非空值回传
- **B 线验证（官方语义）**：DeepSeek 官方文档确认思考模式 + 工具调用必须回传 reasoning_content（无 tools 参数的轮次不需要、会被忽略）；社区同症案例（n8n / claude-code-router #1378 / Cursor 论坛）均为框架默认剥离该字段所致——与我们的修复方向一致
- **长链回归测试**：`ToolCallingAgentTest.longChainKeepsLastNonEmptyReasoningWhenModelOmitsIt`——6 轮链、仅首轮有思考，断言第 2-6 轮请求的最后一条工具调用消息都携带链内非空思考（修复前该形态第 6 轮必 400）
- 已知残留边界：若整条链从未出现过任何 reasoning 输出，无值可回传（provider 侧行为，harness 无法 invent）——如复现需按 provider 指引处理，暂记已知限制
