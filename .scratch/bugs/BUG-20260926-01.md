# BUG-20260926-01 · anthropic 断点 3 组块漏 type 字段遭 422（mock 测不出的协议违约）

**Status**: reported → investigating → fixing → verifying → done

## 症状（建档时记录）
- 发现于：M25 工单 06 真机验收（0.20.0 分支，提交 0d63c0d，anthropic provider）
- 原样引用（用户实测逐字）：
  > `[错误] LLM 调用失败: HTTP 422 - Failed to deserialize the JSON body into the target type: messages[17].content: missing field `type` at line 1 column 19506 (request_id: 735d7dee-...)`
  >
  > `[错误] LLM 调用失败: HTTP 422 - Failed to deserialize the JSON body into the target type: messages[18].content: missing field `type` ...`
- 复现方式：anthropic provider 启动 CLI，向**含历史消息的会话**（messages[17]+，即续接会话或聊过多轮）发任意消息

## 排查记录（定位过程）
- 假设 1：断点 3 组块时 content 块缺 `type` 字段 → 验证：AnthropicMessagesAdapter 组块代码 `blocks.addObject().set("text", content)`——只放了 `text`，没有 `put("type","text")`；Anthropic messages 协议 content 块必须携带 `type`（text/image/tool_use/tool_result）→ 结论：**成立**（直击病灶）。
- 假设 2：为什么套件没抓到 → 验证：AnthropicMessagesAdapterTest 断点 3 用例断言的是 `content` 数组存在 + 末块 `cache_control`——**没有断言块的 `type` 字段**；mock server 只回显不校验协议（M25-06 审查 review-log 已记此盲区："mock 只回显不校验——测不出挂错位"，本次是同族第二击：漏字段也测不出）→ 结论：**成立**（防线缺口确认）。
- 假设 3：为何首轮（新会话）可能不炸而 17 条消息的会话必炸 → 验证：断点 3 只改**末条消息**——新会话首轮末条恰是刚输入的 user 消息，同样组块同样缺 type，理论首轮也炸；用户实录首次报错即在含 17 条历史的消息上（resume 了 04 验证的旧会话 20260925-180850-9f21），与代码路径一致，无首轮豁免 → 结论：不成立（无首轮豁免，任何请求都炸）。

## 根因（机制层）
content 块组装用了 `set("text", content)` 复用 JsonNode 的捷径，产出 `{"text": "..."}` 裸块；Anthropic 反序列化器要求每个 content 块对象有判别字段 `type`，缺字段在 422 拒绝整个请求。深层根因：**mock server 是回显器不是协议校验器**——断点 3 的修复（挂载位从消息顶层改到 content 块）在上一轮审查后补了组块逻辑，但组块产物从未按协议 schema 校验过 `type` 判别字段；"组块"与"合法块"之间的差距恰好落在 mock 的盲区里。

## 修复方案（改前落盘）
1. `AnthropicMessagesAdapter`：组块时 `put("type","text").set("text", content)`——补判别字段。
2. 测试防线：断点 3 用例补断言每个 content 块携带 `type:"text"`（锁住判别字段）；顺带断言既有 `toolResultMessage`/`userOrAssistantMessage` 的既有块不受影响（它们本来就带 type——回归确认）。
3. 影响面：仅断点 3 组块路径（两段 system 块本来就有 type——`put("type","text")` 已在）。

## 修复与验证
- 改动：AnthropicMessagesAdapter.java 组块行补 `put("type", "text")`；AnthropicMessagesAdapterTest 断点 3 用例补块级 type 断言
- 回归测试：AnthropicMessagesAdapterTest 全套件 + llm 三套件 + 全量（结果见修复提交）
- 防复发三问：
  ① 回归测试锁住了吗——**是**：断点 3 用例新增块级 `type` 断言（缺字段即红）。
  ② mock 验证不到的差距——**是**：mock 是回显器，协议合法性只能真机验。处置：本 bug 即真机验收抓到（流程已在干活）；验收对照表补条目——"anthropic 行改动后必跑一次真机 2 轮对话冒烟"记入工单 06 Comments。
  ③ 技能规则缺口——**是**：review-log 2026-09-26 M25-06 节"协议字段挂载位以官方文档为准"只覆盖挂载位，没覆盖**块判别字段**；升级该条为"协议块组装后按官方 schema 自查判别字段（type 等），mock 用例同步断言"。
- 同族查询：`grep -n "mock.*回显\|回显.*校验\|协议" .scratch/bug-log.md` → M25-06 review-log 模式 1（挂错位，本次前置同轮）为同族第一次实战、本 bug 第二击——**升级为结构化防线**：MockAnthropicServer 增加最小协议校验（收到 content 数组时校验每块有 type，违约抛测试内断言）——防线落在 mock 基建，后续所有 anthropic 用例自动受益。
