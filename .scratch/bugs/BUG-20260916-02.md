# BUG-20260916-02 · 会话标题生成后侧栏不同步——title 帧只接了标签页消费路径

**Status**: done（2026-09-16 隔离实例浏览器验证通过——发消息后侧栏与标签页同步显示标题，无需切换会话）

## 症状（建档时记录）

- 发现于：M13 里程碑验收（工单 07，用户手动验证）
- 原样引用：
  > 创建新会话并发送消息后，网页的标签页名称会立即更新，但会话标题保持不变，只有在切换到其他会话时（此时似乎触发了刷新机制）会话标题才会更新。
- 复现方式：新建会话 → 发一条消息 → 观察标签页标题（立即变）与侧栏当前项（保持 id）→ 切走再切回 → 侧栏才显示标题

## 排查记录（定位过程，逐步追加）

- 假设 1：标题生成/落盘延迟 → 排除：标签页立即更新说明 title 事件已实时到达前端（同一帧驱动），且 append 是落盘后广播
- 假设 2：title 帧的前端处理只更新了标签页、未触发侧栏刷新 → 验证：app.js handle 的 session/title 分支仅 `document.title = event.text; return`；侧栏标题来自 refreshSessions()（/api/sessions 的 title 字段），而它只在 afterReplay 与切换后调用 → **成立**

## 根因（机制层）

工单 06 的标题消费接了两条路径但只接通一条：SSE 帧路径（document.title 实时更新）与轮询路径（侧栏 refreshSessions，仅回放结束/切换触发）——title 帧到达时没有桥接到侧栏刷新，两条路径的更新时机断裂。

## 修复方案（计划，改前填写）

handle 的 session/title 分支追加 `app.refreshSessions()`（title append 即已落盘，紧随的 /api/sessions 必返回新标题；title 每会话至多一条，请求频率无压力）。

## 修复与验证

- 改动：app.js handle 的 session/title 分支追加 `app.refreshSessions()`（一行）——title append 已落盘，紧随的 /api/sessions 必返回新标题
- 验证：隔离实例（假 LLM 走超时降级路径，与真实生成同链路）——新建会话发消息后，侧栏与标签页同步显示降级标题（首条前 20 字），无需切换会话
- 防复发：新增 SSE 事件类型时逐面检查全部消费面（消息区/侧栏/标签页/状态面）——已入台账
