# BUG-20260923-01 · Web 面抢占会话致 CLI 永远无法续接

**Status**: done（2026-09-25 C1-12 统一重放演练补档——原修复于 2026-09-23（c98e7c7），当时未走本技能建档；本档案按现行模板以历史事实回填，流程四步判据逐条对照）

## 症状（建档时记录）
- 发现于：M24 工单 09 验收实测（用户手动运行 resume 横幅验证）
- 原样引用：CHANGELOG 0.19.0 Fixed 条目——「web 行先于 cli 行装配（回答者路由契约），Web 面启动 `latest()` 抢走目录最新会话，CLI 随后撞同进程持锁注册表被顶开新建——每次启动都『会话已被占用 → 新建』，resume 续接（模型意图横幅）永远失效」
- 复现方式：先启 Web 面再启 CLI，CLI 每次新建会话

## 排查记录（定位过程，逐步追加）
- 假设 1：CLI 侧续接目标选择错误 → 验证：CliPlugin:199 是 latest() 唯一生产调用点，选择逻辑本身正确 → 结论：排除
- 假设 2：装配顺序（web 先于 cli）导致 Web 启动即消费 latest() → 验证：WebPlugin 启动路径 latest() 抢占成立，且 Web 自建空会话文件成为目录 mtime 最新 → 结论：成立（双因素：抢占 + 空会话污染续接目标）

## 根因（定位后填写）
机制层：WebPlugin 启动复用 latest() 会话（抢占既有持锁会话）+ Session.create 经 Files.createFile 产出 0 字节文件成为目录最新条目——latest 的"最近修改"语义把空会话当作续接目标，CLI 撞锁新建后下一次又抢到空会话，resume 意图永远落空。

## 修复方案（计划，改前填写）
Web 面改自建全新会话（恢复历史对话走 /switch）；Session.latest 跳过 0 字节空会话。影响面：web 装配、session 查询；CLI 续接语义不变。
