# BUG-20260913-02 · agent-demo.yml repeat-reminder 行缺 config 块——boot 整树失败

**Status**: closed（2026-09-13 用户验收首跑发现，即日报修，防回归测试锁定）

## 症状（建档时记录）

- 发现于：M6 工单 05 用户手动验收首跑（exec:java 启动即崩）
- 原样引用：

```
BootException: 插件树启动失败（…/agent-demo.yml），1 个问题：
[repeat-reminder] 插件 dev.duo.harness.example.mcpfs.RepeatReminderPlugin 声明了 config 类型
com.fasterxml.jackson.databind.JsonNode，却未提供配置
```

- 复现方式：跑 AgentReplMain（`exec:java`），boot 阶段整树点名失败退出。

## 排查记录

- 假设 1：插件 configType 应改为 null（无配置）→ 验证：thresholds 可配是工单 04 验收项（configurableThresholds 用例），去掉配置能力是砍功能 → **排除**
- 假设 2：内核应宽容"声明了类型但没给配置"→ 验证：bindConfig 的严格绑定是**有意设计**（报错注释："静默传 null 会让插件在 apply 深处 NPE，报错远离根因"），且 ApprovalPlugin javadoc 明文"config 块在场，块内字段可省"——约定在先 → **排除**
- 假设 3：yml 行漏写 config 块（装配遗漏）→ 验证：对照 ApprovalPlugin 行（带 `config: policy: always-deny`）→ **成立**

## 根因

装配遗漏 + 测试盲区叠加：RepeatReminderPlugin 沿用了 JsonNode configType（可配 thresholds），但工单 05 改 yml 时没给它 config 块；AgentReplMain 的 `run()` 因依赖 ~/.duo/config.yml 真实 key 而无法进入测试覆盖——**yml → Boot 装载路径零断言**，缺陷直通用户验收。

## 修复与验证

- 改动：agent-demo.yml 的 repeat-reminder 行补 `config: {}`（块内字段省略 = 默认阈值 3/5/8），对齐 ApprovalPlugin 同款约定；提交 5354c38
- 回归测试：新增 `AgentReplMainTest.agentDemoYmlBootsCleanly`——直接 `Boot.from(agent-demo.yml)` 断言插件树可干净启动（yml 装载路径首次有断言）；example 模块 21/0/0
- 防复发：
  - "mock 验证机制、真实路径验证装配"第四次出现（前三次：M2 classpath、M3 路径B、BUG-05 思考模型）——本次新增的 yml boot 用例即结构化防线；凡新增/修改 demo yml，配一条 boot 冒烟
  - 插件可选配置的装载约定固化为：JsonNode configType ⇒ yml 行必带 `config: {}`（字段可省）；免配置插件用 `Plugin<Void> + configType null`
