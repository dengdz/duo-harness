## 排查记录
- 假设 1：工单 07 结构化协议回归致计划卡不出 → 验证：计划卡由 `exit_plan_mode` 的 tool/call 渲染（`app.js` `interactiveCard`），该事件从未产生——协议路径未被触达 → 排除
- 假设 2：审批路由或计划模式状态机异常 → 验证：CLI 日志显示计划模式正常进入（提示行），且探索期间的 bash 审批卡在浏览器正常渲染作答（用户截图两张卡，一张已拒绝、一张待批）——路由与状态机均正常 → 排除
- 假设 3：迭代上限（10 轮）被探索耗尽 → 验证：日志明示"已达最大迭代轮数（10），共执行 11 次工具调用"，且 11 次调用全是计划指导鼓励的探索动作 → **成立**
- 补充证据（2026-09-17 用户验收 B）：**Web 面迭代上限终止是静默的**——达上限返回 completed=false 的 AgentReply，CLI 打印 [异常终止] 而 Web 面不渲染（/api/message 不看返回值）→ 会话 213120-b3c8 实测 11 次调用后会话无收尾事件、页面两分钟不动且无错误卡。缺口记 backlog（run/error 帧机制可复用做用户可见化）

## 根因
计划模式为引导式（挂计划指导片段鼓励"先探索再设计"，M7/ADR 既定），主 agent 迭代上限为防失控硬停常量（`ToolCallingAgent.MAX_ITERATIONS = 10`，全仓库唯一消费点 `PresenterAssembly.chatAgent:140`，无任何配置入口）。两者相乘：真实仓库级设计任务（读多份技能/文档/结构）的探索步数超过 10 轮预算，循环在呈交前被硬停——**计划模式在真实任务上不可用**。M7 验收用简单任务未暴露；M15 已因同类原因把子代理上限做成模板可配（30/40），主 agent 侧一直未动。

## 修复方案
呈现位 yml 可配：`web` / `cli` 插件 config 新增可选顶层字段 `maxIterations`（正整数，缺省 `ToolCallingAgent.MAX_ITERATIONS`=10——不配置行为不变）；`PresenterAssembly` 新增严格解析（非正整数点名拒绝）与带上限的 `chatAgent` 重载；两呈现位解析后传入（含换绑重建路径）。文档同步：插件配置参考补字段说明；backend/前端零改动。

## 修复与验证
- 改动：见上（PresenterAssembly / WebPlugin / CliPlugin / 配置参考文档）
- 回归测试：`CliPluginTest` / `WebFaceTest` 装配用例 + 新增解析用例（缺省 10 / 显式 30 / 非法值点名）；全量 `verify`
- 防复发：解析严格校验（配置错误启动即 FAILED，不静默）；limitations 补记计划模式与探索预算的张力（引导式探索无步数感，大任务建议调高 maxIterations）
