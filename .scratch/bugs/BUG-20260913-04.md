# BUG-20260913-04 · Web 对话流 chunk 碎片化——每个增量渲染为独立气泡

**Status**: closed（2026-09-13 根治修复 + WebFaceTest 全绿；服务重启后浏览器终验待用户确认）

## 症状（建档时记录）

- 发现于：M8 工单 06 用户验收（内置浏览器自动化测试场景二）
- 原样引用：页面截图显示助手回复按 chunk 碎片逐行排列（"已知 / 文件 / : / notes / .txt / ` / ` …"），每个流式增量渲染为独立气泡而非追加到同一消息
- 复现方式：Web 面发送任意消息 → 流式回复期间观察消息区

## 排查记录

- 假设 1：index.html 的 SSE onmessage 对 assistant/chunk 每次调 bubble()（新建气泡）而非追加到最后一个助手气泡 → 验证：代码确认 `bubble(event.text)` 每帧新建 → **成立**

## 根因

index.html 的 SSE 渲染把 assistant/chunk 当独立消息渲染——流式增量语义（追加到同一消息）在渲染层丢失。

## 修复与验证（三轮）

1. 客户端聚合修补（streamingBubble 追加）——无效。真因一：**运行中的服务读 target/classes 旧资源**，修复写在 src/main/resources 未刷新，页面永远是旧版（"改了没生效"的元凶）
2. 300ms 时间窗区分回放/实时——无效。真因二：存量回放耗时可能超时间窗，历史 chunk 照样泄漏渲染
3. **根治（replay/done 边界帧）**：服务端存量回放完成后发 `{"type":"replay/done"}` 帧；客户端收到前跳过 chunk 渲染（assistant/message 完整消息为准），收到后实时 chunk 聚合到单气泡、完整消息覆盖。无时间窗、无竞态
- 验证：target/classes 刷新后 WebFaceTest 5 例全绿；浏览器终验（重启服务后）待用户确认
- 防复发：改静态资源必须 `mvn process-resources`（或重启验证）；SSE 回放/实时的分界必须由服务端显式边界帧声明，不用客户端时间窗
