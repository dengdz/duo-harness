# BUG-20261002-01 · /api/status 空响应——状态面自启动起五区块全「—」

**Status**: reported（排查与修复归 M33 后续修复批——M33 为纯测试期不修；发现于 M33 工单 01 环境 smoke）

## 症状（建档时记录）

- 发现于：M33 浏览器实测·工单 01 环境冒烟（隔离实例首启即现）
- 原样引用（curl 证据，2026-10-02）：

```
$ curl -sv -H "X-Duo-Token: <token>" http://127.0.0.1:62980/api/status
> Host: 127.0.0.1:62980
> X-Duo-Token: <token>
* Request completely sent off
* Empty reply from server
* Closing connection
```

  - 同刻对照端点全 200：`/api/sessions`（205B）、`/api/search?q=ls`（433B）、`/`（4031B）、`POST /api/stop`（409 忙时语义正常）
  - 变体：token 走查询参数 `?token=`、无 Origin 头、带 Origin 头——三种形态均 HTTP 000 / curl exit 52（连接被服务端无响应关闭）
  - 页面内 fetch 同报 `TypeError: Failed to fetch`（app.js:57 封装层）
  - 服务端日志零异常行（Exception/ERROR/WARN 全无）——静默失败
- 页面表现：状态面五区块（上下文 / 后台任务 / 连接器 / 插件六态 / 工具）自启动起全部渲染「—」与空表，实时刷新周期不恢复；截图见 `.scratch/m33-browser-audit/evidence/BUG-20261002-01-状态面空-冒烟通过面.png`（同帧左侧对话/工具卡/侧栏均正常工作）
- 复现方式：隔离实例启动（`DUO_HOME=/tmp/duo-m33/home java -jar duo-harness-1.0.0.jar /tmp/duo-m33/m33-smoke.yml`，web 单呈现位装配 + MCP echo 夹具）→ 任意时刻 `GET /api/status` → 空响应

## 排查记录（定位过程，逐步追加）

- 假设 1：tab 上下文缺席路径未兜底——`statusJson`（WebEndpoints.java:522-526）在 `face.tabs.resolveTab(exchange)` 返回 null 时返回 null，响应调用点对 null 无处理 → 写响应前异常/连接直接关闭，与「空响应 + 无日志」吻合 → 验证：源码实读 null 分支存在；同页其他 API 正常排除网络/栅栏面；异常静默符合「未走 WebEndpoints 各 handler 的 catch-and-500 形态」（对照 file-complete handler 的 error-log + 500 兜底）→ 结论：主假设成立度高的待证形态；**调用点 null 处理与 resolveTab 为何对已连接 tab 返回 null 未核**（修复批第一动作）
- 假设 2（待修复批排除）：web 单呈现位装配（无 cli 行）下 tab 注册链路缺环——本实例为首例 web-only 装配冒烟，历史上人工验收均为 web+cli 双位；若修复批在双位装配下不可复现，则病灶在「web-only 时 tab 生命周期」，仍是缺陷（降级形态不应断连）
