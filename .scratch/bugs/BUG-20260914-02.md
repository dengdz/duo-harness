# BUG-20260914-02 · 计划呈交/提问在 Web 无卡片可答——悬空挂起 10 分钟

**Status**: closed（2026-09-14 修复：前端计划呈交卡与回答口径对齐 ExitPlanModeTool；待用户复验）

## 症状（用户验收报告原样）

- 发送 `/plan 整理一下工作目录` 后"新输入的内容在中间卡住，光标闪烁"，回复永远不结束
- 磁盘证据：会话 JSONL 尾部是 `tool/call exit_plan_mode` + 一串 chunk，**没有 tool/result、没有 assistant/message**——回合挂死；约 10 分钟后才有下一条（WebAnswerer 兜底超时 fail-closed）
- 整个会话 549 行中 approval/requested / approval/decided 事件为 0

## 根因

`ExitPlanModeTool` 经交互 seam 呈交计划用的是 **`InteractionRequest.question`（提问类）**，不是 approval 类：

- 审计桥 `AuditingAnswerer` 对提问类**直接透传**（不发 approval/requested 事件）→ 页面收不到任何待答信号
- 前端对 exit_plan_mode 的 tool/call 渲染为**普通工具卡**（⟳ 运行中），没有可回答的卡片
- → WebAnswerer pending 无人能答，挂满 10 分钟兜底超时才 fail-closed

工单 05 checklist 的"提问/计划卡片同管线，工单 06 收口全形态"在 06 未收口——本条即该欠账。

## 修复

1. 前端 sse 分派：`tool/call` 的 `exit_plan_mode` → **计划呈交卡**（interactiveCard：[计划呈交] 标题 + 计划 markdown + 批准/打回按钮）
2. 回答口径对齐 ExitPlanModeTool：批准 = `POST /api/answer {approved:true, values:["批准，开始执行"]}`（values[0] 精确匹配批准选项）；打回 = `{approved:true, values:[反馈文本]}`（approved:false 会落 fail-closed 文案，语义错误）
3. `tool/result` 的 exit_plan_mode / ask_user → 按工具名冻结对应交互卡（回放安全：历史回合的呈交卡随 result 自动冻结）
4. 附带修正：计划卡正文解析 request JSON 的 plan 字段展示 markdown，不再显示原始 JSON

## 防复发

- 交互 seam 的提问类 pending 在 Web 呈现位必须有对应卡片：ask_user（提问卡）/ exit_plan_mode（计划卡）已按 toolName 路由；新增带提问的工具须同步前端路由
- 工单 05 的"提问/计划卡片同管线"欠账已在工单 06 收口记录
