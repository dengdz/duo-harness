## P1（高）——补丁正在制造真实错误行为（全部主审亲核实证）

### P1-1 `tools/fs/FsToolsPlugin.java:128-135` [类型6+1] spill 清理删光共享目录——跨装配数据丢失
- **证据**：`cleanupSpillDir()` 在插件停止时删 `DuoHome/tmp/bash-spill` 下**全部** regular file；`SPILL_SEQ`（FsBashTool.java:44）为 JVM 级静态计数器，文件名无装配隔离。
- **被修补的原始问题**：M23 工单 05（c752f89）"spill 文件进程退出无残渣"——意图是**进程退出**清场，实现却挂在**插件停止**上。
- **产生原因**：快速修 bug 时未对齐"多装配是一等场景"（ReadGate javadoc 明示同进程多装配/Web 多会话；子代理树高频启停）。
- **维护风险**：任一装配/短命子代理树停止即删除同进程其他活装配乃至**其他进程**的活 spill 文件——正在运行会话的"read 回读全文"承诺被静默破坏，输出丢失且无告警（删除失败也被吞）。
- **修法**：spill 文件登记到创建方（FsBashTool/BackgroundTaskRegistry 实例），停止只删自有；或目录按装配 UUID 隔离；`SPILL_SEQ` 换 `Files.createTempFile` 防跨进程碰撞。

### P1-2 `session/Session.java:987-1006` [类型6+1] titleOf 缺 POSIX 锁防线——每次侧栏刷新放掉活跃会话独占锁
- **证据**：`titleOf` 用 try-with-resources `newBufferedReader` 必关 fd；同文件 `permissionModeOf`（:977）有 `heldHere` 特判且注释明言"关了会释放属主的独占锁"。
- **被修补的原始问题**：POSIX fcntl 锁陷阱（M10-03、M13-05 两次实测记档：关任意 fd 释放本进程全部锁）。d2ae156（m19 OCR 终审 #15）只给 **m19 自引入**的 permissionModeOf 加防线；m13 引入（7324626）的同型方法 titleOf 未被同批扫到。
- **产生原因**：防御补丁按"本次审查发现的调用点"打，未做全类同型排查。
- **维护风险**：唯一主调用方 WebSessionEndpoints.java:374（侧栏 `/api/sessions`）对**全部** jsonl 逐个调 titleOf——含活跃会话；页面加载/标题更新/回放完成都触发，每次执行后活跃会话跨进程独占保护即失效，另一进程 CLI resume 可双开同一会话双写分脑；且 `isOccupied` 查注册表仍报"占用"，掩盖锁已失。
- **修法**：titleOf 复用 `heldSession()` 内存直取，或加 `heldHere` 同款防线；并将"静态读取入口"收敛为单一方法（titleOf/permissionModeOf/isOccupied/load 四处共用）。

### P1-3 `cli/ConsoleAnswerer.java:60` + `CliPlugin.java:262` [类型4+6] beginTurn 归零链路断线——测试直调掩盖
- **证据**：`beginTurn()`（approvalSeq 归零）全仓主代码**零调用**（主审 grep 复核：唯一调用方是 ConsoleAnswererTest 直调）；`consoleAnswerer` 字段赋值后只写不读。
- **被修补的原始问题**：审批排队呈现"（本轮第 i 项审批）"（M23 工单 03，8a148da 当时 startTurn 内确有调用）；工单 04（efe0ee6）把 REPL 重构为 turn 线程模型时**删掉该行**未补回。
- **产生原因**：快速重构的半截迁移。
- **维护风险**：真实 CLI 会话审批序号**跨轮累计**——第二轮首项审批误显示"（本轮第 3 项审批）"；测试直调 beginTurn 全绿，断线被测试形态掩盖（典型"假完成"）。
- **修法**：turn Runnable 首行补回 `consoleAnswerer.beginTurn()`；补"经 REPL 全链路驱动、断言第二轮首项零噪声"的集成测试。

## 跨模块模式提炼（系统性根因）

1. **同型补丁只打一处**（最高频根因，P1×3 中占 2、P2-A 全组）：修 bug 时按"本次发现的调用点"打补丁，不做全类同型排查。实例：heldHere 防线漏 titleOf、pipelineTimeout 放宽漏 task-output、beginTurn 重构丢调用、keepRecentRatio 半停用、按 id 回填漏提问卡。**机制对策：修 bug 前 grep 同型调用点/同族工具，应入 review-log 已知模式与 duo-workflow 修复纪律。**
2. **copy-paste 起家、乘法扩张期分叉**（P2-B 全组）：M15（子代理）、M24（多协议/多入口/多呈现位）、M28（呈现位重装）三次"×2 扩张"是复制高峰；每次后续演进被迫双处同步，漏改即行为分叉。**对策：新增"第二实现"时先抽共享骨架（模板方法/工厂/helper），禁止整拷起步。**
3. **字符串匹配代替类型化判定**（P2-C 全组）：异常 message 子串、文案精确匹配、JSON 前缀、哈希后工具名前缀——四处同族，全部反向锁死上游演进。**对策：异常带结构化字段、业务判定收敛单点、工具名提供稳定匹配原语。**
4. **JVM 静态单例错配插件树生命周期**（P2-D 组）：静态板/静态配置/JVM 级计数器挂在"插件停止"生命周期上。**对策：跨树状态一律走服务注册或树根聚合，静态字段仅限纯函数常量。**
5. **test-only 兼容面滞留 main**（P3 大宗）：重构后旧构造/旧工厂/死返回值留在 main 只被测试使用——测试形态掩盖生产断线（P1-3 即极端案例）。**对策：test-only 便捷面收进测试辅助类或删除。**
6. **ObjectMapper 各处 new 的惯性**（全库 23+ 文件）：内核有复用箴言但未沉淀共享设施。**对策：模块级 `Json.MAPPER` 或接口缺省 schema。**
