## T8 发现的 BUG-20260929-02（已修复）

- **现象**：`seq 1 40000` 的 spill 文件只含最后一个 8KB 读缓冲块（行 33716..35000），前 19 万字符丢失——"read 此文件回读全文"承诺对超 8KB 输出失效
- **根因**：`StreamCapture.writeSpill` 每个溢出块重开 `Files.newBufferedWriter`（默认 TRUNCATE_EXISTING=清空重写），多块输出每块互相清空；M23-05（c752f89）引入的存量 bug，非 C2 回归
- **为什么测试没抓到**：M23 既有用例输出 ~1.2KB 恰好落在单个 8KB 读缓冲内（单块），truncate 语义无从暴露——测试形态同质化藏 bug 的又一实例
- **修复**：写手懒开一次后续复用（追加语义）；回归锁 `spillSurvivesMultipleReadBuffers`（30000 行 ≈22 块，断言头行=1、行数=末行号无断档）
- **修复后实测**：spill 连续 1..25000 + 尾窗 25001..30000，合计量恰等于全量，零丢失

## 结论

12 项用户可见功能全过（1 项跳过属可选），途中揪出 1 个存量 bug（spill 多块丢失）并修复验证。C2 处置未破坏任何 Web 面主链路。
