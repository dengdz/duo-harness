# C2 · 补丁式代码处置：P1 止血与系统性重构

Status: ready-for-agent（to-tickets 待用户确认）

## Problem Statement

C2 阶段的全库审计（13 模块 295 文件主代码，报告见 [reviews/2026-09-28-全库补丁式代码审计.md](reviews/2026-09-28-全库补丁式代码审计.md)）实证了 82 处补丁式问题（P1×3 / P2×27 / P3×52），其中三处补丁**正在制造真实错误行为**，且全部是现有测试形态抓不住的断线：

1. **fs-tools 插件停止时删光共享 spill 目录**——同进程多装配（子代理树高频启停）是本项目一等场景，任一装配停止即静默删除其他活装配乃至其他进程的活 spill 文件，正在运行会话的"read 回读全文"承诺被破坏；
2. **侧栏会话列表读取放掉活跃会话的跨进程独占锁**——每次页面加载/标题更新触发，双进程双写分脑的保护由此失效，且占用查询仍报"占用"完全掩盖；
3. **CLI 审批序号跨轮累计**——turn 线程模型重构时丢掉归零调用，第二轮对话首项审批误显示"本轮第 3 项"。

更深一层：六族系统性根因（同型补丁只打一处 / copy-paste 乘法扩张期分叉 / 字符串匹配代替类型化判定 / JVM 静态单例错配插件树生命周期 / test-only 兼容面滞留 main / ObjectMapper 各处 new 惯性）横跨全部模块——不系统处置，M29+ 每次多协议、多呈现位、多入口的"×2 扩张"都会让分叉债按既有斜率继续累积。零打碎敲地逐个修小 bug 正是这些债的产生方式，处置本身必须反其道：成批、按根因、带回归锁。

## Solution

按审计报告五层处置清单的前四层，分四段交付（第五层"记录不改"项与结构性大改明确出范围）：

1. **段一 · 止血**：P1×3 修复，每项带一条"现有测试抓不住"的端到端/跨装配回归用例（spill 跨装配隔离、会话锁保持、审批序号全链路复位）；
2. **段二 · 防分叉抽象**：八项高收益抽象——LLM 双适配器共享骨架、计划批准判定收敛单点、Web/CLI 两处装配序列收敛工厂、工具超时单点、工具钩子 detail 提取 helper、子代理工具参数校验 helper、附件缩放阶梯参数化、审批策略服务参数方向翻转；
3. **段三 · 脆弱契约类型化与作用域归位**：core 类型化异常（作用域销毁）、附件上传异常携带状态码、工具名稳定匹配原语、连接状态板与 CLI 静态配置的树级生命周期归位、workspace 判定 fail-open 纠偏为 fail-closed、若干吞异常点收紧（区分"未挂载"与"服务故障"）；
4. **段四 · 清理批**：死代码（DSH 别名、停用常量、test-only 构造族、死返回值）、FQCN 批、魔法数字命名化、注释与 javadoc 失真修正、配置错误处理策略统一——一次 diff 清完，机械可回滚。

处置全程以"修 bug 前先 grep 同型调用点与同族工具"为修复纪律（已入 review-log 已知模式），每张工单的完成判据包含同型排查证据。

## User Stories

1. 作为多会话 Web 用户，我要插件树启停只清理自己的临时文件，以便正在运行的会话不因另一会话的关闭而丢失输出数据；
2. 作为双开 CLI 与 Web 的用户，我要侧栏刷新不释放活跃会话的独占锁，以便跨进程双写分脑的保护持续有效；
3. 作为 CLI 用户，我要每轮对话的审批序号从零重计，以便"（本轮第 i 项审批）"提示可信不误导；
4. 作为会话管理消费方，我要所有对会话文件的静态读取走同一入口且内置锁保持防线，以便新增读取需求不再重演锁释放缺陷；
5. 作为后台任务使用者，我要长等待工具的参数承诺（等待上限 600s）真实可达，以便模型按工具契约传参不被管线超时腰斩；
6. 作为配置文件作者，我配置的字段要么生效要么被明确警告停用，以便不维护"校验通过但实际被忽略"的假配置面；
7. 作为 Web 提问/计划卡的作答者，我要每次作答按卡片 id 精确回填，以便多卡排队与多标签并发时不答错对象；
8. 作为 LLM 协议适配器维护者，我要两个协议面共享一套流式/错误/重试骨架，以便改一处语义两面同步、行为永不分叉；
9. 作为计划审批链路维护者，我要批准判定只有单点实现，以便审计事件与真实批准状态永远一致；
10. 作为 CLI/Web 呈现位维护者，我要初始会话与换绑会话走同一装配工厂，以便新增能力不发生两处漏改一分叉；
11. 作为插件作者，我要钩子、子代理工具、附件编码等 copy-paste 逻辑收敛为共享 helper，以便规则调整一次生效全部调用点；
12. 作为 MCP 集成维护者，我要异常类别靠类型而非消息文案判定，以便上游文案演进不静默改变我的日志级别与降级行为；
13. 作为扩展开发者，我要工具名提供去哈希的稳定匹配原语，以便安全策略按名字精确匹配不再前缀碰撞；
14. 作为长驻进程运维者，我要连接状态板监听与 LLM 配置随插件树销毁回收，以便多轮装配不留泄漏与互踩；
15. 作为安全策略维护者，我要 workspace 判定的所有兜底方向为拒绝或询问，以便"区外写免审批"不可能因路径异常发生；
16. 作为 CLI 排障者，我要"服务未挂载"与"服务故障"可区分，以便 a/s 键失灵时不用盲猜根因；
17. 作为新加入的代码读者，我要 main 代码不含 test-only 构造、死常量与失效注释，以便把可用的扩展点与残留垃圾一眼分清；
18. 作为后续里程碑的执行 agent，我要修复纪律包含同型排查，以便"同型补丁只打一处"这个本次最高频根因不再新增实例；
19. 作为发版负责人，我要每项用户可见变更在 CHANGELOG 同 diff 记账，以便版本锚点完整（仓库红线 6）。

## Implementation Decisions

以下决策来自 C2 审计报告的五层处置清单与主审合并裁定，编号对应对账顺序：

1. **C2 定位 = 插入计划**（同 C1 先例，编号独立于 M 系列）；与 C1 不同的是本阶段动产品 Java 代码，**须走版本分支**——已裁定（2026-09-28 to-tickets 确认）：**独立 0.24.0 版本分支**，不与 M29 功能混编；
2. **段一三项的修复方向**：spill 清理从"删共享目录全部文件"改为"创建方登记、停止只删自有"（或目录按装配隔离，文件名防跨进程碰撞）；会话文件静态读取收敛为单一入口（内置活跃会话内存直取与 fd 保持防线，titleOf/permissionModeOf/isOccupied/load 四处共用）；审批归零调用补回 turn 边界；
3. **段二抽象的形态**：LLM 骨架用模板方法承载行循环/空闲超时/错误翻译/URL 处理（两适配器只留帧解释器）；批准判定落在交互请求类型上单点提供；装配收敛为呈现位内工厂方法；超时收敛为工具模块单点常量 + clamp + 管线放宽模式化套用；钩子与子代理工具校验收包内 helper；
4. **段三类型化的边界**：作用域销毁异常由 core 提供、MCP 侧消费；上传异常携带状态码、配额判定改结构化字段；稳定工具名匹配原语由工具注册侧提供（示例侧回归精确匹配）；状态板监听提供注销句柄挂到树生命周期；CLI 静态配置字段迁回实例；workspace 判定兜底改拒绝/询问方向并修正"保守放行"注释；
5. **段四清理原则**：test-only 便捷面收进测试辅助类或删除（不留 main）；注释失真随代码同 diff 修正；配置错误处理统一为"异常点名"口径（静默回退两处对齐多数派）；
6. **Web 作答 id 回填**：后端补 id 精确匹配、前端四处分批发点补齐，旧无 id 形态保留一个版本窗口后移除；
7. **行为敏感重构的保护**：双适配器骨架与装配工厂各独立 commit（可整体回滚），对拍/一致性测试先行再动骨架；
8. **每张工单完成判据**含三项：同型排查证据（grep 同型调用点）、最窄测试全绿、CHANGELOG 与文档同 diff 记账（红线 3/6）；
9. **修复纪律沉淀**："修 bug 前先 grep 同型调用点与同族工具"已随 C2 条目入 review-log 已知模式，本阶段工单首次实践并验证其可执行性。

## Testing Decisions

- **好测试口径**：只测外部行为、断言在缺陷存在时会失败——P1×3 的既有全绿证明直调式单元测试抓不住断线，三项回归用例必须走**生产同构形态**（端到端驱动/跨装配并存/插件上下文装配，对应 review-log 已沉淀的"测试形态与生产形态同缝"模式）；
- **seam 选择**（全部优先现有 seam，不新增）：
  - P1-1 用 fs-tools 的装配级测试 seam（两装配并存 + spill 生命周期断言——现有装配测试形态可直接扩展）；
  - P1-2 用会话模块的锁测试 seam（静态读取后第二进程打开仍失败/占用状态一致——现有 SessionLock 测试形态）；
  - P1-3 用 CLI 的 REPL 驱动 seam（turn 全链路，ConsoleAnswererTest 直调形态保留为单元层）;
  - 段二双适配器用两协议面对拍测试（帧序/错误语义/空闲超时二分语义同构断言）；
  - 段三异常类型化用既有 MCP/附件测试的直接扩展；
- **先例**：FsToolsTest（装配形态）、会话锁测试（跨进程语义）、M28 端点测试的插件上下文形态；对拍测试无先例，为段二新增的唯一测试形态；
- **收口判据**：全仓 verify 绿 + 各段独立 commit 后逐段可回滚。

## Out of Scope

- 审计第五层"记录不改"项全部（watch 心跳兜底、竞态转提示降级、静态常驻表、CRLF 近似、glob 双匹配器、rootMessage 隐式契约——后者建议补 ADR 条目，随文档批次另行处理）；
- 后台任务通知路由根治（task owner 加 tab 维度）——呈现位架构级，挂账结构域；
- Web 面会话懒创建（销 latest 空文件滤除的根因还账）——行为变更影响验收面，挂账；
- fileRefs 提供方归位 fs 插件——backlog 已在案，随结构域；
- route() 统一异常兜底与 token URL 面——M28 审查已记档"随安全/结构域评估"，不抢决策；
- ADR 已决策的硬编码表（高危命令表、只读命令表、忽略目录表）——非补丁，不动；
- M29+ 新功能开发。
